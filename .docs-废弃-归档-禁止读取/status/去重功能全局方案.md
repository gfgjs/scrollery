## 当前诚实边界

- P0–P3 已完成；P4 不是 fail-closed 的可用物理清理，而是当前明确未交付的能力。分析只处理字节级精确重复，不自动删除，不把 change fingerprint 当作重复证据。
- P3.2 已是当前唯一重复项体验：主画廊临时重复项镜头（筛选 chip 首位 + 侧栏「重复项」深链入口 + 旧 `/duplicates` 重定向），默认按精确重复组展示全部成员，也可切换为按传递关联文件夹簇排列；文件夹内重复、尚未确认、独有依次排列，独有大段默认折叠。MVP 仅浏览理解，不接入 keeper、建议或清理草案。
- P3.1 前端已于 2026-09-02 退场：`DuplicatesView`、`components/dedup/*`、`dedupFolderStore`、选择/树辅助组合式函数与旧 `duplicates.*` i18n 命名空间删除；后端候选/树/摘要/草案与组清理 IPC 暂保留但无前端调用方，待清理体验设计定案后统一收口。后端快照管线数字（1M 冷构建约 16.9s、峰值约 1.0GiB）仅余历史基准意义。
- 首版 IPC 只接受整个可见资料库；不接受根范围或媒体 ID 数组，避免静默扩大或缩小分析范围。
- 分组和成员默认排除 missing/offline 及零字节项；筛选显式开启时两者复用同一谓词。缺文件、不可读文件和 source drift 只记录稳定错误码，不发布旧摘要。
- Live Photo 的软删除/恢复保留主项与 companion 关系；物理清理因没有可证明的多组件原子性而未开放。
- V31 只做幂等 quick 候选索引修复；历史库中的旧 cleanup journal 保留为未消费数据，避免无确认的破坏性迁移。
- “潜在逻辑大小”不等于真实可释放空间；硬链接、稀疏/压缩文件和 clone/reflink 会降低实际回收量。
- 自动化测试只使用内存库和测试临时目录；未对真实用户媒体执行物理操作。
