## 3. P1(纪律违反 / 潜在 bug / 安全面,应尽快修)

### 3.1 Rust 后端

**B1 `save_version(overwrite)` 读源失败时静默用空备份继续覆盖用户源文件** ✅亲核
`src-tauri/src/ipc/doc_commands.rs:247`:`std::fs::read(&src_path).unwrap_or_default()`——源文件被占用/权限/瞬态 IO 失败时得到**空备份**,随后照常 write_atomic 覆盖源。备份存在的意义正是覆盖前保底,保底失败却继续覆盖,用户唯一副本可能被无备份替换。(R1 编码 seam 修复只解决了「非 UTF-8 被 read_to_string 吞空」,IO 失败路径漏了。)修复:读失败即 Err 中止 overwrite。

**B2 智能重排(reflow)把章节标题黏进正文首段**(agent 取证)
`doc_commands.rs:600-606` + `reader/paragraph.rs:48-64`:标题行无句末标点,`reflow_lines` 将其与下一行无空格黏合成首段;line 604 的标题剥离按 `first() == ch.title` 精确匹配必然失配 → 重排模式下每章标题重复渲染且污染正文首段。另 `text_index.rs:390-394` clip_title 截断加「…」后同一匹配也永不命中(超 60 字符标题同病)。修复:在 `segment()` 之前按「首行==标题」剥离。

**B3 lib.rs 后台任务在 async 块内直跑 rusqlite——且 lib.rs 在 tripwire 法外之地** ✅条款违反
`src-tauri/src/lib.rs:518-540`:PRAGMA optimize 周期任务在 `tauri::async_runtime::spawn` 的 async 块内直接 `db_writer.lock()` + `execute_batch`(违反「async 内 rusqlite 一律 spawn_blocking,零豁免」)。

**B4 `exotic/coordinator.rs` async 正文持写锁同步跑 SQL——同为 tripwire 盲区** ✅亲核
`src-tauri/src/exotic/coordinator.rs:309`:`async fn run_capability_until_drained` 每轮循环在 tokio worker 上 `db_writer.lock()` 并持锁调 `evaluate_run(&conn,…)`。**B3/B4 由两路 agent 独立发现并互证同一根因**:tripwire `ipc_commands_keep_rusqlite_off_async_workers`(blocking.rs:81-89)只扫 `ipc/*.rs + state.rs + volume_watch.rs`,而 `db_writer.lock/db_read_pool.get` 实际分布 27 个文件。修复:两处包 spawn_blocking/write_blocking;tripwire 扫描集加 `lib.rs` 与 `exotic/coordinator.rs`(或改全 src 递归+白名单)。

**B5 `clear_all_thumbnails` 删封面文件但不复位封面派生行——封面永不重跑** ✅亲核(违反 P1-4 已立纪律)
`thumbnail_commands.rs:1149-1191`:删整个 `thumbnails/`(内含 video/audio/doc 封面)+ 复位 thumb_status + 复位 exotic 任务,**唯独不动 `media_derivations`**(对照正例 `config_commands.rs:341-360` 的 clear_cache 已按 kind 复位)。失效链:派生行仍 status=2 → backfill 不再入队 → 封面永不重跑;video/audio/epub 项被主 generator 领走标 UNSUPPORTED_TYPE 灰卡,本会话内无自愈;重启 reconcile 会把死路径提升为 status=1,再经逐项 404 懒自愈,每项一次全量 invalidate+bump → 刷屏级重排 churn。修复:同事务内按 kind 复位派生行并 kick 派生流水线。

**B6 `start_full_thumbnail_generation` 全表复位波及封面类项**(agent 取证,同族)
`thumbnail_commands.rs:578-583`:复位 SQL 无媒体类型过滤,pending 查询只排 pdf/svg → video/audio/epub 被 FullThumbGen 领走标 status=2,**会话内所有视频/音频/epub 封面变灰**(派生行仍 done 不重跑),直到下次启动 reconcile 才复原。修复:复位排除「有 done 封面派生」的项,或同事务把封面派生行退 0。

**B7 锁中毒策略统一(R11)漏 12 处多行写法** (agent 系统性 grep 取证)
`thumbnail_commands.rs:1157-1160`、`scan_commands.rs:64-67/495-498`、`media_commands.rs:72-75/271-274`、`file_ops_commands.rs` 6 处:`db_writer.lock().map_err(System)` 与全库 `unwrap_or_else(into_inner)` 并存——多行写法逃过了 5ae4fd1 收敛时的单行 grep。一次持锁 panic 后,批量收藏/文件移动/清库等 12 条命令路径永久失败而其余自愈,正是 R11 要消除的行为分叉。另:`layout_cache.write().unwrap()` 与 into_inner 两套并存 7 处;ai 域 `thumb_config.read().unwrap()` 6 处、remote_registry CACHE 锁 4 处同病。修复:同一 mutex 全点位统一 into_inner(教训重申:**多行写法要用 multiline grep 验收**)。
