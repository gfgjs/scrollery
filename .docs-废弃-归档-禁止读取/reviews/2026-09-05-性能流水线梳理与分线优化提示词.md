## 共享资源协议（并行优化必读，单线优化不得擅自更改）

1. **DB 单写连接**：全部写路径经全局 `db_writer`（`Mutex<Connection>`，`src-tauri/src/db/connection.rs:41`），批内单事务。扫描、enrichment、缩略图登记、AI Writer、去重写回都在排队这条锁。
2. **BackgroundHeavyLimiter**（`src-tauri/src/exotic/limiter.rs`）：CPU permit 数 = `available_parallelism`，缩略图/派生/AI/exotic 共享；GPU 令牌额度恒 1。**获取顺序天条：先 CPU permit 后 GPU 令牌**。
3. **生命周期闸门**：扫描 generation（`RunTokenSlot`）、DB epoch、`scan_lifecycle_gate`（`src-tauri/src/state.rs:1522`），写操作须过闸。
4. **CAS 语义**：缩略图结果 `update_thumb_result_if_current`（`db/queries/thumbnail.rs:462`，按 `source_revision + cache_key`），失败写不得降级已有产物。
5. **事件契约**：`db:media_enriched`、`thumb:gen_progress`、`dedup:progress`、`enhance:queue_changed` 等事件名/payload 前端有依赖；IPC 命令签名同理。变更须同步前端 + 测试。
6. **派生文件**：先 `*.tmp` 再同卷 rename；用户路径 canonicalize + 边界检查。

## 已识别的可疑瓶颈（静态证据，动手前先实测确认）

B1【最高优先】批内逐文件 SQL（N+1 写模式）：快扫每文件 = 1 SELECT 存在性（media_upsert.rs:266）+ 1 upsert + 1 seen TEMP INSERT（:837）；enrichment 每项 = 1 SELECT 复查（enricher.rs:86）+ 尺寸/meta/sort_datetime 3 条写。全部逐条 prepare+execute，未用多行 VALUES/execute_batch。大库上这是主要写路径成本。方向：批量预查存在性（(directory_id,file_name) IN 一次取回）、合并语句、评估多行 VALUES。
B2 walkdir 目录遍历完全串行（walker.rs:113）：冷盘/网络盘上纯串行 stat。方向：并行目录遍历（如 jwalk 或自研按目录分块），须保持：流式批处理、取消响应、quick 剪枝语义、批次顺序无关性验证。
B3 QuickDirPruner 持 writer 锁判定 + 命中目录逐条 INSERT seen（fast_scan.rs:316,325）：目录多时与其它根扫描写互斥加剧。方向：批量 INSERT、缩短锁内工作。
B4 load_enrichment_source_snapshots 逐 id 单行 SELECT（enricher.rs:49-78）：每批 500/1000 项各一次。方向：WHERE id IN 一次取回。
B5 每批 3 次全局闸门往返（fast_scan.rs:886,948-973：channel send + update_scan_root_status + bump_data_version，每次都过 state.rs:1522 的闸门锁+db_writer）。方向：合并或降频。
B6 pair_live_photos 每次 enrichment 收尾对整根 JPEG/MOV 全量装载（live_photo.rs:63-90）持写锁，无谓词裁剪。
B7 fallback 批选查询无 keyset 谓词（enricher.rs:594-601, 1343-1353），并发插入多时反复触发全量扫描。
B8 TIFF 超时守卫用 detached 线程，超时后线程泄漏自跑完（metadata.rs:25-38），畸形文件批量出现时累积线程。

## 工作方式

- 先量化：给快扫/enrichment 关键段加计时日志（或 tracing span），在测试库（万级+百万级两档）跑基线，确认瓶颈排序后再改；改完同条件复测，报告前后数据。
- 根因修复优先，正确逻辑直接替换错误逻辑；改完主动清理失效分支。保持 MVP，不引入新框架/新依赖，复杂度需实际收益支撑。
- 分批提交：以独立完整子任务为一批（如先 B4/B5 低风险项，再 B1，再 B2），每批集中测试。
- 硬约束：rusqlite + 全参数绑定；async 命令中 rusqlite 走 spawn_blocking；不跨 .await 持 std Mutex；派生文件 tmp+rename；SQL/事件对外契约不破坏（事件名、upsert 语义、缺失检测四道闸、SuspectChanged 指纹定案语义必须保持）；注释中文解释 why。
- 保持共享资源协议：所有写仍经全局 db_writer 单写锁 + 批内单事务；如你认为协议本身该改（如多写连接），只做方案论述不要实施。
