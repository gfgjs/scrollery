# 全仓代码消融实施报告

基线为 `e7db489b66f3d939784678ccf4d6849b7eec5304`，源码终态为 `31cab793934ec8fa1b634414fee00a0229d07bd7`。七批实施已完成，第一方代码 **264,655 → 254,057 LOC，净减 10,598 行（4.00%）**；第一方文件 **927 → 906**。另删第三方分发资源 **162 文件 / 7,862,271 字节**，单独计账。全部为本地中文提交，未推送。

P12 H-Lab 全栈按用户要求保留，P23 不支持任何历史数据库迁移。分析候选见 [第一轮报告](README.md)，量化数据见 [final-metrics.json](final-metrics.json) 与 [接口/配置清单](final-surface.json)。

## 主要复杂度来源

1. 新入口接管业务后，旧 IPC、DTO、查询和仅供旧入口使用的测试仍编译在产品中。旧去重页面是最大闭包，不能只删除命令注册。
2. 实际只有 direct 分发，代码却保留三个渠道、交付工厂、授权空桩与构建互斥检查；存储连接测试也套着未接入扫描的通用后端接口。
3. 画廊同时装配两套虚拟滚动，通过设置切换；布局来源再包一层转发对象，选择模式用动态注册表维护一个实现。
4. 当前结构由 33 段历史数据库升级重建；配置同时存在 DB→TOML 迁移、未知键回落、旧主题别名和旧阅读位置格式。
5. 未接线的未来能力、测试观察接口以及第三方分发附带物缺乏退出机制。纯静态引用不足以裁剪编辑器动态资源，需要实际触发公式、图形和预览加载。

## 后续仍值得消融的区域

- DOM 与 Canvas 都有生产消费者，应先取得平台交互、图像格式与可访问性证据，再决定是否收敛；当前不能按“两个实现”直接删除。
- StartupConfig 与字符串配置还存在序列化成本；下一轮应按真实热点缩小字段类型，避免引入一套配置编译器把复杂度搬家。
- P25 若将来统一图像色彩契约，可重新评估缓存写入路径；本轮不把潜在 ICC 行为变更夹带在剪枝中。
- storage 连接管理当前保留，但扫描只消费 OS 挂载路径。是否删除整个连接管理产品功能属于下一次明确取舍，不能把通用后端裁剪误报为远程扫描能力升级。
