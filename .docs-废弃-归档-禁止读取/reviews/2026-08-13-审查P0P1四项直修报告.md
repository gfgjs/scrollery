### ① P0 —— verify-bundle-content.mjs MSI 载荷断言必误报(门禁硬红)

- **位置**:`scripts/verify-bundle-content.mjs`(拆包校验层 `listArchiveEntries` / `checkPayloadEntries`)
- **问题**:Tauri v2 MSI 把资源文件匿名化为 `PathFile_<hash>`(无扩展名,实测 7-Zip 25.01 递归展开 app.cab 后 4 个 ORT DLL 均为该形态),按名比对永远匹配不到 `onnxruntime.dll` 等四项 → release.yml 的「安装包内容断言」、`build-internal-installer.ps1` 每次构建必红。**实机复现**:对 `target/release/bundle/msi/Scrollery_0.1.0_x64_en-US.msi` 报「载荷缺失:onnxruntime.dll, directml.dll, dxcompiler.dll, dxil.dll」(NSIS 15 条目通过)。注:2026-08-11 的 worklog 曾把该误报当作「断言有效」的证据,实际是匿名化假阳性。
- **修复**:新增 `checkPayloadEntriesMs` —— 侧车(`Bin_` 前缀保留原名)仍按名归一化比对;被匿名化的 4 个 DLL 改为**按字节尺寸**在条目尺寸多重集中逐一匹配(缺项/截断都会错开尺寸被擒);staging 缺文件的 DLL 跳过(① 层已报,不重复)。`listArchiveEntries` 改为同时返回 names+sizes(`Size = ` 前缀与 `Packed Size = `/`Physical Size = ` 不冲突)。selftest 新增 MSI 正样本(PathFile_+Bin_)、缺项反样本、截断(尺寸不符)反样本三例。
- **验证**:selftest 过;实机跑真实 MSI(11 条目)+ NSIS(15 条目)全绿。改前 MSI 必红、改后绿,门禁恢复可用。

### ② P1 —— ask 模式关闭在心跳陈旧时静默直退(6 角度独立命中)

- **位置**:`src-tauri/src/lifecycle.rs`(`FRONTEND_HEARTBEAT_TIMEOUT_MS` / `should_allow_native_close` → `close_decision` + 新增 `resolve_ask_close`)、`src/App.vue`(onMounted 心跳装配)
- **问题**:3s 超时 + 1s 心跳只有 2 tick 余量,`frontend_is_alive()==false` 即放行原生关闭。三个真实缺口:启动首心跳落地前点 ✕、JS 主线程卡顿 >3s(重网格渲染/import storm)、**最小化/隐藏后 Chromium 隐藏页计时器节流**(隐藏约 5 分钟后约 1 次/分)→ `close_behavior="ask"` 用户点任务栏 ✕ 直接退出、无确认框,与配置语义相悖。
- **修复**:
  - 分派重构:`should_allow_native_close`(bool) → `close_decision`(enum `AllowNative`/`Frontend`/`GraceWait`)。`minimize_to_tray` 死臂删除(该分支在 `on_window_event` 提前返回,原 arm 不可达——顺带修掉 simplification 命中项)。
  - ask + 心跳陈旧 → **宽限任务** `resolve_ask_close`:先恢复窗口可见(`unminimize`/`show`/`set_focus`,解除隐藏页节流),250ms 间隔轮询心跳至多 10s;心跳恢复 → 转交前端 `window-close-requested`(确认框照常弹出);耗尽仍无心跳 → `window.destroy()`(失联窗可关的原始修复目标保留,只是延迟有界)。`CLOSE_GRACE_PENDING` 原子位防重复 ✕ 堆叠宽限任务/重复 emit。退出路径(`exit`/未知值+失联)语义不变。
  - 前端补心跳:窗口重新可见(`visibilitychange` 回前台)与 `focus` 时立即补发一发,回前台瞬间刷新存活,不依赖节流计时器。
- **验证**:4 个新单测(`close_decision` 三分支 + exit/unknown 语义,均过,`cargo test -p scrollery lifecycle` 5 passed);`minimize_to_tray` 行为测试移除(实际行为=`on_window_event` 内原生隐藏,窗口级不可单测,已在代码注释说明)。**真机 GUI 手测项**(不可自动化):最小化 >5min 后任务栏 ✕ 应弹确认框而非直退;启动期立刻点 ✕ 应出确认框。

### ③ P1 —— mediaStore navContext 在途窗口脱节(3 角度独立命中)

- **位置**:`src/stores/mediaStore.ts`(`openDetail` / `navigateDetail`)、`src/stores/mediaStore.spec.ts`
- **问题**(两个子缺陷):
  - `openDetail(fromLayout)` 在 fetch 完成**后**才清空 `navContext`:在途窗口内旧搜索上下文残留,方向键按旧列表导航;IPC 失败时清空永不执行 → 旧上下文永久残留。
  - `navigateDetail` navContext 分支在 fetch **前**推进 `currentIndex`:在途窗口内索引超前于展示项,连按方向键时第三次按键以错误的显示项为基准导航(跳项/落错位)。
- **修复**:`openDetail(fromLayout)` 清空 `navContext` 移回 fetch 前(同步,恢复旧代码语义);`navigateDetail` 的 `currentIndex` 提交移入 generation 守卫块内(与 `detailItem` 同批提交),并删除已被结构保证的 `context.currentIndex === nextIndex` 条件。
- **验证**:新增 4 个 spec 测试 —— ①fromLayout 在 fetch 完成前即清空旧上下文;②IPC 失败不残留旧上下文;③currentIndex 只在响应提交时推进;④重叠 navigateDetail 旧响应被丢弃、索引与展示项一致。vitest 全量 134 files / 1532 tests 绿(mediaStore.spec 2→6 项)。
