# 分册 03:前端(aiStore / faceStore / personStore / 视图与组件)

> 快照 2026-07-10,dev `68e23e8`。U=前端。i18n 双语与 serde 契约核验为脚本化静态验证,仅本地。
> ⚠️ **时效**:U1(并行会话 e8820a4)与 U2/U3/U4/U7 已于同日修复(交付清单见 [README 文首标注](README.md)),本册对应段落为修复前现状记录。

## 1. 前端数据流(现状)

- **分析控制流**:aiStore/faceStore 各持完整 status ref,分析半部(2s 轮询、start/pause/restart/stop、断点续传、进度、providerLabel)统一委托 `useAnalysisController`(5 命令+getter+2 回调参数化,S6 去重)。**无后端推送事件**——运行中靠 isAnalyzing 驱动的 2s 轮询;App.vue 启动双 `maybeAutoResume` 并列触发,互斥交后端 GPU 单持有者槽(前端不做顺序假设,边界正确)。
- **语义搜索流**:AppToolbar 三模式(mixed/semantic/normal)→500ms debounce→`runSemanticSearch`→后端写 `ai_search_results` DB 表(≤1000)→前端仅 `invalidateLayout()`,画廊经 useJustifiedLayout 以 filters.aiSearch+aiThreshold 重算——结果不物化前端内存,阈值滑杆(300ms)只重布局不重搜。
- **人脸/人物流**:personStore 持簇数组+审批分组;PersonsView 进页 load+loadLikelyMatches(50);点卡片→viewStore.setActivePerson→画廊按 personId 过滤;查看器人脸框 getFacesForItem 按图拉取投影(faceToken 乱序防护+rAF 节流+旋转态诚实隐藏,俱佳);模型库下载走 Tauri Channel 流式进度。

## 2. 发现清单(U)

### U1 🔴 FaceApprovalPanel / OnboardingWizard 的模态覆盖层样式实际不存在 【亲证(静态);真机终证待办】
- 位置:FaceApprovalPanel.vue:5(`class="dialog-overlay approval-overlay"`)与 :286(注释「复用全局 .dialog-overlay」但 scoped style 只定义 z-index 与卡片宽);OnboardingWizard.vue:5/:201 同病。
- 证据(主审全仓 grep 亲证):`.dialog-overlay/.dialog-content` **只定义在 5 个组件各自的 `<style scoped>` 内**(CloseConfirmDialog:101 / ConfirmDialog:68 / FolderCreateDialog:149 / FolderTreeSelectorDialog:188 / ExoticActivateDialog:137);`src/assets/styles/` 全套无此类,全仓无非 scoped style 块。Vue scoped CSS 编译为 `.dialog-overlay[data-v-xxx]`,**不跨组件生效**。
- 影响:审批面板拿不到 `position:fixed; inset:0`+遮罩+居中——将以普通流内 div 渲染在 PersonsView 底部,非模态。useFullscreenExitGuard 靠 querySelector('.dialog-overlay') 判断,类名仍在,守卫不受影响。
- 存疑说明:OnboardingWizard 曾真机验收过;若真机上向导正常,说明存在未被发现的注入路径——但静态证据链完整,真机一验即知。
- 建议:把 `.dialog-overlay/.dialog-content` 基础样式提升到全局层(index.css),各对话框留特化覆盖,顺带消 5 份重复定义。

### U2 🟠 AI start/restart 的后端拒绝对用户完全不可见 【子代理报告;onError 实现亲读印证】
aiStore.ts:54 的 onError 一律 console;后端在 GPU 槽被 face 占用/模型未装时返回的用户级中文错误(如「人脸分析正在进行,请先暂停…」)没有任何 UI 出口——用户点「开始分析」spinner 转完无事发生。faceStore(:48-55)同场景已走 toast 且注释自述理由,AI 侧未对齐。建议:onError 对 start/restart 走 toast(用 ipcErrorMessage)。

### U3 🟠 rebuildEmbeddings 一键清空全库向量,无确认
SemanticSearchPanel.vue:68-75 的 ghost 小图标直接 `@click="ai.rebuildEmbeddings()"`(后端还会打断运行中分析);侧栏同等破坏性的「重新开始」有 confirm(ToolsSection.vue:328-344)。误点一次=全库重嵌入(GPU 数小时)。建议加同款 confirm 或降级为「补齐缺失项」语义。

### U4 🟠 runSemanticSearch 无 in-flight 令牌,乱序应答污染结果(与后端 A17 全局单表叠加)
aiStore.ts:100-142:两次查询并发在途时,后完成者覆盖 ai_search_results(画廊显示 A 结果而 semanticQuery 是 B)、旧 finally 提前灭 spinner、matchCount 被后落地者覆盖。项目在 ContentViewer 人脸加载已有标准解法(faceToken)。建议:模块级自增 token,应答落地前比对,旧应答连 invalidateLayout 一起丢弃。

### U5 🟠 人物封面 / FaceAvatar 用 CSS background:404 无信号、无自愈、无生成通路 【与 LRU 驱逐孤儿已知病灶互证】
PersonsView.vue:164-184、FaceAvatar.vue:32-53。CSS 背景加载失败无 onerror——LRU 驱逐孤儿(记忆:thumb-lru-eviction-orphan)场景下画廊线有 `<img> onerror → regenerateThumb` 懒自愈(useThumbLoader.ts:96-114),人物墙渲染成空白圆无自愈;coverThumbStatus=0/2 时回退占位且**无任何请求生成路径**(除非用户去画廊滚到那张图)。建议:改 `<img>`(object-fit/position 同样可做脸心定位)以获得 onerror,404 复用画廊 regenerate 通路——顺带解 U12(loading="lazy")。

### U6 🟡 进出语义模式丢用户分组/排序偏好
aiStore.ts:117-126/177-193:用户本就 groupBy='none' 时 previousGroupBy 保持初始 'date',退出被强改;sortWithinGroup='filename' 退出被强设 'datetime' 而非还原。建议进入时无条件快照 {groupBy, sortWithinGroup},退出整体还原。

### U7 🟡 用户可见错误文案带 "IpcError: " 前缀
faceStore.ts:51、PersonsView.vue:156、FaceApprovalPanel.vue:246/278、aiStore.ts:138 均 `String(e)`;utils/ipc.ts:99 已提供 ipcErrorMessage() 未用。统一替换。

### U8 🟡 personStore 写操作失败静默(rename/setHidden/merge)
personStore.ts:41-74 catch 后仅 console 不 rethrow;PersonsView 无 toast;merge 失败时选择集已被清。与同 store 审批系列「传播 reject 由调用方 toast」是两套矛盾策略。建议对齐审批模式。

### U9 🟡 状态栏只显示 AI 进度,人脸分析无任何全局指示(AppStatusBar.vue:79-94 v-else-if 链仅 ai);侧栏折叠时完全不可见。

### U10 🟡 模型下载进度是组件本地态,离开设置页即丢(ModelLibrary.vue:176、FaceModelLibrary.vue:74-76)
后端下载继续但重进页面按钮显示「下载」,用户再点可能并发两条(靠 Range 续传兜底不损坏,体验割裂)。建议下载态上移 store 层,组件只订阅。

### U11 🟡 停止/暂停与 2s 轮询乱序竞态(useAnalysisController.ts:65-75/119-151):在途旧应答晚落地 → UI 闪回「分析中」并重启轮询,2s 后自纠。建议 fetchStatus 加请求代次(与 U4 同一模式)。

### U12 🟡 PersonsView 无虚拟化 + 封面全量即时加载(CSS 背景无 lazy):数百簇可用,数千会卡。与 U5 修法合一(`<img loading="lazy">`)即低成本解决,虚拟化暂不必。

### U13 🟡 SemanticResultCard.vue 整组件死代码(268 行)【亲证:全仓零引用】
语义结果现走 DB 物化→布局管线注入,该卡片(含相似度徽章/选择 UI)被架空;副作用=「逐项相似度徽章」功能在现行路径**不存在**(缺口册 §2.4)。建议删除;徽章若要,应在画廊卡片按 isSemanticMode 实现。
