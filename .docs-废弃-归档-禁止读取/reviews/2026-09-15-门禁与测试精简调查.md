### 测试规模与覆盖边界

- Vitest 配置包含 `src/**/*.spec.ts` 与 `scripts/**/*.spec.mjs`，环境是 node；Vue 组件主要通过 SSR 或 mock 验证，不等于真实 WebView 交互验收。
- 前端共 168 个 spec 文件（src 166 + scripts 2），src spec 约 26,672 行。子代理静态统计 1,820 个 it/test 声明（含参数化声明），不是展开后的执行用例数。
- Rust 项目源码 328 个文件，行首匹配到 1,595 个 `#[test]` 属性、12 个 `#[ignore...]`；这是静态规模，受 cfg、参数化属性、doc-test、平台和运行环境影响，不当作实跑数。
- 根 workspace 10 个 member，raw-worker/raw-probe 在外；raw-worker 的 3 个测试不能用根 workspace test 替代。
- 外部资产验收包含 OCR 模型、FFmpeg、插件 registry/签发目录；ignored 中还混有微基准和会写入前端 golden 文件的生成器。不能统一执行 `--ignored` 当作“补跑全部漏测”。

## 2. 优先做：流水线去重与分流

### A. 按改动范围决定重 job，取消过期日常运行（高优先级）

证据：`ci.yml:14` 的事件配置和各 job 没有 paths/changes 条件，文档修改也会调度 Windows Rust、Linux Rust、前端、RAW。CI 与 docs-governance 都未配置 concurrency；main/dev 分支有打开的 PR 时还可能同时触发 push 和 PR 两次。

建议以少量粗粒度分类处理 docs、frontend、rust、raw、shared/build 配置，不做每个测试文件的复杂依赖图。锁文件、构建脚本、协议/IPC 共用接口、CI 本身进入共享触发范围。日常同分支旧运行可取消，发布和同步保持现有串行、不取消语义。

若线上存在 required checks，优先保持稳定的最终汇总 job，按变化跳过内部重 job，避免直接跳过整个工作流导致待检查状态。实施前要读取线上规则；本轮未查证这些规则。

### B. 去掉同一 job 的前置 cargo check（高优先级候选）

Windows `ci.yml:72` 的 check 紧接着同参数的 clippy 与 test，优先保留 fmt + clippy + test，删除这一次 check。它主要贡献更早的普通编译诊断，并非独立测试覆盖。

Linux `ci.yml:141`、公开投影 `oss-gate.yml:76` 的 check + test 也可核对目标、features、profile 后合并。不要因此删掉 Linux 测试或 RAW 独立 check；它们覆盖不同平台/独立包。

构建缓存使重复命令并非完整重编三次，节省多少尚未测量。首次调整要核对实际目标覆盖，不宣称编译时间可直接减半。

### C. 发布仅构建一份前端，再扫描这份最终产物（高优先级）

`release.yml:89` 先 `npm run build`，`:98` 又运行 Tauri build；`src-tauri/tauri.conf.json:9` 的 beforeBuildCommand 内再次 `npm run build`。同一发布 job 明确构建两次。

建议由一处负责前端构建，渠道扫描绑定打包所用 dist。可让 Tauri 构建后再扫描并在发布前阻断；若 Rust 测试编译需要 dist，需相应重排步骤。也可以显式复用已生成 dist，但需防止本地构建误用陈旧产物。保留预算门和渠道扫描。

### D. NOTICE 生成只解析一次（中优先级）

`release.yml:68` 连跑 `generate-notice --check`、`generate-notice`、`git diff --exit-code -- NOTICE.md`。生成器两次都会扫描固定资源、解析依赖、渲染 NOTICE（`generate-notice.mjs:446`），第二次额外生成 SBOM。

建议提供一次解析同时“校验 NOTICE + 输出 SBOM”的模式。直接删除生成步骤会丢 SBOM，不能这样精简。现有生成后 git diff 方案也可去掉前置 check，但需明确行尾归一化语义，原 check 在 `:462` 专门处理 CRLF。

### E. 文档门按其真实依赖降频（中优先级）

不建议只监听 `docs/**`：`.worklogrc.jsonc` 启用源码引用扫描，源码移动/删除也可能使文档引用失效。可以让纯产品逻辑编辑跳过无关生成步骤，但要涵盖源路径变化、配置、baseline、文档和工作流本身。

2026-09-15实施复核更正：不能从 `index.mode=generated` 推断 CI 的裸 `index` 命令只生成文件。本机已缓存的精确版本 worklog-kit@0.1.0-alpha.4 中，`bin/worklog.mjs:65` 的裸 index 最终调用 `checkIndex`，`src/check-index.mjs:84` 检查目录职责和归档登记双向一致性，不写 `.worklog/generated`。这与正文 check 互补，保留该步骤；原“输出无人消费、可考虑降频”推断撤回。

### F. RAW 与跨平台保留覆盖，调整频率（中优先级）

RAW 默认路径实际是 release test + build，见 `scripts/acceptance/raw-worker-test.mjs:218`、`:227`。按 RAW/协议/构建依赖变化触发可节省独立工具链工作；发布仍保留产物验证。

`--cold-proof` 是显式手动诊断，不在当前 CI 调用中，无须为日常 CI“删除它”。该选项证明 test harness 不能替代普通 worker 二进制。

公开 Rust 测试在 `oss-gate.yml:82` 全部 `--test-threads=1`。这是可测量候选，不能直接改并行：需先找出共享环境变量/路径/进程状态测试，证明隔离后再只串行必要部分。本轮没有并行安全性证据。

## 4. 应保留的门与需要澄清的通过状态

- lint 与 typecheck 检查面不同；当前 ESLint 还守裸 invoke、日志和 i18n 约束。ESLint 使用 skipFormatting，未见独立 Prettier CI 门，因此不存在“删掉重复 Prettier 门”的现成收益。
- 版本、路径、协议同步、主题可读性、主题 token/首帧脚本、bundle 预算保留。生成物一致性与对比度不重复：前者检查是否按锚点生成，后者检查生成出的颜色是否符合阈值。
- DB/文件移动与恢复、扫描代次、异步取消、协议签验/解码、IPC 错误契约测试保留。它们承载真实失败边界，不用测试文件长度作删除标准。
- 投影构建与源仓构建针对不同树；发布测试针对 tag SHA/Windows/安装包。密钥推送前扫描与公开历史扫描时点不同。现阶段无须为了“统一入口”全部合并。
- `video-worker/tests/e2e_ffmpeg.rs:119`、`:317` 在未设 SCROLLERY_TEST_FFMPEG 时直接 return，测试框架会记通过。建议显式 ignored/专项套件，并在要求视频验收时缺依赖报失败，报告区分执行/跳过。
- `thumbnail/thumbhash.rs:164` 的 ignored 测试生成并写入前端 golden；OCR、插件外部目录验收、微基准应分清入口。生成器可逐步迁专用命令，避免“全部 ignored”误运行。
- `tools/check_plan_canonical.mjs` 还在，但当前 CI 已移除调用（`ci.yml:177`），只检查历史 Part 文档七条规则。可标明手动维护或退役，不应宣传删它能加速现行 CI。`scripts/install-skills.mjs` 同理是手动工具，不是当前门禁。
- 旧名门 active=true，不是休眠空跑。其 CI 注释仍讲休眠阶段，判定应以 JSON 配置为准。

## 5. 建议的最小目标结构

1. 每个相关改动：轻量静态检查 + 对应前端/Rust/RAW 任务；稳定汇总结果。同分支过期普通 CI 取消。
2. 前端：lint、typecheck、Vitest、一次构建（含预算）、扫描该次 dist。
3. Rust：Windows fmt/clippy/test；Linux 对相关改动继续编译/测试；RAW 独立验证按范围运行。
4. 公开同步：继续对公开投影独立验证和扫描；如投影树未变，可后续评估无需重复验证的可靠标识。
5. 发布/专项：安装包内容、启动、外部模型/FFmpeg 等按真实验收条件运行，明确缺项；不让单测 green 替代真机能力结论。

先落实 A/B/C，再做 NOTICE 去重与两处重复测试合并。字符串测试替换、全局串行优化、文档 index 降频需要各自补证据，不作为无条件删除清单。
