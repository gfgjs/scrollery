## 0. 综合执行摘要

两份独立评审对同一仓库得出了**高度收敛的总判断**:

> 赛道真实、栈选对了、工程质量高;最大风险是"建的东西比卖的东西多"——产品边界失控、信任闭环(备份/导出/身份)缺失、变现与激活层为零。谁都没有建议推倒重写;两边的第一建议都是**停止扩张**。

在此共识之上,两报告各自贡献了对方没有的关键信息:

- 甲带来了**市场计时器**:直接竞品 Lap(同栈同定位,已发布)、Chinese-CLIP 上游弃养、DirectML 维护冻结、模型/编解码许可地雷图、定价对标——"为什么要快"。

**综合裁决:v0.1 的路径 = 冻结扩张 + 变现闭环与轻量用户验证并行推进 + 一组低成本"数据安全网"随行;深层领域模型重构(Asset v2/统一 Job)作为并行工作线分期落地,不阻塞首发。**(裁定理由见 §4 争点 1/2。)

## 4. 分歧与裁定(本综合的核心增值)

### 争点 1:先变现(甲 P0-3)还是先地基与用户验证(乙 Stage 0/1 作为 release blocker)

两报告的"第一优先"表面冲突:甲主张 Part8 最小变现闭环先于一切新特性;乙主张 Stage 0 用户访谈+Stage 1 数据地基是发布阻断门。

**裁定:拆包并行,不二选一。**
- 乙的 P0 清单里混着两类东西:**低成本安全网**(V-1 fail-closed、迁移前快照+catalog 自动备份、策展导出、V-3 路径验根前置、V-4 向导起扫描——每件都是天级工作)与**深层重构**(Asset v2 分表、统一 Job/Artifact 全量、Operation Journal 完整态——每件都是周级+回归面大)。前者纳入 v0.1 前置;后者**不阻塞 v0.1**,列为并行工作线分期落地。
- 乙的 Stage 0(10-15 名用户访谈)以**轻量形式与 Part8 并行**,不做串行阻塞门——但其"退出门"思想保留:若访谈证伪"零迁移+本地智能找图"痛点,停止扩张性投资(乙 Kill criteria 采纳)。
- 裁定理由:①两报告共同的敌人是"继续扩功能",谁先谁后都好过再造特性;②甲的独有情报(Lap 已发布在迭代)使"先到用户"的权重上升——完美地基+零用户 对阵 粗糙地基+真实反馈循环,后者在本细分的历史上(Immich 多年带着不完美模型高速增长)胜率更高;③v0.1 是单渠道/小体量/单实例场景,安全网四件+D-1 前两步已覆盖乙所述风险的主要暴露面,全量 v2 的边际收益在该体量下不成立。

### 争点 2:Asset Identity 手术深度——全量 v2 模型(乙 §9)vs 渐进三步(甲 D-1)

**裁定:目标图景采纳乙,首期动作采纳甲,合并为一条演进线。**
- **终态**采纳乙的模型方向:asset 与 file_instance 分离、关系显式化(raw+jpeg/live/burst/edited)、extracted vs user-authored metadata 分域、重链接次序(路径→文件系统 id→size+快指纹→全量 hash→模糊候选进人工 Review)与"宁留两个候选,不误合并"原则。
- **首期**只做甲 D-1 步 1/2:派生缓存键改锚 content_hash(解"移动/改名即全量重派生")+content_hash 升一等公民(回填+去重地基),配乙的重链接次序 1/3/4 三级;`file_instances` 物理分表推迟到"去重 UI/多副本管理"需求实证时(乙 15.1 Strangler 思想本身也支持只迁用户事实、分期切换)。
- 同时采纳乙两条约束:content_hash 不设 UNIQUE(同内容多副本合法);系统对象 stable code 化(V-5 的修正)。

### 争点 3:开源投影拓扑——乙建议翻转为"公开 core 是 canonical"(11.9)

**裁定:不翻转。** 乙对"一次漏规则=源码+密钥+构建三重泄漏面"的风险定性正确,但:私有 canonical+Copybara 剥离+四层防线(标记块/glob/lock 剥离/oss-gate+gitleaks+drift-alarm)已建成且经真实推送实证(甲 §4.1/内部 A·B 线收官记录);翻转拓扑=对已验证管线的推倒重来,巨量迁移换边际风险降低,且公开-canonical 会把 pro 开发变成"永远追着公开 API 跑"。**采纳其增量加固**:hermetic projection fixture、SBOM、构建 provenance/attestation 列 P2 渐进补。

### 争点 4:插件商店"退出一级导航"(乙)vs "v0.1 靠 exotic-formats 插件变现"(甲/内部切割线)

**裁定:两者兼容,合并执行。** 商店从一级导航(Library 区)移入 Manage/设置域,以"解锁高级格式支持"的单一购买面存在;营销不打"插件平台"故事;商店的完整市场形态(多插件/浏览/生态)后置。变现载体不变,叙事重量降级——同时满足乙 P0-1 与内部 v0.1 切割线。

### 争点 5:评分口径——乙"商业清晰度 1/5"vs 甲"商业化机械完成度高"

**说明(非真分歧)**:乙评的是"用户可懂的包装"(Free/Pro 能力矩阵、买什么、锁不锁数据——确实为零),甲评的是"工程机械"(seam/渠道/签发——确实已建成)。合并结论:**机械完成、包装未做**,两者之差恰是 Part8 的工作内容,佐证争点 1 的裁定。
