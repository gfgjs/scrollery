## 一、总体判断

- **不误伤的底线**:`layout/items_cache.rs` 双键统一缓存、`db/queries/layout/query_builder.rs` 单一事实源、`utils/natural_sort.rs` 自研排序、`thumbnail/qos.rs` 线程预算、`exotic-protocol` 帧格式、supervisor 进程 kill/reap、pipeline 原子领取+租约+熔断、授权门控纵深、oss-gate/copybara/gitleaks 四层防线——**每处都有实测数字或真实事故背景,属正当复杂度,不应砍**。

## 二、P0(2 条,高复杂度低收益,建议优先处置)

### P0-1(exotic/installer.rs:87 等)——多渠道投机抽象:PluginDeliverySource trait + Steam/Store 死变体 + 双 stub
- **证据**:`pub trait PluginDeliverySource { fn channel(&self) -> InstallSource; }`(仅一个返回常量的方法);`InstallSource { DirectRegistry, SteamDepot, StoreBundled }`;`SteamDepotDelivery`/`StoreBundledDelivery` 注释自认「stub(Part8 实装)」;安装路径第一行 `if source != DirectRegistry { return Err(ChannelUnsupported) }` 即拒绝——**两个渠道值在代码上永远不可能写库**。
- **判据**:投机性泛化 + 过度防御/协议。
- **建议**:砍掉 trait 与两个 stub,`InstallSource` 收敛为单一 direct 事实;渠道落地时再加(YAGNI)。同源连带:channel_stubs.rs 的 MS Store/Steam 授权桩(恒 Unlicensed,Part8 D5-D8 预留,见 P1-2)。

### P0-2(enhance/registry.rs:20 等)——enhance 未发货全套基建:模型清单占位但 host 已交付 1210 行
- **证据**:`PENDING_REPO_BASE = "https://huggingface.co/PENDING_USER_REPO/resolve/main"`;`profile_assets` 产出 `size_bytes: 0, sha256: None`;`enhance_manifest_ready` 恒 false(测试锁定),`download_enhance_model` 对每档恒回 `enhance_manifest_unready`——**端到端对用户不可达**。但 host 侧已交付 `EnhanceService`(job 队列、preview、`estimate_tiles_total`、`admission_check`、EXIF 注入、claim/rename/ingest)+ worker crate + 协议 op + 进度估算。
- **判据**:镀金/无消费者代码。
- **建议**:模型清单 URL/sha256/字节数未钉定前,把 host 编排/队列/驱动/EXIF 注入/ingest 标记为「随模型供应链一起上线」或整体 feature-flag 不编入 Release;保留 catalog 门控与设置页展示。⚠ 勿删:worker 进程隔离、`models_root`/`work_dir` 白名单校验、fail-closed 是正当安全设计。
