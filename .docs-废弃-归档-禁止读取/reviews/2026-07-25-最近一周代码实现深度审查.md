## Findings

### P0

#### F-01：AI/OCR/增强 worker 没有进入正式包，增强在 fresh dev 也不可用

`src-tauri/tauri.conf.json:6,9,54`：🔴 bug：dev 只构建 `ai-worker`，production 不构建它；`enhance-worker` 两条路径都不构建，`externalBin` 只列 `raw-worker`。把实际发货的 worker 全部纳入 target-aware 构建与 Tauri sidecar/resource 打包，并增加安装包内容断言与 fresh-install 启动测试。

证据链：

- `src-tauri/src/ai/worker_client.rs:597-616` 只在主程序同目录找 `ai-worker[.exe]`。
- `src-tauri/src/enhance/service.rs:1043-1063` 同样只在主程序同目录找 `enhance-worker[.exe]`。
- 全仓没有把这两个可执行文件复制进 bundle 的脚本；`src-tauri/binaries/` 在提交树内也没有对应产物。
- `cargo build -p ai-worker` 只存在于 `beforeDevCommand`；`beforeBuildCommand` 是前端构建加 RAW worker。workspace member 只保证全量 workspace 构建可编译，不会让 Tauri 自动把 sibling binary 装进安装包。

影响：增强命令进入 worker 时稳定返回“可执行文件不存在”；正式包的 OCR、语义/人脸 AI 同样无法拉起 `ai-worker`。CI 的 `cargo test --workspace` 会编译 worker 测试目标，却不能证明安装包包含 worker，现有绿灯会漏掉这一发布断链。

### P1

#### F-02：增强模型占位清单被标为 ready，下载按钮必然走向无效地址

`src-tauri/src/enhance/registry.rs:18-39`：🔴 bug：URL 指向 `PENDING_USER_REPO`，`sha256=None`、`size_bytes=0`；`src-tauri/src/ipc/enhance_commands.rs:81-85` 却用 `enhance_assets(...).is_some()` 产生 `manifestReady=true`，`src/components/settings/EnhanceSettingsSection.vue:52-60` 因而启用下载按钮。真实 URL/hash/size 未定案时返回 manifest unready；定案后钉定资产元数据并加可达性/校验测试。

这不是无害 TODO：设置页已经向用户开放入口，点击会进行真实网络请求后报通用下载失败。结合 F-01，增强子系统虽有完整 UI、IPC、queue 和 worker 代码，但 fresh install 没有一条可完成的用户路径。

#### F-03：配置写锁只覆盖单进程，双实例会碰撞固定 tmp 并丢失不同键的并发更新

`src-tauri/src/config/mod.rs:141-184`：🔴 bug：`write_lock` 只属于单个 `ConfigManager`；`src-tauri/src/config/file.rs:369-378` 固定写 `config.toml.tmp`。使用 OS 级跨进程锁，锁内重读、校验和改写；临时名加入 PID/单调序号，并用双 manager/双进程 barrier 测试两键不丢。

另有单进程乱序窗：`src-tauri/src/lib.rs:1066-1069` watcher 取旧快照后直接 `replace_values`，不进入写锁、不校验磁盘版本；它可以在 IPC 已写出新值后用旧快照回退内存，随后自写 fingerprint 又吞掉新文件事件。修复应让 watcher 与 IPC 共用版本化提交入口，而不是只补临时文件名。

#### F-04：配置 schema 只验基本类型，合法 TOML 可停掉流水线或触发巨额分配

`src-tauri/src/config/schema.rs:40-79`：🔴 bug：`SettingDef` 没有区间/离散约束；`src-tauri/src/config/file.rs:119-134` 的 `UInt` 只拒负数。为每键声明 min/max/allowed values，并由文件加载、IPC、迁移共用同一 validator，消费点不再各自 clamp/fallback。

可直接证明的结果：

- `derive_batch_size=0` 进入 `src-tauri/src/derive/pipeline.rs:331-335,459` 的 `LIMIT 0`，流水线拿空批后退出。
- 巨值进入 `src-tauri/src/derive/pipeline.rs:685` 的 `Vec::with_capacity(batch_size as usize)`，可能 panic 或异常分配。
- `thumb_webp_quality=200` 被配置层保存，运行层在 `src-tauri/src/ipc/config_commands.rs:384-386` 静默夹成 100，形成持久值、UI 值、运行值三源分裂。
- `video_keyframe_count=0`、`backup_retention=0` 等同样可过 schema；注释里的“典型范围”不是约束。

#### F-05：`thumb_cache_dir` 热切换把空串当相对路径，并在 async 路径持锁做同步 IO

`src-tauri/src/ipc/config_commands.rs:432-443`：🔴 bug：外部编辑恢复默认空串时直接 `PathBuf::from("")`，随后持 `thumb_config` 写锁执行 `create_dir_all` 和 asset scope 变更。抽出启动/热路径共用的 `resolve_cache_dir(app_data_dir, raw)`；canonicalize、建目录和 scope 处理移入 blocking 段，锁只保护内存赋值。

前端仍有第二个分裂：`src/components/media/ContentViewer.vue:694-705` 等消费方把缓存目录各自存成局部 `ref`，外部配置事件只刷新 store，不更新所有已挂载/KeepAlive 消费者。后端开始写新目录后，现存 URL 仍指旧目录。应改为响应式全局单源，并覆盖“自定义 A→B”“自定义→默认”“KeepAlive 已挂载”三条测试。

#### F-06：RAW externalBin 在非 Windows 与交叉构建目标上必然缺文件

`scripts/build-raw-worker.mjs:24-30,78-95`：🔴 bug：非 Windows 直接成功退出，但 `src-tauri/tauri.conf.json:54` 无条件声明 `binaries/raw-worker`；脚本还按 `rustc host` 命名，而 Tauri 按实际 build target 取 `<name>-<target-triple>`。把 externalBin 移到 Windows 平台配置，或为每个支持 target 产出真实 sidecar；目标 triple 必须来自 Tauri build target，不是编译宿主。

影响：macOS/Linux 的 Tauri bundle 会找不到对应 sidecar；`tauri build --target aarch64-pc-windows-msvc` 会生成/保留 x86_64 名称，ARM64 包无法完成或拿不到正确架构。脚本注释“跳过不阻断跨平台 build”与它自己第 10-12 行记录的“Tauri 对缺失 sidecar 硬失败”互相矛盾。

### P2

#### F-07：外部编辑 `ai_hq_cache_enabled` 不重启派生流水线

`src/composables/useConfigFile.ts:68-78`：🟡 risk：`DERIVATION_RESTART_KEYS` 漏 `ai_hq_cache_enabled`，而派生在 `src-tauri/src/derive/pipeline.rs:303-327` 只于每轮开始快照配置。加入该键，或把 watcher/设置页副作用统一收敛到后端单源；补外部编辑 false↔true 的 backfill 测试。

#### F-08：后一次纯热编辑会清掉仍待重启的提示

`src/composables/useConfigFile.ts:104-114`：🟡 risk：每个事件都用本次 `restart_required` 覆盖 `restartRequiredKeys`。先改冷键再改热键时，第二个空数组会把尚未应用的重启要求清掉。后端维护 startup-applied snapshot，每次发送“当前配置相对启动快照”的完整 pending 集合；不要简单 union，否则用户改回原值时无法销项。

#### F-09：首次迁移把所有 SQLite 错误当“键不存在”，随后永久跳过重试

`src-tauri/src/config/migrate.rs:20-48`：🟡 risk：`query_row(...).ok()` 吞掉锁、IO、schema/类型错误，仍写出 `config.toml`；下次启动因文件已存在直接 no-op。只把 `QueryReturnedNoRows` 映射为 None，其余错误向上传播且不得建文件；补一次失败不落盘、二次可重试测试。

同文件 `:61-69` 还把任何未知 Bool 文本规范为 `false`，会把损坏值伪装成用户明确关闭。只接受 `0/1/true/false` 的已知形式，其余跳过并记录键级警告。

#### F-10：增强“队列”没有 FIFO 调度，多个 job 会同时显示 running

`src-tauri/src/ipc/enhance_commands.rs:243-259`：🟡 risk：每次入队都立即 `spawn_blocking`；`src-tauri/src/enhance/service.rs:316-330` 在取得 worker `Mutex` 之前先把 job 标成 running。`std::sync::Mutex` 不承诺按 job id/FIFO 唤醒，多个任务的实际执行顺序可重排，排队任务也会长期显示 running。改为单一 dispatcher 从显式 FIFO 队列取 job；只有真正取得执行槽后才转 running，取消 queued job 不应再生成等待中的 blocking task。

#### F-11：增强产物 ingest 失败被丢弃，job 仍上报 done

`src-tauri/src/enhance/service.rs:580-607`：🟡 risk：文件落盘后 `ingest_single_file` 的结果被 `let _ =` 吞掉，随后 `process_item` 返回 Ok、done 自增。传播稳定的 saved-needs-index 结果或错误，并安排 root 增量扫描；不要把未入库文件计作完整成功。编辑链 `src-tauri/src/ipc/edit_commands.rs:364-378` 已有 `SavedNeedsIndex` 契约，可直接复用姿态。

#### F-12：增强预览复用固定路径，第二次结果可能继续显示第一次缓存

`src-tauri/src/enhance/service.rs:687-698,775-785`：🟡 risk：每次都覆盖 `enhance_preview/before.png` 与 `after.png`；`src/components/enhance/EnhanceDialog.vue:323-331` 再次赋值时 URL 字符串不变，Vue 不会更新 `<img src>`，asset/browser cache 也没有版本信号。为每次预览使用 request id/随机名或 URL query version，成功切换后清理上一代文件；补连续两组参数预览后像素确实变化的测试。
