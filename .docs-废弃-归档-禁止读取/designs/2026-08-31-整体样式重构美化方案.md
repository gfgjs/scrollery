## 2. 设计方向

### 2.1 定位:「暗房 Darkroom」——专业媒体工具语言

> **界面是暗房,照片是光。** Chrome 后退为安静的中性工作台;内容(媒体)是唯一被允许喧哗的东西。

参照系:Adobe Spectrum(创意工具 token 化中性阶梯)、Linear(密度与 quiet 控件)、Eagle/Picsee(资产管理器的内容优先)、Apple Photos 编辑模式(黑场纪律)。ui-ux-pro-max 产品库对「文件管理/媒体工具」的推荐同向:Flat Design + Minimalism,功能性中性色 + 文件类型色编码。

与清透方案的关系:清透方案验证了「中性 chrome + 受控层级」方向正确,但只落了 token 管道;本方案把同一方向推进到**观感本体**——几何、密度、色板、组件配方全量重写。

### 2.2 设计原则(优先级序)

1. **内容绝对主角**:画廊/查看器的视觉权重全部让给媒体;UI 元素的默认态必须「退后」。
2. **中性 chrome,单一交互 accent**:每主题中性阶梯承载 95% 的像素;accent 只用于选中/当前项、主操作、focus 与位置/进度指示。success/warning/error/info 使用独立语义状态角色,不借用或 alias 到 accent。
3. **层级靠明度阶梯与发丝线,不靠阴影**:普通容器零阴影;阴影只服务 float/modal 两档。
4. **密度是专业感的来源**:13px 基准、紧凑控件、4px 基网;留白靠布局节奏而非控件膨胀。
5. **一套配方,六套个性**:几何/材质/纪律全主题共享;主题只改色板与纹理。
6. **徽章即图例**:文字徽章统一使用高对比 scrim;类别色只作为图标、色条或圆点标记,跨主题保持同一语义,不让整块高饱和底色重新主导缩略图。

### 2.3 非目标

- 不改信息架构、路由、交互模型、数据流。
- 不动 canvas 渲染管线的性能契约(格内绘制、虚拟化、minimap 轴)。
- 不改 Viewer 黑画布豁免;不动 Xuan 纸张纹理的存在权(只约束其使用范围)。
- 不引入新 UI 框架/组件库/Tailwind;Vue SFC + CSS 变量路线不变(项目规则)。

四层结构保留(variables → themes → material → glass),重写的是**数值与纪律**。

### 3.2 字号(13px UI 基准)

| token | 现值 | 新值 | 用途 |
|---|---|---|---|
| --font-size-2xs | 11 | 11 | 徽章/角标/计数 |

### 3.4 阴影与层级纪律

| token | 新用途纪律 |
|---|---|
| --shadow-sm | **仅** sticky 元素与 raised 微托举;普通容器禁用 |
| --shadow-md | float 档:popover/menu/toast |
| --shadow-lg | modal 档:dialog/drawer |
| --shadow-xl | 仅全屏查看器控制条等特殊浮起 |

亮色主题阴影整体减重 30–50%(层级主要由明度阶梯+发丝线承担);暗色主题同样以明度阶梯 + 低 alpha 亮色发丝线分层,不靠一味加深阴影(纯黑附近阴影本身不可见),阴影仅补充 float/modal 与背景的空间关系。material.css 的 inset highlight 高光层默认关闭(那是玻璃语言,非暗房语言)。

### 3.5 色彩角色(架构不变,纪律新增)

- **中性阶梯**:--color-bg-primary/secondary/surface/elevated/inset 五档,**每主题由单一 (H, C) 锚点沿 OKLCH 明度轴派生**,但按角色保持稳定顺序:亮色 `elevated ≥ surface > secondary > primary > inset`,暗色 `elevated > surface > secondary > primary ≥ inset`;禁止出现 elevated 比 surface 更暗、inset 比 secondary 更亮的语义倒置。常规 chrome 色度上限为亮主题 C≤0.012、暗主题 C≤0.02;身份表面例外为 Xuan 暖纸 C≤0.02、Dai 蓝黑 C≤0.03,避免把六主题收敛成同一套灰。
- **accent 五角色**:accent / accent-hover / accent-subtle / accent-text / text-on-accent 由 accent 锚点按亮暗极性派生。accent 服务填充、描边与图标并对 surface ≥3:1(图形态);accent-text 专供链接、active chip/导航文字,对其实际背景 ≥4.5:1,必要时在亮主题中比 accent 更暗;text-on-accent 对 accent ≥4.5:1。hover 亮主题降 L、暗主题升 L;subtle 亮主题 8–10% alpha、暗主题 12–14% alpha,但 alpha 只决定底色强度,不得用 accent 本身兼任不达标的文字色。所有最终合成色进入对比度检查。
- **语义状态色纪律**:沿用当前 success/warning/error/info 按亮/暗槽位固定两套色相的方向,每类扩为 `status`(前景/描边)、`status-subtle`(浅底)、`text-on-status`(实心状态底上的文字)成对角色;不得假定一个 hex 同时适合文字与填充。状态色与 accent 色相接近的主题(Xuan/Ink)中,错误/成功必须同时使用图标或文字标签,不得 alias 或复用 accent token。
- **媒体徽章**:所有带 11px 文字的信息/类型徽章统一用固定暗底 scrim(60% 黑底/白字);AUDIO/DOC/LIVE 的类别色只作为前置圆点、短边条或图标点色,不再让白字直接压类别彩底。类别点色按色相分别校准、对 scrim ≥3:1,不使用跨色相统一 L/C 窗口;ORIG 完全归入 scrim 系。徽章 token 只在共享色板层定义一次,六主题不得重复覆写;palette.ts 只读取 computed style,若保留 fallback,则由同一 canonical 常量生成或用测试断言一致。
- **评分星**:统一 rating 专用 amber `#fbbf24`,只用于媒体 scrim/深底(图形对比约 3.44:1),不复用 warning token;不得直接作为亮色 chrome 上的文字或小图形。评分数值/可访问名称保留,不靠颜色单独表达分数。

### 3.6 动效

- 时长档保留 120/200/350;按压 scale(0.97) 从全局 .btn 移除(移动端语言),桌面按压态改用与背景极性相反的明度变化:亮色主题压暗,暗色主题提亮。
- 所有过渡属性白名单:background-color / color / border-color / opacity / transform(仅指示器);禁 transition: all。

## 4. 主题重设计

### 4.1 派生方法

每主题定义中性色相/最大色度锚点与 accent 的 L/C/H 锚点;仅主题相关的表面阶梯和交互 accent 由其派生。文本、语义状态、徽章及媒体画布遵循各自角色契约,不从 accent 锚点推导。

- 中性五档(顺序均为 primary/secondary/surface/elevated/inset):亮主题 L 基线 `0.975/0.990/0.995/1.000/0.955`;暗主题 L 基线 `0.190/0.220/0.250/0.290/0.170`。Obsidian 的纯黑 primary 与 §3.5 的 Xuan/Dai 身份色度为显式例外;最终值可微调,但不得破坏角色明暗顺序。
- accent 交互态:亮主题 `hover = accent L-0.08`,`subtle = accent 8–10% alpha`;暗主题 `hover = accent L+0.06~0.08`,`subtle = accent 12–14% alpha`。accent-text 独立沿 L 轴向高对比方向派生,直至压最终 subtle 合成背景 ≥4.5:1;不通过无限降低 subtle alpha 来掩盖文字色不足。实测候选 accent 直接压 8% subtle 时 Moonlight/Porcelain/Xuan 分别仅 4.28/4.44/4.40,因此三套亮色主题都必须使用独立 accent-text。
- text-on-accent 按 accent 亮度选择深/浅文字,不假定所有 primary button 都是白字;六主题分别验算。
- 采用**构建期生成静态值**:生成脚本从锚点产出各主题最终 sRGB hex/rgba,快照/契约测试守派生关系;主题 CSS 只落可被现有门禁解析的静态值。运行期 color-mix 仅限少量交互叠层,且必须在门禁先支持浏览器 computed style 或等价合成计算后使用。现有 check-theme-contrast.mjs 只解析 hex/rgb/rgba,在扩展前禁止用运行期 oklch()/color-mix() 承载需要硬门的核心色对。

| 素 Porcelain(亮) | 暖白 + 粉 | accent #e16496→#b83f6d(降饱和降明度;对 #f6f8fa 实测 4.97:1,留出抗混色余量);底暖灰化 |

候选 accent 的 WCAG 快速复核(基于当前相邻背景;B1 仍须对最终生成背景重跑):Moonlight #0273b4 最低 4.77:1、Porcelain #b83f6d 4.97:1、Xuan #b8381f 4.92:1、Ink #2fbd8b 7.10:1、Obsidian #60a5fa 7.74:1、Dai #2dd4bf 9.17:1。原候选 Porcelain #c94f7c 仅 4.03:1,明确废弃。

### 4.3 门禁扩展

- theme-contract.spec:加「五个 accent 角色六主题同构」「状态色按亮/暗槽位同值且 paired roles 齐全」「徽章类别点色只在共享色板定义」「palette.ts fallback 与 canonical token 一致」「中性角色明暗顺序」断言。
- check-theme-contrast:加普通字号 primary/secondary/tertiary/placeholder 文本对全部实际消费 surface ≥4.5:1;accent 图标/focus ring/必要边界对相邻颜色 ≥3:1;accent-text 对实际背景 ≥4.5:1;text-on-accent 对 accent/accent-hover ≥4.5:1;accent-text 对 accent-subtle 最终合成背景 ≥4.5:1;每组 status 前景对实际 surface/status-subtle ≥4.5:1,text-on-status 对实心 status ≥4.5:1;白字对 60% scrim ≥4.5:1;类别点色与 amber 评分星对 scrim ≥3:1。透明/color-mix/scrim 必须先合成再计算,不留给纯人工判断。
- 组件契约/人工验收:Xuan/Ink 的错误/成功反馈必须含 icon 或文字标签,不能由主题色契约测试代替组件级冗余编码检查。

## 5. 组件观感规范(分区蓝图)

### 5.1 全局控件(index.css 配方重写)

- **.btn**:高度档 28(sm)/32(md)两档统一;radius-sm(6);按压去掉 scale;primary 实心 accent + text-on-accent;default=ghost;secondary 1px 描边。
- **.btn-icon / UiIconButton**:28px quiet 化——默认透明无边框,hover 出 bg-hover,active/pressed 出 accent-subtle + accent 图标色。顶栏图标视觉噪声主要落此。
- **.chip**:默认无边框透明(现状已是);hover 仅 bg-hover;**active = accent-subtle 底 + accent-text 文字,去边框去字重跳变**(修 B4);图标可继续用满足 3:1 的 accent;高度 24px;icon 14px。
- **.input/.select**:高度 32→**28/32 按场景区分**(工具栏 28,表单 32);底色 input-bg 减重,border 常态 input-border,focus = accent border + 2px ring(现状保留)。
- **.toggle/.checkbox**:随 13px 基准等比微缩(toggle 40×22→36×20)。
- **滚动条**:--scrollbar-width 6→8,thumb 透明度降一档,track 恒透明;画廊自绘 MediaScrollbar 同步调窄。

### 5.2 卡片与表面

- **.settings-card 重定义**:bg=surface,**去阴影去 inset 高光**,1px border-subtle,radius-lg(10);卡内条目分隔线不变。
- **设置页大表面化**(采纳清透方案 §6.2):同组 section 合并为单卡,卡内标题(2xs 大写)+分隔线+行 hover;危险区/导入导出等保留独立 elevated 卡。消灭同强度卡片墙(修 C1)。
- **accordion**:闭合态去卡片感,仅标题行+细分隔线;展开态内容直接落在页面上不再套底。

### 5.3 浮层(统一收口)

- 全部浮层(popover/dialog/toast/context menu/selection bar)强制走 material float recipe;**14 处 backdrop-filter 使用点全部归 token 管控**(修 C3):裸写点(SettingsView/SelectionToolbar/ToastContainer/MediaThumb/AppShell)改消费 --material-blur-float 或显式豁免注释。
- dialog overlay:亮主题 0.28、暗主题 0.5 仅作起始值,须在 gallery/settings、Xuan 纹理与玻璃模式的真实背景分别验证合成结果和前景隔离度;dialog radius-xl(12)+ shadow-lg。
- UiDialog floatSurface opt-in 提升为默认(清点 7 对话框逐一确认后翻转默认值)。

### 5.4 顶栏/标题栏/状态栏

- 顶栏三段秩序固化:左(品牌+导航动作)/中(标题+计数+筛选芯片)/右(搜索+视图+窗口键);中段落允许 chips 溢出进 ⋯(useToolbarOverflow 已有)。
- 筛选芯片执行 5.1 chip 规范;7 枚芯片文字墙(B1)经「active 才重、inactive 纯 quiet」解决,不删功能。
- 日期分隔符(修 B3):**去全宽 accent 顶条**,改为 13px/600 日期文字 + 计数 12px 次要色 + 底部 1px divider;12px 次要文字仍须对实际背景 ≥4.5:1。sticky 态浮起走 shadow-sm。canvas 与 DOM 两路同改(palette 单源)。
- 状态栏:高度 28→26,字号 12,信息段间用 divider 而非各自容器。

### 5.5 侧栏

- 导航行扁平化:默认透明,hover 低 alpha,active = accent-subtle 底 + accent-text 文字(整行填充,与设置导航一致);选中指示图形可用 accent。
- 分组头:2xs 大写 + tertiary(沿用 settings-card__header 模式),去边框;11px tertiary 仍按普通字号文本 ≥4.5:1,不得降到图形态 3:1 门槛。
- 工具卡(ToolsSection):去 border 去 shadow,改 surface 填充 + radius-lg;进度信息收敛为一行 meta 文本。

### 5.6 画廊

- 徽章体系(修 B2):所有信息与类型徽章统一 scrim(60% 黑底/白字/11px/radius-xs);AUDIO/DOC/LIVE 以共享色板的小圆点/短边条/图标区分类别,白字不直接压彩底;ORIG 完全归入 scrim 系(它是来源标记非状态)。评分星统一为 rating 专用 `#fbbf24`,仅出现在媒体 scrim/深底并与星形/分值共同出现,去掉按分数变色的多色逻辑(StarRating)。亮图、暗图和高对比纹理图分别验证 scrim 合成结果。
- 选中态:accent 2px 内描边 + 角标勾选,选中底色 accent-subtle 不铺整卡。
- 缩略图 1px 内描边(--color-thumb-outline)保留。
- minimap/时间轴:指示色改 accent 派生(随主题),当前位置指示减重。

### 5.7 设置页

除 5.2 外:左导航卡去浮白卡感,融入 chrome(透明底+active 行填充);「使用引导」按钮降 ghost;搜索框 32→28。

### 5.8 查看器

黑画布豁免不动;控制条/底栏材质统一 float recipe;底栏信息行(评分+色标+文件名+元数据)按 13px 基准重排;色标圆点 12→10px。
