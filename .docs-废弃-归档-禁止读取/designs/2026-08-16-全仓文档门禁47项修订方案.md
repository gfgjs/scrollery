# 全仓文档门禁 47 项修订方案

## 1. 目标与边界

本方案处理当前 `worklog-kit check` 报告的 47 项文档门禁违反，目标是让每一项都有明确的字段修订、生命周期裁决和验收证据。

本轮边界明确为：

- 只修改 `docs/` 文档及其治理元数据，不修改 `src/`、`src-tauri/`、配置代码或测试代码。
- 不把问题重新登记进 brownfield baseline 来换取绿灯；baseline 只记录经明确裁决、暂不处理的存量问题。
- 不在同一批次顺手重排正文、更新易漂移的代码行号或改写未授权的技术结论。
- 不吞并当前工作树已有的无关未跟踪文件；每批只触及本方案列出的文档。

## 2. 问题盘点

当前 47 项违反可以按“文件数 × 字段缺口”复算：

| 批次 | 文档 | 文件数 | 当前问题 | 项数 |
|---|---|---:|---|---:|
| A | `docs/planning/2026-07-25-超长文件拆分方案/analysis/` | 14 | `type: analysis` 非法；除 `tierB-2.md` 外缺 `line` 和 `id` | 41 |
| B | `attachments/尺寸榜单-2026-07-25.md` | 1 | `type: attachment` 非法；缺 `line`、`id` | 3 |
| C | `reviews/2026-07-31-全仓代码深度审查与直修.md` | 1 | `status: 快照`、`type: 审查快照` 非 canonical | 2 |
| D | `reviews/2026-08-10-中断工作盘点与核验.md` | 1 | 缺完整 YAML frontmatter | 1 |
| **合计** | **17 个文档** | **17** |  | **47** |

当前机器真源是 `.worklogrc.jsonc` schemaVersion 5：`status`、`type` 使用 ASCII canonical，`line` 必须引用 `docs/lines/<line>.md` 实体。`docs/README.md` 中保留的中文枚举说明已经漂移，本方案不把它当作门禁判定源；治理说明的同步另列后续任务。

## 4. 执行批次

### 批次 0：冻结基线（只读）

记录以下结果后再编辑：

```powershell

npx.cmd --yes --package worklog-kit@0.1.0-alpha.4 worklog-kit baseline

```

将门禁输出中的 47 项与本方案第 2 节对照；若清单发生变化，停止批次 A，先重新盘点，不用旧输出施工。

只改 14 份 `analysis/*.md` 的 YAML 头。采用显式文件清单和 `apply_patch`，不得对整个 `docs/planning/2026-07-25-超长文件拆分方案/` 做无差别格式化。完成后先执行：

```powershell
npx.cmd --yes --package worklog-kit@0.1.0-alpha.4 worklog-kit check
```

预期违反数从 47 降至 6（B=3、C=2、D=1），且不应出现新的断链或位置错误。

### 批次 2：B/C/D 语义修订

依次修改尺寸榜单附件、2026-07-31 review 和 2026-08-10 review。除 frontmatter 外只加入本方案明确的时效/后继提示，不重写正文。完成后运行：

预期目标清单违反数为 0；若全仓仍非 0，必须列出新增/既存来源，不得用 `baseline --update` 直接消除。

### 批次 3：生命周期收口（独立后续，不作为本次清账前置）

`2026-07-25-超长文件拆分方案` 三件套已经记录阶段完毕，但其 `findings.md` 仍声明 F-057/F-058，且 `docs/planning/2026-07-25-超长文件拆分施工/`、`docs/completed.md` 等文件仍引用 planning 路径。待用户另行确认收口后再：

此批次不应与 A/B/C/D 元数据清账混在同一提交中：它涉及候选蒸馏、路径移动和索引同步，回滚面明显不同。

## 5. 验收标准

### 必过项

- 目标 17 个文档的 47 项违反全部消失。
- `type: analysis`、`type: attachment`、中文机器枚举值不再出现在这 17 个文档的 frontmatter 中。
- 每个非三件套文档都有合法 `id`、`status`、`type`、`line`、`created`；`line` 实体真实存在。
- `check --links-only` 通过，未引入跨目录断链。
- `git diff --name-only` 只包含本方案列出的文档，不包含任何源码、测试或构建产物。
- `git diff --check` 无空白错误。

### 需人工抽查

- 14 份分析稿仍明确“方案/草案”，没有被误标为已执行或现行正典。
- 尺寸榜单仍带 2026-07-25 快照边界。
- 2026-08-10 盘点报告明确后继关系，且没有把历史候选自动转成当前待办。
- baseline 条目数没有因本批次机械放大；任何新增挂账必须单独说明理由。

## 6. 回滚与停止条件

- 每个批次单独提交，提交前保存 `worklog-kit check` 输出和显式文件清单；发生问题时用对应提交的 `git revert` 回滚，不使用 `reset --hard`。
- 如果门禁在批次 1 后没有从 47 降到 6，停止后续编辑，先核对门禁版本、文件路径和清单漂移。
- 如果批次 2 引入断链、重复 ID 或 line 实体冲突，回滚批次 2，不触碰已通过的批次 1。
- 如果发现 2026-07-25 任务的候选处置无法在本轮裁决，保留 planning 目录，不能为了清零门禁擅自迁移或删档。

## 7. 不在本方案内的治理债

`docs/README.md` 仍使用中文 taxonomy 说明，而 `.worklogrc.jsonc` 已采用 ASCII canonical；这是治理文档漂移，不属于当前 47 项的直接违反。应另立治理同步方案，明确“展示本地化”和“机器 schema”两层，避免在本批次混改造成新的门禁噪声。
