# 时间轴密度带 canvas 升级方案

> 快照日期:2026-07-10。本方案承接「canvas 转正」对比结论(见 dev 分支 `fa7ff96`/`7fd39ea`:
> 两版已同标准,DOM 在当前「数百离散标记」量级全面占优)。当密度可视化升级到**日级分辨率 +
> 连续密度带 + 全轨渐变聚光**这三点同时成立时,标记数与视觉复杂度越过 crossover,canvas 成为
> 结构性正解。本方案即设计这个 canvas 子系统。

## §0 背景与决策

三个下一步需求——**①日级粒度、②高级视觉、③实时全轴渐变高亮**——本质是**同一个 canvas 子系统的
三个面**,而非三个独立特性:

- 统一心智模型:把主轴从「离散月密度条」升级为**一条重采样到屏幕像素行的连续密度带(density
  ribbon)**,叠加**光标跟随的渐变聚光**。
- 数据分辨率 = 日级(甚至逐项);**渲染分辨率 = 轨道像素行数(≈700,与库大小解耦)**。数据层只在
  预计算时遍历一次 splat 进 ~700 个桶,**每帧绘制成本恒定 O(trackH),与库规模无关**——这把
  「canvas 在大数据下赢」从口号变成本设计的结构性事实。

### 决策(2026-07-10 用户拍板)

坐标系与视觉形态两处分叉,用户裁定:**两种坐标 + 三种视觉全部做成可一键切换的开关,真机体验后
再定留舍**。理由:视觉/交互分叉只有真人看过才知道选哪种(承 `no-contract-freeze-during-dev`:
开发期不以未实测的判断冻结契约)。

- 坐标与视觉**正交**:坐标 = 数据怎么摆(y 的含义),视觉 = 摆好的密度怎么画。故是 **2 + 3 两组
  独立开关**,共用同一条 `rowIntensity` 数据管线,非 6 个实现。

## §1 坐标系(两种,可切)

主轴纵向 y 的含义,两种坐标各有取舍:

### A. item-proportional(项累计空间;当前设计,零后端)
- y ∝ 项累计 → scrubber = **精确滚动 minimap**,点击 y 像素级精确映射滚动位置(现契约零回归)。
- 密度呈现:每像素行「该处 items/天」→ 横向长度。繁忙期 = 又厚又亮的宽带。
- 数据来源:直接从现有 `separators` 的 `(y, count)` 推导,**无需后端改动**。
- 空日:项空间无「空日」概念,天然无缝。

### B. time-proportional(日历时间空间;经典照片时间轴)
- y ∝ 日历时间 → 呈现纵向疏密:繁忙周挤成尖峰、淡季留白低谷(近 Apple/Google Photos)。
- 密度呈现:纵向尖峰(某日项数 → 该日历位置的强度)。
- 跳转:点 y → 反查该日历位置对应的日 → 该日 logical y → 跳转(需 day→y 映射)。
- 后端改动:需每个 date 模式 separator 携带 **`epochDay: i64`**(见 §9),用于线性日历定位 +
  空日间隙检测(相邻 epochDay 间隔 >1 = 空日,前端零填充成低谷)。

> 两坐标各产出一个 `Float32Array(trackH)` 的 `rowIntensity` + 一个 `rowJumpY` 映射(点某行跳到哪个
> logical y),下游视觉/交互统一消费,坐标切换只换这两个数组的构建方式。

## §2 视觉形态(三种,可切;纯前端)

同一 `rowIntensity`,三种绘制:

1. **填充包络 + 轻热力(envelope)**:横向长度 = 密度,右对齐填充,顶部 accent「山脊线」;填充色按
   强度在 `--color-border`→`--color-accent` 插值(低淡高浓,alpha 0.15~0.5)。长度 + 颜色**双通道**
   编码密度,信息量最高。
2. **纯热力色带(heat)**:全轨等宽,仅用颜色浓淡(border→accent)表达密度。极简、像「地铁线密度」,
   信息量较低。
3. **包络 + 强热力/光谱(spectral)**:横向长度 + 更强的冷→暖光谱映射。最抢眼,需克制避免喧宾夺主。

外加保留 **0. 离散月条(bars,当前实现)** 作对比基线 → 视觉模式共 4 档循环。

公共叠加(所有视觉/坐标通用):年分界亮线(复用 `isYearBoundary`)、active 段整段提亮、当前位置线
(已两版对齐)。folder 模式同款(文件/文件夹密度带,零特判)。

## §3 统一数据层:rowIntensity

纯函数(带单测),放 `timelineScrubber.helpers.ts`:

```
buildRowIntensity(separators, totalHeight, trackH, coord): {
  intensity: Float32Array(trackH),   // 已归一化 [0,1]
  rowJumpY:  Float32Array(trackH),   // 每像素行点击 → 跳转的 logical y
}
```

- **item 坐标**:遍历 separators,separator i 覆盖 y 区间 `[y_i, y_{i+1})`(末个到 totalHeight)→
  映射像素行区间 `[r0, r1)`,累加 `count_i` 与权重;`intensity[r] = Σcount / Σweight`(该行平均
  items/天);`rowJumpY[r] = (r/trackH)*totalHeight`。
- **time 坐标**:需 separator 带 `epochDay`;按 `[firstDay, lastDay]` 线性铺行,day d → 行
  `(d-first)/(last-first)*trackH`;`intensity[r]` = 落该行的日的项数(空日间隙 = 0);
  `rowJumpY[r]` = 该行对应日的 `y`(从 separators 的 day→y 查)。
- 成本 O(separators + trackH),仅数据引用变 / 尺寸变时重算(与现 canvas watch 时机一致)。

## §4 渲染管线(canvas 双缓存)

让 hover/聚光近乎免费:

1. **底层带(offscreen 缓存)**:数据/尺寸/坐标/视觉模式变时,把 `intensity` 画进一张 offscreen
   canvas(每行一段 `fillRect`,700 次,一次性;可选纵向 3-tap 平滑柔化包络)。
2. **每帧合成**(滚动/hover):`drawImage(底层带)` + 聚光(§5)+ 当前位置线 + LOD 刻度/年标 +
   active 段提亮。每帧 ≈ 1 drawImage + 1 渐变填充。

## §5 特性③:实时全轴渐变聚光

光标行 `cursorRow`,合成实现(推荐):一个竖直 `createLinearGradient` 三段(0→透明、cursor→
accent@0.6、→透明,`R ≈ trackH*0.18 ≈120px`),覆盖全轨矩形以 `source-atop` 只染到带上 →
**每帧一次渐变填充**,成本可忽略。逐行 `mix(base, accent, smoothstep(...))` 为更可控备选(700 次/帧
仍轻松 60fps)。

> canvas 杀手锏演示:DOM 做等效全轨 falloff 需 700 元素或逐帧改 CSS mask,基本不可行。

## §6 特性①:日级粒度(LOD 刻度/标签)

密度带本身已日分辨率。**刻度/标签**按像素预算分级,避免 700px 塞 7300 日刻度:
```
ppMonth = trackH/总月数;  ppDay = trackH/总天数
year 标签:恒显(复用去挤叠逻辑)
month 刻度:ppMonth ≥ 8px 才显
day   刻度:ppDay  ≥ 4px 才显(多为短跨度/小库触发)
```
概览尺度大库通常停 month;日级细节主战场仍是放大镜(已 K=9 每日 label+count,零改动)。

## §7 交互 / a11y / 跳转

- 键盘 `stepScrubberIndex`、role=slider、放大镜:**零回归**。
- 跳转吸附:item 坐标复用 `nearestSeparatorIndex`;time 坐标点行 → `rowJumpY[row]`。
- hover 高亮、当前位置线:两坐标通用。

## §8 切换 UI + 持久化

canvas 时间轴上一组紧凑控件(承 MediaGrid 现有 `timeline-mode-btn` 惯例):
- 渲染层:`[DOM | Canvas]`(现有)
- Canvas 下:`坐标 [项 | 时间]`、`形态 [条 | 包络 | 热力 | 光谱]`
- 各自 localStorage 持久化(`timelineCoord`、`timelineVisual`),与现 `timelineRenderMode` 同惯例。

## §9 后端改动清单

- **item 坐标 + 三视觉 + 聚光 + LOD:零后端**(全由现有 `separators`/`monthBuckets` 推导)。
- **time 坐标:唯一后端改动** = `SeparatorInfo` 加 `epochDay: i64`(date 模式填该日 epoch 天数;
  folder 模式可置 -1/None)。落点 = `layout/cache.rs` 现 `count` 累加同一处,~3 行;前端
  `LayoutSummary.separators` 类型同步加 `epochDay`。**不需**稠密日直方图(epochDay 间隙即可零填充)。

## §10 分期(每期独立 gate:vue-tsc / eslint / vitest / vite build)

- **P1(零后端)**:`buildRowIntensity`(item 坐标)纯函数 + 单测;canvas 渲染三视觉(envelope/heat/
  spectral)+ 保留 bars 基线;视觉模式切换 + 持久化。→ 真机先体验视觉分叉。
- **P2**:全轨渐变聚光(合成实现)+ active 段提亮。正交作用于所有视觉/坐标。
- **P3(🟢 已交付 2026-07-10,仅本地验证)**:time 坐标全链落地。后端 `SeparatorInfo.epoch_day`
  (`sort_datetime.div_euclid(86400)`,与 `GroupMark::Day` 同源;穿过 `LayoutRow::Separator`→
  `store_layout`,folder/none=None)+ round-trip 特征化测试;前端 `buildTimeBand`(intensity 日历铺行 +
  空日 rowJumpY 线性插值 + 月/年 LOD 刻度)+ `logicalYToTimeFrac`(指示线逆映射)+ 9 单测;canvas
  坐标切换按钮(coordApplies 双门控:date 分组 + 密度带视觉)+ 持久化 `timelineCoord`;time 坐标下
  band/jump/hover/loupe 统一走 `fracToLogicalY`(唯一分叉点)、指示线逆映射、年标改 yearTicks 重定位、

  **诚实边界**:视觉/交互观感⏸真机;time 坐标下放大镜命中语义仍按 nearestSeparatorWindow(loupeLogicalY
  已按坐标校正,命中正确)。
- **P4**:真机 Performance 面板抓 scroll/飞掠 paint timing,与 DOM 版并排实测;定视觉/坐标留舍;
  DOM 版去留决策(§12)。

## §11 性能预算 + 真机验证 + 诚实边界

- 预计算 O(separators+700),数据变时一次,~sub-ms。
- 每帧双缓存 ≈ 1 drawImage + 1 渐变,预期 <0.3ms。
- **诚实边界**:以上为路径推理,**未真机抓 paint timing**;P4 须实测坐实,方可作 canvas 转正 /
  DOM 退役的 Done 证据(承 CLAUDE.md「Done = 有证据」)。

## §12 DOM 版去留

密度带三视觉(700 行渐变)+ 聚光,DOM 结构上做不了 → canvas 成主实现。策略:canvas 承载新特性 →
P4 真机达标 → 退役 DOM 版(或降级留「低功耗简条模式」)。达标前 A/B 并存,不急删。
