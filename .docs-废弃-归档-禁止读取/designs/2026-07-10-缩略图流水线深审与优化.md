## 0. 背景与方法

用户指令「深度 Review 缩略图生成流水线(图片/视频/PDF/TXT/EPUB…),优化代码、完善功能、提升性能」。
方法:两路只读 agent 分域勘查(后端 Rust 流水线全图 / 前端请求·渲染·缓存链)→ orchestrator 亲核全部关键
写路径(五条流水线的 `thumb_status` 写入点、DocThumbRenderer 主泵、canvas 状态机)→ 分批施工,每批全量
验证后独立 commit。

**流水线全景**(审查时点):`media_items.thumb_status/thumb_path` 有五个写入方——主图像生成器
(batch/full-gen 两命令)、派生流水线 writer(video/audio/epub 封面)、exotic worker 落库、
`store_doc_thumbnail`(pdf/svg 前端渲染回传)成败两支——全部汇聚到 `db::queries::update_thumb_result`。
状态语义:0=待生成 / 1=已生成(相对缓存路径)/ 2=失败·无缩略图 / 3=小文件直显(绝对源路径)。

## 3. 生成引擎 A/B(方案一 Rayon vs 方案二流水线)——✅ 已裁决收官(2026-07-10,`cfe63d8`)

### 3.1 背景

`thumbnail_commands.rs` 自早期起并存两套并发架构,由编译期 `const USE_PIPELINE=true` 选择,方案一
(Rayon 直线并发:每项全程一个工作线程,work-stealing 均衡)从未在真实负载上与方案二(多阶段流水线:
解码 `cores×2` / 编码 `cores` / CPU 兜底 `cores/2` 三线程池 + channel,IO·GPU·CPU 重叠)实测对比,
注释「方案一在多核上性能最好」为未经实测的历史直觉。Part3-T13 原裁决「死代码暂缓删除」已被本线推翻:
**先运行时化 + 公平化,实测后据实裁决去留**(正文已回写 Part3 §3.1.4 / T13)。

### 3.2 A/B 公平性修复(`daab834`,不修则测的是 bug 不是架构)

- **F1** 方案一全库生成进度 IPC 零节流(逐张发送,方案二正是因「8 万+ 条挤掉侧栏 rAF」加的节流)→
  `PROGRESS_THROTTLE=100ms` 提升为两方案共用;方案一 par_iter 内共享 `Mutex<Instant>`。
- **F2** 方案一批量路径 `filter_map`+`zip` 错位雷(§1-#3)+ 加载失败静默跳过违反「每请求 id 恰一结果」
  不变量(问题9)→ 改 `map` 显式携带 id,失败发失败结果;仅「已取消」不产结果(对齐方案二 dispatcher)。
- **F3** 方案二全库 Phase 2(GPU 回退的 CPU 项)单线程逐个消化(自家批量路径 T12 有 cores/2 专用池)→
  rayon 分块并行(块=max(cores,10)),每块一次事务批写。

其余核对项两侧对等不动:取消语义(双方都跳过已取消项)、失败计入进度、DB 批写节奏(每 50 一事务)、
方案二通道 drop 顺序(无死锁/无泄漏)。已记录不改:方案二批量路径每批 spawn ~3.5×核数临时线程
(架构本身,若 A/B 后方案二胜出可做常驻池优化)。

### 3.3 运行时开关

- 真相源 `AppState::thumb_use_pipeline`(AtomicBool),配置键 `thumb_use_pipeline`(默认 true=方案二);
  设置页**开发者工具**节 toggle「缩略图引擎:多阶段流水线」;每次生成命令调用读一次(在途批不换挡),
  日志 `[FullThumbGen] START: … pipeline=…` 打印当次引擎;切换不触发任何存量失效(产物逐字节同源)。

### 3.4 实测协议(用户在环,✅ 已完成)

1. 设置页清除全部缩略图 → 开关**开**(方案二)→ 全量生成 → 取日志 `[FullThumbGen] FINISHED … elapsed=…ms`;
2. 再清缓存 → 开关**关**(方案一,无需重启)→ 重跑 → 取 elapsed;
3. 各跑两遍取次优(排文件系统冷缓存),顺带记录期间画廊滚动手感;可选:解码策略切 GPU 后重复一轮
   (F3 修复后 GPU 档对比才有意义)。

### 3.5 裁决位(✅ 已实测裁决,2026-07-10)

> **✅ 用户真机 A/B 实测(同库同标准双引擎全量生成;实测数权威源=`cfe63d8` 文件头注)**:
> **方案二(多阶段流水线)稳定 7.3s / 方案一(Rayon 直线)16-20s(慢 2.2~2.7 倍)**——
> 「方案一在多核上性能最好」的历史直觉被证伪。
> 按预定规则(方案二不输 → 删方案一)执行:**方案二成唯一生成引擎;方案一分支 ~300 行×2 命令 +
> 运行时开关 `thumb_use_pipeline` 全链退役**(AppState 字段/lib.rs 读取/set_app_config 分支/前端
> toggle+i18n),提交 `cfe63d8`。full-gen 的 if/else 以匿名块替换保括号平衡与通道 drop 语义;
> 旧库残留 `thumb_use_pipeline` 配置键无读者无害;复盘旧实现走 `daab834` 前 git 历史。
