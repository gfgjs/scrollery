# 日志能力重构方案(调研报告 + 落地设计 + 裁决清单)

> 状态:**已裁决(2026-07-20)——Q1..Q8 全部采纳推荐项,主动建议(丢弃计数可见化/脱敏前提/worker 摸底/defer 清单)一并采纳(D-305)。施工由 Sonnet 5 承担,按 §9 施工指引执行(D-306)。S1..S6 全部落地完成(2026-07-21),commit b20e9e6..a64c169 区间+S6 收尾提交,cargo test 816/vitest 1328 全绿;本线暂未 push**。两项 defer(span TopN 数据源 / worker 日志汇入)已由 2026-07-21 独立后续任务落地(D-309..D-315,见 §3.4/§5/§8)。
> 需求:功能全面、应用内 UI、分析能力、人类友好、agent 读取友好;各重负载流水线(缩略图/AI/人脸/视频提取)日志量大,**不得或尽量小影响流水线性能,用户可完全关闭日志**。
> 调研底稿:三份 sonnet researcher 报告全文在 `docs/worklogs/2026-07-20-日志能力重构/attachments/`(A=Rust 后端与性能、B=应用内 UI 先例、C=agent 格式与治理);现状摸底在同目录 findings.md。本文只引结论,证据与出处见底稿。

## 1. 现状与差距

| 维度 | 现状 | 差距 |
|---|---|---|
| 后端内核 | tracing 三件套已在依赖树,377 处调用;registry + reload(EnvFilter) 热切级别已实现且写法正确 | 骨架可保留,无需换库 |
| 落盘 | 纯文本、双语 message;自定义 RealTimeDailyAppender **每条日志 open+append+fsync** | 非结构化,agent 只能全文 grep;每条 fsync 在高频流水线下 IO 昂贵 |
| 滚动/保留 | daily 按天分文件,**无大小上限、无自动清理**(clear_logs 手动全删) | 无限累积 |
| 默认级别 | DB 配置 log_level 默认 **debug** | 逐文件 CACHE_HIT/MISS 全量放出,随库规模线性 |
| 崩溃留痕 | 无 panic hook、无 minidump | panic 消息只进 stderr,用户场景不可见 |
| 前端 | 84 处裸 console.*,无封装、无后端桥 | 前端错误不落盘,发布后不可诊断 |
| UI | 设置 debug 区仅 logLevel/logDir/clearLogs | 无查看/过滤/搜索/分析 |
| 关联性 | 无 session/operation id | 一次用户操作的日志链路无法拼接 |
| guard | WorkerGuard 用 Box::leak 持有 | 退出时不 flush,崩溃前最后日志可能丢 |

关键调研实证(详见底稿):GitButler、Spacedrive(同为复杂 Tauri 应用)均绕开 tauri-plugin-log 直接用 tracing 三件套自建——与本仓现状同线,**换库无必要**;tracing 禁用态每调用点 ~0.7ns(callsite Interest 缓存);reload::Layer 是官方点名给「设置页日志开关」的机制;调研范围内的知名 Rust 桌面应用(GitButler/Spacedrive/Zed)均无运行时 GUI 日志开关先例(只有环境变量)——本方案的「off 档 + 应用内 UI」组合是超出先例的差异化点,消费级 app 也均无 message 聚合分析能力(同为差异化机会)。

## 2. 目标架构(五层)

```
┌─ L5 前端桥 ──────────────────────────────────────────────┐
│ logger.ts 封装(替换 84 处裸 console)                     │
│ window.onerror / unhandledrejection → IPC 批量上报        │
└──────────────────────┬───────────────────────────────────┘
                       ▼ IPC log_frontend_events(批量)
┌─ L1 内核(tracing registry,三 Layer 各带独立 filter)────┐
│ ① JSONL 文件层: 信封 FormatEvent + RollingFileAppender     │
│    + non_blocking(lossy) ← 事实源,agent/UI 历史都读它    │
│ ② 控制台文本层: 仅 dev 构建(cfg(debug_assertions))       │
│ ③ UI 环形缓冲层: 自建 Layer,有界队列+Tauri event 批推     │
│    (无订阅者时零广播;订阅由日志窗口打开/关闭驱动)         │
│ 顶层 reload::Layer<EnvFilter>: off..trace 运行时热切       │
└──────────────────────┬───────────────────────────────────┘
                       ▼
┌─ L2 治理 ────────────────────────────────────────────────┐
│ target 规范 + per-target directive(流水线默认降噪)        │
│ WARN/ERROR 重复压缩(签名计数);保留策略(启动时清理)      │
└──────────────────────┬───────────────────────────────────┘
┌─ L3 schema(JSONL 每行自包含)───────────────────────────┐
│ ts/level/target/session_id/operation_id/msg/attributes    │
└──────────────────────────────────────────────────────────┘
┌─ L4 应用内 UI(独立日志窗口 + 设置区入口)────────────────┐
│ MVP: 实时流+过滤+搜索+跟随底部  P1: 聚合  P2: 直方图/诊断包 │
└──────────────────────────────────────────────────────────┘
```

不引入的东西及理由:**tauri-plugin-log**(log-crate 基底,结构化弱,双轨割裂;GitButler/Spacedrive 实证绕开);**OpenTelemetry SDK/collector**(单机本地 app 无收集端,文件即终点;schema 字段语义对齐 OTel,未来要接时 operation_id 可机械映射 trace_id);**第三方限流/滚动 crate**(tracing-throttle 等均为新兴,BUS 因子高;需求可用 EnvFilter directive + 少量自写覆盖);**MCP log server**(JSONL+rg/jq 已够 agent 用,先例采用度极低)。

## 3. 后端设计(L1-L3)

### 3.1 内核重写(lib.rs 日志初始化段)

- **废除 RealTimeDailyAppender**(每条 open+fsync 是为「用户在资源管理器实时看到文件增长」服务的;有了应用内 UI 实时视图后此需求消失)。改官方 `RollingFileAppender`(Rotation::DAILY,`max_log_files` 自动清理)+ `non_blocking`(默认 lossy,缓冲 128k 行;**丢弃计数 ErrorCounter 暴露到 UI 诊断页**,丢日志可见不静默)。
- WorkerGuard 改 `app_handle.manage(guard)`(GitButler 实证惯例),退出时正常 flush。
- 文件层 JSONL:**自定义 FormatEvent 信封格式化器**(定型见 §9.3-A;内置 `.json().flatten_event(true)` 无法注入 session_id/operation_id 信封字段,勿用)+ ChronoLocal rfc_3339(保留本地时区:主要用户群无 DST,含 +08:00 偏移的 RFC3339 对 agent 无歧义)。
- 控制台层 `cfg(debug_assertions)` 门控,release 不装(现状 release 也装 ANSI 控制台层,白付格式化成本)。
- panic hook:接 `tracing-panic`(LukeMathWalker 维护,活跃)或等价自写 3 行,panic 消息+backtrace 作为最后一条 ERROR 进文件(non_blocking 场景配合 guard 落盘)。
- **原生崩溃 minidump(EmbarkStudios crash-handler/minidumper)不在本线**——需要「重拉自身进程当 crash reporter」的架构改动,风险收益独立评估(§7 Q7)。

### 3.2 性能设计(硬性要求专节)

分层开销预算(数据来源与置信度见底稿 A §8/§10):

| 状态 | 每调用点成本 | 机制 |
|---|---|---|
| 完全关闭(off 档) | **0.18 ns**(实测,criterion,`benches/logging.rs::logging_per_event_cost/off`) | callsite Interest::never 缓存;字段表达式**不求值**(宏展开先判 enabled) |
| target 被 directive 压掉(如流水线默认 warn,该模块 debug! 调用) | **0.18 ns**(实测,同上 `/filtered_by_target`,与 off 态同量级) | 同上 |
| 通过 filter,JSONL 序列化+入队 | **1.60 µs**(实测,同上 `/enabled_full_path`,writer 套 `tracing_appender::non_blocking` 而非裸 sink,含 crossbeam 入队开销——首版基准漏套此层,经审查修正) | serde_json 序列化在业务线程,写盘在后台线程 |
| 现状对照 | 每条 open+append+**fsync**(毫秒级 IO 摊到后台线程,吞吐瓶颈) | — |

**流水线宏基准实测**(`benches/logging.rs::logging_pipeline_thumbnail_batch`,CPU 解码+编码全链路,30 张合成 PNG/批,20 样本):off 104.74 ms/批、info 105.54 ms/批、debug 105.30 ms/批(批均值,单张约 3.5 ms)。off 态相对 info/debug 差值 **0.53%~0.76%**,低于 §7 Q2 验收门槛(>1% 视为未完成),**S1 验收基准通过**。实测环境:Windows 11、release profile、开发机(dev-machine-hw-instability 记忆记录的同一台,数字仅供量级参考,非跨机型 SLA)。

落地手段:
1. **完全关闭 = logLevel 增加 off 档**,经既有 LOG_RELOAD `handle.modify()` 切 `EnvFilter::new("off")`。切换动作付一次 rebuild_interest_cache(官方定性 relatively costly,一次性),稳态回到 ~1ns。不卸 Subscriber(收益未经量化证实,牺牲架构简洁性,底稿 A §8.5 论证)。不做编译期 release_max_level 变体(与「用户运行时可开回」语义冲突)。
2. **流水线 target 规范 + 默认降噪**:重负载模块统一 target 前缀(`scrollery::pipeline::thumb|ai|face|video`),默认 directive=`info,scrollery::pipeline=warn`(具体默认级别见 §7 Q2)。用户在 UI 开「流水线详细日志」时才放开——高频路径的 debug!/trace! 调用点在默认态即 never 缓存,近零成本。
3. **进度不走日志**:流水线进度/心跳类高频信息继续走既有事件体系(derivationStore 等),日志只记「任务级汇总一条 info(总数/耗时/失败数)+ 异常 warn/error」。设计原则:**日志记状态变化与异常,不记吞吐流**。
4. **WARN/ERROR 重复压缩**(自写,不引新兴 crate):签名=target+AppError code(或 message 模板),首条全量,窗口期内重复只递增计数,窗口关闭时补一条 summary(`repeat_count=N`)。定型=error.rs:205 调用点前辅助函数(§9.3-C),**不做 tracing Layer/Filter**(吞事件需 per-layer `Filter::event_enabled` 且 summary 补发有重入复杂度;收益集中在 AppError 流,单点足够;裸 warn! 风暴不在首期)。批量扫描中「同目录反复权限拒绝」类风暴从 N 条压到 2 条。
5. **UI 环形缓冲层零成本路径**:Layer 内先查「有无活跃订阅者」原子标志,无订阅者(日志窗口未开)直接返回,不格式化不入队不广播。
6. **验收基准**:施工 S1 附带 criterion 微基准(禁用态/过滤态/全开态每事件成本)+ 流水线宏基准(缩略图批量 N 张,off vs info vs debug 吞吐对比),数字回写本文,不达标(off 态对吞吐影响 >1%)视为未完成。

### 3.3 JSONL schema(信封+attributes)

```json
{"ts":"2026-07-20T21:03:11.284+08:00","level":"WARN","target":"scrollery::scanner","session_id":"s-7f2a9c1e","operation_id":"op-4b6e2d90","msg":"scan root auth failed","attributes":{"root_id":12,"error.code":"scan_root_auth","error.chain":["Access is denied. (os error 5)"],"repeat_count":1}}
```

- 信封字段固定:`ts/level/target/session_id/operation_id/msg`;领域字段进 `attributes`(顶层不爆炸)。
- `session_id`:启动时生成短 id(systemd _BOOT_ID 类比),一次运行的全部日志可 `rg` 一把抓出。
- `operation_id`:**显式字符串传参**贯穿「前端发起 → IPC command → spawn_blocking/worker」——tracing span 不跨 spawn_blocking 自动传播(底稿 C §2 查证),本仓 DB 全走 spawn_blocking,不能依赖 span 机制。前端 invoke 封装统一注入,后端 command 宏/辅助函数透传。
- `error.chain`:字符串数组(非 `{:?}` 整段多行文本)——防多行撕裂 rg/jq(anyhow Caused-by 组合的前瞻风险,底稿 C §7)。
- backtrace 默认不入日志,仅 bug 复现模式附带。
- 双语 message 与路径明文与否见 §7 Q3/Q4。

### 3.4 调用点治理与迁移

- 新增日志一律信封+结构化字段规范(`warn!(path = %p, "msg")` 形态,禁字符串插值埋值)——**脱敏 Layer 只能拦截结构化字段,插值烧进 message 的内容无法事后过滤**(底稿 C §5 技术限制,lib.rs:400 为现存实例)。
- 存量 377 处分批迁移(范围见 §7 Q8):优先级=①高敏感(含路径/文件名的调用点)②高频(pipeline target 归一)③错误路径(接 error.code)④其余顺带。
- error.rs:205 单点富化:AppError→`error.code`(既有稳定契约直接复用)+`error.chain`+重复压缩。四类预期分支(LayoutNotReady/Cancelled/ViewStale/VolumeOffline)不记 error 的现状降噪先例保持。
- bin/ 下 148 处 println(sort_profile/worker_e2e 诊断二进制)不在范围。
- **worker 子进程日志(2026-07-21 已落地汇入,D-310 取代 D-308)**:ai-worker/psd-worker stderr 改行协议输出——`exotic-protocol::WorkerLogLine{lvl,msg,fields}` 单行 JSON;supervisor 对 stderr 字节流行缓冲扫描,逐行解析后以固定 `target: "scrollery::worker"` + `worker` 字段(运行时来源区分,同 S3 frontend 先例)转发进主 tracing,统一入 JSONL/UI;非 JSON 行(panic/三方噪声)以 WARN+`unparsed=true` 原文兜底;64KiB 环形缓冲+异常摘尾保留(崩溃路径行双写,已接受)。原 D-308「现状已足够」是 S6 时点裁决,2026-07-21 用户改裁 IPC 汇入并已施工,三件套=docs/worklogs/2026-07-21-span埋点与worker日志汇入/。

### 3.5 保留与治理默认值

| 项 | 默认(细值见 §7 Q5) | 说明 |
|---|---|---|
| 滚动 | daily + max_log_files=14 | GitButler 同款务实方案 |

## 4. 前端桥(L5)

- `src/utils/logger.ts` 封装:`logger.debug/info/warn/error(msg, fields?)`;dev 构建同步镜像到 console(保开发体验),生产仅入队。
- 批量上报:队列 + 定时/阈值 flush(如 2s 或 50 条),经单一 IPC command `log_frontend_events` 入后端 tracing(target=`scrollery::frontend::*`),前后端日志汇入同一套 Layer 扇出——文件/UI/压缩治理全部复用。
- `window.onerror` + `unhandledrejection` 全局兜底,立即 flush(不等批)。
- 84 处裸 console.* 机械替换(S3 期);ESLint 规则 `no-console` 上闸防回流。
- off 档联动:后端 off 时前端队列直接丢弃(启动时/切换时经事件同步开关态),不白付 IPC。

## 5. 应用内 UI(L4)

入口:设置 debug 区加「打开日志窗口」按钮 + 紧凑「最近错误」预览(复用环形缓冲尾部);主体是**独立日志窗口**(Tauri v2 多 WebviewWindow;设置面板窄,塞不下三件套,Postman 弹窗先例)。

**MVP(与 S4 同期)**
- 实时流:订阅 Tauri event 批推(后端 ~100ms/批节流),环形缓冲默认 10k 行(设置可调 5k-20k,量级依据 Postman 5k/Docker 100k 光谱)。
- 虚拟滚动:`@tanstack/vue-virtual`(headless、官方 Vue adapter、持续维护;`anchorTo:'end'`+`followOnAppend`+`measureElement` 三原语恰好覆盖「行高不一+实时追加+底部跟随」,免自写滚动锚定状态机)。备选=参照既有 useVirtualScroll.ts 自研单列版(零新依赖但须自写 rAF 批量+跟随状态机)。
- 交互(三方收敛惯例):默认跟随底部,用户上滚自动退出跟随(不强拽),显示「跳到最新」按钮;Pause/Resume/Clear 分离(Grafana 范式)。
- 过滤:级别多选 + target 前缀 + 文本子串(大小写不敏感);级别徽标颜色+文字双编码(WCAG 1.4.1),debug 用低饱和灰(视觉降权),六主题体系过对比度。
- 历史:读 JSONL 文件按日分页加载(文件即事实源,重启后可查)。
- 复制行/复制可见区/清空视图;打开日志目录按钮。
- **关闭态约束**:日志 off 或窗口关闭时,前端零订阅零轮询零渲染。

**P1(分析入门)**
- 正则搜索、过滤条件 preset(Docker 范式)。
- 错误聚合:按 `error.code` 分组计数+首末时间+样本展开(**复用 AppError 稳定 code 契约,比文本模板挖掘便宜且精确**;消费级 app 无此能力,差异化点)。裸文本 warn/error 才用轻量模板启发式,不引 Drain3。
- 丢弃计数/压缩计数可见(日志系统自身可观测)。

**P2(分析进阶)**
- 时间线直方图+级别分布:JSONL 按需导入 rusqlite 临时表,Rust 侧 `GROUP BY strftime` 分桶,前端只渲染(契合「DB 只用 rusqlite+spawn_blocking」硬约束;**不引 duckdb-wasm**)。
- span 耗时 Top N 表(轻量,不内嵌火焰图)——**2026-07-21 已落地**:数据源=SpanTimer 结构化事件(D-311,判据 attributes.span_name+duration_ms),前端 `aggregateSpanDurations` 聚合(count/totalMs/avgMs/maxMs/lastTs,totalMs 降序前 20);「导出 Chrome tracing JSON 给 Perfetto」仍 defer 当高级动作。
- 诊断包导出:日志尾部+system-info(版本/OS/GPU/DB 大小/扫描根**数量**)打 zip,**仅落盘不自动上传**;导出前本地正则脱敏扫描(用户名/路径),长期目标=写入点源头排除(1Password 姿态)。
- 双窗格「过滤命中↔原文上下文」(klogg 范式)。

### 9.3 实现定型(免探索;骨架非成品,补全时保持接口不变)

**A. JSONL 信封格式化器(S1)** — session_id 为构造参数;visitor 收集字段:`message` 提为 `msg`、`operation_id` 提升进信封、其余进 `attributes`:

```rust
struct EnvelopeFormat { session_id: Arc<str> }

impl<S, N> FormatEvent<S, N> for EnvelopeFormat
where S: Subscriber + for<'a> LookupSpan<'a>, N: for<'a> FormatFields<'a> + 'static {
    fn format_event(&self, _ctx: &FmtContext<'_, S, N>, mut w: Writer<'_>, ev: &Event<'_>) -> std::fmt::Result {
        let mut v = FieldCollector::default();   // 自写:impl tracing::field::Visit
        ev.record(&mut v);                        // record_str/record_debug/record_i64…
        let meta = ev.metadata();
        let line = serde_json::json!({
            "ts": chrono::Local::now().to_rfc3339_opts(chrono::SecondsFormat::Millis, false),
            "level": meta.level().to_string(), "target": meta.target(),
            "session_id": &*self.session_id,
            "operation_id": v.operation_id,       // Option<String>,无则 null
            "msg": v.message, "attributes": v.attributes,   // serde_json::Map
        });
        writeln!(w, "{line}")
    }
}
// 挂法:fmt::layer().event_format(EnvelopeFormat{..}).with_ansi(false).with_writer(non_blocking)
```

**B. off 档(S1)** — settingsMap logLevel 选项加 `off`(`"off"` 是 EnvFilter 合法 directive);复用既有 LOG_RELOAD 路径:

```rust
handle.modify(|f| *f = EnvFilter::try_new(directive).unwrap_or_else(|_| EnvFilter::new("info")));
// directive:off 档 = "off";其余 = "{level},scrollery::pipeline=warn,reqwest=warn"
```

**C. 重复压缩(S2)** — 定型为 error.rs 的 AppError::serialize 调用点前辅助函数(理由见 §3.2):静态 `Mutex<HashMap<Sig, DedupEntry>>`,Sig=(target, error code);首见放行附 `repeat_count=1`;窗口(30s)内同签名**在 error 档吞掉**并计数,同时降档以 debug 级落一条全量证据行(附 `dedup_swallowed=true` + error.code/error.chain,D-307);窗口过后首条放行附 `suppressed=N`。无后台定时器、无 summary 补发。clear_logs 时重置该表。
> D-307(2026-07-20,S2 收口后裁决):Sig=(target,code) 在唯一调用点下 target 恒为 `module_path!()`,事实上退化为仅按 code 去重——不相关错误撞泛化 code(Io/Db/System 等)会被误吞。裁决=Swallow 臂降档 debug 留证(error 档保风暴压缩、debug 档保全量真相),**不扩签名**(扩 message/chain[0] 会在风暴场景因变量内容致签名基数爆炸、压缩失效,反杀主目的)。tracing 宏先查 callsite enabled 再求值字段,默认 info 档下降档行的 chain 序列化不执行,热路径成本不变。

**D. UI 环形缓冲层(S4)** — 自建 Layer:`AtomicBool` 订阅标志,false 直接 return(不格式化不入队);true 时轻量 struct 入 `Mutex<VecDeque>`(cap=环形上限),tokio interval ~100ms drain 批推 Tauri event;标志由日志窗口 open/close 的 IPC command 翻转。

**E. 前端 logger(S3)** — `src/utils/logger.ts`:模块级队列;`flush()` = `invoke('log_frontend_events', { events })`;触发=2s 定时或 50 条阈值;onerror/unhandledrejection push 后立即 flush;dev 构建同步镜像 console;off 态(启动读取+切换事件同步)直接丢弃不入队。
