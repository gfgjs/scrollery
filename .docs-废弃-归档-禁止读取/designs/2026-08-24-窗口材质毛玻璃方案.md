# 窗口材质(毛玻璃)方案:默认 Mica + Acrylic 用户可选

> 方案日期:2026-08-24
> 方案状态:**已定稿,反馈修复与透明度配置化(含画廊底面)已施工,待真机验收**(工作记忆见 `docs/planning/2026-08-24-窗口材质毛玻璃/`)
> 上游关系:[Scrollery 清透材质化 UI 建议方案](C:/workspace/scrollery/docs/designs/2026-08-15-Scrollery清透材质化UI建议方案.md)的 Windows 原生背板扩展——本方案不改该文的层级纪律与媒体 Canvas 边界,只在其 material 层之上叠加一层**可选的**原生玻璃模式。
> **2026-09-06 修订**:决策记录第 7 条「具体媒体/卡片表面承重」在设置页被真机证伪(设置行设计语言融入页面、无卡片面,玻璃模式抽掉画布后文字页裸坐在 DWM 背板上),已修订为文字密集视图根以 `--glass-content-fill` 半透明画布承重,见[玻璃模式内容底面修复方案](C:/workspace/scrollery/docs/designs/2026-09-06-玻璃模式内容底面修复方案.md);正文相关表述已同次改正。
> 需求来源:标题栏/底部状态栏/全局增加半透明毛玻璃,能半透看到 Windows 桌面;裁决取「默认 Mica,Acrylic 做成用户可选项」。

## 1. 摘要

新增热键 `window_material`(enum:`mica`/`acrylic`/`none`,默认 `mica`),三层配合生效:

1. **原生层(Rust)**:直接调 `window-vibrancy 0.6`(已是 tauri 2.11.4 的传递依赖,Cargo.lock 已锁,提升为直接依赖零新增编译)给主窗口挂 DWM 背板。`mica` 失败(Win10)自动退化 `blur`;`acrylic` 实时透出窗口背后内容;`none` 清除全部效果。
2. **窗口层(config)**:`tauri.conf.json` main 窗口加 `"transparent": true`——已核实 macOS/Linux 下是 trait 默认 no-op 静默忽略(tauri-runtime-wry 2.11.4 `src/lib.rs:1118` 的 `#[cfg(any(not(target_os = "macos"), feature = "macos-private-api"))]` 门控),跨平台安全。
3. **CSS 层(前端)**:`uiStore` 新增 `data-glass` 单源写点(仅 `isWindows && material != none` 时设置),新 `glass.css` 让 chrome 四表面(标题栏/侧栏/工具栏/状态栏)半透明、内容布局容器透出 DWM；媒体像素 canvas 各自承重，文字密集视图根由 `--glass-content-fill`(≈90% 主题画布色,opt-in,2026-09-06 修订)承重，避免祖先实色截断背板。原生背板仍无需任何按区域的原生 API(Windows 亦无公开的 per-region acrylic)。

`none` = 原生效果清除 + `data-glass` 移除 + `body` 回落 reset.css 不透明背景,观感与现状逐像素一致。

## 2. 调研结论(施工前无须重查,均已核实)

### 2.1 Windows 材质对比

| 材质 | 版本门槛 | 看到什么 | 状态 |
|---|---|---|---|
| Mica / MicaDark | 仅 Win11(build≥22000,22H2+ 走 SYSTEMBACKDROP) | 采样**壁纸**(不是窗口背后的内容),静态 | 推荐,近零 GPU 开销,稳定 |
| Acrylic | Win10 1809+(SWCA)/ Win11 22H2+(SYSTEMBACKDROP) | 实时模糊**窗口背后的一切** | 最接近「半透看到桌面」,但见 §6 上游坑 |
| Blur | Win7 / Win10 1809+(SWCA) | 老式 Aero 模糊 | 本方案仅作 Win10 上 mica 的退化 |

版本分派实证(window-vibrancy 0.6.0 `src/windows.rs`):`is_swca_supported()`=build≥17763、`is_undocumented_mica_supported()`=≥22000、`is_backdroptype_supported()`=≥22523;`apply_acrylic` 的 `color` 参数只作用于 SWCA 路径,22H2+ 的 SYSTEMBACKDROP 路径忽略之——**Win11 上的观感浓度必须由 CSS 层控制**,这正好落在 material 主题 token 体系里。

### 2.2 为什么不用 Tauri 的 `set_effects`

tauri 2.11.4 内置 vibrancy 封装(`tauri/src/vibrancy/windows.rs`)有两个不可绕过的语义:① `apply_effects` **吞掉内部错误**(`set_effects` 恒返回 Ok);② effects 列表是「取第一个支持的」而非按序 fallback——`["mica","blur"]` 在 Win10 上会**静默无效果**。要做 Win10 退化必须拿到 `Result`,故直用 `window-vibrancy` crate(`apply_mica().is_err()` → `apply_blur()`)。

### 2.3 上游已知问题(选择「默认 Mica」的直接依据)

- Acrylic 窗口拖动/缩放卡顿:[window-vibrancy#47](https://github.com/tauri-apps/window-vibrancy/issues/47)(open,上游无解)
- Win11 失焦后 acrylic 失效:[window-vibrancy#139](https://github.com/tauri-apps/window-vibrancy/issues/139)
- Win10 效果可能溢出窗口边界:[tauri#12849](https://github.com/tauri-apps/tauri/issues/12849)
- **可见性变化可能重置材质**:[tauri#12854](https://github.com/tauri-apps/tauri/issues/12854)——本项目主窗口以 `visible:false` 创建，setup 修正装饰后立即显示并在配置就绪时挂载材质；托盘隐藏/显示仍有多路往返，全部由 §4 的 show 后重应用覆盖。

### 2.4 本仓库现状锚点

- Windows 侧已 frameless(`src-tauri/src/lib.rs:175-180` 运行时 `set_decorations(false)`,前端 WindowChrome 自绘),挂 DWM 背板无原生标题栏冲突;macOS 保留原生装饰 + Overlay。
- chrome 四表面(WindowChrome/AppSidebar/AppToolbar/AppStatusBar)已统一消费 `--material-recipe-chrome-*`(清透材质化首批 caebb68 落地),玻璃化只需在 `html[data-glass]` 下覆写 `--material-chrome` 一个角色 token。
- 旧 DWM 染色链(SET_WINDOW_THEME)已随自绘标题栏废弃;`windows` crate 的 `Win32_Graphics_Dwm` feature 仍在,但本方案不需要它(window-vibrancy 自带 windows-sys 0.59)。

## 3. 总体架构

```text
config.toml window_material (mica|acrylic|none, 默认 mica, hot)
   │
   ├─ Rust:window_material.rs → DWM 背板(mica→blur 退化 / acrylic / none 清除)
   │    应用点:setup 显示主窗口后(首帧) + apply_setting_effects(热切换)
   │          + lifecycle/tray 三处 show 后(对抗 tauri#12854)
   │
   └─ 前端:uiStore.applyWindowMaterial → html[data-glass='mica'|'acrylic']
        glass.css:chrome 角色 token 半透明 + body/壳/内容容器透明 + 媒体 canvas/文字页 fill 承重
```

与父方案的关系/边界:

- 玻璃模式只在 `html[data-glass]` 下覆写 `--material-chrome`(color-mix 派生,不新增 `--color-*` 源 token,不触碰 MATERIAL_CONTRACT 契约测试),material 层的层级纪律(canvas→chrome→surface→elevated→float)与导入顺序全部保留。
- **媒体 Canvas 边界(父方案 §5.1)修订后保持**:玻璃模式下 `.app-content` 仅作透明布局容器;画廊媒体像素仍由自身绘制,但 Mica/Acrylic 的 Canvas 底面改为 alpha+透明清屏以露出 DWM,`none` 保留 `alpha:false` 不透明快路径;文字密集视图根(设置/收藏/人物/插件商店/文档阅读器)由 `--glass-content-fill`(≈90% 主题画布色)承重(2026-09-06 修订,原「设置页由卡片/控件表面承重」被真机证伪),不把照片像素变成桌面玻璃。
- 画廊底面可独立配置:玻璃模式下 `.media-grid-layout` 用 `glass_gallery_opacity` 生成主题色遮罩,默认 0% 以完全透出 DWM；Canvas 透明间隙与该遮罩叠加,`none`/非玻璃模式不消费此变量并保留原底色。
- 父方案「Blur 是浮层材料,不是页面背景」原则不冲突:本方案**不用 CSS backdrop-filter**,模糊全部由 DWM 合成器在窗口层完成,GPU 成本与 WebView 合成层无关。
- 不动 `material.css` 本体,玻璃层独立 `glass.css`(避免 MATERIAL_CONTRACT 联动与导入顺序测试风险)。

```rust
//! 窗口材质(毛玻璃)——window_material 配置键的 DWM 背板应用器。
pub fn apply_from_config(app: &tauri::AppHandle) {
    let value = app
        .try_state::<std::sync::Arc<crate::state::AppState>>()
        .and_then(|s| s.config.get("window_material"))
        .unwrap_or_else(|| "mica".to_string()); // ConfigManager::get 对 schema 键自带默认
    apply(app, &value);
}

pub fn apply(app: &tauri::AppHandle, value: &str) {
    if let Some(main_win) = app.get_webview_window("main") {
        let win = main_win.clone();
        let v = value.to_string();
        let _ = main_win.run_on_main_thread(move || apply_material(&win, &v));
    }
}

#[cfg(target_os = "windows")]
fn apply_material(win: &tauri::WebviewWindow, value: &str) {
    // Win11 22000–22522 的 Acrylic(SWCA) 与 Mica(旧 DWM 属性)状态通道不同,
    // 目标材质前先清理旧通道,避免热切换互斥失败。
    let _ = window_vibrancy::clear_acrylic(win);
    let _ = window_vibrancy::clear_mica(win);
    let _ = window_vibrancy::clear_blur(win);
    match value {
        "acrylic" => {
            // 色调仅作用于 Win10 SWCA 路径;Win11 22H2+ 走 SYSTEMBACKDROP 忽略 color,
            // 观感浓度由前端 glass.css 半透明层控制。
            if let Err(e) = window_vibrancy::apply_acrylic(win, Some((28, 28, 32, 40))) {
                tracing::warn!(error = %e, "apply_acrylic failed");
            }
        }
        "none" => {
            // 目标通道已在 match 前清理,none 不再挂效果。
        }
        _ => {
            // mica:Win11 专属;失败(Win10)退化到 DWM blur,与 CSS 玻璃层仍成配对观感。
            if window_vibrancy::apply_mica(win, None).is_err() {
                let _ = window_vibrancy::apply_blur(win, Some((28, 28, 32, 60)));
            }
        }
    }
}
#[cfg(not(target_os = "windows"))]
fn apply_material(_win: &tauri::WebviewWindow, _value: &str) {}
```

## 5. 配置键与热应用链路

与现有 config.toml 子系统完全同构,无新机制:

- **UI 改值**:`setWindowMaterial` → `SET_APP_CONFIG` → `validate_ipc_value`(Enum 白名单,错误码 `config_invalid_value`)→ `set_and_persist`(toml_edit 原子写)→ `apply_setting_effects` 新分支挂 DWM;前端乐观应用 CSS。
- **外部编辑**:watcher diff → `apply_setting_effects`(同分支挂 DWM)+ `config-file-changed` → `refreshFromBackend` → hydrate 白名单 → CSS 侧同步。两侧天然同拍。
- **透明度改值**:设置页 5 个数字输入或直接编辑 `[ui]` 下 `glass_chrome_opacity` / `glass_sticky_opacity` / `glass_surface_opacity` / `glass_control_opacity` / `glass_gallery_opacity`；前四项经 `SET_APP_CONFIG` 调整 CSS scale，画廊项经同一链路调整直接百分比，外部文件均由 watcher 触发 `refreshFromBackend`。前四项统一收敛到 20–120、100 保持当前材质默认值；画廊项收敛到 0–100、0 保持完全透出。
- **新装置自愈**:`append_missing_keys` 会把新键补进老 config.toml;`get_startup_config` 经 `ConfigManager::get` 对未设键回落 schema 默认(`window_material=mica`,4 组 opacity=100,`glass_gallery_opacity=0`)。

## 6. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| Acrylic 拖动/缩放卡顿(上游无解) | 拖窗口掉帧 | 默认 Mica;Acrylic 为显式可选项,设置描述明示卡顿提示 |
| Win11 失焦 acrylic 失效(#139) | 切走再回来玻璃消失 | `Focused(true)` 与 show 后路径均按配置重挂;验收清单含该项 |
| 可见性变化重置材质(#12854) | 托盘隐藏/显示后玻璃丢失 | 四处 show 点重应用(§4 ⑥⑦⑧) |

| 透明 webview 合成开销 | GPU 占用微增 | Mica 为静态壁纸采样近零成本;Acrylic 由用户自选承担;`src/perf` 基线对比 |

| transparent 窗口边缘 artifact | Win11 圆角/阴影处白边 | 验收清单专项;必要时试 `"shadow": false`(tao#72 workaround 链,tauri set_effects 文档亦引用) |
| macOS/Linux 误伤 | — | transparent 为 no-op(§2.2 已核实);`data-glass` 由 isWindows 门控;Rust 侧 cfg(windows) 空实现 |

## 8. 明确不做(出界)

- macOS vibrancy(NSVisualEffectView,需 `macos-private-api` feature + `macOSPrivateApi` config,另行立项)
- 媒体像素画布全局玻璃(画廊照片/像素区域透出桌面——可读性/性能双输)
- chrome 表面 CSS `backdrop-filter`(原生背板已提供模糊,且违反父方案 blur 纪律)
- FOUC 快照扩展(主窗口启动时不可见,首帧无玻璃需求)
- Win10 暴露第四选项(blur 仅作退化,不进设置项)

## 9. 决策记录

| 决策 | 取舍 | 理由 |
|---|---|---|
| 默认值 = mica | 非 none/acrylic | 用户裁决;Mica 稳定近零开销,微软设计指南推荐的窗口底材 |
| Win10 mica→blur 自动退化 | 不暴露第四选项 | 设置面收敛;退化后与 CSS 玻璃层仍成配对观感 |
| 直用 window-vibrancy 而非 tauri set_effects | 需要 Result 做退化 | set_effects 吞错误 + 列表非 fallback 语义(§2.2) |
| 色调浓度走 CSS(color-mix)而非 DWM color | — | SYSTEMBACKDROP 忽略 color;且落在主题 token 体系,六主题可读性可调 |
| 玻璃层独立 glass.css | 不改 material.css | 避免 MATERIAL_CONTRACT 契约联动;导入顺序测试零风险 |
| 设置行全平台可见 | 不新建平台隐藏机制 | desc 注明「仅 Windows 生效」即可,机制留待真需求 |
| 内容布局容器透出,文字密集视图根以 `--glass-content-fill` 半透明画布承重(2026-09-06 修订) | 推翻初版"内容区整块不透明";修订原"具体媒体/卡片表面承重" | 真机截图证明祖先实色 canvas 会截断 DWM;修订原因「设置页用 surface 保可读」被真机证伪——设置行设计语言融入页面、无卡片面,可读性实际押在页面画布上,玻璃模式抽掉画布后裸坐在 DWM 背板(回退死灰时整页不可读)。修订为视图根 opt-in 领 ≈90% 主题画布色([2026-09-06 修复方案](C:/workspace/scrollery/docs/designs/2026-09-06-玻璃模式内容底面修复方案.md)),画廊完全透出与层级纪律不变 |
| sticky 标题/路径行使用低 alpha 玻璃遮罩 | 完全透明会让滚动文字穿过固定头栈 | 保留 sticky 的遮挡职责,普通树行透明；浓度由 `glass_sticky_opacity` 调整 |
| 4 类玻璃表面使用独立 opacity scale | 单一总开关无法处理窗口栏与白色控件的不同突兀程度 | 100 保持 Mica/Acrylic 相对配方,设置页和 config.toml 共用 hot 水合链路 |
| 画廊底面使用独立直接 opacity | 画廊透明路径没有可供乘法缩放的原始表面 alpha | `glass_gallery_opacity` 默认 0%,仅玻璃模式绘制主题色遮罩,none 保持原 opaque 快路径 |
| 非 none 先清旧背板 + Focused(true) 重挂 | 额外三次清理调用/少量前台重挂 | 覆盖 Win11 跨通道互斥与 Acrylic 失焦丢失,错误仍按版本探测静默处理 |
| 单 commit 交付 | Rust+前端+CSS 原子性 | AGENTS 批次提交纪律;两侧任一缺位功能不成立 |
