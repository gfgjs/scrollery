# 主题配色全新设计

> 2026-09-16 已按 A–D 分批实施。背景／前景／强调色与层次对比度驱动统一色板，不兼容旧主题配置。本文是当前主题模型约定；定向测试和浏览器示例画廊已验证，原生玻璃与跨平台仍待实机验收，范围见 §10。

## 1. 设计裁定

- 核心输入：背景 background、前景 foreground、强调色 accent、层次对比度 contrast。
- 浅色、深色独立保存；appearance 继续表示 system / light / dark。
- 画廊底色 gallery 提供 auto 或指定颜色；auto 跟随界面底色／窗口材质。
- 预设只是完整参数的快捷填入，不参与运行时继承；修改后得到独立参数。
- 用户可将调好的完整主题命名保存到“我的主题”：包含浅色、深色配色及窗口材质／不透明度；支持重新应用、另存、更新、重命名和删除。外观模式独立于主题保存。
- 颜色生成只有一个纯函数入口，组件、Canvas、预览与默认启动样式消费同一结果。
- 重构主题相关重复层与无效逻辑；不修改照片色彩管线、ICC、布局算法、业务功能或独立阅读主题。
- 旧主题 ID、旧浓度、旧快照与相关设置不迁移、不双读、不双写。移除后按新配置的缺省规则处理；不清除其他用户设置。

## 2. 用户界面

外观页顺序：外观模式 → 主题选择（内置主题／我的主题）→ 浅色配色卡 → 深色配色卡 → 窗口材质 → 应用／取消／保存为主题。宽屏可将两张卡并排，窄屏纵排。

每张配色卡包含：

1. 当前模式缩略预览（侧栏、文件夹、缩略图、选中态、按钮）。
2. 背景、前景、强调色三个色块与 HEX 值。
3. 层次对比度 0–100 滑条。
4. 可展开的画廊背景：跟随界面 / 指定颜色。
5. 编辑、恢复该模式默认配色；命名保存统一放在完整主题入口。

选择编辑后进入一份完整主题的临时草稿会话，初值为当前两套配色与材质：

- 点击色块打开二维饱和度／明度面板、色相条、HEX 输入、常用色块。颜色不含透明度，透明度属于材质。
- 拖动即时预览，颜色计算与发布最多每动画帧一次；不写配置或启动缓存。
- 正在编辑非当前模式时，可临时预览该模式；appearance 偏好不变，结束后恢复偏好对应模式。
- 应用：将两套配色和材质一次提交现有 writeSettings；失败使用已有可见错误与回滚机制。仅应用不会新增或覆盖“我的主题”。
- 取消／Esc／退出设置：丢弃草稿；无需额外退出确认。
- 色板弹层收起只收起控件，主题草稿仍在；应用／取消针对完整主题。
- 浅色、深色卡及材质共用这份草稿，可来回调整；不为每张卡再维护独立提交状态。
- 配置热更新或跨窗口事件改变当前两套配色或材质时，丢弃草稿并提示已加载新配置；重置也取消草稿。无关设置变化不打断。
- 切换预设先进入草稿；不静默覆盖已保存配色。
- HEX 输入未完成时不发布非法颜色；失焦恢复最后有效值。

内置主题先做三套：中性、暖纸、冷夜，每套包含浅／深配色与材质参数。默认采用中性底色与绿色强调色。首版不做导入导出、分享或主题市场。

### 2.1 命名保存与“我的主题”

- 用户调色后点击“保存为主题”，输入名称，点击“保存并应用”；未进入编辑时也可直接保存当前已应用配色。
- 保存内容取完整有效草稿；若只调整了深色，浅色沿用当前配置，不生成或覆盖成默认值。预览正在显示浅色还是深色，不影响保存范围。
- 保存并应用一次提交当前配色／材质与新的主题条目。持久化成功后才提示已保存；失败保留草稿供重试，不留下只保存名称或只保存一半配色的结果。
- “我的主题”展示名称及浅／深缩略预览。选择一个主题将其完整参数复制到草稿，实时预览；点击“应用”后保存当前配置，外观模式仍保持用户原先的 system / light / dark。
- 名称去除首尾空白后不能为空；与已有个人主题重名时提示改名，绝不按名称自动覆盖。内置和个人主题分组展示。
- “另存为新主题”创建新 ID；“更新此主题”明确选择已有个人主题作为目标并替换其参数、保持 ID 和名称。内置主题只能另存。
- 重命名只修改名称，不改变 ID 或配色；删除只删除已保存条目，不改变正在使用的配色。删除提供一次撤销入口。
- 已保存主题是独立快照，继续调色不会自动更新它。选择、更新和删除均按稳定 ID 定位，不按颜色或名称猜测目标。
- 恢复当前配色默认值不删除“我的主题”；全局“重置所有设置”会一并清空个人主题，遵循现有全局重置语义。

## 3. 配置结构

运行期领域类型：

```ts
type ThemeMode = 'light' | 'dark'

interface ThemeSeed {
  background: string // 规范 #rrggbb
  foreground: string // 规范 #rrggbb
  accent: string // 规范 #rrggbb
  contrast: number // 0–100 整数
  gallery: string // auto 或规范 #rrggbb
}

interface ThemeDefinition {
  light: ThemeSeed
  dark: ThemeSeed
  material: 'none' | 'mica' | 'acrylic'
  opacity: number // 0–100 整数
}

interface SavedTheme extends ThemeDefinition {
  id: string
  name: string
}
```

字符串在输入／设置边界统一校验，不为每次内部使用重复检查。不支持任意 CSS 表达式或任意 CSS token 覆盖。

config.toml 继续使用已有顶层键风格与原生 TOML 值：

| 键 | 类型与语义 |
|---|---|
| appearance | system / light / dark，沿用原有语义 |
| theme_light_palette | ThemeSeed 固定结构的内联表 |
| theme_dark_palette | ThemeSeed 固定结构的内联表 |
| theme_saved_themes | 命名主题数组，默认空；每条保存 ID、名称、两套配色与材质 |
| window_material | none / mica / acrylic，新默认 none |
| window_opacity | 0–100 整数，默认 90，仅材质开启时使用 |

不保存选中主题 ID：当前完整参数与唯一主题一致则展示其名称，无匹配或多条同配色匹配时显示“自定义”。当前参数始终独立存在；主题列表中的编辑操作使用条目 ID。删除个人主题不改变已应用颜色。

复用已有 Struct / StructList、整数范围和 settingsPersistence；为颜色字段增加一个允许配置 auto 与否的颜色字段校验种类即可，不增加通用嵌套配置系统。运行期使用上面的具名 light / dark 结构；theme_saved_themes 的持久化条目使用固定扁平字段 id、name、light_background / light_foreground / light_accent / light_contrast / light_gallery、对应 dark_* 字段、material、opacity，由 themes/config.ts 集中转换。两组颜色字段复用种子字段校验规则，不在各组件拼接。主题 ID 与个人名称去重在设置校验边界处理。

权威默认种子只写一份：两个 default-light.json / default-dark.json；前端预设导入，Rust schema 以 include_str! 引用为结构默认值。schema 继续负责字段合法性与缺省应用，禁止另写一份 HEX 默认值。其他预设也只保存种子，预览现算。

## 4. 默认配色与生成规则

### 4.1 初始种子

| 输入 | 浅色 | 深色 |
|---|---|---|
| background | #ffffff | #181818 |
| foreground | #202024 | #f4f4f5 |
| accent | #087f5b | #34d399 |
| contrast | 45 | 60 |
| gallery | auto | auto |

侧栏、顶栏、底栏共享基础背景，保持当前融合布局；照片颜色不受主题处理。普通文字和图标取前景派生色，强调色用于选中、按钮、焦点等小面积区域。

### 4.2 生成契约

`generateTheme(seed, mode) → ThemePalette` 为不访问 DOM、存储或框架的纯函数。结果是用途明确的有限颜色集合，最终颜色为 HEX / rgb / rgba，不向 Canvas 传递 var() 或 color-mix()。

使用简单 RGB 通道插值，`mix(a,b,t)` 表示从 a 向 b 混合 t；`c = contrast / 100`。采用统一系数表，避免在组件里重复计算。以下为首版起始系数，实际视觉验收可集中调节系数，但保持输入语义不变：

| 用途 | 起始规则 |
|---|---|
| 基础背景、共享窗口底色 | background 原值 |
| 正文 | foreground 原值 |
| 辅助文字 | mix(background, foreground, 0.66 + 0.10c) |
| 次要元信息 | mix(background, foreground, 0.48 + 0.12c) |
| 普通边框 | mix(background, foreground, 0.08 + 0.06c) |
| 强边框 | mix(background, foreground, 0.14 + 0.10c) |
| 输入边界／开关轨道 | 从背景向前景混合，集中反推在基础底面、面板、浮层上的最低 3:1（轨道 3.5:1） |
| 悬停背景 | mix(background, foreground, 0.04 + 0.04c) |
| 深色普通面板 | mix(background, foreground, 0.025 + 0.025c) |
| 深色浮层 | mix(background, foreground, 0.06 + 0.04c) |
| 浅色普通面板／浮层 | background 向白混合 0.35 / 0.70；白底时以边框和阴影区分 |
| 选中浅背景 | mix(background, accent, 0.10 + 0.06c) |
| 强调色填充 | accent 原值 |
| 强调按钮文字 | 按计算对比选择黑或白 |
| 强调色文字 | 以 accent 为起点，必要时向黑／白调整以改善实际背景上的可读性 |
| 画廊与格缝 | auto 取 background，显式值原样使用 |
| 占位块、纸面、时间轴文字 | 从对应实际画廊背景派生，不能错误地始终拿窗口背景计算 |

层次对比度不能改变三个用户种子，不能作用于整页滤镜，也不能处理照片本身。相同种子与模式必定产生相同色板。

文字、边框默认输出已混合的实色，减少透明层叠导致的发灰；遮罩、玻璃填充等确需透明的用途保留 alpha。图片上方的时长／徽标继续使用专用遮罩色，独立阅读器主题保留，其“跟随应用”模式读取新主题。

错误、警告、成功及媒体类别保持各自语义色，不随 accent 改成同一种颜色。相应文本／底色由同一生成入口产出；状态浅底 alpha 为浅色 0.10／深色 0.08，按实际合成面验证文本对比。画廊正文／辅助文字由 canvasText／canvasTextSecondary 提供，对实际 gallery 底色校正可读性，DOM 与 Canvas 共用。用户自由选色，即使背景与前景相近也不强制改写；编辑器显示对比不足提示与恢复默认入口。默认预设正文／辅助文字目标对比至少 4.5:1，有含义的控件边界目标 3:1；装饰性分隔线不套用控件要求。内置预设必须实测，任意自定义色及玻璃混合结果不承诺自动达标。

## 5. 材质与画廊

- 新默认使用纯色，用户选定的背景有确定呈现；Windows 现有 Mica / Acrylic 保留，不扩展原生平台范围。
- 保留全窗口共享一层玻璃填充，避免各区叠加出不同色块。
- 用户只调一个窗口不透明度，共享窗口底层直接对应 0–100%（100% 完全不透明）；控件、内容面、浮层按固定角色规则派生填充，不再分别暴露 chrome / sticky / surface / control / content 五个浓度。草稿仅预览 CSS 填充，原生材质在应用后生效。
- gallery=auto 时沿用共享底面，DOM 与 Canvas 的背景处理一致；玻璃开启时 Canvas 清透明，透出同一个底面。
- gallery 指定颜色时该区使用不透明实色，格缝与清屏使用相同颜色。它是明确覆盖，不再叠加旧 glass_gallery_opacity。
- glass.css 只负责原生玻璃适配与透明度，不定义第二套颜色。平台不支持材质时使用纯色结果。
- 材质修改不调用图像解码、缩略图派生、布局重排或资产重载。

## 6. 代码结构与数据流

```text
src/themes/
  types.ts               种子、模式、色板、预设类型
  colors.ts              颜色解析、混合、亮度、对比度及黑白选择
  generate.ts            唯一颜色生成函数及系数表
  presets.ts             内置种子集合与预设匹配
  config.ts              主题配置及命名主题的具名结构转换
  presets/*.json         基础种子；默认值前后端共用
  apply.ts               色板 → CSS 变量；单次主题发布
  snapshot.ts            已确认色板的首帧缓存
  bootstrapScript.ts     阻塞首帧脚本源码；Vite 按统一变量清单生成
  readerThemes.ts        保留独立阅读主题
src/stores/themeStore.ts 配置适配、临时草稿、有效模式、当前色板
src/components/settings/
  ThemeSettings.vue      内置／我的主题列表、命名操作、两套配色与材质入口
  ThemePaletteCard.vue   单套配色与编辑状态
  ThemeColorPicker.vue   选色器与键盘交互
  ThemePreview.vue       使用真实生成色板的预览
```

这些是具体职责的模块，不额外增加主题服务、主题管理器、插件或注册机制。

数据流：settingsPersistence 的已保存／待提交值 + 一份完整主题临时草稿 → themeStore → generateTheme → apply + Canvas 当前色板。草稿包含两套配色及材质，当前预览模式决定显示哪套；非颜色设置变化不重新生成。命名主题只存参数快照，不另存生成色板。

uiStore 移出全部主题、浓度、主题缓存及材质配置职责；侧栏模式切换等调用迁到 themeStore，避免转发旧 API。原生窗口明暗同步由主题应用入口协调，保留现有平台必要行为。

CSS 继续使用有意义的 --color-* 用途名；这是最终样式接口，不是旧配置兼容层。删除 material.css 中仅转发颜色／属性的 --material-*、--material-recipe-* 别名链，直接消费者在同批迁到明确颜色／阴影变量。variables.css 保留字号、尺寸、间距、动效等基础值；颜色来源收归主题域。

Canvas 接收生成后的具体色板，替换 themeToken / tintToken / textToken 三个刷新参数。mediaGridCanvas.palette.ts 只保留网格所需字段的投影与非颜色尺寸读取；不维护另一份颜色默认值、不逐帧 getComputedStyle。尺寸变化仍按现有机制读取，颜色更新只重绘当前可见画布。时间轴等其他 Canvas 消费者按同一原则接入。

## 7. 首帧与持久化

- 继续使用 config.toml 与现有集中保存；完整主题应用一次批量提交两套配色与材质。“保存并应用”在同一批 patch 内加入 theme_saved_themes，命名主题落原生 TOML 结构数组，复用已有批量提交的原子写入。
- 不给主题新增落盘队列、防抖服务或跨窗口消息总线。
- 缓存只取后端已确认配置生成的两套最终 CSS 变量、appearance、材质和不透明度；包括 appearance 在内的未确认写入和草稿均不能污染下次启动。首次 settingsReady 水合必须应用并重写缓存，即使权威值与默认占位相同也要覆盖旧缓存。
- 新启动缓存使用独立新键；不读取 scrollery.themeSnapshot.v1。缓存结构只接受当前格式，失效直接使用默认值。
- 阻塞式 /theme-bootstrap.js 只恢复已生成变量、解析当前系统明暗，不含颜色算法或主题 ID 清单。源码由 themes/bootstrapScript.ts 生成，Vite 插件在开发通过中间件、构建通过资产输出交付同一路径；期待变量键集由唯一色板映射注入，不维护 public 中的第二份手写清单。
- 缺少缓存时使用生成的默认主题 CSS。现有 Vite 开发启动／构建路径调用同一 generateTheme 生成这份 CSS，不引入依赖、不手写第二套默认色板；启动层直接消费 --color-*。
- 删除 index.html 的六套 --startup-* 配色分支。启动遮罩与应用窗口使用相同背景，避免先露旧主题。
- 设置热更新、重置与跨窗口同步都复用现有机制；主题缓存是可丢弃的派生值，不能反向恢复用户偏好。

## 9. 分批实施与验收
