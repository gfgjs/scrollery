# 前端 UI 优化与多主题系统

> 日期: 2026-07-06 | 状态: **施工中** | 决策人: GJS(三问拍板见 §1.2)

## 1. 背景与决策

## 2. 调研结论(决定架构的两条硬约束)

### 2.1 感知学红线:画布区必须中性
照片工具的 UI 底色会直接扭曲用户对照片颜色的感知:背景的明度与色相影响主体颜色与饱和度的观感(Adelson 同色错觉);ICC 色彩管理规范以**中性灰**为标准观察环境;Lightroom/Photoshop 等专业工具全线采用中性深灰 UI 正是此因。
**落地约束**:任何主题(包括暖调的宣)中,**画廊画布区与看图 overlay 的背景必须是低饱和中性色**;主题的「花样」只允许落在 chrome(侧栏/工具栏/状态栏/对话框)上。为此新增语义 token `--color-bg-canvas`(§4.3)。
来源: [Envato Tuts+ 中性灰工作区](https://photography.tutsplus.com/tutorials/want-better-color-use-neutral-gray-themes-in-adobe-photoshop-and-lightroom--cms-23342)、[dark mode 设计指南](https://www.jamesrobinson.io/post/a-guide-to-dark-mode-design)。

### 2.2 架构范本:Obsidian 式「主题 = 语义变量覆写」
Obsidian 的主题生态(数百个社区主题)架构:foundation → semantic → component 三层 CSS 变量;主题只是一份在 `.theme-dark`/`.theme-light` 作用域下覆写变量的 CSS 文件 + manifest 元数据;无 JS、可热插拔。VS Code 同理(JSON token 映射)。
**落地约束**:我们的内置主题与未来商店主题走**同一契约**——「一份只含 CSS 自定义属性覆写的样式文件 + 一条注册表元数据」,内置与外置的差异仅在加载器(静态 import vs 运行时注入)。
来源: [Obsidian Build a theme](https://docs.obsidian.md/Themes/App+themes/Build+a+theme)、[Obsidian CSS variables](https://docs.obsidian.md/Reference/CSS+variables/CSS+variables)、[三层 token 实践](https://www.contentful.com/blog/design-token-system/)。

### 2.3 传统色取值权威源
主题色值实现时从 [zhongguose.com](https://zhongguose.com/en) / [ichuantong.cn](https://colors.ichuantong.cn/) 取值起步,再按 WCAG 对比度微调;**禁止凭印象编造色值**,每套主题跑对比度脚本留证(§7)。

## 4. 主题架构设计(normative)

### 4.1 分层与文件布局
```
src/assets/styles/
  variables.css          # 不动:主题无关 token(间距/圆角/字阶/动效/z/尺寸)
  themes/
    ink.css              # [data-theme='ink']      墨(现 theme-dark.css 迁移精修)
    porcelain.css        # [data-theme='porcelain'] 素(现 theme-light.css 迁移精修)
    xuan.css             # [data-theme='xuan']     宣(签名主题)
    obsidian.css         # [data-theme='obsidian'] 玄(OLED 纯黑)
    dai.css              # [data-theme='dai']      黛(青灰冷调)
src/themes/
  registry.ts            # ThemeDefinition + BUILTIN_THEMES + 查询工具
  contract.md            # token 契约清单(未来商店 manifest 校验的雏形)
```
- 每份主题文件 = **完整语义色层覆写**(bg 层/文本层级/accent/border/shadow/scrollbar/状态色/sidebar/徽章/focus-ring/表单控件,与现契约同构)+ `color-scheme: light|dark`(原生滚动条/表单控件跟随)。
- `theme-light.css`/`theme-dark.css` 迁移后删除,`index.css` 改 `@import` 五份主题文件(内置主题随包静态打包)。

### 4.2 注册表与加载器(为商店预留的解耦边界)
```ts
// src/themes/registry.ts
export interface ThemePreview { bg: string; surface: string; text: string; accent: string }
export interface ThemeDefinition {
  id: string                    // data-theme 值,亦是持久化值
  nameKey: string               // i18n key,设置卡片显示「墨 · Ink」
  kind: 'light' | 'dark'        // 决定 SET_WINDOW_THEME 与 data-color-scheme
  preview: ThemePreview         // 设置页主题卡片的四色预览(与 CSS 同步维护)
  source: 'builtin'             // 预留 'external'(商店/本地导入)
}
export const BUILTIN_THEMES: readonly ThemeDefinition[]
export function getTheme(id: string): ThemeDefinition | undefined
export function themesByKind(kind): ThemeDefinition[]
```
- **UI 一律读注册表渲染**(设置卡片/侧栏切换),不硬编码主题清单。
- 未来商店只需: `source:'external'` + 一个「manifest 校验 + `<style>` 注入」的 loader + 注册表变为响应式列表;本轮**不实现** loader/manifest/下载/签名,只保证上述三个接缝存在(§9)。

### 4.3 新增语义 token(所有主题必须提供)
| token | 用途 | 红线 |
|---|---|---|
| `--color-bg-canvas` | 画廊画布区 / 看图 overlay 背景 | **一律低饱和中性色**(§2.1);MediaGrid/MediaDetailOverlay 改挂此 token |
| `--color-badge-doc-word/excel/ppt` | 文档类型徽章品牌色(现硬编码在 MediaThumb.vue:666-681) | 入主题文件,暗色主题可降明度 |
| `--texture-chrome` | chrome 区材质叠层(宣的纸纹;其余主题为 `none`) | 纯 CSS(渐变/SVG feTurbulence data URI),禁位图 |

### 4.4 状态模型与持久化(uiStore 改造)
```ts
appearance: Ref<'light'|'dark'|'system'>   // 外观模式,保留现三态 UX
lightThemeId: Ref<string>                  // 亮色位主题,默认 'porcelain'
darkThemeId: Ref<string>                   // 暗色位主题,默认 'ink'
resolvedThemeId: computed  // appearance(+systemIsDark) → light/dark 位 → themeId
isDark: computed           // getTheme(resolvedThemeId).kind === 'dark'
```
- **应用**: `documentElement.dataset.theme = resolvedThemeId`、`dataset.colorScheme = kind`、`SET_WINDOW_THEME(kind)`;删除 AppShell.vue:5 的第二写点(P1)。
- **持久化**: app config 三键 `appearance` / `theme_light` / `theme_dark`;**迁移**: 旧键 `theme` 的 `light→(appearance:light)`、`dark→(appearance:dark)`、`system→(appearance:system)`,主题位取默认;迁移只读旧键不删除(回滚安全)。
- **组件侧 dark 判定**: 组件样式一律走语义 token;确需按明暗分支的用 `[data-color-scheme='dark']`(施工时全库 grep `data-theme` 清点存量选择器,逐处改造)。
- 侧栏 SidebarFooter 升级三态循环 light→dark→system(Sun/Moon/Monitor 图标),修 P2。

### 4.5 FOUC 消除(P3)
- `setTheme`/`setAppearance` 时同步写 localStorage 快照 `scrollery.theme.snapshot = {appearance, light, dark}`;
- `index.html` 加内联脚本:读快照(无则 matchMedia)→ 首帧前写好 `data-theme`/`data-color-scheme`;
- IPC config 仍是权威源,onMounted 校正(与快照不一致时以 config 为准并刷新快照);main.ts:18-19 现逻辑保留为无快照时的兜底。

### 4.6 token 契约测试(P9 守护)
vitest 节点测试 `src/themes/__tests__/theme-contract.spec.ts`:
1. 解析 `styles/themes/*.css`,提取每份文件的自定义属性名集合;
2. 断言:五套主题键集**完全相等**且非空;每套含 `color-scheme`;每套 `[data-theme='<id>']` 选择器与文件名一致;
3. 注册表断言:BUILTIN_THEMES 的 id 与 CSS 文件一一对应,preview 四色为合法 hex。
这份测试就是未来商店 manifest 校验器的雏形——外置主题上架前跑同一套键集校验。

## 5. 内置主题家族规格

命名: 设置卡片显示「<中文单字> · <英文名>」,i18n key `theme.name.<id>`。色值实现时从权威源(§2.3)取值起步 + 对比度脚本验证,下表「基调」列为设计意图而非最终 hex。

| id | 名 | kind | 基调 | accent | 定位 |
|---|---|---|---|---|---|
| `ink` | 墨 · Ink | dark | 中性深灰(≈#1b1b1f 档),即现 dark 精修 | 沿用蓝紫系,微调对比 | **默认暗色**;专业暗房感,ICC 中性观察环境 |
| `porcelain` | 素 · Porcelain | light | 展厅白(近白微暖灰),即现 light 精修 | 沿用蓝紫系 | **默认亮色**;画廊留白感 |
| `xuan` | 宣 · Xuan | light | 宣纸暖白 chrome + 墨色文本层级 | **印章朱红**(印泥红/朱磦系,AA 达标后定值) | **签名主题**;唯一「敢下手」的一套,其余保持克制 |
| `obsidian` | 玄 · Obsidian | dark | OLED 纯黑(#000 底,表面层极低明度) | 低发光量,微 glow | 媒体沉浸/OLED 省电/夜间 |
| `dai` | 黛 · Dai | dark | 青灰冷调(Nord 系气质,蓝灰 hue 但低饱和) | 冷青蓝 | 冷调审美备选 |
| `moonlight` | 月白 · Moonlight | light | 冷偏灰(slate)+纯白表面+发丝线边框+轻阴影 | 虹蓝(#2177b8,靛青做 hover/激活) | **2026-07-06 GUI 手测后追加**:用户反馈五套「发脏」,参考 Codex 桌面端做「干净清凉」配方;成因诊断=等值 RGB 纯灰感知偏闷+中间灰阶靠太近+阴影偏重 |

### 5.1 全家族公共红线
- `--color-bg-canvas` 一律低饱和中性(宣也不例外——纸色只到 chrome 为止,§2.1);
- 正文文本对比 ≥4.5:1、次级文本 ≥3:1,明暗各自独立验证(不得由另一侧推断);
- 状态色(success/warning/error/info)语义不变,各主题只调明度/饱和适配底色;
- 每套主题必须同时校验 hover/active/disabled 三态在该底色上可辨。

### 5.2 宣主题签名细节(全味道版)
- **纸纹**: `--texture-chrome` 用纯 CSS 实现(SVG feTurbulence data URI 噪点,opacity ≤0.03,叠在侧栏/工具栏/状态栏背景上);`prefers-reduced-transparency`/低端机不额外分支——纹理是静态的,无动效成本;
- **印章朱红**: 用于 accent/选中态/focus-ring/收藏星标激活色;禁大面积铺色(印章逻辑:小而重);
- **墨色文本**: 文本层级用「浓墨→淡墨」的暖黑阶,不用纯 #000;
- **克制清单**: 不做毛笔字体、不做卷轴动画、不做水墨晕染动效——签名感来自「纸 + 墨 + 一点朱」,到此为止。

## 9. 为主题商店预留的边界(本轮明确不做)

**不做**: manifest schema 定稿、主题下载/更新、签名校验、运行时热插拔 loader、主题导入 UI。
**只保证四个接缝**(未来商店的全部改造点):
1. 主题 = 纯 CSS 变量覆写文件,无 JS(外置主题即同格式文件);
2. 一切主题 UI 读注册表渲染,`ThemeDefinition.source` 已预留 `'external'`;
3. token 契约测试即 manifest 校验器雏形(键集校验逻辑可直接复用);
4. `data-theme` 值即主题 id,持久化即 id 字符串——外置主题无需新状态模型。
