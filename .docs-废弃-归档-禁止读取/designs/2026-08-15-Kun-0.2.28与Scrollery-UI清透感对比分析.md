# Kun-0.2.28 与 Scrollery UI 清透感对比分析

> 研究日期：2026-08-15
> 对比基线：`C:\workspace\Kun-0.2.28` 与当前 `C:\workspace\scrollery` 代码
> 文档性质：代码与截图证据型快照，不代表 Scrollery 已经采用后文建议

## 1. 结论摘要

Kun-0.2.28 看起来更“清透”，核心不是它使用了某一个更漂亮的蓝色，也不是简单地给所有元素加 `backdrop-filter: blur()`。它形成了一套连续的材质关系：浅蓝灰画布作为底，半透明白色表面承载内容，少量渐变、雾化和高光把层级连起来，阴影只负责把真正浮起的对象托出来，再用更大的留白和更少的外层容器保持呼吸感。

Scrollery 的 Moonlight 主题与 Kun-0.2.28 默认浅色的色相已经比较接近：都是冷白、浅蓝灰、深蓝灰文字和蓝色强调色。因此，当前两者的主差异不是“Scrollery 颜色选错了”，而是以下四项组合差异：

- Kun 把材质处理放在宿主级 shell、canvas、topbar、sidebar 和浮层上，Scrollery 更多把材质处理留在具体组件或单个主题文件里。
- Kun 的大部分界面由连续画布与少量大表面构成，Scrollery 在 Settings、sidebar 工具区和 toolbar 中更常出现重复的实心卡片、边框和胶囊控件。
- Kun 的页面密度更低，标题、说明、分组之间有更大的间距；Scrollery 是资产管理器，信息密度和可操作入口明显更高，这会自然削弱“轻透感”。
- Kun 的阴影、渐变和 blur 有明确的层级职责；Scrollery 也有这些能力，但分布较局部，尚未形成统一的 host-level material recipe。

可以把本次观察归纳为：

```text
清透感 = 连续的底色关系
       + 透明度与层级关系
       + 足够的留白
       + 低噪声边界
       + 克制的强调色
       + 合理的信息密度
```

这意味着 Scrollery 最值得先借鉴的是“表面系统和分组方式”，而不是先重做六套主题的色板。

## 3. 两个项目的 UI 入口与基本架构

| 维度 | Kun-0.2.28 | Scrollery |
| --- | --- | --- |
| UI 技术 | Electron + React + TypeScript | Tauri 前端、Vue 3 Composition API、TypeScript |
| 全局样式入口 | `src/renderer/src/main.tsx` 依次加载 `index.css`、`styles/base-shell.css` 及编辑器/工作流样式 | `src/main.ts` 加载 `src/assets/styles/index.css` |
| 全局 token | `base-shell.css` 中的 `--bg-*`、`--surface-*`、`--ds-*` 和阴影/渐变变量；Tailwind 映射到语义 token | `variables.css` + 六套主题 CSS；组件通过 `var(--color-*)` 等语义变量取值 |
| 组件样式方式 | Tailwind utility 与全局 `base-shell.css` 组合，少数组件有专门 CSS | 全局 CSS、主题 CSS、Vue SFC scoped style 三层并存 |
| 主题切换 | `data-theme="dark"`，另有可选 iKun/Retroma 模式 | `ThemeRegistry` 注册六套主题，默认浅色为 Moonlight、默认深色为 Ink |
| 材质覆盖范围 | shell、stage、topbar、sidebar、composer、popover、timeline 等已有统一材料变量 | 表面颜色由主题统一，渐变/blur/阴影更多由具体组件局部声明 |

相关入口： [Kun main.tsx](C:/workspace/Kun-0.2.28/src/renderer/src/main.tsx:1)、[Kun base-shell.css](C:/workspace/Kun-0.2.28/src/renderer/src/styles/base-shell.css:1)、[Scrollery index.css](C:/workspace/scrollery/src/assets/styles/index.css:1)、[Scrollery variables.css](C:/workspace/scrollery/src/assets/styles/variables.css:1)。

这个架构差异很关键：Kun 更像“先定义一套应用外壳材质，再让页面内容落在外壳中”；Scrollery 更像“先定义主题语义颜色，再由各组件自行组合表面”。后者更灵活，但如果组件都使用 `card + border + radius`，最终就容易出现局部正确、整体不连续的效果。

## 4. Kun-0.2.28 的清透机制

### 4.1 默认浅色的基础色并不极端

Kun 默认浅色的关键值来自 [base-shell.css](C:/workspace/Kun-0.2.28/src/renderer/src/styles/base-shell.css:1)：

| 角色 | Kun-0.2.28 实际值 | 视觉作用 |
| --- | --- | --- |
| 应用底色 | `#f3f5fc` | 冷静的浅蓝灰背景，不是纯白 |
| sidebar 底色 | `#eef2fa` | 与主画布分离，但差异很小 |
| canvas | `#fafbff` | 近白内容画布，给内容留出亮度空间 |
| surface-1 | `rgba(255,255,255,0.9)` | 半透明白色普通表面 |
| surface-2 | `rgba(255,255,255,0.98)` | 更稳定的高层表面 |
| surface-3 | `#ffffff` | 需要最清晰边界的内容表面 |
| 弱边框 | `rgba(20,47,95,0.13)` | 低对比度分隔 |
| 强边框 | `rgba(20,47,95,0.2)` | 交互或浮起表面的边界 |
| 主文字 | `#233659` | 深蓝灰，不是纯黑 |
| 次文字 | `#54678c` | 说明和辅助信息 |
| 强调色 | `#3b82d8` | 用于真正可操作的重点 |

这些值本身并没有神奇之处。真正重要的是：白色表面不是一律不透明，画布、chrome 和卡片之间保留了非常轻微的色彩透叠；边框也不是靠深色线条制造区块，而是作为低噪声的层级提示。

### 4.2 大气层在宿主级统一发生

Kun 的 `base-shell.css` 在 body 和 shell 层就建立了整体氛围：

- `body` 使用系统/CJK 友好的字体栈，并以 `--bg-app` 作为全局背景。
- `body::before` 覆盖窗口，提供浅色渐变。
- `body::after` 叠加 radial/linear glaze，让纯色背景不显得干涩。
- `.ds-stage-surface` 使用从 `#fafbff` 到白色的纵向渐变，给中心内容一个非常轻的亮度方向。
- topbar 使用三段式白色透明渐变，并配合内高光和低对比阴影。
- sidebar 使用浅色纵向渐变和蓝色 radial haze，不是单一的 `background-color`。

这套处理的价值在于：即使某个页面没有单独写复杂样式，用户仍会感受到统一的光照和材质背景。它让“清透”成为应用环境，而不是某个组件的装饰。

### 4.3 表面层级有明确梯度

Kun 的表面大体可以分为以下几层：

1. 应用背景：浅蓝灰，承担全局留白。
2. 主画布：接近白色，作为内容阅读和工作区域。
3. 普通表面：`surface-1`，略带透明，适合卡片和工具区。
4. 强表面：`surface-2/3`，用于需要更稳定阅读对比的区域。
5. 浮起表面：popover、menu、composer、plan panel 等，叠加更明显的阴影和局部 blur。

`.ds-shell`、`.ds-panel`、`.ds-composer-shell` 已经把这些角色映射到不同的背景、边框和阴影。`.ds-frosted` 使用 `backdrop-filter: blur(18px)`，但它是一个有名字、有场景边界的材料类，不是所有容器的默认样式。菜单和计划面板也有各自的局部 blur 与阴影。

因此，Kun 的透明感并不是“所有东西都透明”，而是“低层能透出高层的来源，高层又有足够的边界和阴影保持可读”。

### 4.4 阴影是托举，不是描边

Kun 的浅色阴影大致是：

- shell：`0 12px 30px rgba(20,47,95,.08)`
- panel：`0 16px 44px rgba(20,47,95,.06)`
- composer：一层较宽的 `rgba(...,.1)` 阴影，加一层较近的 `rgba(...,.06)` 阴影

阴影的共同特点是蓝灰色、低不透明度、较大扩散半径。它们把层级从背景中托出，而不是沿卡片边缘画一圈黑线。边框仍然存在，但边框与阴影的对比都被压低，视觉焦点自然回到内容和操作。

### 4.5 布局通过留白降低噪声

Kun 的 Settings 页面使用较大的外边距和大卡片：标题区域有明显上下留白，内容区使用 `px-10 py-10`，卡片内部再用分隔线组织条目，而不是每一行都变成一个新卡片。聊天 topbar 约 46px 高、圆角约 22px，消息之间留出较明显的间距，空状态 hero 标题可以放大到 56px。

这会产生两个结果：

- 同样数量的边框和控件，被更大的空白分隔后，视觉密度下降。
- 一个大表面内部由分隔线、标题和说明完成层级，页面不会出现“卡片套卡片”的连续硬切换。

### 4.6 字体与字号承担层级，但不是主因

Kun 使用 `-apple-system`、`BlinkMacSystemFont`、`SF Pro Text`、`Segoe UI`、CJK 字体等系统字体栈。常规 UI 文本多在 11–16px，设置页标题、空状态和 hero 区域再使用更大的字号。字体更贴近平台，字面和控件之间的关系较自然。

不过，字体不是本次差异的第一原因。Scrollery 的 Inter Variable 也具备清晰、现代的 UI 特征；如果只替换字体而不改变表面层级、留白和卡片分组，整体仍然不会变成 Kun 的清透感。

### 4.7 默认模式与可选模式需要分开理解

Kun-0.2.28 的 `ui-mode.ts` 默认值是 `default`。`ikun` 和 `retroma` 是可选模式，分别通过 `data-ikun-mode`、`data-retroma-mode` 扩展样式。本文比较的是默认模式下的蓝灰、白色、玻璃化外壳，不把可选主题的暖色或复古处理当作 Kun 默认清透感的来源。

相关代码： [ui-mode.ts](C:/workspace/Kun-0.2.28/src/renderer/src/lib/ui-mode.ts:1)、[apply-theme.ts](C:/workspace/Kun-0.2.28/src/renderer/src/lib/apply-theme.ts:1)。

## 5. Scrollery 当前 UI 机制

### 5.1 Moonlight 的颜色方向已经正确

Scrollery 的默认浅色主题在 [registry.ts](C:/workspace/scrollery/src/themes/registry.ts:73) 中指定为 Moonlight。其关键值来自 [moonlight.css](C:/workspace/scrollery/src/assets/styles/themes/moonlight.css:1)：

| 角色 | Scrollery Moonlight 实际值 | 与 Kun 的关系 |
| --- | --- | --- |
| 主背景 | `#f4f8f9` | 同样是浅冷色，但更偏灰青 |
| 次背景/表面 | `#ffffff` | 与 Kun 的白色表面相近，但默认更实 |
| elevated | `#eaf1f4` | 有明确的浅蓝灰层级 |
| canvas | `#f3f5f6` | 适合资产画布，色彩相对中性 |
| 主文字 | `#15222e` | 比 Kun 主文字更深、更接近黑蓝 |
| 次文字 | `#56697a` | 与 Kun 次文字的功能接近 |
| 强调色 | `#2177b8` | 同样是克制的蓝色强调 |
| 弱边框 | `rgba(23,48,73,.1)` | 接近 Kun 的低对比边框 |
| 阴影 | `.05/.06/.08/.11` 多级 token | 已具备层级基础 |

所以，直接把 Moonlight 改成更蓝或更白，收益可能很小。它需要的是把已经存在的语义色变成更连贯的材料配方，并降低局部组件之间的硬切分。

### 5.2 Scrollery 的全局层更偏“实心基座”

`variables.css` 已经有 `--toolbar-bg`、`--popover-bg`、`--card-bg` 等角色，但它们主要是主题颜色映射。全局 `index.css` 的 `.btn`、`.chip`、`.input`、`.settings-card` 使用语义背景、边框和圆角，形成的是稳定、清楚、易维护的 UI 基础。

这套基础的优点是可预测、主题切换简单、对资产管理中的高信息密度友好；缺点是当多个层级都采用“实心背景 + 细边框 + 8/12px 圆角”时，组件之间的材质差异主要只剩颜色差异，整体会显得更像一组平铺的 UI 模块。

### 5.3 AppShell 的层级存在，但连续光照较少

`AppShell.vue` 当前的主要关系是：

- `.app-shell` 使用主背景。
- `.app-sidebar` 使用 secondary 背景，并可叠加主题 texture。
- `.app-toolbar` 高度 48px，使用 toolbar 背景和底部边框。
- `.app-statusbar` 高度 28px，使用 secondary 背景和顶部边框。
- viewer toggle、fullscreen hint 等局部控件使用 `color-mix`、阴影和 blur。

因此 Scrollery 不是没有玻璃或阴影，而是这些效果更多停留在局部控件：viewer toggle、fullscreen hint、settings header、toolbar popover 和媒体 overlay。AppShell 的大面积 sidebar、toolbar、statusbar 仍然更接近稳定的色块分区。

相关位置： [AppShell.vue](C:/workspace/scrollery/src/components/layout/AppShell.vue:252)。

### 5.4 Settings 的信息组织更碎片化

`SettingsView.styles.css` 当前有明显的结构化能力：

- 顶部 header 使用半透明背景、`blur(12px)`、底部边框和三列 grid。
- 左侧导航是约 210px 宽的独立导航区域。
- 主内容区宽度约 960px，外层 gap 约 32px。
- 内容 section 间距约 24px，重复使用 `.settings-card`。
- `.settings-card` 内部有 header、item padding 和行间分隔线。

问题不在于单张 settings card 做得差，而在于许多 section 都以同样的外框重复出现。与 Kun 的“一个大表面承载多个相关设置”相比，Scrollery 更容易让用户感知到多个连续的浅色板块，视觉节奏因此变密。

### 5.5 toolbar、chip 和 sidebar 有较高的交互密度

Scrollery 是资产管理器，toolbar 需要同时承载搜索、过滤、视图切换、排序和状态；sidebar 还包含 Library、Tools、Folders 等多级入口。当前样式中：

- toolbar search、view popover、filter popover 都有 surface 背景、边框、8px 圆角和 shadow-lg。
- `.chip` 使用胶囊形状，适合标签和过滤状态，但大量并列时会增加轮廓噪声。
- Library 导航项使用 6px/8px padding 和 8px radius，工具卡片使用 surface、border、8px radius 与轻微阴影。

这些规则单独看都合理，组合后却会使顶部、侧栏和内容区同时出现很多小型“独立对象”。Kun 通过更少的 top-level surface 和更大的空白，把视觉重心放在单一工作区；Scrollery 则把可操作性优先，导致更强的模块化感。

### 5.6 六套主题主要改变颜色，只有 Xuan 改变 chrome 纹理

Scrollery 的主题文件主要提供语义变量，不直接改变组件几何和布局。Moonlight、Porcelain、Ink、Obsidian、Dai 的 `--texture-chrome` 基本为 `none`，只有 Xuan 带有纸张噪声类 data SVG texture。

这保证了主题切换的稳定性，但也说明当前“材质感”更多是主题局部能力，而不是全局宿主能力。若要借鉴 Kun，应新增可选的 host material recipe，并让主题只提供颜色、透明度和纹理参数；不应把 Kun 的浅色玻璃效果硬编码到所有主题。

## 6. 逐维度对比

| 维度 | Kun-0.2.28 | Scrollery 当前 | 对清透感的影响 |
| --- | --- | --- | --- |
| 画布 | `#f3f5fc` / `#fafbff` 等连续浅蓝白层 | Moonlight 已有主背景和 canvas，但 shell 分区较实 | Kun 的页面底色更连续，Scrollery 更容易被栏和卡片切开 |
| 普通表面 | 多级半透明白色 surface | 多数是主题提供的稳定 surface/card 背景 | Kun 的表面能透出环境，Scrollery 的表面更像独立板块 |

| 浮层 | 有命名的 frosted、popover、composer 材料 | popover/dialog 已有 shadow 和局部 blur | 能力接近，但 Scrollery 的浮层与宿主背景联系较弱 |

| 阴影 | 大扩散、低不透明度、蓝灰调 | 有 sm/md/lg/xl token，组件局部使用 | 基础能力存在，缺的是统一的层级配方和使用纪律 |

| 产品密度 | memory/chat/settings 偏阅读与对话 | asset manager 偏检索、筛选和批量操作 | 不能简单追求 Kun 的低密度，需要在高密度下减噪 |

## 7. 截图观察与解释边界

### 7.1 Kun 截图表现出的机制

Kun-0.2.28 的 memory UI 截图显示：

- 页面底色是浅蓝灰，不是纯白大画板。
- 主内容通常落在一个大圆角表面中，边框细而浅。
- 设置页的标题、说明、卡片和分隔线之间有明显留白。
- 下拉菜单是单一的浮动圆角表面，阴影比普通卡片更明确。
- chat 页面保留大面积空白，composer 作为底部浮起对象出现。

这些截图与 `base-shell.css` 中的 surface、gradient、shadow、frosted 规则相互印证。

### 7.2 Scrollery 截图表现出的机制

Scrollery Moonlight 的 settings/gallery 截图显示：

- 整体色调已经是干净的冷白/浅蓝灰。
- 左侧 sidebar、顶部 toolbar、设置导航、设置内容卡片、工具卡片同时承担分区作用。
- gallery 的 toolbar 和过滤入口信息量大，媒体网格还需要 badge、状态和选择反馈。
- settings 页面中多个浅色圆角卡片连续排列，边框和背景重复出现。

这说明 Scrollery 的主要问题不是“视觉脏”或“颜色不统一”，而是界面在多个层级上都使用了相似强度的容器表达，缺少明确的“背景—chrome—表面—浮层”优先级。

### 7.3 截图不能支持的结论

截图不能证明以下判断：

- Kun 的所有工作台页面都比 Scrollery 更适合资产管理。
- Scrollery 必须完全复制 Kun 的布局、字体或圆角。
- 全局 blur 一定会带来更好的视觉效果。
- 减少卡片后一定不会损失可用性。

这些只能作为后续原型和回归测试的假设。尤其是 Scrollery 的 gallery 需要比 Kun chat 更高的信息密度，清透方案必须围绕“在高密度下减少轮廓噪声”设计。

## 8. 差异的根因排序

### P0：材质作用范围不同

Kun 把材质当作应用外壳：body、stage、topbar、sidebar、panel、composer 和 popover 共享同一组光照和层级变量。Scrollery 的主题变量有颜色角色，但 host-level 的透明度、渐变、glaze、浮层阴影组合还不统一。

### P0：表面分组策略不同

Kun 倾向于“大表面承载多个相关内容”，Scrollery 倾向于“每个 section 一个 settings-card，每个工具一个 tool card”。前者减少了顶层轮廓，后者强化了局部可读性但增加了整体分割。

### P1：信息密度不同

Scrollery 的产品任务要求同时展示更多入口和状态。若不改变信息架构，不能单纯照搬 Kun 的留白；应优先压低非关键边框、背景和阴影的视觉重量，让同样密度的内容更安静。

### P1：主题与材质的职责边界不同

Scrollery 的主题文件承担了大量表面语义色，但材质 recipe 分散在全局 CSS 和组件 scoped CSS 中。未来如果每个主题自行定义一套玻璃/阴影规则，维护成本会迅速上升。更稳妥的方向是宿主 recipe 固定结构，主题只调颜色与材质参数。

### P2：字体和几何尺度

字体栈、字号跨度、圆角和间距会影响感受，但不是第一改造点。先解决连续背景、外框数量和层级对比，再评估是否需要微调 Inter Variable 的字号或改用更平台化的字体栈。

## 9. 对 Scrollery 的直接启示

1. 不应先全面重做 Moonlight 色板。它与 Kun 的冷白蓝灰方向已经相容。
2. 应新增一层“宿主材质配方”，把 canvas、chrome、surface、elevated、overlay 的背景、边框、阴影、渐变和 blur 角色明确化。
3. Settings 应先减少重复的外层卡片，把分组更多交给大容器、分隔线、标题和行 hover；危险区、明确的独立操作区仍可保留卡片。
4. Sidebar 的普通导航可以更接近连续背景，工具卡片应区分“真正需要托起的工具”和“只是一个入口”的两种状态。
5. Toolbar 保留高密度功能，但把非激活 chip、按钮和 popover 的边界对比压低；强调色只集中在当前过滤、选择和主要动作。
6. 媒体画布保持相对中性，不把蓝色玻璃光照铺到图片内容上；清透效果应集中在 chrome 和浮层。
7. blur 只用于顶栏、popover、dialog、composer 等浮起对象，避免对大面积滚动内容做默认 backdrop blur。
8. Xuan 等有明确纸张身份的主题继续保留自己的纹理；宿主材质层需要允许主题关闭 glaze 或替换纹理，不把冷白玻璃强加给所有主题。

具体实施顺序见 [Scrollery 清透材质化 UI 建议方案](C:/workspace/scrollery/docs/designs/2026-08-15-Scrollery清透材质化UI建议方案.md)。

## 11. 快照结论

Kun-0.2.28 的清透感可以迁移，但迁移对象应是“材质层级、光照连续性、留白和分组纪律”，不是 Kun 的页面结构或某几个 CSS 数值。Scrollery 当前已经有足够好的主题颜色和局部浮层能力，下一步应在不破坏资产管理密度、主题身份和性能的前提下，把这些能力提升为统一的宿主级材料系统。

本快照只记录现状。任何 token 命名、组件替换、主题默认值或信息架构调整，都需要通过后续设计评审和视觉回归后再写入现行实现。
