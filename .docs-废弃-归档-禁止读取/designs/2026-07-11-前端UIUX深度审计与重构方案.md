# 前端 UI/UX 深度审计与重构方案

> 范围：UI、UX、配色、信息架构、操作逻辑、accessibility、responsive 与视觉回归能力。
>
> 当前状态：用户已于 2026-07-11 批准全部推荐项并提供真实 Tauri 截图，进入分阶段实施。
>
> 与现有方案关系：承接 2026-07-06 多主题体系与 2026-07-08 顶栏重构，不重复建设已完成的主题注册表、命令注册表和自绘窗口层。

## 1. 结论摘要

当前前端不是“没有设计系统”，而是已经有一套较完整的 foundation token、多主题、路由查看器、CommandRegistry、虚拟网格与 accessibility 修复基础。质量门禁也全部通过：TypeScript、ESLint、615 项前端测试、6 套主题对比度和 production build 均为绿色。

真正限制体验继续提升的不是换一套颜色，而是以下结构性问题：

1. **信息架构混合**：一部分页面由 route 表达，一部分由 Pinia 临时状态或全屏 overlay 表达，导致刷新、返回、深链和导航高亮不稳定。
2. **命令层级重复**：ContextualToolbar 与 Viewer/Reader/Audio 局部工具栏同时提供相同命令，用户需要在两个位置寻找操作。
3. **组件原语缺失**：Modal、Popover、IconButton、Field、ToggleChip 等仍散落在大量 scoped style 中，行为和 accessibility contract 漂移。
4. **窄窗规则不足**：Tauri 窗口可自由缩放，但多数页面没有明确的 compact/minimal 模式；DocumentViewer 和标题栏工具尤其拥挤。
5. **管理操作不够可逆**：Persons 的隐藏/误检入口小且隐蔽，隐藏后没有管理入口；Collections/Persons 卡片的键盘和读屏路径不完整。
6. **视觉回归不可自动化**：普通浏览器因 WindowChrome 直接依赖 Tauri API 而无法挂载应用，现阶段无法稳定做 Playwright 截图回归。

因此，本方案的方向是：**保留现有主题资产，先统一导航与操作模型，再建立 component-level UI primitives，最后做视觉收敛与主题打磨。**

### 2.2 尚未验证

- Tauri 真机下主图库、窄窗 overflow、设置页、查看器的真实观感。
- 6 套主题在真实照片、不同 DPI、Windows/macOS 下的逐页对比。

- 空图库、海量图库、离线卷、缺失文件、AI 未安装等所有状态的视觉一致性。

### 2.3 浏览器验证失败的实际原因

`WindowChrome.vue:53` 在 setup 阶段直接调用 `getCurrentWindow()`。普通浏览器没有 Tauri metadata/invoke，应用整棵组件树无法挂载。浏览器首帧只验证到主题快照能正确应用 `porcelain/light`，不能代表产品 UI。

这不是 Tauri 产品运行故障，但会阻断自动视觉测试。实施阶段应补一个可控的 platform adapter 或 UI harness。

### 2.4 真实截图校准结论（2026-07-11）

- Gallery 宽窗的标题栏承载过多：标题、数量、filters、view controls、实验入口、搜索、undo/redo、全屏和窗口三键竞争同一行。
- Gallery 内容上沿的路径与“画布”标记像调试信息；右侧 timeline rail 过窄且标签被裁切。
- 窄窗 filter popover 大面积覆盖 Sidebar/内容且视觉上脱离 trigger，固定网格宽度问题已在真机成立。
- Settings 单列 card 在宽屏留下大面积无效空白，正式 route + 分区导航方案成立。
- Viewer 顶栏和底栏命令重复在真机上非常明显；底栏适合连续操控，顶栏应只保留导航级命令。
- Viewer route 默认折叠 Sidebar，给媒体更多空间；保留显式恢复入口与用户偏好。

### 3.3 P3：维护性与性能问题

- 68 个 Vue 文件中 67 个带 scoped style；样式修复需要跨文件重复施工。

## 4. 目标体验原则

### 4.1 产品定位

Scrollery 的核心不是“带很多主题的文件浏览器”，而是**媒体工作台**：快速进入图库、定位内容、批量整理、专注查看/阅读，并在需要时使用 AI 和插件能力。

### 4.2 六条不可变原则

1. **内容优先**：照片画布与查看器维持低饱和中性色，主题风格只进入 chrome、surface 和 accent。
2. **位置可寻址**：用户能看见的主要页面与筛选结果，都应能由 URL 或稳定 descriptor 恢复。
3. **一个命令一个主入口**：同一操作不在标题栏、内容栏、悬浮栏重复出现。
4. **渐进披露**：高频任务常驻，低频/危险/专业设置收进明确分组，不靠 hover 隐藏唯一入口。
5. **可逆优先**：隐藏、移除、清空、重建等操作提供 confirm 或 undo，并能在管理页恢复。
6. **状态不能只靠颜色**：active/error/offline/missing 必须同时有形状、图标、文字或 pattern。

## 5. 目标信息架构

### 5.1 Route 作为页面单一事实源

| 页面 | 建议 route | 状态来源 |
|---|---|---|
| 全部/智能相册 | `/library/:album` | route param |
| 目录 | `/folders/:id` | route param |
| 收藏夹列表 | `/collections` | route |
| 收藏夹内容 | `/collections/:id` | route param |
| 人物列表 | `/persons` | route |
| 人物照片 | `/persons/:id` | route param |
| 设置 | `/settings/:section?` | route param + query 搜索词 |
| 插件 | `/plugins` | route |
| 查看器 | `/view/:id`、`/doc/:id`、`/audio/:id` | route param |

Pinia 继续持有已加载实体、缓存和异步状态，但不再用“先写 active object 再 push `/`”表达页面位置。

### 5.2 Gallery query contract

建议进入 URL 的状态：

- `types=image,video`
- `favorite=1`
- `live=1`
- `rating=3`
- `color=4`
- `from=YYYY-MM-DD&to=YYYY-MM-DD`
- `group=month`
- `sort=taken_at&order=desc`
- `layout=justified|masonry|grid`
- `q=<query>&scope=filename|semantic|mixed`

不建议进入 URL 的状态：sidebar 宽度、row height、theme、tooltip 偏好等纯视觉偏好；它们继续本地持久化。

### 5.3 Sidebar active 状态

新增 `useViewDescriptor(route)` 或扩展现有 descriptor，使以下内容从同一个 descriptor 计算：

- active nav item
- 页面标题
- Gallery backend filter
- breadcrumb
- 返回落点
- empty-state 文案

禁止 Sidebar 再分别判断 `route.path` 与多个 `viewStore.active*`。

## 6. Shell 与操作层级重构

### 6.1 标题栏职责

标题栏只承担：

- WindowChrome 拖拽与窗口三键。
- 当前位置：品牌/返回/页面标题或简短 breadcrumb。
- 当前页面的 1–4 个最高频跨内容命令。
- 全局 search 入口。
- overflow 入口。

标题栏不承担：完整筛选面板、复杂表单、播放器 transport、Reader 全部工具。

### 6.2 Command ownership

| 命令类型 | 主入口 | 例子 |
|---|---|---|
| 窗口级 | WindowChrome | 最小化、最大化、关闭 |
| 导航级 | 标题栏 | 返回、上一项、下一项、沉浸 |
| 视图级 | 页面 toolbar / filter bar | filter、group、sort、layout |
| 连续操控 | 内容区局部 controls | 播放、seek、zoom、页码、音量 |
| 对象级 | context menu / inspector | 评分、颜色、收藏、移动、删除 |
| 批量级 | Selection action bar | 批量评分、标签、移动、删除 |
| 低频级 | overflow / command palette | 外部打开、调试、重建 |

ContextualToolbar 保留 CommandRegistry 驱动，但只渲染“导航级”主命令；Viewer 底栏移除与顶栏重复的 close/prev/next/immersive，保留 zoom/媒体信息等局部操控。Reader/Audio 同理。

### 6.3 统一 ToolbarOverflow

- 以 item priority 和 group 为输入，不以组件硬编码宽度为输入。
- 折叠顺序稳定且单调，避免搜索 focus 时反复折入/弹回。
- overflow menu 使用内容驱动宽度：`min-inline-size` + `max-inline-size` + viewport clamp。
- menu 打开时聚焦第一项，Escape 关闭并还焦 trigger。
- Toolbar 使用 roving tabindex；menu 使用 ArrowUp/Down/Home/End。

### 6.4 Search

- 搜索框占用稳定槽位，不通过 focus 从 200px 突增到 280px 挤压整条标题栏。
- normal/semantic/mixed 采用可读的 segmented 或 menu，不只靠一个会变图标的小按钮。
- mixed suggestion 使用 combobox/listbox/option contract。
- 查询和 scope 写入 URL；搜索中、失败、无结果均有明确状态和取消/重试动作。

## 7. 页面级方案

### 7.1 Gallery

- 宽窗：标题/搜索在标题栏；下方单独的 filter bar 显示当前 active filters 与 view controls。
- 中窗：filter bar 只显示 active chips，其余进入“筛选”与“视图”两组 overflow。
- 窄窗：搜索成为独立一行或 overlay command，不与窗口三键争宽。
- compact media 模式切换时显示一次轻量说明：“密集浏览模式仅保留选择与状态标记”。
- Selection action bar：**🔴 2026-07-13 用户裁决覆盖原设计**。原文「固定在内容安全区底部；默认不可拖动，若保留拖动则放到『自定义工具栏』高级选项」**已作废**——可拖拽正是为解决「胶囊遮挡内容」而存在的核心能力，**予以保留**（非降级为高级选项）。新方向：selection bar 支持**合并/分离一键切换**（参照标题栏 useTitlebarMode 范式）——**分离**（默认）=浮动可拖胶囊（保留拖拽+位置持久化）、**合并**=选区动作并入底部状态栏 `AppStatusBar`（docked 不可拖，28px 恒高替换式共存），两形态均支持收窄窗口折叠（useToolbarOverflow + UiPopover ⋯ 溢出菜单，菜单行含可见文字标签）。**完整设计+施工方案已于 2026-07-13 批准落盘：`designs/2026-07-13-SelectionBar合并分离一键切换方案.md`（单一真源，本条不再展开）**。要点修正：会话续16 评估的「使能前提=批量动作抽共享 composable」已被该方案推翻（docked 用 Teleport 实现，9 个批量 handler 原地留 MediaGrid）；`bottom:32px` 经测绘证实为内容区内审美间距（状态栏在 `.app-content` 定位上下文之外，物理不重叠），非 safe-area 缺失。
- 所有 empty state 都包含下一步：添加目录、清除筛选、恢复离线卷、安装解码插件等。

### 7.2 Settings

推荐改为 `/settings/:section?` 路由页，布局为：

```text
┌ 分区导航 200–240 ┐ ┌ 搜索设置 / 当前分区标题 ─────────┐
│ 外观             │ │ 常用设置                         │
│ 图库与缩略图     │ │ -------------------------------- │
│ 阅读             │ │ 高级设置（默认折叠）             │
│ AI 与模型        │ │ 危险操作（独立 danger zone）     │
│ 存储             │ │                                  │
│ 高级             │ │                                  │
└──────────────────┘ └──────────────────────────────────┘
```

- SettingSpec 新增 `keywords`、`advanced`、`danger`、`requiresRestart`、`validation`、`accessibleName`。
- 每个控件与 label/description/error 由 id 关联。
- 立即生效项显示即时反馈；需要 restart/重算项明确标记影响。
- 危险项不与普通设置混排，统一 confirm、影响说明和执行进度。
- 搜索结果显示所属分区，并可跳转定位。

### 7.3 Collections

- 卡片为 article 容器，内部有一个覆盖卡片主要区域的真实链接/按钮。
- rename/delete 为独立 IconButton，hover 显示但 keyboard focus 时同样显示。
- 双击重命名保留为快捷方式，显式“重命名”按钮是可发现主入口。
- 新建卡片使用 button，不使用 clickable div。
- 打开后进入 `/collections/:id`，breadcrumb 可回到列表。

### 7.4 Persons

- 与 Collections 使用同一 CardAction pattern。
- 选择、隐藏、标记误检均为真实按钮，命中区至少 compact 标准。
- 隐藏与误检操作后给 undo toast。
- 增加“已隐藏/已忽略”管理视图，支持恢复。
- 多选合并条固定在可见区域，并显示目标与不可逆影响。

### 7.5 Viewer

- 顶栏：返回、上一项/下一项、文件名、沉浸、overflow。
- 内容底部：zoom、fit mode、rotate、媒体局部状态；删除与顶栏重复命令。
- Inspector 作为右侧可折叠 panel，承载元数据、人脸、评分、颜色、文件操作。
- 图片容器可聚焦，提供快捷键帮助入口；沉浸模式保留 F10 标题栏逃生路径。
- missing/offline/unsupported state 继续使用现有明确占位，并增加可执行下一步。

### 7.6 Reader

- 顶栏只保留返回、标题、阅读进度、搜索和 overflow。
- 阅读侧面板承载 TOC、书签、排版、版本、校对、替换；互斥 panel 用一个 panel controller 管理。
- 播放/自动滚动等连续动作留在阅读区。
- 窄窗下 select 收入设置 panel，不允许横向压缩正文标题。

### 7.7 Audio

- transport controls 始终留在播放器内容区，标题栏不重复放 play/seek。
- 顶栏仅保留返回、标题、收藏/外部打开/overflow。
- 时间、音量、歌词滚动使用 tabular numerals 和明确 focus 状态。

### 7.8 Plugin / AI

- 下载、安装、初始化、索引、失败必须使用同一 AsyncTask pattern：状态、进度、取消、重试、错误下一步。
- destructive rebuild 保留现有 confirm，进一步补预计影响与可取消边界。
- 未安装模型/插件的 empty state 直接给唯一主动作，不显示无响应的禁用控件堆。

## 8. 视觉与配色方案

### 8.1 保留的资产

- 保留 6 套主题、ThemeRegistry、light/dark slot、system mode、FOUC snapshot 和 contrast contract。
- 保留“画布中性、chrome 承载主题性格”的现有原则。
- 保留 Inter Variable、Lucide、现有 spacing/radius/type scale 基础。

### 8.2 新增三层 token

1. Foundation：现有 spacing、radius、font、duration、z-index。
2. Semantic：现有 bg/text/accent/status/canvas。
3. Component：新增以下 contract：

- `--control-size-compact/default/touch`
- `--control-padding-inline`
- `--control-focus-ring`
- `--toolbar-bg/border/gap`
- `--popover-bg/border/shadow/max-inline-size`
- `--card-bg/border/hover/selected`
- `--selection-ring/selection-fill`
- `--danger-bg/danger-text/danger-hover`
- `--media-overlay-bg/media-overlay-text`

组件只消费 component/semantic token；主题只覆写 semantic，不逐组件写选择器。

### 8.3 默认视觉方向

建议以 **Moonlight（亮）+ Ink（暗）**作为产品默认对，并保留 Porcelain/Xuan/Obsidian/Dai 作为可选风格：

- Moonlight 负责清爽、现代、低脏感的默认亮色体验。
- Ink 负责专业媒体工作台的默认暗色体验。
- Gallery canvas 在所有主题下继续保持中性。
- Xuan 的纸纹只进入 Sidebar/Toolbar/Dialog，不进入媒体画布。

用户已确认替换当前 Porcelain 默认：Moonlight 为默认亮色，Ink 保持默认暗色。

### 8.4 状态配色

- Accent 只用于 selected/current/focus/primary action，不用于所有可点击元素。
- Error 只用于错误与 destructive action，不用于普通 close hover。
- Offline、missing、unsupported 使用不同图标与文案，不只换颜色。
- Rating 与 color label 属内容元数据，保持其真实色，但外围选择/hover 仍走 UI token。

## 9. UI primitives 清单

实施时优先建立以下 repo-native primitives，不引入大型 UI framework：

| Primitive | 统一内容 |
|---|---|
| `UiButton` / `UiIconButton` | size、variant、loading、disabled、focus、tooltip、aria-label |
| `UiField` | label、description、error、id/name/autocomplete |
| `UiSelect` / `UiNumberField` | control contract 与 validation |
| `UiToggle` / `UiToggleChip` | checked/pressed、label、hit target |
| `UiPopover` | placement、viewport clamp、focus、Escape、return focus |
| `UiDialog` | overlay、focus trap、scroll lock、confirm/danger、reduced motion |
| `UiToolbar` / `UiOverflowMenu` | roving tabindex、priority、groups、shortcuts |
| `UiCardAction` | primary action、secondary actions、selection、hover/focus |
| `UiEmptyState` | icon、title、description、primary/secondary action |
| `UiAsyncState` | idle/loading/success/error/cancel/retry/progress |
| `UiToast` | polite/alert、undo、timeout、persistent error |

这些 primitives 应先以最小 API 覆盖现有页面，不在第一阶段追求抽象所有特殊场景。

## 10. Responsive 与窗口策略

不建议只用全局 viewport breakpoint；Toolbar、Settings content、Reader toolbar 应优先用 container query/可用宽模式。

定义三种行为模式：

| 模式 | 行为 |
|---|---|
| Full | 文本标签与高频命令展开，Inspector/Sidebar 可并存 |
| Compact | 次要命令进入 overflow，label 缩短，Sidebar 可收窄 |
| Minimal | 搜索/筛选打开为 overlay 或 panel，Sidebar 可隐藏，窗口三键永不被挤压 |

每个模式必须验证中文、英文、100%/125%/150% 系统缩放，不以单一 252px 中文魔数通过。

## 11. Accessibility 非阻断基线与 motion DoD

用户裁决：accessibility 本轮暂不作为必须支持项。以下项目按“已有能力不回退、机械修复顺手完成、复杂模式不阻断交付”执行；不再作为阶段验收硬门槛。

- 所有 action 使用 button，navigation 使用 link/route link。
- icon-only button 必须有可访问名；装饰图标 `aria-hidden="true"`。
- 所有表单有程序性 label、name、合适 type/autocomplete。
- Dialog/Popover 打开聚焦、Escape 关闭、关闭还焦。
- Toolbar 使用 roving tabindex；Card grid 有稳定键盘路径。
- active/toggle 状态使用 `aria-current`/`aria-pressed`/`aria-selected`。
- async 更新使用 `aria-live`，阻断错误可用 alert。
- 删除全部 `transition: all`；动画只使用 transform/opacity 或显式 color/border。
- 所有装饰动画服从 `prefers-reduced-motion`。
- 文本、状态、focus、hover/active 的主题组合纳入 contrast 检查。

## 14. 风险与止损

| 风险 | 缓解 |
|---|---|
| 大 SFC 拆分同时改变行为 | 先 characterization tests，再提 primitive，最后迁移页面 |
| Route 化导致 KeepAlive/滚动位置回归 | 保留当前 MediaGrid KeepAlive，route descriptor 与 scroll anchor 分开提交 |
| Toolbar 再次出现折叠振荡 | 单一可用宽测量、稳定 priority、不用 focus 改 natural width |
| 主题一次改太多难定位 | foundation/semantic/component token 分阶段，每阶段只改一层 |
| Canvas 性能被 DOM a11y 镜像拖慢 | Canvas 主渲染不回退；只为当前焦点/可见选择提供最小语义桥接 |
| Harness mock 掩盖 Tauri 差异 | harness 仅做视觉/DOM contract；窗口拖拽/三键仍做真实 Tauri GUI 验收 |
