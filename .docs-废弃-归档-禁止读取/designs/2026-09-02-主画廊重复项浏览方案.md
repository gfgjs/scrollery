# 主画廊重复项浏览方案

## 0. 演进关系

本文取代“独立重复内容页作为核心入口”和“文件夹候选树作为首要结果页”的产品方向。此前已经落地的精确摘要、Live Photo 逻辑单元、`source_revision`、去重任务和当前有效组查询继续作为技术基础，见[去重功能全局实现方案](2026-08-30-去重功能全局实现方案.md)。

[内容去重文件夹优先复核方案](2026-09-02-内容去重文件夹优先复核方案.md)保留为已实现方案快照，其中的文件夹统计、清理草案和 preview/apply 不进入本方案 MVP 主流程。

本文只设计浏览、理解与普通画廊交互。keeper、自动建议、整组清理、文件夹清理草案和磁盘删除均不属于本阶段。

## 1. 产品裁定

主画廊增加“重复项”入口。它在界面上表现为筛选 chip，在状态模型中是临时画廊镜头：

```text
duplicateLens = off | groups | folders
```

- `off`：普通主画廊，沿用用户已有筛选、分组和排序。
- `groups`：只显示精确重复组，完整展示每组全部当前有效成员。
- `folders`：按重复关系组织文件夹上下文，文件夹内先显示重复项，再显示尚未确认项，最后显示独有项。

首次进入默认 `groups`。切换镜头不修改或持久化普通画廊的 `groupBy`、`sortWithinGroup`、`sortOrder` 和 `seamlessGroups`；退出镜头后原样恢复。

MVP 固定使用全库可见媒体范围。普通媒体筛选、语义搜索、人物、收藏夹、目录和日期范围在镜头内暂停，不与成员级筛选做交集，避免隐藏组内成员。进入镜头前的路由、筛选和滚动位置作为返回快照保留。

## 2. 目标与非目标

### 2.1 目标

1. 用户在主画廊中一键查看全部精确重复内容，不进入第二套工作区。
2. 按重复组时，每组边界明确、成员完整、文件夹位置可辨认。
3. 按文件夹时，共享重复组的文件夹形成连续关联簇，所有直接文件夹只出现一次。
4. 文件夹内部固定为“重复 → 尚未确认 → 独有”，大量独有项默认折叠。
5. 继续复用主画廊的布局、缩略图、虚拟滚动、查看器和选区体验。
6. 百万级资料库不向前端发送全量关系图或全量重复 ID，不在 UI 线程聚合和排序。
7. 屏幕集合与后端布局 `flat_ids` 始终一致；查看器按布局版本逐项查询相邻项，不向前端复制全集。

### 2.2 非目标

- 相似图片、裁剪、转码或感知相似关系。
- 指定 keeper、自动选择待删副本、整组清理或文件夹清理草案。
- 系统回收站、磁盘文件移动/删除或真实可释放空间估算。
- 在重复镜头中叠加普通成员级筛选。
- 为文件夹关系建立永久表或全局两两 pair matrix。
- 延续独立 `/duplicates` 页的树—摘要—草案交互。
- MVP 中的卡片选择、Ctrl+A、右键菜单和批量操作；这些能力后续单独恢复，不随主画廊组件自动带入。

## 3. 核心语义

### 3.1 重复组

重复证据只来自当前有效的精确逻辑摘要：

```text
group identity = unit_digest + unit_size
```

有效成员必须满足当前 `hash_version`、`source_revision`、可见资料库、未软删除、非 companion 主项等现有边界。`media_items.content_hash`、文件名、路径、物理身份或相似度均不能替代精确摘要。

“展示全部成员”指一个当前有效精确重复组中的全部位置主项；不排除所谓原件，不只显示代表项，也不因为路径或普通筛选隐藏成员。

### 3.2 直接文件夹

文件夹模式使用媒体实际所在的直接 `directory_id`。每个直接文件夹只出现一次，只包含直接归属该目录的媒体，不把后代项目重复卷入祖先块。

目录祖先路径仅用于展示位置，不作为独立关联节点。这样可以避免父子目录统计重叠，也能保证每张卡片在当前布局中只出现一次。

### 3.3 关联文件夹簇

文件夹关系使用二部图表达：

```text
文件夹节点 ←→ 精确重复组节点
```

同一重复组涉及的全部直接文件夹互相连通。通过一个或多个重复组直接或间接连接的文件夹组成一个连续“关联文件夹簇”。

例如 A 与 B 共享组 X、B 与 C 共享组 Y，则 A/B/C 属于同一个连续簇。方案不承诺交叉图中的每一对文件夹都严格紧挨，只承诺整个连通簇不被无关文件夹插入，并尽量让共享组较多的文件夹相邻。

### 3.4 文件夹内项目分类

| 分类 | 判定 | 展示规则 |
|---|---|---|
| 重复 | 当前有效精确组成员数至少为 2 | 始终展示 |
| 尚未确认 | 未完成当前分析、pending、error、stale、unstable、offline、missing、零字节或其他无法安全定案状态 | 始终展示在重复项之后 |
| 独有 | 最近一次完整分析已证明当前范围内没有精确副本，包括唯一大小桶、quick 已排除碰撞或有效精确摘要单成员 | 排在最后；默认折叠 |

分析没有完整完成时，不得仅凭缺少 `dedup_index` 行把项目称为独有。

文件夹模式只纳入至少含一个当前有效重复成员的直接文件夹。纯独有或纯尚未确认文件夹不单独进入关联簇。

## 4. 入口、URL 与返回行为

### 4.1 工具栏入口

在主画廊筛选 chip 集合首段增加固定可见的 `CopyCheck + 重复项`：

- 未激活：点击进入 `groups`。
- 已激活：chip 使用选中态；再次点击退出镜头。
- 激活反馈在 100ms 内出现，不等待后端布局完成。
- chip 不因顶栏宽度不足而只剩无标签图标；窄屏时进入可操作的 overflow 菜单。

激活后：

- 普通筛选值原样保留但暂停，不参与重复镜头查询。
- 已激活的普通筛选折叠为一个 `已暂停 N 个筛选` 摘要 chip；展开可查看暂停项，不能在镜头中修改。
- 行高与宫格/等高行布局继续可用。
- 普通“按日期/文件夹/不分组”、组内排序和无缝分组控件被镜头排列控件替换。

### 4.2 排列控件

```text
[按重复组] [按文件夹]       文件夹模式：[ ] 显示独有项
```

- 使用有文本的分段控件，不用两个仅图标按钮。
- `显示独有项` 只在 `folders` 中出现，默认关闭。
- 排列切换使用 URL replace，不为每次切换制造浏览器历史节点。

### 4.3 侧栏与旧路由

- 侧栏“重复内容”改名“重复项”，行为改为进入主画廊 `groups` 镜头。
- 旧 `/duplicates` 在新镜头验收后重定向到 `/?duplicates=groups`，保留旧书签可达性。
- 直接打开重复镜头深链时，退出回到普通 `/`；从其他画廊进入时，退出或系统返回恢复进入前完整路由、筛选、焦点和滚动锚点。

### 4.4 URL 契约

```text
?duplicates=groups
?duplicates=folders
?duplicates=folders&duplicateUnique=1
```

- 缺失 `duplicates` 表示 `off`。
- `duplicateUnique=1` 仅在 `folders` 下有效；其他组合规范化移除。
- 普通筛选 query 可以保留在返回快照中，但不与重复镜头同时编码为有效条件。

### 5.1 桌面宽屏

```text
│ ✓ 已分析 · 83 个重复组 · 214 个位置             [重新分析] [退出] │
```

文件夹模式：


### 5.2 窄桌面与平板

- 分段控件移至状态条首部，保持整段文字可见。
- `已暂停 N 个筛选`、分析时间和次级统计进入 overflow，不截断核心模式标签。
- 关联簇、文件夹头和组头保持全宽；路径可省略中段，并用 tooltip 展示完整路径。

### 5.3 手机

- 第一行固定为返回、标题“重复项”和 overflow。
- 第二行使用全宽 `按重复组｜按文件夹` 分段控件。
- 文件夹模式的“显示独有项”放在第二行右侧或 overflow 中，触控目标至少 44×44pt。
- 保留单一纵向滚动，不增加横向文件夹列表或嵌套滚动区。
- 组头/文件夹头使用 sticky。

## 6. 按重复组模式

### 6.1 组头

组头固定包含：

```text
重复组 {ordinal} · {memberCount} 项 · {folderCount} 个文件夹 · 每份 {unitSize}
```

- `ordinal` 是当前布局内的短编号，供跨卡片识别，不暴露摘要原文。
- `groupKey` 仍是内部稳定身份和 separator key。
- 组边界始终存在；重复镜头不支持 `seamlessGroups`。
- 分隔符使用文本、间距和图标共同表达，不只依赖颜色。

### 6.2 卡片

- 缩略图继续使用主画廊卡片尺寸和占位策略。
- 卡片底部或聚焦浮层显示文件名和直接文件夹名；完整路径按需元数据加载。
- 卡片信息包含：文件名、`重复组 N 的第 M/总数 项`、文件夹路径和可用状态。
- 文件夹标签不使用颜色作为唯一身份；文本始终可读。
- 不显示“原件”“建议删除”“keeper”或危险操作状态。

### 6.3 稳定顺序

组排序：

```text
组内最新 sort_datetime DESC
group_key ASC
```

组内成员排序：

```text
sort_datetime DESC
normalized_directory_path ASC
file_name COLLATE NOCASE ASC
item_id ASC
```

`item_id` 是最终 tie-break。布局宽度或行高改变只能改变换行，不能改变成员顺序。

## 7. 按文件夹模式

### 7.1 关联簇头

```text
关联文件夹簇 {ordinal} · {folderCount} 个文件夹 · {groupCount} 个重复组
```

簇头解释“以下文件夹通过一个或多个重复组相连”。不使用“来源”“目标”“建议处理”等清理语义。

### 7.2 文件夹头

```text
{relativePath}
{duplicateCount} 重复 · {unconfirmedCount} 尚未确认 · {uniqueCount} 独有（已隐藏/已显示）
```

- 文件夹头可 sticky；进入下一文件夹时替换。
- 首个文件夹头同时显示关联簇信息，避免叠加两层长期 sticky header。
- 独有项关闭时仍显示准确数量和“已隐藏”，不能让用户误以为没有独有项。

### 7.3 卡片

- 重复卡片显示 `组 N` 文本徽标，使同一组在不同文件夹块中可追踪。
- 尚未确认卡片显示问号图标及具体状态文本，不只用灰色。
- 独有卡片显示“未发现重复”，不使用“安全”“可删除”等推断性词语。

### 7.4 文件夹簇计算

后端从当前有效重复成员流式读取：

```text
(group_key, directory_id, item_id)
```

使用 Union-Find 求连通分量，不生成一个重复组内所有目录的 O(k²) pair。一个组涉及 A/B/C/D 时，以组节点或 star 连接保持 O(k) 关系即可。

簇顺序：

```text
簇内最新重复项 sort_datetime DESC
component_key ASC
```

簇内目录使用确定性二部图遍历：

1. 以重复位置数最多的文件夹为起点；相同则按规范化路径、`directory_id`。
2. 从已经展示的组节点寻找未展示文件夹，优先与已展示集合共享组更多者。
3. 再按最新重复项时间、规范化路径、`directory_id` 打破平局。
4. 当前连通分量全部展示后再进入下一个簇。

该顺序优化相邻关系，但正确性只依赖“整个连通簇连续”，不依赖某一种启发式恰好最优。

### 7.5 文件夹内稳定顺序

```text
bucket_rank: duplicate=0, unconfirmed=1, unique=2

duplicate:
  group_ordinal ASC
  sort_datetime DESC
  item_id ASC

unconfirmed / unique:
  sort_datetime DESC
  file_name COLLATE NOCASE ASC
  item_id ASC
```

关闭“显示独有项”时，unique 项不进入布局 `flat_ids`，但 `uniqueCount` 仍进入文件夹头。打开后重新生成 layout，unique 项出现在每个文件夹块的末尾。

## 8. 选择、查看器与滚动

### 8.1 选择

- MVP 是明确的浏览态：进入镜头立即清空普通画廊选区，并隐藏选择工具栏、checkbox、卡片收藏/评分快捷动作、拖拽和右键菜单。
- 单击、Enter 或 Space 打开查看器；Ctrl/Cmd、Shift 与 Ctrl/Cmd+A 在镜头中不进入选择，也不触发批量操作。
- 切换 `groups/folders` 或打开/关闭独有项时，若焦点项目仍存在于新布局则按 item ID 恢复焦点；否则聚焦新布局主标题并回到顶部。
- 镜头不自动选中整组、整文件夹或所谓副本，也不提供 keeper、清理建议或去重专用删除命令。
- 以后恢复普通选择和批量操作时，必须先证明 `ViewDescriptor`、布局 `flat_ids` 与屏幕集合完全一致，并另行决定哪些危险动作可见；不得因为复用了 `MediaGrid` 就自动继承现有 SelectionToolbar。

### 8.2 查看器

- Enter 或双击打开当前项目；移动端单击打开。
- 查看器上一项/下一项使用当前重复镜头后端缓存的 `flat_ids` 顺序；每次只按 `layoutVersion + itemId + offset` 返回一个相邻项。
- 关闭后恢复原 item ID、组/文件夹 separator 和滚动位置。
- 查看器期间布局版本失效时，优先按 item ID 返回；项目已不存在则回到原 separator，仍不存在则回到顶部并说明结果已更新。

### 8.3 滚动与轴

- `groups` 使用重复组 separator 作为跳转轴，不显示日期月份轴。
- `folders` 使用关联簇/直接文件夹作为跳转轴，不把 duplicate group ID 当作目录树 ID。
- 主侧栏文件夹高亮不随重复镜头内部滚动变化，避免把关联块误当普通目录导航。
- 重排锚点、viewport priority reset 和 scroll cache key 必须包含镜头模式、独有项开关与去重结果版本。

## 9. 状态与文案

| 状态 | 主文案 | 次文案 | 操作 |
|---|---|---|---|
| 从未完成分析 | 尚未建立精确重复结果 | 完成分析后可按重复组或文件夹浏览 | 开始分析、退出 |
| 分析中且无已发布结果 | 正在分析重复内容 · {percent}% | 完成前不会显示不完整的重复组 | 停止、退出 |
| 分析中且有旧结果 | 正在更新重复结果 · {percent}% | 当前继续显示上次完成的结果 | 停止、退出 |
| 已完成且有重复 | 已分析 · {groupCount} 个重复组 · {positionCount} 个位置 | 最近完成于 {time} | 重新分析、退出 |
| 已完成且无重复 | 未发现精确重复项 | 当前可见资料库中没有字节级相同的内容 | 重新分析、退出 |
| 更新失败且有旧结果 | 更新失败，继续显示上次完成结果 | {safeErrorMessage} | 重试、退出 |
| 更新失败且无旧结果 | 无法完成重复分析 | {safeErrorMessage} | 重试、退出 |
| 来源变化 | 部分结果需要重新确认 | 已变化项目归入“尚未确认” | 更新分析、退出 |

加载反馈规则：

- 镜头按钮立即进入 active 状态；布局 300ms 内完成时不闪烁 spinner。
- 超过 300ms 显示保留预计布局高度的稳定骨架。
- 超过 1s 时显示当前阶段，例如“正在整理重复组”或“正在生成关联文件夹”。
- 错误必须给出可执行恢复动作，不能只展示错误码或空白画廊。

## 10. 前端状态与视图描述符

### 10.1 镜头状态

建议新增独立 `duplicateLensStore`，不把镜头塞入普通 `filterStore` 或持久化 `uiStore.groupBy`：

```ts
export type DuplicateLensMode = 'groups' | 'folders'

export interface DuplicateLensState {
  mode: DuplicateLensMode | null
  showUniqueItems: boolean
  returnFullPath: string | null
  returnViewKey: string | null
  returnAnchorItemId: number | null
}
```

URL 是可恢复镜头模式的事实源；return snapshot 只属于当前会话。大数组继续留在 `mediaStore`/layout cache，使用 `shallowRef`，镜头 store 不保存成员数组或文件夹图。

### 10.2 ViewDescriptor

前后端 `ViewDescriptor` 增加可选镜头描述符；缺失时完全保持现有 wire 形状和普通路径：

```ts
export interface DuplicateLensDescriptorDto {
  mode: 'groups' | 'folders'
  showUniqueItems: boolean
  orderingVersion: 1
}

export interface ViewDescriptorDto {
  scope: ViewScopeDto
  filter: GalleryFilterDto
  sort: SortSpecDto
  duplicateLens?: DuplicateLensDescriptorDto
  layoutVersion: number
}
```

MVP 校验规则：

- `duplicateLens` 存在时 `scope` 必须为 `all`。
- 普通 `filter` 必须为空；不接受静默忽略的额外成员级谓词。
- `showUniqueItems` 在 `groups` 中必须为 false。
- `orderingVersion` 防止未来调整排序后旧描述符仍被错误执行。
- `groups` 的 `view_to_sql` 与 layout 使用同一 lowering；镜头保持 browse-only，不调用 `GET_VIEW_IDS` 或 SelectAll，查看器直接查询布局缓存邻居。`folders` 因包含内存关系图排列，继续拒绝 SQL lowering。

## 11. 布局投影

### 11.1 项目最小增量

常驻逐项投影只增加小标量，避免在百万项布局中复制路径或长 group key：

```ts
export type DuplicateBucket = 'duplicate' | 'unconfirmed' | 'unique'

export interface LayoutRowItem {
  // 既有字段……
  duplicateBucket?: DuplicateBucket
  duplicateGroupOrdinal?: number
  duplicateMemberOrdinal?: number
  duplicateMemberCount?: number
}
```

完整文件名和路径继续通过 viewport metadata 按需加载。内部 `groupKey` 留在后端布局分组和 separator，不在每个 item 上重复传输。

### 11.2 Separator 增量

```ts
export type GallerySeparatorKind =
  | 'date'
  | 'folder'
  | 'duplicateGroup'
  | 'duplicateFolder'

export interface LayoutRowSeparator {
  // 既有字段……
  separatorKind: GallerySeparatorKind
  parentGroupId?: string
  parentGroupLabel?: string
  parentGroupStart?: boolean
  duplicateCount?: number
  unconfirmedCount?: number
  uniqueCount?: number
  uniqueHidden?: boolean
}
```

`duplicateGroup` 对应按组组头；`duplicateFolder` 对应文件夹头，`parentGroup*` 描述关联簇。第一版不增加可交互的逐文件夹折叠行，独有项统一由顶栏开关控制。

Canvas 模式继续直接绘制缩略图、重复组头、关联簇头和文件夹头。所有动态列表 key 使用 `groupKey/componentKey/directoryId/itemId`，不得使用数组下标。

## 12. 后端派生与缓存

### 12.1 数据源

不新增永久 duplicate group 或 folder relation 表。继续以 `dedup_index` 为精确证据，从现有主画廊 canonical item cache 派生镜头布局：

```text
canonical LayoutItem
  + 当前有效 duplicate membership map
  + unconfirmed item set
  + folder → component/folder rank map
  → 过滤与稳定排序
  → 既有 layout geometry/cache/flat_ids
```

- `groups`：只保留 membership map 中的重复成员。
- `folders`：先确定重复成员所在的直接文件夹；只保留这些文件夹中的项目。独有项关闭时跳过 unique，打开时纳入。
- compact map 只存 item ID、短 ordinal、bucket 和目录 rank，不复制缩略图、路径或完整 DTO。

这样可以复用现有 `LayoutItem` 查询、几何排版、布局缓存与 viewport hydrate，而不是把旧 `DuplicateFolderItem` 管线嵌入 `MediaGrid`。

### 12.2 已发布结果版本

镜头只消费后端标记为最近一次完整完成的去重结果版本：

```text
dedupViewEpoch
analysisGeneration
dataVersion
hashVersion
completedAt
```

- 新分析分批写入时不驱动主画廊逐批重排。
- 完整成功后只发布一次新 `dedupViewEpoch` 并使相关布局失效。
- 取消或失败不发布半成品；有旧版本时继续显示旧版本，并把当前失效项目标为尚未确认。
- 扫描、软删除、恢复或来源变化继续通过 `source_revision + dataVersion` 排除陈旧成员。

`dedupViewEpoch` 可以先作为 `AppState` 中的独立内存版本与完成事件实现；若重启后需要严格保留已发布代次，再把已完成代次写入现有 metadata，不因此建立关系表。

### 12.3 缓存键

重复布局缓存至少包含：

```text
dataVersion
dedupViewEpoch
hashVersion
mode
showUniqueItems
orderingVersion
layoutMode
container geometry
```

普通 `off` 路径保持现有 cache key，不因为新增镜头降低普通画廊命中率。

现有百万规模文件夹统计快照冷构建约 16.9s、峰值约 1.0GiB，不进入新浏览热路径。新缓存只保留紧凑 membership、未知集合、文件夹 component/rank 和统计，不缓存 O(folder²) 关系或第二份完整媒体 DTO。

## 14. 验收矩阵

| 场景 | 预期 |
|---|---|
| A1/A2/A3 与 B1/B2 | groups 严格显示 `A1 A2 A3 | B1 B2`，组头和成员数准确 |
| 同一组分布于三个文件夹 | groups 全成员连续；folders 三个文件夹属于同一连续簇，每张重复卡显示同一组编号 |
| A-B 共享 X，B-C 共享 Y | A/B/C 同簇且不被无关目录插入；顺序确定、重算不抖动 |
| 两个互不相关簇 | 完整显示第一个簇后再进入第二个簇，不交错文件夹 |
| 一个文件夹含 2 重复、1 未确认、5 万独有 | 默认只显示 2+1，文件夹头显示“5 万独有（已隐藏）”；开启后独有项只出现在该文件夹末尾 |
| 分析未完成 | 不显示“暂无重复”或“独有”，显示进度/旧结果和明确状态 |
| source revision 变化 | 陈旧成员退出当前精确组并归入尚未确认，布局版本失效后安全刷新 |
| Live Photo | 主文件与全部 companion 仍是一个逻辑单元和一张卡，不独立重复计数 |
| 进入前有普通筛选 | 镜头内显示“已暂停 N 个筛选”；退出后筛选与滚动位置完整恢复 |
| 进入时普通画廊已有选区 | 进入镜头后选择清空，SelectionToolbar 消失，不把旧选择带入镜头 |
| 查看器往返 | 上一/下一项按当前布局版本逐项遵循镜头 flat_ids；版本失效不回退普通顺序；关闭返回原卡和滚动位置 |
| Ctrl+A/范围选择/右键 | MVP 中不产生选择、不显示批量工具条或菜单；普通画廊退出后恢复原交互 |
| Canvas/DOM 切换 | 项目顺序、组/文件夹边界和组编号一致 |
| 旧 `/duplicates` 链接 | 重定向到 `/?duplicates=groups`，不存在双重去重页面状态 |

## 15. 性能验收预算

以下是施工目标，需由 100K/1M 合成库和真实库共同校准：

- 点击入口 100ms 内出现 active 反馈；300ms 内未完成则出现稳定 loading 状态。
- 已缓存镜头切换 p95 不超过 300ms。
- 100K 冷 groups 布局不超过 1s，folders（隐藏独有项）不超过 2s。
- 1M 冷 groups 布局目标不超过 3s，folders（隐藏独有项）目标不超过 5s；期间 UI 保持可交互并显示阶段反馈。
- 新镜头相对已有 canonical item cache 的额外峰值内存目标不超过 256MiB；不得接近旧 folder stats 快照约 1.0GiB 的额外成本。
- UI 线程单次同步任务不超过 50ms；滚动和缩放沿用主画廊分段虚拟化与缩略图节流。
- 任何超预算结果先优化 item projection、graph map 和排序，不以把全量关系或 DTO 下发前端作为退路。

## 16. 明确拒绝的实现

| 方案 | 拒绝理由 |
|---|---|
| 在 MediaGrid 可视 rows 上前端过滤 | 总高度、虚拟化、flat_ids、全选和导出全部漂移 |
| 把镜头塞进持久化 `uiStore.groupBy` | 退出后污染普通画廊偏好，也无法表达集合变化 |
| 使用当前文件夹树顺序代替关联簇 | 不满足共享重复组的文件夹相邻 |
| 把全部独有项先发送到前端再隐藏 | 大库 payload 和响应式内存失控 |
| 为每个文件夹 pair 建关系表 | 同组跨大量目录时趋近 O(folder²)，源变化后大面积失效 |
| 在 folders 中同时保证组成员连续 | 与“每个文件夹形成连续上下文块”冲突；两种需求由两个排列分别满足 |
| 缺少 sidecar 就标独有 | 分析未完成、错误、离线和来源变化都会被误判 |
| 在新镜头接入旧 keeper/草案/apply | 把已确认的浏览 MVP 再次膨胀成高风险清理工作台 |
