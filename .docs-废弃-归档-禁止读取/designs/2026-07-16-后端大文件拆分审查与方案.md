## 1. 结论(总览)

后端 ≥900 行的文件共 16 个。逐文件测绘后按三档裁决:

| 档 | 文件(行数,快照 `13a3192`) | 一句话理由 |
|---|---|---|
| **已有方案** | queries.rs(11,228) | T 线已批准,本文 §3 做时效性核查:方案主体仍成立,一个结构性前提被推翻后已按 T-D-012 方案 a 修订迁移序 |
| **拆分**(U-P1) | lib.rs(1,062) | 42 commits/半月的 churn 之王;~232 行 invoke_handler 清单(≈186 命令)+ ~585 行 setup 巨闭包,零测试;Review 后拆成 P1-a 必做、P1-b 重测后可选 |
| **拆分**(U-P2) | ipc/ai_commands.rs(1,191) | **层次倒挂**:4 个 `ai/*` 核心模块反向 import 本 IPC 文件的 runtime helper;AI/face 共享的 Channel 下载编排寄居在单一命令文件 |
| **拆分**(U-P3) | exotic/worker.rs(1,397)、exotic/pipeline.rs(1,239) | AI 层跨层伸手拿 worker.rs 的纯校验器与 pipeline.rs 的 `EmbedWorker` trait;worker.rs 半月 +726 行仍在长 |
| **拆分**(U-P4) | ipc/thumbnail_commands.rs(1,118) | 零测试;QoS/线程调度块完全自包含可下沉;两条 ~400 行近重复流水线登记为行为债(本线不动) |
| **观察** | db/models.rs(995)、ipc/doc_commands.rs(912)、ipc/file_ops_commands.rs(928)、ai/face_pipeline.rs(1,083) | 缝已找好、触发条件已写明(§5),现在拆收益不抵扰动 |
| **豁免** | exotic/supervisor.rs(1,010)、exotic/installer.rs(931)、ai/worker_client.rs(1,203)、layout/items_cache.rs(1,083)、layout/justified.rs(1,063)、scanner/fast_scan.rs(914) | 生产代码紧凑(行数是内联测试撑大的)或内聚算法/状态机,拆了反而制造跨模块耦合(§6) |

核心判断:**queries.rs 之外,后端没有第二个「巨石」**——1,000–1,400 行区间的文件是否该拆,取决于内聚性与层次,不取决于行数。本轮真正值得动手的是四个「结构问题恰好住在大文件里」的案例(churn 热点、层次倒挂、半途迁移、自包含块寄居),而不是机械消灭千行文件。

## 2. 判据与分型

沿 T 线 F-001(拆分判据=领域数、调用面、churn、历史缺陷综合,不以 LOC 单指标裁决),本轮测绘补充四个分型,作为三档裁决的操作化标准:

| 分型 | 特征 | 裁决倾向 |
|---|---|---|
| 测试撑大 | 内联 `#[cfg(test)]` 占 40–60%,生产代码紧凑 | 豁免——这是 Rust 惯例的正常代价,不是结构问题 |
| 内聚算法/状态机 | 单一状态机、共享可变状态、刚性等价契约 | 豁免——拆开会把编译器可见的内聚变成跨模块纪律 |
| 零测试巨命令 | IPC 命令文件,数百行命令体,无回归网 | 按缝拆 + 登记测试债;纯搬迁不算行为变更,但重构(如去重)必须先补 characterization |
| 层次倒挂寄居 / 注册清单热点 | 共享底座寄居错层,或每次加功能必碰 | 拆分——收益是层次修复与冲突面消灭,行数下降只是副产品 |

实测分布:supervisor 61% / installer 57% / worker_client 53% / worker 49% / items_cache 43% / justified 34% / fast_scan 29% 为测试占比;thumbnail_commands、file_ops_commands、lib.rs、models.rs 为零测试。

## 4. 拆分方案(U-P1 ~ U-P4)

四个批次互相独立,可单独回滚;每批沿 T 线纪律:**纯搬迁 commit 不夹带行为修改**(D-003 同款)、公开路径尽量以 re-export 保持稳定(D-001 同款)、每批开工前按当时 HEAD 重验本节行号快照。代码审查后的优先级 = **P1-a(注册清单) > P2(层次倒挂) > P3(worker 接缝) > P4(QoS) > 可选 P1-b(bootstrap)**;P1-b 不再与 P1-a 捆绑为连续必做。

### U-P1:lib.rs 注册清单与引导块下沉

现状(快照):`run()` 单函数 1,062 行装 8 职责;invoke_handler 宏清单 724–955(~232 行,≈186 命令);setup 闭包 136–721(~585 行);2026-07-01 以来 42 commits——每加一个 IPC 命令必碰此文件。

目标结构:

```text
src-tauri/src/
├── lib.rs                 # 模块声明、BUILD_VARIANT、run() builder/event 骨架
├── ipc/registry.rs        # invoke_handler 清单:handler() 返回 Tauri 所需闭包
└── bootstrap/
    ├── mod.rs             # setup(app) owner:保有完整启动顺序与共享局部量
    ├── logging.rs         # 日志初始化(含 RealTimeDailyAppender)
    ├── ort.rs             # ORT DLL 环境解析
    ├── maintenance.rs     # 开机 WAL checkpoint + cover reconcile
    ├── tasks.rs           # volwatch/rank/PRAGMA optimize/缓存治理
    └── tray.rs            # 系统托盘
```

- **P1-a(先做,收益最大且独立收尾)**:invoke_handler 清单 → `ipc/registry.rs`。本地锁定依赖源码(Tauri 2.11.4 + tauri-macros 2.6.3)已确认 `Builder::invoke_handler` 接受 `Fn(Invoke<R>) -> bool + Send + Sync + 'static`,`generate_handler!` 展开为同形 `move` 闭包,故 `handler()` 返回 `impl Fn(...)` 是主路径;`macro_rules!` 只作为 10 分钟 compile spike 失败时后备。此后**新增命令只碰 registry.rs + 命令文件**,lib.rs 淡出高频冲突面。迁移前后须规范化抽取命令路径做集合对拍,不能只靠编译证明清单无漏项。
- **P1-b(重新测量后可选,不与 P1-a 捆绑)**:先把整个 setup 闭包原样迁为 `bootstrap::setup(app)`,让单一 owner 保持「DB→配置→logging→self-heal→AppState→Coordinator→tasks→tray」顺序与共享局部量;`lib.rs` 只留 `.setup(bootstrap::setup)`。随后才在 `bootstrap/` 内逐块下沉私有子模块,不得把捕获量摊成 `lib.rs` 参数袋。`fatal_startup_error` 随 setup owner 迁移。外壳迁移一 commit,内部每块一 commit,均可独立停下。
- **不变量**:命令集合不增不减(编译期由 generate_handler 保证符号存在;P1-a commit 前后对宏清单做逐行 diff,只允许位置移动);builder 链顺序(plugins → setup → invoke_handler → events → run)不变;`BOOT_INSTANT`/`handles_pool` 等跨闭包共享量的传递显式化但语义不变。
- **验收**:`cargo check/clippy/test --workspace --locked` + 既有 `PICASA_SMOKE_TEST` 启动门 + 一次真机 smoke(App 起、托盘在、任一命令可调、退出 WAL checkpoint 日志正常)。P1-a 后先重测 churn;若执行 P1-b,lib.rs 目标 ≤ ~300 行(软目标)。

### U-P2:ai_commands.rs 层次纠偏 + 下载引擎收尾

现状(快照):1,191 行、15 命令、9 个 `pub(crate)` helper 被 7 文件消费;**层次倒挂**——`ai/worker_client.rs`、`ai/face_pipeline.rs`、`ai/worker_pipeline.rs`、`ai/pipeline.rs` 四个核心模块反向 import IPC 层的 `models_dir` / `active_profile(_with)` / `active_face_profile(_with)` / `persist_provider_echo` / `warn_legacy_ai_backend`。另有 AI/face 两个 IPC 文件共享的 Channel 下载编排(`download_assets` + `DownloadProgress` + `is_safe_model_file_name` + `dest_safety_tests`,~320 行)寄居 `ai_commands.rs`;通用 `download/mod.rs` 已正确承接 HTTPS/Range/镜像/校验机制,其模块契约明确要求领域清单与进度聚合留调用层。

目标结构:

```text
src-tauri/src/
├── ai/runtime_config.rs   # 跨层共享:models_dir、active_profile*、active_face_profile*、
│                          # variant_installed、persist_provider_echo、warn_legacy_ai_backend
├── download/mod.rs        # 保持 transport-agnostic,不引 Tauri IPC
└── ipc/
    ├── model_download.rs  # DownloadProgress、download_assets、is_safe_model_file_name、dest_safety_tests
    └── ai_commands.rs     # 15 个命令 + arch_for_image_file/variant_fixed_batch 等命令私有 helper
```

- **P2-a**:仅把跨层共享 helper → `ai/runtime_config.rs`,四个 ai 模块及 face/exotic commands 一步改直接 import;不保留让核心层继续依赖 `ipc::ai_commands` 的过渡路径。只被本命令文件消费的 `arch_for_image_file`/`variant_fixed_batch` 原地保留,避免为缩行扩大核心 API 面。
- **P2-b**:共享 IPC 下载编排 → `ipc/model_download.rs`,ai_commands/face_commands 从兄弟模块引用;`download/mod.rs` 不动且不得出现 `tauri::ipc::Channel`。P 线 A15 的同步 `.part` metadata/remove/rename 是独立行为债,在纯搬迁 commit 后另做 `tokio::fs`/`spawn_blocking` 修复,不得混入本批结构 diff。
- **边界**:生命周期 8 命令(start/restart/pause/stop/reload/rebuild + `launch_ai_pipeline`)共享 GPU 槽/续跑标志状态机,**整体留在 ai_commands.rs 不拆**;`registry`/`switch`/`status` 命令组同留(它们是真 IPC 语义)。
- **不变量**:helper 签名与行为不变;`#[tauri::command]` 集合不变(lib.rs/registry 清单零改动);`DownloadProgress` serde 形状不变(前端契约)。
- **验收**:workspace 四门 + `rg 'ai_commands' src-tauri/src/ai` 归零(2026-07-16 二次复核加固:原样式 `ipc::ai_commands::` 会漏 `use ... as` 别名与 `ipc::{ai_commands, ...}` 花括号导入形态;宽松样式偶发命中注释也应清,过时路径注释随迁移一并更新)+ `rg 'tauri::ipc::Channel' src-tauri/src/download` 归零 + AI 面 smoke(检测 provider、起/停分析、下载入口可达)。ai_commands.rs 预期 ~700–750 行。

### U-P3:exotic ↔ AI 接缝重整(worker.rs / pipeline.rs)

现状(快照):worker.rs 1,397(测试 49%,生产 ~708)三个 bounded context——进程创建(26–147)、`WorkerConn` 协议状态机(173–409,必须整体)、**4 个纯输出校验器 + outcome 类型(411–724)**;校验器不被 `WorkerConn` 调用(缩略图那个除外),主要消费者是 `ai/worker_client`、`ai/face_pipeline`、`bin/worker_e2e`。pipeline.rs 1,239 的 trait 分类学(62–174:`WorkerTask`/`ThumbnailWorker`/`EmbedWorker`/`WorkerFactory`/`SupervisorFactory`)中 `EmbedWorker` 只服务 ai 层,本文件流水线用不到。即:**AI 层现在从两个 exotic 状态机文件里各伸手拿一块与状态机无关的纯件**。worker.rs 半月 +726 行,仍在增长。

目标结构:

```text
src-tauri/src/exotic/
├── worker.rs          # 进程创建 + WorkerConn 状态机;pub use outcome::*、validate::* 保旧路径
├── outcome.rs         # RawOutcome、TaskOutcome、EmbedItemOutcome、FaceItemOutcome
├── validate.rs        # validate_thumbnail_output、validate_embed_batch_output、
│                      # validate_face_batch_output、validate_encode_text_output、default_thumbnail_limits
├── worker_traits.rs   # WorkerTask/ThumbnailWorker/EmbedWorker/WorkerFactory/SupervisorFactory + 对 WorkerSupervisor 的 impl
└── pipeline.rs        # 只剩流水线状态机(loop 五函数 + 私有结构 + 常量)
```

- outcome 枚举是 WorkerConn 与校验器的共享词汇,单独成模块、两边引用;worker.rs 与 pipeline.rs 均以 `pub use` 保住现有 `exotic::worker::{...}` / `exotic::pipeline::{...}` import 路径(T-D-001 facade 同款),消费方零迁移,后续再择机把 AI 层 import 改指新模块(独立小 commit,非必须)。
- 各自测试模块随被测符号走:校验器测试(在 726–1397 大测试模组内,按测试目标拆)迁 validate.rs;`WorkerConn` 管道 harness 测试留 worker.rs。
- **不可动**:`WorkerConn` + `handshake`/`run_request`/`run_thumbnail`/`send_shutdown`(单一状态机,共享 request_id 分配与 silence-timeout 不变量);pipeline 五 loop + `PipelineDeps`/`PipelineStats` + 常量(单一状态机,channel 协议 + lease 条件写不变量)。
- **验收**:workspace 四门;`bin/worker_e2e` 编译;`cargo test -- --list` 按 T-D-011 归一化对拍,确认 20+7 个测试无静默消失。

### U-P4:thumbnail_commands.rs QoS 下沉 + 去重债登记

## 6. 豁免档(不拆的理由,一次说清)

- **exotic/supervisor.rs(1,010,测试 61%,生产 ~396)**:四职责经 `kill_and_reap` 共享 alive+session 不变量**刻意纠缠**(「session 随实例清」防孤儿进程);生产代码紧凑,唯一干净缝(stderr 诊断 ~50 行)不值一次搬迁。
- **exotic/installer.rs(931,测试 57%,生产 ~403)**:无共享可变状态,函数经文件系统布局约定协作;安全耦合簇 `resolve_worker_path`+`installed_worker_path`+`verify_installed_integrity`(verify-before-trust 顺序)必须共存,其余本就近独立。结构健康。
- **ai/worker_client.rs(1,203,测试 53%,生产 562)**:会话状态机 + 重试/硬停协议引擎共享 `MAX_ATTEMPTS` 与 respawn 不变量,不可分;可抽件均 ≤100 行不值动。半月 +1,235 行是**新建**(W1/W2/W3 回归测试),非失控增长。
- **layout/items_cache.rs(1,083,测试 43%,生产 ~615)**:`derive_order`+`can_derive_axis`+`is_hit_valid` 是「改一处必改全」刚性三联,顺序等价契约由 queries.rs 对拍测试钉住;16 commits churn 是 B-file-iii 施工期峰值,已收口。
- **layout/justified.rs(1,063,测试 34%,生产 ~706)**:wire 类型被 4 文件消费,搬动=纯 import churn;`div_euclid(86400)` 日桶是跨 items_cache/SQL 的分布式不变量,聚在原地反而好审。
- **scanner/fast_scan.rs(914,测试 29%)**:已良构——5 个私有 helper 刻意抽出供独立单测,`run_fast_scan` 单编排器,批循环内联块共享 loop-local 状态不可拆。这是大文件的**正确形态**,可作范本。

以上均是对快照 `13a3192` 的**本轮豁免**,不是永久免审。任一文件出现以下条件之一即重新测绘:新增不相关 bounded context、出现新的跨层消费者、生产代码较本快照增长 25% 以上、后续审查发现缺陷/返工集中成簇。
