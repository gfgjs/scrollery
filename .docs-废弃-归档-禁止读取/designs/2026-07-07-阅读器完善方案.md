## 1. 目标与范围

### 1.1 本方案解决什么

1. **修缺陷级体验问题**(用户明确点名):
   - txt 编码:非 UTF-8(GBK/GB18030/Big5 等)今天要么打不开、要么乱码;须自动识别 + 手动切换。
   - txt 排版:整篇等宽 `<pre>` 密密麻麻;须智能分段、段首缩进、段间距,读起来像书而不是日志。
   - epub 内嵌图片:须稳定显示(现状依赖 epub.js 默认行为,无自定义处理,真机表现待证)。
2. **补齐一般阅读器的常见功能**:目录(TOC)、排版设置(字体/字号/行距/边距/对齐)、阅读主题与背景(护眼/牛皮纸/夜间等)、进度百分比、书内搜索、书签,以及为高亮/笔记、TTS、阅读统计预留结构。
3. **落地特色功能**:纵向竹简阅读(vertical-rl / vertical-lr 可选)、简繁转换、以及已有的替换规则(角色扮演)/版本管理/AI 校对与新阅读器 UI 的融合 —— 后三者是市面阅读器普遍没有的差异化能力。
4. **架构升级**:txt/md/epub 归一到统一的 Book Model + 单一排版渲染管线,使主题/竖排/简繁/搜索/进度**一次实现、全格式生效**;格式接入做成 FormatAdapter 接口,为 mobi/azw3 等后续格式(含冷门格式插件形态)预留插槽。
5. **free/pro 解耦**:所有功能挂能力注册表(capability registry),分级是政策数据;边界未定,先全量可用,发布前一键划线。

### 1.2 不在本方案范围

- PDF 体验深化(textLayer 选择/搜索、缩放):PDF 保持现有 canvas 懒渲染路径不动,仅接入新阅读器 Shell 的公共 UI(主题外壳/工具栏),其排版类功能(竖排/简繁/字体)天然不适用。
- office 格式(doc/docx/xls/...):维持「调系统程序打开」兜底,不做内嵌渲染。
- AI 校对/版本管理/替换规则的功能扩展(它们已交付;本文只定义其与新 UI 的集成点)。
- 跨设备进度同步、书城/书源:不做。

### 1.3 交付原则

- 每期以 `vue-tsc` + `eslint` + `vitest` + `cargo check/clippy/test` 全绿为下限;涉及 Rust 的每次提交前 `cargo fmt`。
- 纯前端渲染类改动无自动化覆盖时,按项目校准的 Done 定义给出「手动验证步骤 + 编译通过」,并显式标注「未被自动化测试覆盖」;文本处理核心(编码检测/分段/章节识别)**必须**有 Rust 单测(风险定测点:这是零测试命门路径)。

## 2. 现状盘点(2026-07-07 代码取证,文件:行)

### 2.1 架构与打开链路

- 入口:画廊/文件夹树双击 document 类型 → `router.push('/doc/:id')`(`src/components/media/MediaGrid.vue:1032`)→ 独立路由页 `src/views/DocumentViewer.vue`(**未接入** viewStore 四互斥视图域,是普通路由)。
- 分发:按扩展名分三类渲染器(`DocumentViewer.vue:242-261`):`pdf`→PdfReader、`epub`→EpubReader、`TEXT_FORMATS`→TextReader、其余→「不支持,外部打开」。渲染器 `defineAsyncComponent` 懒加载(`:190-192`)。
- 取字节:一律 asset protocol —— `convertFileSrc(absPath)`(`:232`)→ `http://asset.localhost/...`;文本另有 IPC `GET_DOCUMENT_TEXT` 取「生效文本」(当前版本或源文件)作为 `content` prop 优先注入(`:316-319`)。
- CSP(生产,`src-tauri/tauri.conf.json:41`):`connect-src` 已含 `asset:/blob:/data:`(P1-23 修复),`img-src`/`frame-src` 已含 `blob: data:`,`script-src` 仅 `'self' 'wasm-unsafe-eval'`(无 unsafe-eval)。**结论:epub 章节 iframe + blob 资源(含内嵌图片)在当前 CSP 下畅通;任何新引擎不得依赖 eval。**
- assetProtocol 静态 scope 仅 `$APPDATA/**`,扫描根在运行时经 `scope.allow_directory` 授权(`src-tauri/src/lib.rs:287-300`)。

### 2.2 三个渲染器现状

**TextReader(`src/components/doc/TextReader.vue`)**
- 加载:`content` prop 优先,否则 `fetch(url).text()`(`:74-80`)——`Response.text()` 恒按 UTF-8 解码。
- 渲染:整篇一次性 `v-html`;纯文本 = 单个转义 `<pre class="doc-plain">`,等宽字体、`pre-wrap`(`utils/markdown.ts:141-143` + `:108-117`)。**无分段模型、无虚拟化、无任何排版设置**。
- 进度:`scroll:<ratio>`(滚动比例 4 位小数);`next/prev` = 滚 0.9 屏。
- md:自研零依赖渲染器 `utils/markdown.ts`(标题/粗斜体/行内码/围栏/列表/引用/链接/hr/段落),先转义防 XSS;**不支持图片 `![]()`、表格、嵌套列表、任务列表**。
- rtf:被归入 TEXT_FORMATS 却按纯文本渲染 —— 控制字面直接可见(视觉上是坏的)。

**EpubReader(`src/components/doc/EpubReader.vue`)**
- epub.js 0.3.93,`ePub(url)` URL 直喂,`flow:'paginated', spread:'none'` 固定(`:79-85`);滚轮 350ms 节流翻页 + 两侧按钮。
- 进度:仅 `cfi:<epubcfi>`;**从未生成 `book.locations`** → 无百分比/总页概念。
- **零主题接线**(`rendition.themes` 未用)、**零 TOC**(`book.navigation` 全库未引用)、无字号控制、无 scrolled 流(注释 `:26-27` 自认后续增强)。
- 唯一 hook:每章渲染后对 iframe DOM 应用替换规则(`:87-95`)。
- 内嵌图片:无自定义处理,纯依赖 epub.js 默认 blob 解析;代码内无「图片不显示」的已知问题记录,坏例须真机取证。

**PdfReader(`src/components/doc/PdfReader.vue`)**
- pdf.js 4.10.38 canvas 逐页懒渲染(IntersectionObserver,rootMargin 600px),DPR≤2、长边≤2200,`isEvalSupported:false`;进度 `page:N`;向工具栏发 `info{page,pages}`(唯一会发的渲染器)。
- **无 textLayer** → 原设计的「PDF 选中/搜索」实际未落地。

### 2.3 翻页/进度/持久化底座(可复用资产)

- `usePager`(`src/composables/usePager.ts`):渲染器无关的输入→导航映射,三模式 scroll / wheel-snap / keyboard,注释明确预留「双页 / 卷轴 / 自动滚动」扩展位;键盘 ←→/PageUp/Down/Space/Home/End 恒可用,输入框聚焦不劫持。
- 进度:`reading_progress(item_id PK, position TEXT, updated_at)`(`schema.rs:301-305`),渲染器发 `progress` 字符串 → 1200ms 去抖 `SET_READING_PROGRESS`,卸载冲刷。每文档一条,无历史。
- 全局配置:仅 `doc_pager_mode` 一键存 `app_config`。**无任何每书设置**(字号/主题/编码均无处可存)。
- `document_meta(item_id PK, page_count, doc_subtype)`:epub 按 spine 数、pdf 按 numPages 回填;**未随 MediaDetail 下发给前端**。

### 2.4 Rust 侧文本命令与已知缺陷

- `get_document_text` / `read_ref_text` 用 `std::fs::read_to_string`(`doc_commands.rs:109-124,150-161`)——**非 UTF-8 文件直接 InvalidData 报错**,连带编辑/版本/AI 校对链路对 GBK 文件全部不可用;前端 fetch 兜底则输出 U+FFFD 乱码。编码修复点必须在这个 seam。
- `save_version` 原子落盘(tmp→rename)已达标;版本文件 `<appData>/documents/<item_id>/<id>.<ext>`。
- 派生:doc_thumb 仅 pdf/epub/svg(epub 封面后端 zip 解析,pdf/svg 前端离屏渲染回传);txt/md 画廊用 CSS 文本卡。
- AI 校对命令独立在 `proofread_commands.rs`(config 存 app_config,key 存 OS keyring)。

### 3.2 商业/中文阅读器功能格局(功能池按「基础必备 / 进阶常见 / 特色少见」分级)

**基础必备**(缺了不像阅读器):字体/字号/字重、行距/段距/**四边独立边距**、段首缩进(legado 做成 0-4 字符五档,实现即插全角空格)、两端对齐、预设主题(白/护眼绿/羊皮纸/夜间)、深色配对、TOC、进度显示、书签、书内搜索、txt 编码识别+手动兜底(Moon+ 宣称 40 种编码)、txt 智能分章、记住位置、键盘/滚轮翻页。

**进阶常见**(好用的分水岭):翻页动画(legado 五种:仿真/覆盖/滑动/滚动/无,**可按书设置**)、上下滚动模式(网文用户第一公民)、自动阅读(Moon+ 五种滚屏+实时调速)、宽屏双页(legado 四档:全局单/全局双/横屏双/平板横屏双)、页面宽度三档(微信读书网页版:满屏/80%/默认)、自定义背景图+虚化(legado)、页眉页脚信息槽(legado 6 槽×12 选项,断层领先)、TTS、选词词典/翻译、笔记导出(Readest 导出 Markdown)、阅读统计、简繁转换(legado 三态:关/繁转简/简转繁)、音量键翻页(移动端)。

**特色少见**(差异化池):legado 的 **TXT 目录规则生态**(26 条带 name+example 的可编辑正则,含 `节(?!课)` 这类负向断言防误判、双标题去重 lookaround —— 民间打磨多年的正则资产,**思路直接借鉴,规则自写并做成用户可编辑数据**,legado 本体 GPL);微信读书 AI 问书/AI 大纲、热门划线、墨水屏「唯阅读」减法策略;多看**引擎级中文排版**(避头尾+标点挤压,口碑来源);Apple Books 的 Page Curl(动画=情感记忆点,iOS16 移除翻车被迫加回)与「主题=配色+字体+间距的打包预设,微调藏第二层」;Kindle 剩余阅读时间/X-Ray;Readest 双屏平行阅读。

**桌面端布局惯例**:三段式(侧栏→限宽阅读区→右侧面板);←/→/空格/滚轮翻页 + Ctrl+F 书内搜索;宽屏默认双栏可退单栏;**快捷键成文档是普遍短板(机会点)**。

### 3.3 「高级感」的来源(设计基调,直接约束 §5 各项)

1. **中文排版三件套是分水岭**:避头尾(`line-break: strict`)+ 两端对齐(`text-align: justify`)+ 段首两全角缩进;标点挤压/悬挂是进阶加分(多看口碑本质)。浏览器默认排版不达标,须显式补。
2. **配色是整套不是换底色**:每套阅读主题=「背景(色/纹理)+文字色+辅助色」×「日/夜配对」(legado 三份配色结构、Apple Books 每主题带深色版)。主题切换不蒸发用户微调。
3. **默认值即产品**:豆沙绿护眼(#c0edc6 系)被 legado 直接做成第一预设「微信读书」;默认排版值要像做品牌一样调。
4. **滚动是 CJK 网文第一公民,翻页动画是情感附加值**——两者都要,动画速度可调,且**可按书记忆**。
5. **txt 的诚意在脏数据处理**:编码识别+手动兜底、可编辑分章规则(带实时预览)、断行合并/重新分段、替换净化 —— 这是「下载的 txt 直接能看」与「先用 Calibre 洗一遍」的区别;我们已有替换规则底座,补前三件即闭环。
6. **进度三心智可切**:百分比(网文)/页码(出版)/剩余时间(Kindle 特色,基于个人速度)。
7. **对 Scrollery 的定位启示**:品牌即「画卷/Scrollery」——竖排竹简模式天然是**品牌签名功能**(usePager 当年就预留了「卷轴」模式位);叠加已有的替换规则(角色扮演)/版本管理/AI 校对,差异化故事完整:「把收藏的文本资产读出书的质感」。



## 4. 总体架构

### 4.1 分层模型:一条管线吃下所有可重排格式

核心决策:**txt / md / epub 归一到同一个 Book Model 与同一个渲染引擎**,排版设置、主题、竖排、简繁、搜索、TOC、进度、书签**一次实现、全格式生效**;PDF(固定版式)保持现有 canvas 路径,仅共享外层 Shell。

```
┌─ Rust 侧 ────────────────────────────────────────────────────────┐
│ SourceProvider      读字节;文本经「编码检测+解码」seam 输出 UTF-8      │
│ TextIndexer         txt 章节切分/智能分段(流式,50MB 级),返回章节索引  │
└──────────────────────────┬───────────────────────────────────────┘
                           │ IPC(索引一次,章节内容按需)
┌─ 前端 ────────────────────▼──────────────────────────────────────┐
│ FormatAdapter       epub=foliate-js 原生 loader                    │
│  (格式→BookModel)    txt/md=SyntheticBook(实现 .sections+.load())   │
│                     [插槽] mobi/azw3… = exotic 插件 Text 能力(后期)  │
```

### 4.2 渲染引擎裁决:epub.js → foliate-js(vendored)

| 判据 | epub.js 0.3.93(现用) | foliate-js(裁决) |
|---|---|---|
| 维护 | npm 停更于 2022-02(0.3.93),开放 issue 500+,GitHub 许可证字段 NOASSERTION(2026-07-07 `gh api` 亲证) | 2026-05-01 仍有 push、MIT、未归档(同日亲证);Foliate(GTK)/Readest(Tauri, 22k stars)两个量级产品在用;KDE Arianna、Booklore 均已/正从 epub.js 迁来 |
| 嵌入图片 | 经典 issue 群:#317(重载失图)/#734(base64)/#838(URL-encoded href 404)/大书失图 | 资源按需 blob: 惰性加载,量级产品验证 |
| 竖排 | 无一等支持 | **paginator 源码一等支持** vertical-rl/lr(轴向翻转、RTL 翻页方向自动) |
| 定位/进度 | CFI(我们连 locations 都没生成) | CFI 完整实现 + progress 模块 + TOC/pageList |
| 主题注入 | Themes API(工程已死) | `renderer.setStyles(css)` 每 section 注入 + `::part()` 容器钩子 |
| 格式面 | 仅 EPUB | EPUB/MOBI/AZW3/FB2/CBZ(+实验 PDF);**book 接口开放**(`.sections`+`.load()`),自定义格式直接实现接口喂入 |
| 发行 | npm | **无 npm 发行,API 自认不稳定 → vendor 钉版**(见下) |
| 安全 | iframe sandbox,开脚本即自认不安全 | closed shadow DOM + sandbox iframe + blob:,官方要求强 CSP(与我们现有 CSP 兼容:`frame-src/img-src/connect-src` 已含 `blob:`,无 eval 依赖) |

**vendor 方式**:复制上游钉定 commit 到 `src/vendor/foliate-js/`(保留 LICENSE,`NOTICE.md` 增记 MIT 条目与 upstream commit hash,增 `src/vendor/foliate-js/VENDOR.md` 记录来源与升级步骤),不用 git submodule(避免公开镜像/自托管 CI 的 submodule 摩擦);纯 ESM 零构建,Vite 直接吃。需要补丁时优先参考 readest/foliate-js fork(MIT,取用前逐文件核许可头);**AGPL 红线:Readest app 层、Koodo/kookit、Vivliostyle、Foliate GTK app 只可借鉴思路,禁止抄码**。

**喂书链路**:沿用 asset protocol —— `fetch(convertFileSrc(absPath))` → `arrayBuffer` → `File` → foliate-js `makeBook`。**零新增权限面**(不引入 plugin-fs;这是 2026-07-07 安全加固后有意保守的选择);epub 体量(几十 MB 内)整读可接受。若未来实测超大 epub 有内存压力,再评估 plugin-fs + 随机访问 Blob 的旁路。

**过渡策略**:EpubReader 重写为 BookReader(统一渲染器)后,epub.js 依赖直接移除——不做双引擎并存期(replacer/进度契约有既有手测路径,foliate-js 侧等价功能齐后一次切换,回滚=git revert)。

### 4.3 SyntheticBook:txt/md 进同一管线

**txt(重排版的主战场)**:
- Rust `TextIndexer`(新模块 `src-tauri/src/reader/`):流式读源文件 → 编码检测+解码(§5.1)→ 章节切分(内置规则集 + 按命中数自动选规则 + 伪章兜底,详 §5.2)→ 智能分段(§5.2)→ 返回 `TextBookIndex{ encoding, confidence, chapters:[{title, charRange}] }`,章节全文经 `get_text_chapter(itemId, idx)` 按需取。
- 前端 `TextBookAdapter` 实现 foliate-js book 接口:每章 = 一个 section,`load()` 时把段落数组渲染为 `<p>` 序列(转义后),套统一排版 CSS。50MB 小说 = 数百个惰性 section,**天然虚拟化**,无单 DOM 爆炸。
- 版本管理/替换规则兼容:生效文本(当前版本)仍经 `GET_DOCUMENT_TEXT` 语义 —— TextIndexer 接受「源文件路径 **或** 版本文件路径」输入,索引的是生效文本。
- 借鉴 Readest TxtToEpubConverter 的**思路**(阈值分流、流式解码、两级章节正则、伪 TOC 防误判),但不学它内存组 EPUB zip——直接实现 book 接口,省 zip 往返(该文件 AGPL,只可复刻方法)。

**md**:
- 前端解析:`markdown-it`(CommonMark 兼容性最佳,插件生态全)+ `DOMPurify` 消毒渲染产物(白名单允许 img/table/ruby,剥 script/form/iframe)→ 按 h1/h2 切 section,heading 树即 TOC。
- **本地相对图片**:`![](./img.png)` 相对 md 所在目录解析为绝对路径 → `convertFileSrc` → asset protocol 加载(修复现状 md 图片完全不渲染)。
- 替换现有自研 `utils/markdown.ts` 于阅读器路径(工具函数保留给画廊文本卡等轻用途,或一并升级后删除,施工期定)。
- 新依赖:`markdown-it` + `dompurify`(均 MIT,进 NOTICE.md)。

**epub**:foliate-js 原生 loader;内嵌图片/字体由引擎 blob 供给(修复关键痛点);`book.toc` 直接供 TOC 面板;CFI 续用现有 `cfi:` 前缀持久化格式。

### 4.5 主题:应用主题(chrome)× 阅读主题(paper)双轴

## 5. 功能设计(逐项:设计 → 技术裁决 → 分级建议)

> 分级标记仅为**首发划线建议**,最终以 §4.4 政策表为准(开发期全 core)。「⚠️GUI」= 该项含「静态过验 ≠ 已修」性质的真机验收点,汇总入 §9。

### 5.1 txt 编码自动识别 + 手动切换(P0 · core)

- **管线**(Rust,新 `src-tauri/src/reader/encoding.rs`):
  1. `encoding_rs::Encoding::for_bom(head)` 判 UTF-8/UTF-16LE/BE BOM,命中即定;
  2. 无 BOM 补 UTF-16 启发(前 N KB 零字节奇偶分布;中文 txt 场景占比极低,失败就走 4 的告警兜底);
  3. `chardetng::EncodingDetector` 喂**前 64KB**(Firefox 1KB 首猜/VS Code 64KB 上限/legado 8KB 的折中,理由:中文小说开头常有大段 ASCII 广告),`guess(None, allow_utf8=true)`(独立 app 无浏览器的禁 UTF-8 顾虑);
  4. `encoding_rs` `decode_with_bom_removal` 解码,统计 U+FFFD 替换率,>0.5% 在 UI 亮「编码可能误判」提示;
  5. 手动覆盖列表(存每书 prefs):UTF-8 / GB18030 / Big5 / Shift_JIS / UTF-16LE / UTF-16BE / Windows-1252。
- **要点**:chardetng 有意把 GB18030 报成 GBK——无害,WHATWG 规范明文 GBK 的 decoder 就是 gb18030 decoder,4 字节序列照样解;chardetng 不测 UTF-16 系,BOM 层必须自己做(上面 1/2 步)。
- **seam 一次修三处**:`get_document_text`/`read_ref_text` 全部改走该解码 seam → 阅读、编辑、版本、AI 校对对 GBK 文件同时复活。编辑保存(`save_version`)统一写 UTF-8 并在 UI 注明(覆盖源文件时提示「将以 UTF-8 保存」)。
- **测试**(cargo,命门路径必测):GBK/GB18030(含 4 字节)/Big5/Shift_JIS/UTF-16LE±BOM/UTF-8 夹杂坏字节 各一份 fixture;替换率阈值断言;BOM 剥离断言。
- 新依赖:`chardetng`(Apache-2.0/MIT)、`encoding_rs`(已是 tauri 传递依赖,显式声明)。

### 5.2 txt 智能分章 + 智能分段(P0 · core;「重排」子项默认关)

**分章(TextIndexer,`src-tauri/src/reader/text_index.rs`)**:
- 规则体系仿 legado(GPL,**只借鉴机制,规则自写**):内置一组带 `name/rule/example/enabled/priority` 的正则规则(中文「第X章/节/回/卷…」含大写数字与全角空格容错、`节(?!课)`/`集(?![合和])`/`部(?![分赛游])` 类负向断言防误判、序章/楔子/番外/后记族、Chapter/Part/Section 族、`1、标题` 分隔符型、纯数字型默认关);做成**数据文件**(`resources/txt-toc-rules.json`),为将来「用户可编辑规则」(pro 候选)留门。
- 选规则算法(legado 机制):对启用规则逐个跑**前 512KB**,相邻命中 <1000 字符只计一次(防正文连续引用误判),命中最多者当选,平手按 priority。
- 索引产物:`Vec<Chapter{title, byte_start, byte_end}>`(命中位置天然在行首,不会切进多字节序列);无规则命中兜底按 ~10K 字符切伪章;单章超 ~100KB 可选再切。100MB 文件 = 一次顺序 IO + regex,`spawn_blocking` 秒级,索引缓存入库(§6),文件 mtime/size 变即失效重建。
- **分页/滚动两模式下前端只挂「当前章±1」三章滑窗**,段落层再加 `content-visibility: auto` + `contain-intrinsic-size: auto 2.5em` 兜底 —— 不上通用 JS 虚拟列表(T16 教训:变高文本手写 windowing 是深坑;滑窗已把 DOM 锁死在三章)。
- **测试**:规则命中/负向断言/伪章兜底/相邻去重/偏移正确性(切片解码回文对拍)。

**分段(两级,`src-tauri/src/reader/paragraph.rs`)**:
- **一级(默认开,保守)**:段界直判——空行分段;行首全角空格(≥1 个 U+3000)或 2+ 半角空格视为新段;既有换行即段界。产出段落数组后由渲染层统一施加「段首缩进(0-4 字符可调,默认 2)+ 段间距」——**注意:缩进/段距是 CSS(`text-indent: 2em` / `margin`),不改文本本身**,与 legado 插空格实现不同,可随设置即时变化。
- **二级「智能重排」(每书 opt-in,默认关)**:处理「硬换行断句」的脏 txt——legado reSegment 机制:行尾非句末标点(`。?!?!~」』"`)则与下行黏合;引号相邻处/说话动词+句号处重切;词典防误切(引号包裹、≤16 字、出现≥2 次的词不切)。**重排会改变文本内容 → 进度定位必须走 text-context 重锚(§5.7),此开关切换时强制按上下文恢复位置**。calibre 的中位行长检测(median line length,判「是否存在硬换行」)作为进入二级前的自动建议信号:检测到硬换行特征时 UI 提示「本书疑似断行错乱,建议开启智能重排」。
- **测试**:直判分段快照对拍;黏合规则(句末标点表 `?。!?!~`+右引号复合);重排幂等性(重排两次=一次)。

### 5.3 排版设置(P0 · core)+ 中文排版基线

- **参数面**(全局默认 + 每书覆盖,legado 对齐):字体(系统列表+内置可下载字体包)、字号、字重(正常/粗/细)、行距、段距、**四边独立边距**、页面宽度三档(满屏/80%/限宽 ~46em,微信读书网页版模式)、段首缩进 0-4 字符、对齐(两端/左)、字距(letterSpacing)。章节标题独立字号/间距(legado 特色,低成本高感知)。
- **中文排版三件套(默认值即产品)**:`text-align: justify` + `line-break: strict`(避头尾)+ `text-indent: 2em`;`text-autospace`/标点挤压视引擎支持渐进增强;**不做标点悬挂**(hanging-punctuation 为 WebKit 独占,Chromium 不支持,跨平台不一致宁可不做)。
- **注入机制**:一份 `buildReaderCSS(prefs)` 纯函数生成 CSS 字符串 → Shell 容器 + `renderer.setStyles()` 双路下发(§4.5);变更即时生效无需重开书。

## 6. 数据模型与 IPC 契约

### 6.1 新表 DDL(SCHEMA 增量,沿用现有版本迁移机制)

```sql
-- 每书阅读偏好:只存与全局默认的 diff(JSON),读时 merge。
CREATE TABLE IF NOT EXISTS reader_book_prefs (
    item_id    INTEGER PRIMARY KEY REFERENCES media_items(id) ON DELETE CASCADE,
    prefs      TEXT NOT NULL,               -- 版本化 JSON {"v":1,"encoding":"gb18030","vertical":true,...}
    updated_at INTEGER NOT NULL DEFAULT (strftime('%s','now'))
);

-- 书签:locator 与阅读进度同编码(§6.2),snippet 为现场引文。
CREATE TABLE IF NOT EXISTS reader_bookmarks (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id    INTEGER NOT NULL REFERENCES media_items(id) ON DELETE CASCADE,
    locator    TEXT NOT NULL,
    snippet    TEXT,
    created_at INTEGER NOT NULL DEFAULT (strftime('%s','now'))
);
CREATE INDEX IF NOT EXISTS idx_bookmark_item ON reader_bookmarks(item_id);

-- txt 章节索引缓存:源指纹变即失效重建(布局缓存 bump 纪律同族)。
CREATE TABLE IF NOT EXISTS text_book_index (
    item_id    INTEGER PRIMARY KEY REFERENCES media_items(id) ON DELETE CASCADE,
    src_key    TEXT NOT NULL,               -- 指纹:源文件 mtime+size,或生效版本 id;+reflow 开关位
    encoding   TEXT NOT NULL,               -- 检出/覆盖后的最终编码名
    confidence TEXT NOT NULL,               -- 'bom' | 'detected' | 'manual' | 'lossy'(替换率超阈)
    chapters   TEXT NOT NULL,               -- JSON [{t:标题, s:byte_start, e:byte_end}, ...]
    updated_at INTEGER NOT NULL DEFAULT (strftime('%s','now'))
);
-- 预留(P2 期建,不在本期 DDL):reader_annotations(高亮/笔记,locator 体系)、reading_stats(会话时长)。
```

### 6.2 复合定位器规范(`reading_progress.position` / `reader_bookmarks.locator` 共用)

- 新值:`loc1:` 前缀 + JSON(见 §5.7 示例);字段:`k`(txt|md|epub)、txt/md 用 `c`(章 index)+`o`(章内字符偏移)、epub 用 `cfi`,公共 `p`(章内 progression 0-1)、`tp`(全书 progression)、`t{b,h,a}`(前文/锚点/后文各 ~40 字)。
- **偏移的锚定空间 = canonical 文本**:解码 + 分章 + 分段/重排之后、替换规则/简繁转换之前的章内字符流。替换/简繁是纯显示层变换(不改 canonical、不改偏移);text-context 重锚也在 canonical 空间搜索。推论:重排开关/版本切换会变 canonical → 走 `t` 重锚(§5.7 恢复算法);替换/简繁切换不影响定位。
- 旧值兼容:`scroll:`/`page:`/`cfi:` 前缀按旧语义恢复一次,下次保存自然升级为 `loc1:`;不做批量迁移。

> 勘查 vendored foliate `paginator.js` 确认 **竖排轴对换是渲染器内建、非自研**:`getDirection`(paginator.js:178)从 `getComputedStyle(doc.body).writingMode` 探测 `vertical-rl`/`vertical-lr`,`#vertical` 一路驱动分页列轴 / 触摸滑动 dx↔dy / 滚动轴 / snap / overlayer 定位 / `dir=rtl`。**激活点**:paginator 每 section load 的 `onLoad`(paginator.js:1008)**先 `setStyles(#styles)` 再 `dispatchEvent('load')`,二者都在 `getDirection` 之前**;故 BookReader 的 `load` 事件处理器把 `writing-mode` 落到 `doc.documentElement`(可继承 → body 生效)即被随后的 `getDirection` 探测到 → 全部轴对换自动生效。**「轴对换翻页语义(热区/键位翻转)」因此几乎零成本**(与 R2 阅读流切换同属"一次注入,渲染器接管")。**切换须 remount**:`getDirection` 仅在 section load 运行,改 prop 不重探测已加载 section,故竖排↔横排走 `reloadToken++`(位置由保存 CFI 恢复)。已含 vertical-lr 左起变体。**本段其余仍待起**:字体包下载位(重基建,复用模型库)、竖排排版参数联动(行距→列距 / logical 属性调优,属设备调优)、**真机矩阵验收(§9,竖排在 WebView2 实际渲染 + CJK 字体可用性只能真机证)**。
