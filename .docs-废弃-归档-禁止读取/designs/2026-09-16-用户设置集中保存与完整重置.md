# 用户设置集中保存与完整重置

> 2026-09-16 代码与相关验证已完成，记录见[实施归档](../worklogs/2026-09-16-设置集中保存实施/closeout.md)；真实应用交互验收仍以[本线状态](../status/应用配置重构-外置配置文件与热应用.md)为准，本文不代表全部平台已实机验收。用户明确：尚未正式上线，不考虑旧设置迁移。本方案不设计旧数据导入、双读、双写、版本兼容或迁移标记。

## 1. 目标与决策

所有全局用户偏好统一保存到 `<app_data_dir>/config.toml`，复用现有 `ConfigManager`、`toml_edit` 和文件监听。数据库保存资产相关数据和内部运行状态。前端只保存可由配置重建的启动缓存。

完成后应满足：

- 找设置只看一个文件，设置页与文件编辑修改同一份值。
- 设置页、播放器、阅读器、布局和桌面窗口的偏好全部可恢复默认。
- 清除设置不会删除资产、阅读进度、任务状态，也不会再次触发首次使用引导。
- 重启后不会从旧数据库记录、旧 localStorage 或窗口插件文件恢复偏好。
- 不增加依赖、不新建通用配置框架、不重写设置页视觉结构。

本机当前标准目录为 `C:/Users/gf/AppData/Roaming/com.scrollery.app/`；运行时始终使用 Tauri 路径解析，不硬编码用户名或平台路径。

### 3.2 留在数据库

从 `STATE_KEYS` 移出上表偏好，剩余内部键保留：

- `schema_version`：数据库版本。
- `last_directory_id`：与当前资产库关联的最后访问目录。
- `first_launch`、`guide_seen`：首次使用与引导完成标记，重置设置不重放引导。
- `ai_gpu_name`、`ai_provider`：运行环境探测结果。
- `exotic_paused`、`ai_analysis_active`、`face_analysis_active`、`derivation_active`：任务启停与续作状态。
- `backup_last_success_at`、`last_cover_stat_reconcile`：后台工作时间戳。

资产记录、标签、评分、扫描根、单资产阅读／播放进度及任务记录继续留各自业务表。是否自动备份、采用什么分析参数属于配置；备份何时完成、任务是否正在运行属于状态。

自定义 ICC 文件、AI 模型、插件程序、日志和缩略图属于资源或产物，不塞进配置文件；配置只保存选择项或路径。恢复默认会取消相关自定义选择，不删除导入资源。资产备份系统本轮不扩展为配置备份系统。

### 3.3 前端本地存储

- 仅保留现有 `scrollery.themeSnapshot.v1` 启动主题快照，供首帧避免闪烁；权威值从后端快照到达后覆盖它。缓存不得反向写回配置。
- 首次配置快照就绪前不挂载资产内容及侧栏，避免演示打码尚未水合时显示真实内容；读取失败提供重试。窗口外壳、关闭确认和错误提示常驻，保证失败时仍可关闭。实际首帧渲染需单独交互验收。
- `sortModeUsage` 属开发统计，改为开发构建内存计数；不带入配置文件。
- `scrollery.debug.*` 属开发诊断开关，仅开发构建读取；不作为产品设置，不承诺生产持久化。
- 其余用户偏好停止读取和写入 localStorage。旧键可以物理留存但不再有读者；不增加启动清理程序。

## 4. 文件结构、类型和默认值

继续使用现有顶层键和中文分组注释，不把全文件改成嵌套 TOML 表。新增 `reader`、`player`、`layout`、`window` 分组仅用于排版。

`schema.rs` 仍是类型、默认值、校验和热生效标记的唯一权威：

- 现有 Bool / UInt / Str / Enum / Path 保留。
- 按真实数据增加有符号整数和有限小数：窗口坐标可能为负，音量／倍速／行高等不能截为整数；拒绝 NaN 和无穷值。
- 列表、展开映射、日志预设、窗口几何结构使用明确的数据结构和字段校验，TOML 写成原生数组／内联表，不在文件里嵌套 JSON 字符串。
- 仅加入实际需要的结构种类，不开放任意对象、任意动态设置名；映射中的 ID 使用实际设置卡片／阅读器分组／窗口注册表校验。
- 数值范围和枚举沿用当前控件与业务函数的约束，集中至 schema；例如音量 0–1、倍速 0.25–3。现有合法默认行为保持原样。
- 既有配置有效值保留；文件中未出现的新键直接采用 schema 默认值。文件缺失时生成带注释的默认模板。这是常规缺省规则，不读取其他存储补值。

IPC 可以继续在内部使用当前规范文本转换，但数组／对象对前端提供具名 TypeScript 类型和集中转换函数，禁止各组件自行拼接 JSON 与重复校验。前端初始化占位值不能在后端快照加载前自动保存。

## 5. 读写与运行时应用

### 5.1 统一入口

扩展既有配置模块，不另造持久化服务框架：

- `get_settings_snapshot`：一次返回全部已注册设置的生效值和本进程 revision，包含缺省值，供运行时刷新使用；启动使用下述合并批次，避免逐控件请求。
- `set_app_settings`：接受一次具名键值 patch；仅校验本次 patch 中全部键及其值，成功后写盘一次，并返回最新快照／revision、变化键和需重启键。patch 中任意键非法则整批拒绝；文件中其他被加载器忽略的键不阻塞本次保存。
- `clear_settings`：保留现有命令名称，移至 `config_commands.rs`，语义改为完整重置用户设置；返回与批量写入相同的应用结果。
- `get_app_config` / `set_app_config` 最终仅为保留的内部状态服务，设置消费者切到上述入口；不为旧前端保留设置分流兼容。
- `get_startup_config` 保留一次合并启动往返，返回 `{ settings: SettingsSnapshot, state: StartupState }`。settings 调用同一个快照构造函数，删除原来逐字段列举的重复设置读取；state 只读启动所需内部状态，仍保持一次批量 DB 读取。
- `open_config_file`、`get_config_status` 继续复用。注册 IPC 与权限随实际变更同步，移除退役命令声明。

前端在现有 `configStore` 内集中接入快照、写入与缓存失效；`uiStore` 和各 composable 保留领域行为，通过该入口取值和保存。避免把所有 UI 操作塞入配置管理器。

启动继续只有一个就绪 Promise：取得合并结果后先应用设置，再应用内部状态，完成后才解除设置交互／自动保存门控并执行依赖这些值的首屏与引导逻辑。读取失败显示可重试的初始化错误，不把占位默认值当作用户修改写回。重置只刷新 settings，不重跑引导状态初始化。

### 5.2 普通设置与高频调整

普通切换立即提交，后端确认写盘才视为保存完成。前端可以即时预览；写盘失败需提示并恢复最后确认值，不能默默显示成已保存。

滑块、宽度、音量等连续操作先在前端更新显示，经一个集中待保存集合按键合并；空闲 300ms 提交，连续操作最长 1s 提交一次。桌面窗口几何事件由后端合并，空闲 500ms／最长 2s 提交一次。上述数值为首版实现参数，可在相关验证中调整，不新增产品设置。

同一批修改只读改写一次 TOML。文件 IO 放 `spawn_blocking`；继续临时文件写完后同卷原子替换，正常保存保留其他键的注释与排版。前端控件不得各自建立独立落盘定时器。

### 5.3 写入、外部编辑、重置共用串行入口

设置提交、外部文件重读和全量重置在配置编排层串行执行；若需要跨 await 串行，使用短作用域的 tokio Mutex，文件工作仍交给阻塞线程，禁止跨 await 持有 std Mutex。

每次提交基于最新文档合入当前 patch，不用较早读取的整份内存快照覆盖文件。watcher 只提供“需要重读”的信号，进入串行入口后再读取磁盘，不能携带旧 LoadedConfig 在重置后覆盖默认值。

运行时维护递增 revision，用于前端丢弃过时响应和重复事件；另维护仅在全量重置时递增的 generation，所有 patch 携带采集时 generation，后端拒绝旧代写入，防止其他窗口和旧定时器晚到回灌。二者不落盘、不构成版本迁移协议。自写指纹继续抑制 watcher 回环。

UI 写入、外部编辑和重置共用一条“差异 → 应用影响 → 广播结果”流程。前端收到快照只应用，不触发保存 watcher。关联副作用按最终配置合并：例如同时改缩略图尺寸和质量，每批仅安排一次派生重启，不逐键反复重启流水线。

### 5.4 错误与退出

文件语法损坏仍保留最后有效配置并展示已有错误提示，普通保存不得静默覆盖坏文件。单键非法沿用当前跳过该键、采用默认值并报告警告的行为。

加载映射设置时，未知卡片／分组 ID 只忽略该条目并报告警告，其余条目正常使用；不因一个未知 ID 拒绝整份文件或阻塞无关 patch。新提交 patch 中的未知 ID 则直接拒绝，不主动导入、转换或清理旧来源数据。

文件写入成功而运行时影响应用失败，返回“已保存、部分需重新应用／重启”的独立结果；不能报告“完全成功”，也不伪装成文件未保存。沿用稳定 IPC code/variant，不透传内部异常字符串。

正常退出在现有生命周期入口等待前端在途提交和后端窗口待保存值完成；不能依赖浏览器 unload 中发异步 IPC。前端统一保存集合提供 flush，后端关闭流程协调 flush 完成后再退出。写盘失败保持窗口可用并提供重试／明确放弃未保存修改的选择。隐藏到托盘不视作进程退出。强制结束进程可能损失防抖窗口内的调整，不增加日志式配置存储。

## 6. 窗口状态纳入同一文件

在 `lifecycle.rs` 或专门的 `config/window.rs` 中接入现有桌面窗口事件，复用配置提交入口，停止独立插件读写。确认全部窗口调用者替换后移除 `tauri-plugin-window-state` 依赖、初始化与权限。

- 按实际持久化窗口 label 注册，覆盖主窗口和现有辅助窗口；不把任意临时窗口永久记入配置。
- 保存正常窗口位置／尺寸、保存时 scale factor、最大化状态；不保存 visible 和最小化状态。
- 使用当前平台返回的正常物理边界配合 scale factor，恢复时按目标屏幕 DPI 换算尺寸，校验目标显示区域；屏幕消失或完全离屏时回到可见屏幕居中。
- 启动继续先恢复边界，再按现有流程展示窗口；程序恢复导致的 move/resize 不当成用户新设置写回。
- 最大化时保留原正常边界，避免保存最大化尺寸覆盖还原尺寸。
- 重置默认主窗口为当前配置的 1280×820 逻辑尺寸、居中、非最大化，最小尺寸仍为 800×560；辅助窗口采用各自现行创建默认值。
- 移动端略过窗口恢复与捕获；文件中桌面窗口记录不影响移动端启动。

## 7. 恢复默认设置的完整流程

按钮名称统一为“恢复默认设置”，说明覆盖外观、布局、播放／阅读偏好和窗口位置；保留既有一次确认。不要增加多层确认。

1. 暂停用户设置提交，取消尚未发送的防抖 patch，等待已经发送的设置请求结束；所有存活窗口共同停止旧偏好回写。
2. 后端暂停窗口几何采集，取消待保存的旧几何值；与普通提交和 watcher 一起进入配置串行入口，确保已开始的写入先完成。
3. 直接从 schema 生成全默认模板，原子替换 config.toml 一次。显式重置允许替换语法损坏的文件，不依赖先解析坏文件；说明会恢复文件默认内容，包括手写注释。不删除目录，不执行 app_config 清表 SQL。
4. 写盘成功后更新配置内存、清除配置加载错误、增加 revision，按整批差异统一应用运行时影响并向所有窗口广播默认快照。
5. 各前端窗口替换中央设置状态，更新布局、阅读器和播放器，清除并按默认值重建 localStorage 中的主题启动快照。应用快照不触发设置保存 IPC、不写回 config.toml；重建启动缓存是明确保留的本地缓存写入。
6. 恢复窗口默认几何；程序触发的恢复事件不采集回写。完成后重新启用设置提交与窗口采集。
7. 可以热应用的即刻生效；只在启动期读取的参数明确显示“默认值已保存，重启后生效”。不把 window.location.reload 当作后端重启，也不自动中断任务或重启进程。

若第 3 步写盘失败，保留重置前最后确认的文件与内存值，解除暂停并报告失败；本次已取消但尚未保存的预览回到最后确认值。若保存成功但应用部分失败，保留已保存的默认值，清楚报告需要重启的项目。

重置期间再次点击去重；用户关闭窗口／退出与重置串行协调。暂停与恢复均须 finally 兜底，不因异常永久禁用保存。无需跨 SQLite、文件和 localStorage 建分布式事务：SQLite 不参与重置，缓存可由权威快照重建。

## 8. 不做旧设置迁移的实施规则

- 本轮不读旧 DB 偏好、不读旧 localStorage 偏好、不读旧窗口插件文件。
- 新配置中已有合法同名值照常生效；原来仅在其他地方存在的偏好首次使用默认值。
- 删除被替代的读写分支、死的主题补写／迁移分支和相应注释；不存在的历史迁移文件不重新创建。
- 数据库残留行和旧前端键不影响功能，不增加自动批量删除脚本，不重建用户数据库。
- 测试通过临时数据目录或测试夹具隔离设置，真实本机配置不自动删除。

| 批次 | 主要文件／模块 | 独立交付标准 |
|---|---|---|

| C：窗口与重置入口 | `lifecycle.rs`、窗口创建点、`lib.rs`、Cargo 依赖及 capability、`DynamicSettingControl.vue`、中英文文案 | 独立窗口存储退场；退出 flush 和完整重置完成；移除 scan_commands 旧清表实现 |

批次顺序 A → B → C → D，按完整子任务交付，避免在中间状态宣称“全部设置已统一”。具体编码优先委派白名单子代理，主会话审查关键差异与验证证据。全量构建、依赖安装／升级另需明确授权。

## 10. 验收与验证范围

核心行为改变前先补现状表征测试；本次方案编写不运行应用测试、不安装依赖、不构建。

| 场景 | 必须观察到的结果 |
|---|---|
| 设置存储 | 从每个偏好分组至少修改一项，config.toml 出现对应原生值；DB 与 localStorage 不新增这些偏好 |
| 默认值 | 新文件／缺失键采用 schema 默认值；旧 DB／localStorage 中故意放冲突值，启动结果仍不受其影响 |
| 类型 | 小数不截断、负坐标合法；无穷值、错误对象字段和未知设置名被拒绝；一项非法时整批不落盘 |
| 原子保存 | 多键 patch 只落盘一次；模拟写盘失败时最后确认的文件和内存值一致 |
| 并发 | UI 写入、窗口调整和外部文件编辑交错，互不覆盖不相关键；过时 watcher／响应不能恢复旧快照 |
| 重置 | 改过的每类偏好、所有窗口和内存值恢复默认；延迟定时器与在途请求不会回写旧值；重启仍为默认 |
| 业务保留 | 重置前后资产、标签、进度、扫描根、任务标志、引导标志保持不变 |
| 文件错误 | 普通编辑遇坏文件保持旧值并报错；明确重置可生成新模板；写盘失败不显示成功 |
| 热应用 | UI 写入／文件编辑／重置使用同一效果路径；每批派生重启最多一次；需重启项有准确提示 |
| 前端缓存 | 旧主题快照最多影响首帧；权威配置水合后覆盖，不能反写；重置完成后快照对应默认值 |
| 生命周期 | 调整后立即正常退出可保存；托盘隐藏、真正退出和重置互不串扰；保存失败不会假装已保存 |
| 桌面窗口 | 普通／最大化切换、负坐标副屏、显示器断开、DPI 变化、辅助窗口与重置均保持可见和正确尺寸 |
| 写入频率 | 连续拖动 10s，落盘遵循既定防抖／最长等待间隔，不逐事件写文件；结束后最后值被保存 |

验证选最低充分范围：配置模块局部 Rust 测试、前端配置与关键 composable 测试、相关 lint/typecheck，加临时数据目录的人工交互验收。Windows 为当前实机验收平台；macOS 和移动端按可用环境分别记录结果，不能把静态检查记成实机通过。

最终完成条件：上述验收通过且清除旧设置路径；没有“先集中主要设置，其余以后再收”的遗留分支。若实施发现新的独立偏好，将其补进本方案同一清单并接入，不扩展到资产数据重构。
