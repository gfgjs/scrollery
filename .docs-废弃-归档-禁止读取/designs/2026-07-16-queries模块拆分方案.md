## 1. 结论

拆分有必要，且应在继续向 `queries.rs` 增加新领域 DAO 前实施。

这不是基于“单文件超过一万行”的机械判断，而是以下信号同时成立：

- 立项快照 `33e5846` 中，`src-tauri/src/db/queries.rs` 实测 `10,804` 行、`481,355` bytes，含 `211` 个 `pub fn`、`18` 个公开 struct/enum/type/const、`29` 个私有函数。
- 二次 Review 时源码已由 `f3498dd` 增加 81 行和 2 个公开函数；当前实测 `10,885` 行、`485,129` bytes，含 `213` 个 `pub fn`、`18` 个公开 struct/enum/type/const、`29` 个私有函数，即 `231` 个顶层公开项。
- 测试仍为 `125` 个、`21` 个测试模块；测试代码约 `4,453` 行（约 `40.9%`），排除测试后约 `6,432` 行。
- 同一文件承担扫描、目录、媒体、布局、筛选、选区、缩略图、元数据、AI、人脸、派生任务、文档、合集、exotic 插件、存储后端与卷等十余个 bounded context。
- 当前约 `41` 个 Rust 文件通过 `crate::db::queries` 或 `scrollery_lib::db::queries` 消费该模块；立项快照为 `39` 个。
- 2026-07-01 至二次 Review，已有 `59` 个提交修改该文件，累计约 `5,097` 行增删，是高频冲突热点。
- 2026-07-10 的全库审查已把 “R21 queries.rs 巨石”判为恶化，并记录重复列清单曾导致 P0 缺陷；当时文件仅 `9,133` 行、`198` 个公开函数，六天后又增加 `1,752` 行和 `15` 个公开函数。

以上数字是 Review 证据，不是施工期硬编码常量。P0 必须以开工时 HEAD 重新生成完整 public API、测试与消费文件 manifest；后续验收以 manifest 对拍为准。

拆分的直接收益是正确性隔离、审查聚焦、测试就近和减少 Git 冲突；**不把运行性能或编译速度提升列为收益承诺**。

## 2. 目标与非目标

### 2.1 目标

1. 让每个查询文件只承担一个可描述的领域职责。
2. 保持现有调用方路径 `crate::db::queries::<symbol>` 与 `scrollery_lib::db::queries::<symbol>` 不变。
3. 将行位置敏感的 mapper、SELECT 列清单和对应测试放在同一模块。
4. 将现有内联测试迁到所属领域，保证生产实现与回归钉同步演化。
5. 每个迁移提交可独立验证、独立回滚。
6. 最终让 `queries.rs` 只保留模块声明、兼容 re-export 和顶层文档。

### 2.2 非目标

本线不得顺手实施下列改动：

- 不优化 SQL、不改索引、不改分页或查询策略。
- 不改事务边界、锁粒度、批次大小、状态码或错误映射。
- 不改任何函数签名、返回类型或公开 symbol 名。
- 不收紧现有 `pub` 可见性；公开面清理另立任务。
- 不合并“看起来重复”的 SQL、mapper 或状态机。
- 不调整 DB schema、migration 或 `models.rs`。
- 不借拆分修复审查报告中的性能/正确性债；发现问题只登记，不混入搬迁 commit。
- 不引入 repository trait、ORM、宏生成 DAO 或新的抽象框架。

## 3. 不变量

### 3.1 外部 API 不变量

所有现有调用方继续使用原路径：

```rust
use crate::db::queries::{get_config, query_layout_items};
crate::db::queries::set_config(&conn, key, value)?;
```

实现采用 `queries.rs` 门面加 `queries/*.rs` 子模块：

```rust
// db/queries.rs
mod config;
mod layout;

pub use config::*;
pub use layout::*;
```

不采用 `queries/mod.rs` 取代 `queries.rs`，理由：

- 保留现有文件入口，减少活跃文档和开发者导航的路径破坏。
- Rust 原生支持 `queries.rs` 作为父模块、`queries/` 存放子模块。
- facade re-export 可让 P0 冻结的全部调用文件零迁移（当前实测 41 个）。

第一轮允许 glob re-export，以机械保持 P0 完整 public API manifest；manifest 必须覆盖 `pub fn` 以及公开 struct/enum/type/const，不能只核对函数数目。若出现名称冲突，才对冲突模块改显式列表。禁止在本轮借显式列表收紧公开面。

### 3.2 行为不变量

每个搬迁 commit 必须满足：

- SQL 字符串内容不变。
- 参数绑定顺序不变。
- mapper 列索引与 SELECT 列顺序不变。
- `Connection` / transaction 的创建与提交位置不变。
- 错误传播与 `OptionalExtension` 行为不变。
- 测试数据、断言和 `#[ignore]` 状态不变；只允许因模块路径变化修正 import。
- 不改变函数相对调用关系；只允许把路径改为 `super::<module>::<helper>`。

### 3.3 依赖方向不变量

```text
P0 冻结的全部现有调用文件（当前 41 个）
        │
        ▼
db/queries.rs（稳定门面，只声明与 re-export）
        │
        ├── queries/scan.rs
        ├── queries/layout.rs
        ├── queries/thumbnail.rs
        └── ...领域模块
                │
                ▼
db::models / error / exotic::task / utils / rusqlite
```

约束：

- 调用方不得改为直接引用 `db::queries::<child_module>`。子模块一律以私有 `mod` 声明（如 §3.1 示例），该约束由编译器强制，而非仅靠纪律。
- 子模块不得反向通过 `crate::db::queries::*` 导入 facade，避免循环和所有权模糊。
- 跨子模块 helper 默认 `pub(in crate::db::queries)`；只有编译证明需要时才开放，禁止 `pub(crate)` 扩面。
- 不建泛化 `common.rs`。共享内容先归最强 owner；只有至少两个领域确实共享且无法消除时，才建立名字具体的内部模块。

## 4. 目标目录与领域所有权

```text
src-tauri/src/db/
├── queries.rs                 # 稳定门面，目标 ≤ 200 行（软目标）
└── queries/
    ├── scan.rs                # 扫描根、目录、fast scan 写入与缺失判定
    ├── media.rs               # 媒体读取、用户属性、companion、回收站、统计
    ├── layout.rs              # 布局查询、filter/sort builder、view、selection
    ├── thumbnail.rs           # 缩略图 pending/reconcile/result/cache
    ├── metadata.rs            # image/video/audio enrichment DAO
    ├── storage.rs             # storage backend、volume、availability
    ├── search.rs              # 文件名搜索与按 id 回表
    ├── config.rs              # app_config KV
    ├── ai.rs                  # embedding 与 AI 状态机 DAO
    ├── faces.rs               # face/person/approval/cluster/recluster DAO
    ├── derivations.rs         # media_derivations 状态机与 payload
    ├── documents.rs           # document meta/version/replacement/reader 状态
    ├── collections.rs         # albums/album_items 合集语义
    └── exotic.rs              # exotic plugin/task/lease DAO
```

文件行数只作审查信号，不设 CI 硬门。第一轮允许 `faces.rs`、`layout.rs` 比其他文件大，只要领域内聚；等第一轮拆分稳定后，再基于实际变更冲突决定是否二次拆分。

### 4.1 现状到目标映射

| 目标模块 | 从现文件迁移的职责 | 关键边界 |
|---|---|---|
| `scan.rs` | scan root、directory tree、subtree、fast scan upsert、source changed、mark missing、`list_directory_files`、`find_directory_id`、`map_child_directory_ids`、`map_media_entities` | `invalidate_derived_for_item` 继续由 source-change 事务 owner 持有；两个 FS 文件树实体关联 DAO 同迁，且 `map_media_entities` 与 `list_directory_files` 的可见项谓词保持一致 |
| `media.rs` | `MediaItem` mapper、get/detail、批量 meta、favorite/rating/color、companion、trash、stats、cache key/path info、`duplicate_media_item_into_dir` | 不吸收 layout SQL builder；用户属性批写与 selection 解析分开 |
| `layout.rs` | `LayoutItem` mapper、canonical layout、`push_query_body`、`push_where_predicates`、`push_order_by`、view、selection、dir labels | mapper + SELECT 列清单 + 三个 builder + 等价性测试必须同模块移动 |
| `thumbnail.rs` | pending/count、cover reconcile/reset、eviction reset、exotic route、`update_thumb_result` | 写边界防降级测试与实现同迁 |

### 4.2 mapper 归属

不建立集中式 `mappers.rs`：

| 当前 mapper | 目标 owner |
|---|---|
| `map_scan_root`、`map_dir_node` | `scan.rs` |
| `map_volume`、`map_storage_backend` | `storage.rs` |
| `map_media_item` | `media.rs` |
| `map_layout_item` | `layout.rs` |
| `map_collection` | `collections.rs` |
| document replacement/version mapper | `documents.rs` |
| exotic task mapper | `exotic.rs` |

理由：位置 mapper 与对应 SELECT 是同一契约。集中 mapper 会把原巨石问题缩小后重新制造一次，并增加跨模块列顺序漂移风险。

## 5. 测试迁移规则

当前 `125` 个测试中约 `101` 个集中在文件尾部，另有多个测试模块穿插在生产代码之间。迁移规则：

1. 测试模块跟随被测主 owner，不留在 facade。
2. `use super::*` 改为子模块局部 import；只补编译所需项，不重写 fixture。
3. 测试函数名、断言、SQL fixture、pragma 和 ignore 状态保持不变。
4. 跨领域 characterization test 归“被保护的不变量 owner”，不是归调用入口：
   - layout SQL/内存序等价 → `layout.rs`；
   - source change 全失效 → `scan.rs`；
   - thumb 写边界防降级 → `thumbnail.rs`；
   - face 聚类并发/人工审批 → `faces.rs`。
5. facade 不新增行为测试；只依赖 workspace 编译证明 re-export 路径仍成立。
6. P0 使用 `cargo test --workspace --locked -- --list` 生成测试 manifest。Rust test harness 会输出完整模块路径，测试迁入 `queries::<domain>` 后该路径必然变化，因此不得直接逐行 diff：
   - 对 `db::queries` 测试提取末级测试函数名并排序对拍；
   - P0 先断言末级测试函数名无重复（2026-07-16 当前 125 个测试、重复数 0）；若以后出现重复，改用“测试模块名 + 函数名”并登记预期 owner 前缀变更；
   - 其他 workspace 测试保持完整路径逐项对拍；所有 `#[ignore]` 状态另行保留并核对。

## 6. 分阶段实施

每个领域单独 commit。禁止把“搬迁 A + 修复 B”放在同一提交。

## 7. Commit 纪律

推荐提交形态：

```text
refactor(db): 拆出 queries config DAO
refactor(db): 拆出 queries collections DAO
refactor(db): 拆出 queries documents DAO
...
refactor(db): 拆出 queries layout 查询核心
docs(db): 更新 queries 拆分后的现行引用
```

每个提交只包含：

- `queries.rs` 的对应删除和 module/re-export 声明；
- 一个新领域文件；
- 与该领域同迁的测试；
- 必要的局部 import/可见性路径修改。

若某一提交出现行为修复需求：停止该提交，把缺陷登记到 findings/todo；除非用户另行批准，先完成纯搬迁或撤回该领域迁移。

## 9. 风险与防线

| 风险 | 触发方式 | 防线 |
|---|---|---|
| mapper 静默串列 | mapper 与 SELECT 分到不同文件后单边改动 | mapper 与 owner 查询同文件；位置锁定测试同迁 |
| facade 漏 re-export | 移走函数或公开类型但未导出 | P0 consumer manifest 的 workspace check + 完整 public API manifest 对拍 |
| 测试“消失” | 测试模块漏迁或 `cfg` 位置错误 | `cargo test --workspace --locked -- --list` 按 §5 归一化对拍（P1 末首查，P5 终查） |
| helper 可见性扩散 | 为快速编译改成 `pub(crate)` | 默认 `pub(in crate::db::queries)`，扩面须单独 Review |
| 跨域循环依赖 | 子模块通过 facade 互相 glob import | 子模块禁止 `crate::db::queries::*`；从 owner 定向引用 |
| 搬迁夹带修复 | rustfmt/diff 噪声掩盖 SQL 变化 | 一领域一 commit；行为修改另 commit、另授权 |
| 活跃文档锚点失真 | function 移走后旧 `queries.rs#L...` 仍可点击但语义错误 | P5 更新现行/normative 文档；历史快照冻结 |
| 与并行工作冲突 | S 线 P3 会改同一 `push_where_predicates` / `search_media`，或其他线继续写 `queries.rs` | S-P3/P4 完成后才启 T-P0；T 实施期冻结旧 facade 写入；插队则停止并重建基线；显式 pathspec 仅用于隔离不重叠文件 |

## 10. 回滚策略

- 无 schema/migration 变化，不涉及数据回滚。
- 一领域一 commit，发现问题时优先 revert 对应领域 commit，不回滚已验证模块。
- facade 保持旧公共路径，回滚不要求修改调用方。
- P4 的 `layout.rs` 若无法在单提交内保持等价，停止并保留其在 `queries.rs`；其余已拆模块仍可独立成立，不要求全有或全无。
