# 内容去重文件夹优先复核方案

> **取代说明（2026-09-02）**：本文对应的候选树—范围画廊—清理草案实现保留为历史快照，不再是去重功能的目标主体验。现行方向改为[主画廊重复项浏览方案](2026-09-02-主画廊重复项浏览方案.md)：重复项进入主画廊，提供按重复组与按关联文件夹两种排列；首版只浏览和理解，不接入本文的 keeper、建议或清理草案。

## 1. 裁定

内容去重的用户主轴从“逐个精确重复组”调整为“先定位冗余集中的文件夹，再用画廊复核具体位置项”。

> 文件夹决定先处理哪里，精确内容组决定哪些内容确实相同，画廊决定用户是否愿意清理这一项。

文件夹只是结果组织、优先级和批量选择范围，不是重复证据，也不是递归删除单位。唯一可执行动作继续是：把用户确认的库内位置项移入 Scrollery 回收站。磁盘文件不移动、不删除，也不承诺释放空间。

现有精确摘要、Live Photo 逻辑单元、源代次和清理前重验证全部保留，见 [当前全局实现基线](2026-08-30-去重功能全局实现方案.md)。

## 2. 目标与非目标

### 2.1 目标

1. 首屏直接回答“重复内容主要集中在哪些目录分支”。
2. A 有 100 项、B 有 55 项且 B 中 50 项已被 A 覆盖时，优先推荐处理 B 中的 50 个重复位置，保留 B 的 5 个独有位置。
3. 文件夹选择可一次形成跨多个精确内容组的清理草案，避免逐组点选。
4. 用户始终能在画廊中看到草案包含什么、保留什么、为什么有例外。
5. 大库不向前端下发全库 ID，不在数据库持久化易漂移的“永久重复文件夹关系”。
6. 执行前按当前源状态重新生成并验证整批选择，任一组漂移则整批不执行。

### 2.2 非目标

- 相似图、裁剪、转码或感知相似关系。
- 自动删除整个文件夹、自动合并目录、自动移动磁盘文件。
- 自动合并收藏、评分、标签、相册、书签等元数据。
- 多个目标文件夹同时进入一份清理计划。
- 全局 set-cover、图优化或不可解释的“最佳保留目录”算法。
- 系统回收站、永久删除、真实可释放空间估算。

## 3. 核心概念与统计口径

### 3.1 三层模型

| 层 | 对象 | 职责 |
|---|---|---|
| 证据层 | 精确内容组 `unit_digest + unit_size` | 证明多个位置项字节级相同；清理后至少保留一个当前有效成员 |
| 聚合层 | 文件夹范围 `directory + descendants` | 统计重复集中度、外部覆盖关系和处理优先级 |
| 操作层 | 文件夹清理草案 | 把一个文件夹范围内多个精确组的建议选择汇总，允许用户覆盖 |

普通文件是一个逻辑单元；Live Photo 的主文件与全部 companion 是一个逻辑单元、一个画廊卡片和一个软删除单位。companion 不独立计数。

### 3.2 文件夹范围

文件夹范围恒指“当前目录及全部后代目录”。UI 必须写明“含子文件夹”，不得把子树统计伪装为直接文件数。

父目录与子目录的统计不可相加。同一位置项在一个范围内只计一次。祖先和后代范围互相重叠，不生成二者之间的覆盖建议；应继续下钻到互斥的兄弟分支或其他扫描根。

### 3.3 计数

每个文件夹节点至少提供：

| 字段 | 含义 |
|---|---|
| `totalPositions` | 子树内全部当前库位置主项，含暂不可分析项 |
| `analyzedPositions` | 已完成本轮去重判定的位置项 |
| `duplicatePositions` | 当前有效精确重复组中的位置项 |
| `externalCoveredPositions` | 组内至少有一个当前有效成员位于范围外的位置项 |
| `internalDuplicatePositions` | 重复只发生在当前范围内部的位置项 |
| `unreviewedPositions` | pending、error、offline、missing、stale 等不能形成安全建议的位置项 |
| `protectedPositions` | 带收藏、评分、颜色、相册、标签或书签等保护元数据的重复位置项 |
| `recommendedPositions` | 默认草案会选择的位置项 |
| `recommendedLogicalBytes` | 默认草案按逻辑单元大小累加的逻辑字节，不是磁盘节省量 |

分析完整且没有未知项时，`totalPositions - duplicatePositions` 可向用户表述为“未发现重复”；存在未知项时必须单列“尚未确认”，不能称为独有。

### 3.4 A/B 示例

若 A 有 100 个位置、B 有 55 个位置，B 中 50 个位置的精确内容在 A 中存在：

- B 的外部覆盖率为 `50 / 55 = 90.9%`；
- A 的外部覆盖率为 `50 / 100 = 50%`；
- B 排在 A 前；
- 默认草案只包含 B 内满足安全规则的重复位置；
- B 中 5 个未发现重复的位置永远不进入默认草案；
- 若 50 个重复位置中有 3 个受保护，摘要应诚实显示“50 个已覆盖，默认处理 47 个，3 个需复核”。

## 4. 推荐与默认选择规则

### 4.1 文件夹优先级

不使用混合权重总分。候选列表使用可解释的稳定排序键：

1. `recommendedPositions > 0` 的可操作范围优先；
2. `recommendedPositions / totalPositions` 降序；
3. `externalCoveredPositions / totalPositions` 降序；
4. `recommendedLogicalBytes` 降序；
5. 保留/未知位置数升序；
6. 目录深度升序；
7. `nodeKey` 稳定排序。

真实文件树仍按目录结构与既有树序展示，不为推荐排序打散。页面初次进入时定位到最高优先级候选，并在树中展开到该节点。

### 4.2 默认草案

用户点击“采用建议”后才建立草案；只选中文件夹不会产生任何清理选择。

对目标范围内的每个精确内容组：

1. 范围外有当前有效成员时，可把范围内的普通未保护成员加入默认草案。
2. 范围内带保护元数据的成员默认保留并进入“需复核”。保护信息优先于文件夹偏好。
3. 范围外没有成员、重复只发生在范围内部时，按现有 keeper 排序保留一个成员，只把其余未保护成员加入草案。
4. unique、pending、error、offline、missing、stale、同一物理对象别名及重叠扫描根产生的位置不进入默认草案。
5. 用户可以把建议项改为保留，也可以把“需复核”的精确重复项手动加入；任何操作都不能让某个精确组零保留。

keeper 的确定顺序继续以在线状态和保护元数据为先；“目标文件夹外”只作为保护条件相当时的偏好。首版不做元数据合并。

### 4.3 覆盖来源

覆盖来源只用于解释建议，不限制 keeper 必须来自某一个文件夹。

选中 B 后，后端按需统计互斥范围中的来源目录。候选来源必须与 B 不构成祖先/后代关系；对同一外部位置沿祖先链向上归并到最高的互斥目录，因此 A 的多个子目录可汇总显示为“A 覆盖 50 项”。共同祖先同时包含 A 与 B 时不作为来源。

多来源时展示前若干来源及“其他”，不声称存在唯一文件夹赢家。

## 5. 页面结构

保留当前顶部分析状态与进度区域，下方替换为文件夹树和画廊工作区。

```text
┌ 分析状态：已完成 · 83 组精确重复 · 12.4 GB 逻辑重复 ┐
├───────────────────────────────────────────────────────┤
│ 文件夹候选树  │ B 文件夹及子文件夹                    │
│                │ 55 项 · 50 项已覆盖 · 5 项未发现重复 │
│ ▾ Root         │ 主要来源：A 50 项                    │
│   A   50/100   │ [采用建议（47 项）]                  │
│   B   50/55  ● ├───────────────────────────────────────┤
│   C    8/80    │ 建议处理 47｜需复核 3｜保留 5｜全部 55│
│                │                                       │
│                │            虚拟化缩略图画廊           │
│                │                                       │
├────────────────┴───────────────────────────────────────┤
│ 清理草案：B · 47 个位置 · 3.1 GB 逻辑大小  [复核并继续]│
└───────────────────────────────────────────────────────┘
```

### 5.1 文件夹候选树

- 仅展示媒体库目录，不混入文件行。
- 默认过滤掉完全没有重复或未知状态的无关分支，但保留通往命中节点的祖先。
- 每行显示目录名、`externalCoveredPositions / totalPositions` 和状态图标。
- 选中状态、建议状态、需复核状态不能只靠颜色表达。
- 树保持懒加载和虚拟化，身份继续使用后端 `nodeKey`。
- 点击目录只改变查看范围；不选中、不加入草案、不导航离开页面。

### 5.2 文件夹摘要

摘要固定回答五件事：

1. 当前范围包含多少位置；
2. 多少位置已被范围外精确副本覆盖；
3. 多少位置未发现重复；
4. 多少位置受保护或尚未确认；
5. 采用建议后会把多少位置移入 Scrollery 回收站。

文案使用“建议处理 B 中的 N 个重复位置”，禁止使用“删除 B 文件夹”或“释放 N GB”。

### 5.3 画廊

画廊提供四个互斥过滤视图：

- **建议处理**：默认草案候选；
- **需复核**：保护元数据、内部重复或关系冲突；
- **保留**：未发现重复和用户明确保留项；
- **全部**：当前文件夹范围内全部位置。

卡片最小投影：缩略图、文件名、相对路径、文件大小、媒体类型、目标状态、覆盖来源、保护标记。卡片状态使用文字/图标加边框，不只用颜色。

单击聚焦；Space 切换是否进入草案；Enter 或双击打开比较抽屉；查看原图继续复用现有查看器路由。

### 5.4 比较抽屉

比较抽屉展示当前 `groupKey` 的全部有效成员：

- 各位置的缩略图、完整路径、根/卷、在线状态和保护元数据；
- 哪些位置会保留、哪些进入草案；
- 元数据冲突原因；
- “保留此位置”与“从草案移除”动作；
- 打开查看器和在树中定位。

抽屉关闭后焦点回到原卡片。首版不允许从 B 的清理草案顺带选择 A 中的位置，避免一份计划跨多个目标范围。

### 5.5 清理草案栏与确认

页面底部固定草案栏，显示目标文件夹、位置数、受影响内容组数、逻辑大小和例外数。没有草案时不显示危险主按钮。

确认对话框必须再次显示：

- 目标文件夹及“含子文件夹”；
- 将处理的位置数和内容组数；
- 明确保留的未重复、受保护和未知位置数；
- 主要 keeper 来源；
- “只移入 Scrollery 回收站；磁盘文件不会移动，也不会释放硬盘空间”。

执行成功后刷新当前文件夹与树统计并显示成功状态；提供“查看 Scrollery 回收站”入口。执行失败保持草案，提示刷新后重新复核。

## 6. 响应式与可访问性

### 6.1 响应式

- `>= 1100px`：常驻左树（260–300px）+ 右侧摘要/画廊；比较为右侧抽屉。
- `768–1099px`：文件夹树改为可收起面板；比较使用覆盖抽屉。
- `<= 640px`：顺序流程“文件夹候选 → 文件夹画廊 → 全屏比较 sheet”；草案栏固定底部并预留安全区。
- 移动端不出现横向滚动和多层竞争滚动；系统返回键先关闭比较，再返回候选树。

### 6.2 键盘与语义

- 文件夹树沿用 `role=tree/treeitem`、roving focus、方向键展开/移动和 `aria-expanded`。
- 画廊使用 grid/gridcell 或等价语义，Space 切换草案、Enter 打开比较、Escape 关闭抽屉。
- 卡片暴露文件名、完整路径、重复关系和当前草案状态；计划数量在一个 `aria-live=polite` 区域完整播报。
- 可交互目标桌面至少满足 WCAG 24×24 CSS px，触控布局至少 44×44；焦点环不得被固定草案栏或抽屉遮挡。
- 状态变化需在 100ms 内有视觉反馈；超过 1 秒的聚合/加载使用稳定骨架或进度，不闪烁 spinner。

## 7. 前端状态与复用边界

### 7.1 状态

去重页使用独立作用域状态，不复用主画廊全局 `useSelection`：

```text
status / viewStamp
treeNodes / selectedFolderId
folderSummary / topCoverSources
galleryFilter / galleryItems / galleryCursor
planBaseMode: none | recommended
includedItemIds / excludedItemIds
planPreview
treeRequestGeneration / summaryRequestGeneration / galleryRequestGeneration
```

`galleryItems`、树拍平结果和 override 集合使用 `shallowRef` 或非深响应容器。切换文件夹时隔离迟到响应；若当前草案非空，切换前明确询问是否放弃。

### 7.2 复用

复用：

- 顶部分析进度、错误和完成状态；
- `DirNode` 路径身份、文件树懒加载、虚拟化数学和键盘导航；
- `MediaThumb`、缩略图加载与占位能力；
- 现有查看器路由、`UiButton`、`UiDialog`、焦点陷阱和主题变量。

不直接复用：

- 侧栏 `FoldersSection`：点击语义会导航主画廊，且混入文件行；
- 整个 `MediaGrid`：绑定全局 `mediaStore`、布局和选区；
- 全局 `useSelection`：其全集来自主画廊 `useViewIds`，会造成跨页面串选；
- 原生 `window.confirm`：无法展示草案摘要和例外。

建议新增：`DedupFolderTree`、`DedupFolderSummary`、`DedupGallery`、`DedupComparisonDrawer`、`DedupCleanupPlanBar`、`useDedupSelection`。

## 8. 后端查询与 DTO

### 8.1 不新增持久化关系表

`dedup_index` 继续是唯一内容身份 sidecar。文件夹统计与覆盖关系从当前有效 exact 组和目录父子关系动态派生，不新增 `dedup_folder_edges` 或永久 cleanup plan 表。

首版采用按当前树层/当前选中范围的递归 CTE 与 keyset 分页，不做全库文件夹两两比较。1M 基准已证明重复运行动态聚合不达标，因此增加按 `analysisGeneration + dataVersion + hashVersion + filters` 失效的进程内只读快照缓存；不增加 schema 复杂度。快照只驻留目录统计，计划组与目标画廊仍按目标范围动态读取。

### 8.2 命令面

```text
list_duplicate_folder_candidates(cursor, limit, filters)
list_duplicate_folder_roots(filters)
list_duplicate_folder_children(parent_id, cursor, limit, filters)
get_duplicate_folder_summary(folder_id, view_stamp, filters)
list_duplicate_folder_items(folder_id, view_stamp, filter, cursor, limit)
list_duplicate_group_members(group_key, view_stamp, cursor, limit)
preview_dedup_folder_cleanup(selection)
apply_dedup_folder_soft_delete(selection)
```

树、候选、关系和画廊都使用后端不透明 keyset cursor。候选排序的 cursor 使用排序字段的整数分子/分母与稳定 ID，不使用浮点覆盖率。

### 8.3 最小投影

```ts
interface DuplicateFolderNode {
  nodeKey: string
  folderId: number
  rootId: number
  parentId: number | null
  name: string
  relPath: string
  depth: number
  stats: DuplicateFolderStats
  state: 'ready' | 'review' | 'none'
  viewStamp: string
}

interface DuplicateFolderItem {
  itemId: number
  groupKey: string | null
  directoryId: number
  fileName: string
  directoryPath: string
  fileSize: number
  mediaType: 'image' | 'video' | 'audio' | 'document'
  width: number
  height: number
  durationMs: number | null
  thumbStatus: 0 | 1 | 2 | 3
  thumbPath: string | null
  placeholderColor: string | null
  relation: 'coveredOutside' | 'internalDuplicate' | 'protected' | 'unmatched' | 'unknown'
  defaultAction: 'clean' | 'keep' | 'review'
  protection: DedupProtectionSummary
}
```

`viewStamp` 是由 `analysisGeneration + dataVersion + hashVersion + filters` 组成的后端不透明版本戳，不等价于数据库快照。清理安全仍由执行时重查询保证。

### 8.4 草案描述符

首版一次只允许一个目标文件夹：

```ts
interface DedupFolderCleanupSelection {
  viewStamp: string
  targetFolderId: number
  baseMode: 'recommended' | 'none'
  includedItemIds: number[]
  excludedItemIds: number[]
  expected: {
    selectedPositionCount: number
    affectedGroupCount: number
    logicalBytes: number
  }
}
```

`recommended` 让后端按本方案规则重新生成默认选择，前端只提交少量例外；`none` 只使用显式包含项。这样“采用整个文件夹建议”不物化数万个 ID，清空草案也不需要传大排除集。

后端 preview 和 apply 共用同一个纯计划生成器，避免前后端各实现一套默认规则。

## 9. 执行契约

`preview_dedup_folder_cleanup` 和 `apply_dedup_folder_soft_delete` 均在 `spawn_blocking` 中运行。apply 在去重 lifecycle 读锁和数据库 writer 临界区内：

1. 校验 `viewStamp`、目标目录存在且范围没有重叠根歧义；
2. 重新生成默认选择并应用 include/exclude overrides；
3. 对所有涉及组重新查询完整 current exact-ready 成员；
4. 校验 selected item 仍在目标子树、仍属于该组、source revision 未变；
5. 校验每组删除后至少保留一个当前有效成员；
6. 校验最终计数、组数和逻辑字节与 expected 一致；
7. 任一条件失败，整批返回稳定错误码且不产生部分软删除；
8. 全部通过后在一个事务中调用通用软删除逻辑，连带 Live Photo companion、推进 revision、清 sidecar；
9. 提交后只 bump 一次 data version，并返回处理摘要。

错误至少区分：`DEDUP_VIEW_STALE`、`SOURCE_CHANGED`、`FOLDER_SCOPE_CHANGED`、`KEEPER_CONFLICT`、`SELECTION_INVALID`、`CLEANUP_INTERNAL`。错误 DTO 只暴露稳定 code 和可安全展示的计数，不泄漏内部路径或数据库原始错误。

部分成功被明确拒绝：它会让用户难以理解文件夹统计为何只变化一半，也可能改变后续组的 keeper 关系。

## 10. 性能约束

- 目录统计、覆盖来源和草案生成全部在后端完成；前端不汇总全库组成员。
- SQL 参数全部绑定；递归 CTE 只展开当前分页目录或当前目标子树。
- 文件夹候选、树子节点、画廊和比较成员全部 keyset 分页。
- 树和画廊超过 50 项必须虚拟化；缩略图只对可视窗口请求并保留尺寸占位。
- 首次聚合超过 1 秒时显示明确阶段进度；交互期不在 UI 线程做 hash、聚合或大数组深响应。
- 以 100K/1M 合成库建立查询基准；只有基准证明动态 SQL 不足时才引入进程内快照缓存。
- 不建立 O(folder²) 全局 pair matrix；选中一个目标范围后才计算覆盖来源。

## 11. 实施顺序

### P1：查询与契约

- 增加文件夹统计、候选、范围画廊和 viewStamp DTO；
- 用 A/B、父子目录、A/B/C、内部重复、保护/未知项测试冻结口径；
- 建 100K/1M 聚合基准，决定是否需要进程内缓存。

### P2：文件夹优先只读 UI

- 替换结果区为去重文件夹树、摘要和只读画廊；
- 接入缩略图、虚拟化、迟到响应隔离、键盘和响应式；
- 旧组列表暂保留为比较抽屉的数据来源，不保留双入口。

### P3：草案与跨组原子软删除

- 实现后端纯计划生成器、preview/apply、稳定错误码和事务测试；
- 接入采用建议、逐项覆盖、确认对话框和成功刷新；
- 真机验证磁盘文件不变、Scrollery 回收站可恢复。

### P4：收拢

- 比较抽屉转用新投影后删除无消费者的旧组首页状态和 IPC；
- 更新权威设计、状态、i18n 和操作说明；
- 跑去重 Rust 聚焦、前端 Vitest、vue-tsc、eslint、生产构建和相关 CI 门禁。

## 12. 验收矩阵

| 场景 | 预期 |
|---|---|
| A100 / B55，B50 被 A 覆盖 | B 优先；草案只含 B 中安全的重复位置；5 个未重复位置保留 |
| A 是 B 祖先 | 不生成 A 覆盖 B；继续显示互斥兄弟来源，统计不重计 |
| A/B/C 交叉覆盖 | 一次只处理一个目标文件夹；每个精确组始终至少保留一个成员 |
| 同文件夹内部三份重复 | 标为内部重复；按保护排序保留至少一个，只处理其余安全成员 |
| Live Photo | 主文件与 companion 一个卡片、一个逻辑大小、一个软删除单位 |
| 收藏/评分/标签冲突 | 受保护成员默认不入草案，比较抽屉解释原因 |
| 离线、missing、pending、error | 单列未知，不计入安全覆盖，不允许默认处理 |
| 重叠扫描根或相同 physical key | 只展示/警示，不生成默认草案 |
| 确认后源漂移 | 整批失败，零部分删除，草案保留并提示刷新 |
| 软删除完成 | 库内位置进入 Scrollery 回收站；原磁盘文件仍存在；统计刷新 |
| 50K 建议项 | IPC 不下发/回传完整 ID 集；recommended 描述符和少量例外保持有界 |
| 键盘/读屏 | 树、画廊、抽屉、确认全程可操作；焦点返回正确，状态不只靠颜色 |

## 13. 明确拒绝的替代方案

| 方案 | 拒绝理由 |
|---|---|
| 前端拉取所有重复组后自行按路径聚合 | 全库 payload、大数组和双份统计逻辑，不适合大库 |
| 持久化所有文件夹 pair 关系 | 文件夹数平方级膨胀，源变化后大面积失效 |
| 按目录大小或文件数量直接决定删除侧 | 不能证明内容相同，也会忽略独有和保护项 |
| 选中文件夹即自动全选/执行 | 混淆查看范围和清理意图，容易造成误操作 |
| 多目标文件夹一份首版计划 | A/B/C 关系容易互相删除 keeper，交互与验证复杂度过高 |
| 分组逐个部分成功 | 结果难解释，后续覆盖关系变化，无法提供稳定的文件夹级反馈 |
