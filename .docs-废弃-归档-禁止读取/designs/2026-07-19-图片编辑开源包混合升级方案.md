# 图片编辑升级:开源包混合方案(v2)

> 背景:方案 C v1(几何链:EXIF orientation + 90° 旋转 + 翻转 + 裁剪)阶段 1-4 已落地(本地未提交),用户反馈功能太简陋,要求调研开源包替换。本稿是 2026-07-19 两路联网调研(前端包一路、Rust 包一路)的落地方案。契约立场:**开发期可推翻,待用户裁决后施工**;施工时按 /planning 纪律建三件套,本稿只定方向与契约。
> 调研核心结论:**不存在可整体替换的成熟开源编辑器**;v1 的「前端预览+参数、Rust 真处理」总架构被两路调研独立印证是对的,应升级零件而非换架构。
>
> **修订记录(2026-07-19 第 2 版)**:按[审查稿](../reviews/2026-07-19-图片编辑开源包混合升级方案审查.md)六项 finding(4×P1 + 2×P2,核实全部成立)修订;F-01 色彩策略经用户裁决走**真色彩管理重路线**(D-108)。另修正审查未列、自查发现的一处:fast_image_resize 已是项目依赖(缩略图链在用),非「留作日后引入」。修订对照见 §10。
> 同日用户补充裁决:**图片编辑整体为高级功能,free 版不提供,做成付费插件,参考 psd 支持插件**(D-112,§4.5)。

### 1.3 调色预览的决定性发现(施工红线级)

- **CSS filter 与 image crate 现成函数数学不等价,已逐公式实证**:CSS `brightness()` 是纯乘法,`image::imageops::brighten` 是纯加法;CSS `contrast(x)` 系数线性,`image::imageops::contrast` 参数先经 `((100+x)/100)²` 平方映射。直接混用 ⇒ 预览与保存结果肉眼可辨不一致。
- ⇒ **调色预览禁用 CSS filter,禁直接调用 `imageops::{brighten,contrast,huerotate}`**;走「双端同源公式」路线(§4.3)。
- 规范澄清(审查 F-05 修订):W3C Filter Effects Level 1 明文「Filter Functions must operate in the sRGB color space」且「color-interpolation-filters has no affect for Filter Functions」——CSS 简写滤镜函数色彩空间是钉死的 sRGB;原稿引用的 Safari/Chromium `color-interpolation-filters` 分歧只涉 SVG filter primitives,**不构成禁用论据,已撤销**。禁用结论由上条数学不等价独立支撑;且 CSS filter 无法表达 D-108 色彩管理链,维持禁用。
- 业界重量对照:RapidRAW(Tauri+Rust RAW 编辑器,8.9k star)用 wgpu+WGSL 单管线让预览=导出。是正确的重解,但为三滑杆引入整条 GPU 管线不成比例,v2 不采,留作日后专业调色档位的路标。

## 4. 设计要点

### 4.1 E1:裁剪组件双候选 spike(1 天,过门才替换)

现状:`EditOverlay.vue`(596 行)自研 8 手柄拖拽 + 归一化坐标;`useImageEditor.ts` 持几何状态,契约=「变换后坐标系的归一化矩形」→ `cropToPixelRect()` 送后端。

集成的真实难点:两候选均自带「图像显示 + 裁剪框」一体渲染;vue-advanced-cropper 的 `coordinates` 相对**原始图像坐标系**,与我方「变换后坐标系」契约存在映射换算;其内建 rotate/flip 预览与我方 CSS transform 链存在双源风险。改喂 D-109 预览位图后,coordinates 还需按「预览尺寸 → 全分辨率变换后坐标系」比例换算(缩放因子=后端已知常量,黄金测试钉死)。

**Spike 验收单**(两候选各过一遍,同表打分):
1. **维护门**(F-06 修订新增):最后发版/最后 commit 时间、未决高危 issue 数、依赖审计(`npm audit` + 传递依赖清点)、可锁定版本;
2. TS strict + `vue-tsc` 全绿(vue-advanced-cropper 类型发布状态两说需装包实测;Cropper.js v2 需自写 Web Components 标签 `.d.ts`);
3. 受控集成:`useImageEditor` 保持唯一状态真源,组件作受控层(监听 change 回写,拒绝内部状态自治);内部结果 canvas 关闭(`:canvas="false"` 或等价);
4. coordinates 语义:可无损换算到现后端契约(或证明改契约为「源坐标系矩形+变换参数」代价更小——若走后者,后端 `apply_geometry` 的 crop 语义同步改,黄金测试全部重钉);
5. 90/270° 旋转 + 翻转组合下裁剪框行为正确(v1「旋转清空裁剪框」取舍能否被组件原生解掉,顺带验证);
6. 替换成本与回退成本对照(含从组件迁回自研的逃生路径)。

决胜规则:两候选按验收单同权打分,平票时维护活跃度优先(Cropper.js v2 现势占优:v2.1.1=2026-04;vue-advanced-cropper 2.8.9=2024-06 后停更 ~25 个月)。双双不过:回退自研拖拽层手感打磨,替换项记 no-go 存证(U-5)。

### 4.2 E2:拉直(straighten)

- UI:工具条加拉直滑杆,域**闭区间 [-45.0°, +45.0°]**(D-111),步进 0.1°,拖动时叠加三分网格;预览 CSS `transform: rotate(θ)`(D-105)。
- 前端裁剪框/postWidth/postHeight 计算升级:拉直激活时,可用区域=旋转矩形的**保持原始宽高比的最大内接矩形**(Lightroom 同款语义);闭式几何解,前后端各实现一份,黄金向量对拍(与 D-104 同一 fixture 机制)。
- 后端:`rotate_fine` ≠ 0 时,`imageproc::geometric_transformations::rotate_about_center_no_crop`(Bicubic,border 填充)→ 按同一内接矩形公式裁剪。角度为 0 时零开销跳过(不触插值,v1 像素级 golden 不变)。
- 契约:`EditOps.rotate_fine: Option<f64>`,**闭区间 [-45.0, 45.0]**,非有限值(NaN/∞)与超域拒 `edit_invalid_ops`;域常量前后端同源(常量值与语义写进 IPC 契约注释,测试覆盖 **-45.0 / 0 / +45.0 / 45.0+ε / NaN / ∞** 六点)。用户 crop 框坐标系升级为「fine rotate 内接后坐标系」(D-107 链序决定,前端 postWidth/postHeight 同步)。

### 4.3 E3:调色三滑杆(真色彩管理 + 双端同源公式)

公式钉死(v ∈ [0,1] 为 **sRGB 编码域**归一化值,f32;工作空间由 D-108 色彩管理保证两端一致——公式**有意**作用在 gamma 编码域而非线性光,与 CSS/主流简易编辑器语义对齐,记入两端注释防未来误「修」):

- 亮度 b ∈ [-100, 100]:`k_b = 2^(b/100)`,`v' = v · k_b`(乘法,±100 恰为 ±1EV,曝光语义并入,见 U-1);
- 对比度 c ∈ [-100, 100]:`k_c = (100+c)/100`,`v' = (v − 0.5) · k_c + 0.5`(线性系数,**不采用** image crate 的平方映射);
- 饱和度 s ∈ [-100, 100]:`k_s = (100+s)/100`,W3C Filter Effects saturate 矩阵,luma 权重 `[0.213, 0.715, 0.072]`(矩阵法,不走 HSL;权重仅在 sRGB 原色下成立——D-108 保证进公式前已在 sRGB);
- 每步 clamp [0,1];alpha 通道不动;应用序:亮度 → 对比度 → 饱和度(钉死,写入两端注释)。

实现:**契约以 f32 直算公式为准**(修订:原稿 256 项 LUT 从契约降级为 8-bit 快路径的可选优化,是否启用由施工期基准决定;16-bit 与 f32 管线不走 256-LUT)。Rust 侧新建 `editing/adjust.rs` 纯函数模块(不用 imageops 现成函数,§1.3);前端 TS 同公式作用于 D-109 预览位图的 canvas(rAF 节流)。

**黄金向量单源**:fixture JSON 一份入库(建议 `src-tauri/tests/fixtures/adjust_golden.json`:f32 输入向量 × 参数组 → 期望输出,含 8/16-bit 量化端点),Rust `include_str!` 消费,vitest 读同一文件消费。两端各自实现、断同一份期望——防「两套公式各自漂移」。

预览一致性诚实声明:预览位图由后端 CMS 转好 sRGB(D-109),前端 canvas 无浏览器色彩管理变量、无 taint;公式阶段黄金对拍**精确**;预览与导出的唯一系统性差异=降采样分辨率(与 v1 缩略图预览同级的既有心智,不另设契约)。

- IPC:`EditOps.adjust: Option<AdjustOps>`(`{ brightness, contrast, saturation }` 各 i8 域校验,全 0 视同 None);超域拒 `edit_invalid_ops`。
- `useImageEditor` 状态机扩三滑杆 + `hasChanges` 并入;重置连带清零。

### 4.4 色彩管理管线细则(D-108)

**无 adjust(几何-only)**:完全走 v1 原路径——源位深保持、ICC blob 直通、不经 CMS,输出与 v1 字节级一致(D-106;回归 golden 钉死)。

**有 adjust**:
1. 解码 → f32 通道化(8/16-bit 均升 f32,不量化);
2. 源 ICC 存在:CMS 转换 源空间 → sRGB(rendering intent 与黑点补偿参数由 P0-CM spike 定,倾向 relative colorimetric + BPC);源 untagged:按 sRGB 直入(与查看器/浏览器事实行为一致);
3. §4.3 公式(sRGB 编码域 f32);
4. 输出:**位深=源位深**(8→8,16-bit PNG/TIFF→16);**profile=嵌入显式 sRGB**(不再回写源 ICC——像素已在 sRGB,回转源空间会引入二次 gamut 损失且收益存疑;广色域→sRGB 的溢色裁剪如实作为「简单编辑档位」取舍记录,真广色域工作流归日后专业档位,与 §1.3 RapidRAW 路标同串)。

**P0-CM spike(施工硬门,先于 E3)**:
- moxcms 解析真实 ICC 样本集:相机 JPEG(Adobe RGB/Display P3)、编辑器导出(v2 与 v4、matrix-TRC 型与 LUT 型)、灰度 profile;
- 转换结果与 lcms2(参考实现)对拍,误差阈值定量记录;
- 16-bit 往返精度、异常 profile(截断/畸形)的失败姿态(须落 `edit_decode_failed` 族稳定码,不 panic);
- moxcms 不过门 → 切 lcms2(vendored FFI),此时 spike 补四平台(Windows/macOS/iOS/Android)交叉编译验证;
- CMYK JPEG:image crate 解码已转 RGB(无 ICC 参与),样本纳入 spike 确认行为并如实记录支持边界。

### 4.5 商业形态与授权门(D-112)

**裁决**:图片编辑(v1 几何 + v2 全部能力)整体为高级功能,free 版不提供,产品形态=付费插件,参考 psd 支持插件。

**实现形态:授权门控内置代码(非动态载荷)**。psd 等 exotic 插件是「签名 zip 载荷经 registry 分发 + license token 激活」;编辑功能的 Rust 命令与 Vue UI 编译在 host 内,不适用载荷下发。但 exotic 授权链与载荷解耦,整链复用:

- **上架**:registry 里新增编辑插件条目(plugin id 暂定 `feature.editing`,命名归 Part8 口径),包体=仅 manifest 的最小签名 zip(走既有 install/验签/生命周期,商店卡片、购买、激活 UX 与 psd 完全同构;host 检测到该 id 时不做载荷解压,只落激活状态)。若施工发现 manifest-only 包与 installer 白名单冲突,降级为「商店虚拟条目」形态,差异记 findings。
- **前端门**:编辑入口(查看器底控条 + ContextualToolbar)接既有 `PluginGate.vue` / `usePluginEntitlement` 四分支(放行/购买引导/不可用);free 版入口默认**显示并引导购买**(与 psd 格式项一致的姿态),是否改为隐藏见 U-7。
- **后端门(真门)**:`save_edited_image` 与 `get_edit_preview` 入口校验 `exotic::license` 的 `evaluate(plugin_id, sku, now)`,未授权拒稳定码 **`edit_not_entitled`**(新增码;前端 gate 只是 UX,后端校验才是边界——与 exotic processing 侧同款纪律)。
- **v1 处置**:v1 几何编辑已按核心功能建成(未提交);本裁决生效后,v2 施工第一步即给 v1 入口挂同一 gate(free 版从未见过编辑功能,无「功能回收”体验问题——v1 尚未发布)。
- **口径红线**(与官网线一致):对外口径「免费版/高级功能」,**不提定价**;生产 CDN/密钥/定价归 Part8,本线只做门控接线与内测链(编译期 keyset + 内测 registry)可验证的部分。
