# 顶栏重构:自绘标题栏 + 上下文工具栏(Command 化)

> **立项日期**:2026-07-08(快照日,后续被推翻的结论须回文首补「已过时」标注)
> **性质**:架构级重构,横跨窗口装饰层 / 视图层 / 操作层。normative 文档,施工以本文 §3–§5 为准;重大状态变更同步本线 [status/ 分片](../status/顶栏重构.md) 与 [todo.md](../todo.md) 线索引表。
> **前置纪律**:承接「开发期不冻结契约」——本文所有默认呈现集 / 分色方案 / 键位在真机 GUI 验收前均为候选,不定死。

## 0. 目标与动机

### 0.1 用户诉求(2026-07-08 原始需求)
1. 进入文件内容页(阅读 / 大图 / PDF / 视频 / 音频)后,顶栏应**动态切换**(通用工具按钮 + 各媒体类型专有工具按钮);现状写死。
2. 参考 VSCode 但**不照搬**:常用操作用图标按钮**点击直达**,只有不常用操作才进二级(溢出)菜单。
3. **把工具栏合并进标题栏**,做**自绘标题栏**,取得更整体的观感。
4. 不仅适配文档 / 图片 / PDF,还要支持视频 / 音频等更多格式,并为未来功能**做好预留**(不惧工作量)。
5. 商业化产品,**完善 / 全面 > 上线速度**,宁可晚上线也不出残次品。
6. 部分操作迁入顶栏(大图的详情 / 收藏、阅读页常用操作等),但不必全迁以免拥挤;未来支持**用户自选**哪些按钮入顶栏——本期只**做好预留**,不出 UI。
7. 联网调研业界成熟方案(VSCode / Office / Eagle 等)。
8. **macOS 保留原生红绿灯**。
9. 用户在环,拿不准的决策先通知。
10. 忽略记忆中任何废弃的旧工具栏重构案。

### 0.2 一句话目标
把「写死的、画廊专用的单条工具栏」升级为「**自绘标题栏承载的、由当前视图/媒体类型驱动的上下文工具栏**」,底层由一套 **Command 贡献注册表**支撑,为后续**插件化 / 用户自定义 / OS shell 集成**铺好可寻址、可扩展的地基。

## 1. 现状取证(四路只读 agent 调研综合,2026-07-08)

### 1.1 顶栏与窗口装饰
- **无任何自绘标题栏**:main 窗口 `decorations:true`([tauri.conf.json](../../src-tauri/tauri.conf.json) 主窗口段),用系统原生标题栏;最小化 / 最大化 / 关闭全为原生按钮;全局零 `data-tauri-drag-region` / `startDragging`。
- 「顶部工具栏」= 原生标题栏**下方**的 [AppToolbar.vue](../../src/components/layout/AppToolbar.vue),恒定为**画廊网格专用**(面包屑 + 筛选 chips + 撤销重做 + 全屏 + 三模式搜索 + 行高滑块 + 分组排序 + 布局切换),耦合 `uiStore/viewStore/filterStore/mediaStore/aiStore/historyStore`,**不随内容页变化**。
- 布局壳 [AppShell.vue](../../src/components/layout/AppShell.vue) 是纯 slot:`sidebar / toolbar(header) / 默认(content) / statusbar` 四槽,`--toolbar-height:48px`([variables.css](../../src/assets/styles/variables.css))。
- **Windows 原生标题栏染色桥**:`uiStore.applyAppearance` 取 `--color-bg-secondary/--color-text-primary` 经 `SET_WINDOW_THEME` 传 Rust,Win11 用 DWM `DWMWA_CAPTION_COLOR` 等刷原生标题栏([system_commands.rs](../../src-tauri/src/ipc/system_commands.rs) `set_window_theme`)。**改自绘后此段失去意义,主题色改由 CSS 直接画。**
- **前端无平台判断**:`isMac/isWindows` 一个都没有,平台分支全在 Rust `cfg(target_os)`;未引 `@tauri-apps/plugin-os`。
- **mac 红绿灯零处理**,需从头做。

### 1.2 两套并存的内容页机制(核心张力)

### 1.3 操作层现状
- **无统一 command 抽象**,四种触发并存:直接函数 / store action / `invokeIpc(IPC.XXX)` / emit(仅 [SelectionToolbar.vue](../../src/components/media/SelectionToolbar.vue))。
- **两个极好的抽象锚点**:① 后端操作已统一走 `invokeIpc`,命令名集中在 [constants/ipc.ts](../../src/constants/ipc.ts);② 右键菜单已有 `ContextMenuItem { id, label, icon, action }` 雏形([ContextMenu.vue](../../src/components/common/ContextMenu.vue)),且已在 MediaGrid / MediaDetailOverlay **两处按 mediaType 动态增删项**(壁纸项仅图片)——**这正是「按媒体类型换按钮」的现成逻辑,只是硬编码、未共享**。

- **现有可命令化操作全景**见 §附录 A(按视图分类清单)。

### 3.2 L1 · WindowChrome 自绘标题栏层
**新增组件** `src/components/layout/WindowChrome.vue`,承载「标题栏 = 工具栏容器」的物理层:
- **平台分叉(读 L0 平台工具)**:
  - **macOS**:`tauri.conf.json` 主窗口 `titleBarStyle:"Overlay"` + `hiddenTitle:true` + `trafficLightPosition:{x,y}`(y 对齐标题栏高度使红绿灯垂直居中),`decorations:true` 保持。**不自绘窗口三键**(用系统红绿灯);工具栏内容左侧用 CSS 变量 `--titlebar-controls-inset` 留 ~78px 避让红绿灯。
  - **Windows**:`decorations:false`,**自绘最小化/最大化-还原/关闭三键**(靠右),绑 `@tauri-apps/api/window` 的 `getCurrentWindow().minimize()/toggleMaximize()/close()`;`--titlebar-controls-inset` 右侧 = 三键宽度,供内容避让。
- **拖拽区**(🔴 **2026-07-14 真机推翻,现行方案见本条;下方原文作废存档**):
  - **现行 = `useWindowDrag` 阈值委托拖拽**(`6eccd08`+`361ad30`+`523cd0c`+`3cae44e`):**全局删除 `data-tauri-drag-region`**(WindowChrome / TitlebarBrand / AppToolbar 三处),改由 WindowChrome 根上单一委托监听 —— 按下后位移越阈值(`WINDOW_DRAG_THRESHOLD`,`361ad30` 解耦为独立常量并 5→3)才调 `startDragging()`,未越阈值松手则浏览器照常派发 click。**推翻理由**:`data-tauri-drag-region` 只作用于命中元素自身(不冒泡)→ 按钮不在拖拽面、整行大片区域拖不动;且 mousedown 即拖、无阈值 → 无法区分点击与拖动(真机「打滑」)。现行三路径:排除件/纯空隙面 `matches` 即时移窗 / 按钮距离 2px + 按住 300ms 降阈 / 卡片手柄零阈值。原生表单控件(行高滑块/搜索框/下拉)与窗口三键经 `data-no-window-drag` 两级排除选择器排除。权限 `core:window:allow-start-dragging`(§4.6 已列)。
  - **双击最大化 = 手动判定**(`3cae44e`,纯函数 `isDoubleClick`:上次空隙面按下时间 ≤500ms + 坐标 ≤4px,不依赖 `detail` / `dblclick` 事件)。**推翻理由**:阈值委托拖拽下首击即 `startDragging()` 会打断浏览器 click 计数 → DOM `dblclick` 不派发、`pointerdown.detail` 也到不了 2,**原「Tauri 内建 `e.detail===2`」判定形同虚设**。首击 `startDragging()` 无位移=空操作,不妨碍随后第二击判为双击(同 Tauri 语义),故无双 toggle。`onDblClick` 退化为只管惰性元素(品牌/标题)的双击最大化。

### 3.3 L2 · viewerStore(activeViewer 单一事实源)
**新增 store** `src/stores/viewerStore.ts`,补现状缺失的「当前打开资产」全局态,贯穿所有查看器:

```ts
// activeViewer:当前内容查看器的上下文;null=在主视图(网格)
interface ActiveViewer {
  kind: ViewerKind          // 'image' | 'video' | 'audio' | 'pdf' | 'epub' | 'text' | 'markdown'
  mediaType: MediaType      // 'image' | 'video' | 'audio' | 'document'
  fileFormat: string        // 'jpg' | 'mp4' | 'pdf' | 'epub' | 'txt' | ...
  id: number | null         // 库内资产 id;外部文件为 null
  path: string | null       // 外部文件路径(为 OS shell 集成预留;库内可空)
  title: string
  api: ViewerApi | null     // 查看器暴露的命令 API(见 §4.3)
  immersive: boolean        // 沉浸模式(隐藏 chrome)
}
```

- L4 ContextualToolbar 与 L3 命令 `when` 谓词的上下文均以此为准。

### 3.4 L3 · CommandRegistry(VSCode 贡献点范式)

```ts
interface Command {
  id: string                          // 稳定唯一 id,如 'viewer.image.zoomIn'(为自定义/插件持久化用)
  title: string | (() => string)      // 支持 i18n 惰性求值
```

### 3.6 L5 · useToolbarOverflow(响应式收纳)
> 🔴 **2026-07-09**: 本引擎为**同质按钮行**的逐项 Priority+ 溢出而设。Phase G 的演进见下(G3→G4→G5):
> - **~~G3: 视图控件整块折,未用本引擎~~**(已被 G5 取代): 曾用内容溢出检测(ResizeObserver + 纯核 `decideCompact` + `getBoundingClientRect`)把视图控件整块二值折/不折。因整块只需二值、且视图控件当时在 `.toolbar__right` 定宽右段无天然测量容器。
> - **~~G4: 筛选 chips 逐项折(接本引擎),但与视图控件分两套系统~~**(振荡, 被 G5 取代): G4 用 `useToolbarOverflow` 把 chips 折进「筛选 ⋯」。**引擎首次真正被消费**。但 chips(观 `.toolbar__filters` flex:1)与视图控件(`decideCompact` 观整行)是**两套独立系统抢同一块 flex 空间**——视图控件一折, flex:1 的 filters 长大, chips 可用宽跳变 → 真机振荡(已折 chips 弹回)。
> - **🟢 G5: 统一单测量(现行)**: chips + 视图控件并入一个 `flex:1` 容器 `.toolbar__foldable`, **一套** `useToolbarOverflow` 按优先序逐项折(视图控件整块作一个 `data-toolbar-item` 放末尾→最先折, chips 从尾折)。单容器 → 折叠某项不改容器自身 flex 宽度 → 可用宽随窗口单调 → **振荡从构造上消失**。`viewControlsFolded = hasOverflow`(VC 在末)、`filterChipsFolded = visibleCount < chipCount`。`decideCompact` 双系统随之删除(死代码)。见 §5 Phase G G5。
>
> **G4 顺带硬化引擎测量精度(唯一消费者, 低风险)**: 纯核 `computeOverflowSplit` 加可选 `gap` 参数(默认 0 向后兼容);composable 从 `getComputedStyle` 读 flex `columnGap` + 水平 `padding` 校正——`offsetWidth` 不含 gap/margin、`clientWidth` 含 padding, 不校正会低估总宽致末项被 `overflow:hidden` 裁半而非干净折叠。纯核由 6 测增至 8 测。
**新增 composable** `src/composables/useToolbarOverflow.ts`,Priority+ 模式:
- `ResizeObserver` 观察容器宽度;**缓存各按钮 `offsetWidth`**,仅在 observer 触发时更新,避免每帧读宽触发强制回流(layout thrash)。**缓存失效时机(2026-07-08 评审补)**:命令集变化、locale 切换、字号/字体变化时须重测量。
- 放不下的低优先命令按 `order` 从尾部移入 ⋯ 溢出;变宽时逐个放回。
- **右侧区(窗口三键 + 全局项)也纳入宽度预算**(绕开 Fluent CommandBar `farItems` 不参与溢出的已知缺陷)。
- 大列表状态用 `shallowRef` 承载命令数组(遵项目前端规范)。

- 🟢 **G7 折叠动画改 CSS Grid 收缩(2026-07-09 交付, 989586a; G6 max-width「闪一下」修正)**: 真机反馈 G6 收拢「太快像闪一下」。根因=`max-width` 从上限(260)降到内容实宽(~90)那段**不可见空转**, 只末段可见故短促。改用 **CSS Grid 折叠格**: 每项包 `.fold-item`(`grid-template-columns:1fr`)+ `.fold-item__inner`(`overflow:hidden`), 折叠 `1fr→0fr` 动画**真实宽度全程**(无空转)+ opacity 淡出 + inner `translateX(10px)` 横向「收入」感, 时长 0.28s。测量对象从控件本体移到 `.fold-item` 包裹层(`data-toolbar-item`)。菜单变体 folded 恒 false → grid 1fr 全宽行 + v-show 显隐。
- 🟢 **G8 视图控件拆为独立折叠项(2026-07-09 交付, bd20c7b)**: 真机反馈「视图控件(行高+分组排序)整块折, 预期独立依次折」。改法: `GalleryViewControls` 拆成 **3 个独立折叠项**——行高(offset0)/布局(offset1)/分组排序(offset2), 各自 `data-toolbar-item`, 由统一 `useToolbarOverflow` 依次折(`globalIndex = baseIndex + offset`, `baseIndex=chipCount`→视图控件排 chips 之后最先折; 从尾折: 分组排序→布局→行高→chips)。组件改**多根 `fold-item` 片段**(去 `.toolbar__view-controls` 单根 + `view-as-menu`), props 加 `visibleCount/measuring/baseIndex` + `inDom/folded` 助手(同 GalleryFilterChips 模式); 只传 props 不透传(承 G6 崩溃纪律)。AppToolbar 去 `.vc-cell` 包裹直接渲染组件, 「视图 ⋯」弹层改 flex column。`viewControlsFolded=hasOverflow` / `filterChipsFolded=visibleCount<chipCount` 不变(视图控件仍在末)。门禁四件套全绿(仅本地)typecheck/eslint/vitest/build。
- 🟢 **G9 两弹层展开布局打磨(2026-07-09 交付, 多提交; 真机验收通过)**: G4/G5 的「筛选 ⋯」「视图 ⋯」弹层初版仅竖排堆叠(短按钮独占整行、宽控件错排、单按钮项孤零), 观感差。分两块打磨, 均由**父弹层 `:deep()` 覆盖子组件 `.fold-item`** 实现「菜单侧异形陈列、内联侧零影响」(同一份双渲染 DOM 两处不同呈现, 组件本体近零改动):

**全局/通用**:收藏切换、评分(1-5/清零)、颜色标签(7 档)、软删除、移动、复制、加入收藏夹、全选/反选、在资源管理器显示、复制图像到剪贴板、外部程序打开。(**缺**:媒体项重命名、复制路径文本、导出/分享、自由文本标签——按需新增。)

**网格视图**:行高滑块(60-960)、布局模式(grid/justified)、分组(日期/文件夹/无)、组内排序(时间/文件名/相似度)、升降序、筛选 chips(图片/视频/Live/收藏/评分/颜色/日期范围)、清除筛选、三模式搜索(普通/语义/混合)+ 范围、撤销/重做、全屏、时间线跳转。

**看图台(image/video)**:关闭、缩小/放大/百分比、缩放模式循环(auto/1:1/fit-width/fit-height)、滚轮缩放/翻页、拖拽平移、上/下张、序号、Live 播放、人脸框显隐、收藏、在资源管理器显示、信息/EXIF 面板、评分、颜色标签、右键(复制图像/移动/复制/壁纸)。(**缺**:旋转、删除、幻灯片——旋转本期新增,余按需。)

**阅读器(pdf/epub/txt/md)**:上/下页、TOC + 跳转、书内搜索(流式逐章)、书签 CRUD、排版设置(字号/行距/字体族/栏宽/字重/字距/对齐/章题缩放/段距)、阅读流(翻页↔滚动)、epub 排版模式(自带↔智能)、阅读主题(日夜双槽+每书)、简繁转换(每书档)、翻页动画(none/slide/curl)、沉浸模式、自动翻页(调速)、竖排(off/rl/lr)、编码覆盖+重排(txt)、进度自动存恢复、PDF 翻页模式(scroll/wheel-snap/keyboard)、页码、文本编辑+版本+校对+替换、外部打开、返回。

**音频**:播放/暂停、快退/快进 10s、seek、音量、封面、元数据面板、同步歌词跳转、外部打开、返回。

**视频**:原生 `<video controls>`(播放/暂停/进度/音量)+ 缩放/拖拽/上下张(复用看图台);关键帧 scrubbing 预览。(**缺**:独立视频播放器——按需)。
