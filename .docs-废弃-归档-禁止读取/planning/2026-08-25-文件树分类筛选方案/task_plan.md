## 关键决策
| 决策 | 理由 | 候选 ID |
|------|------|---------|
| 四类媒体类型以 `filterStore.mediaTypes` 为共同真值，树端只保留 `other`/“仅目录”扩展 | 共同入口必须同时影响图库与注册库文件树；生命周期、URL、`other` 仍保持边界 | D-001 |
| registeredOnly 按匹配后代裁剪目录，allFiles* 保留惰性目录骨架 | DB 可递归聚合且有稳定实体；磁盘模式若预扫会破坏懒加载与大目录性能 | D-002 |
| FS 分类必须在后端分页前完成 | 前端过滤已分页结果会产生空页、漏项及错误 cursor/total | D-003 |
| `other` 是文件分类器无法识别的文件，不加入领域 `MediaType` | 未知文件通常不入库；扩展图库领域类型会污染 SQL、URL 与选择协议 | D-004 |
| 树端五类默认全选，清空表示只保留目录；五类全选省略后端过滤 | 文件树是可见性设置，显式勾选比“空集合=不限”更清楚，也支持文件夹导航场景 | D-005 |
| 四类媒体类型由 `filterStore.mediaTypes` 作为共同真值源，树端只保留 `other`/“仅目录”扩展 | 选择任一入口都必须同时影响图库与树；现有两套空值语义不能直接合并 | D-006 |
| `other` 不回写图库；只作为明确标注的文件树专用项 | 未收录文件不在图库实体/URL/SQL 中，强行并入会制造虚假的全局结果集 | D-007 |
| 目录裁剪只隐藏确定无匹配后代的目录，保留祖先链并保持原排序 | 既满足结果聚焦，又不破坏深层导航、稳定排序和惰性树模型 | D-008 |
