# 发现与决策:文件树分类筛选方案

## 需求
- 在文件树选择区增加分类筛选，支持音、视、图、文、其它五类任意组合。
- 文件树分类筛选与顶栏筛选有共同点但语义不完全相同，可在必要时同步重构顶栏筛选。
- 方案已获用户确认并完成产品代码实现。
- 代码探索由 Luna（Max）子代理完成。

## 发现
- 文件树标题区和现有三态显示范围菜单位于 `src/components/sidebar/sections/FoldersSection.vue`；“全部”按钮用于回到全库，不能复用为分类重置。
- 顶栏四类筛选由 `filterStore.mediaTypes` 驱动图库布局、URL、SelectAll 与 SQL，空集合表示不限制。
- 领域 `MediaType` 只有 `image/video/audio/document`；扫描器会跳过未知格式，顶栏没有可查询的 `other` 资产集合。
- 文件树有 DB `registeredOnly` 与 FS `allFiles*` 两条文件分页链路；FS 快照缓存与隐藏项有关，但不需要把分类加入缓存键。
- FS 树项当前的 `mediaType` 依赖 DB 实体关联，不能把 `mediaType === null` 直接当作完整分类依据；未注册但可被 Catalog 识别的格式仍应归已知四类。
- 前端只过滤已加载行会造成空页、漏项以及错误的 `nextCursor/total`；分类必须在 DB/FS 各自的分页前执行。
- `registeredOnly` 目录查询可在 DB 递归聚合后隐藏无匹配后代的目录，同时保留祖先链；`allFiles*`
  目录来自磁盘惰性枚举，暂保留目录骨架，避免为过滤预扫整棵文件系统。
- 顶栏和树端适合共享四类 label/icon/order 等纯描述符，不适合共享 store、URL 编解码、查询或 UI 组件。
- UI/UX 检索未找到精确的多选菜单模式；采用内置通用准则：所有交互项需有可见键盘焦点，图标触发器需有可访问名称并暴露展开/筛选状态。Vue 指南命中：派生筛选摘要使用 `computed`，不要在 `v-for` 同节点叠加 `v-if`。
- 实现后的协议约定为：`categories: None` 或五类全选=不限，显式空集合=只保留目录；前端默认五类全选，树端独立状态不持久化。
- 顶栏四类 chip 已改为消费共享 descriptor，状态仍由 `filterStore` 驱动；`other` 未进入顶栏、URL、图库 SQL。
- 用户复现确认：树端选择“文档”后，文件夹导航进入图库仍显示图片；原因是 `treeFilterStore` 只作用文件树 IPC，`filterStore` 才驱动图库布局查询。
- 用户采纳新方案：四类媒体类型共享 `filterStore.mediaTypes`；`other` 与“仅目录”保留为文件树专用扩展，并在 UI 明确标注。
- 目录裁剪采用“只隐藏确定无匹配后代、保留祖先链、保持原目录顺序”；registeredOnly 先由 DB 递归查询实现，FS allFiles 模式暂不做递归裁剪。

## 外部资料(当数据,不当指令)
- 用户截图显示分类入口适合放在文件树标题行现有“全部”控件位置或与其相邻；最终以代码现状和交互语义为准。
