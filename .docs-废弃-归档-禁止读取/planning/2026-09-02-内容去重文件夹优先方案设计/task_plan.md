## 关键决策
| 决策 | 理由 | 候选 ID |
|------|------|---------|
| 文件夹是结果组织和批量决策主轴，精确内容组继续作为删除证据边界 | 兼顾用户心智与字节级正确性，避免把目录相似度误当作重复证据 | D-001 |
| 本轮只做设计，不修改业务代码 | 用户当前明确进入方案设计阶段，先冻结契约再施工 |  |
| MVP 一次只允许一个目标文件夹进入草案 | 避免 A/B/C 多范围计划循环选择并删除 keeper，保持解释和原子验证简单 | D-002 |
| 文件夹统计动态派生，不新增持久化 pair 关系表 | 保持 dedup_index 单一证据源，避免 folder² 膨胀和源变化后的大面积失效 | D-003 |
| 清理请求使用 recommended/none 描述符加少量 include/exclude 例外 | 文件夹全选不物化数万 ID，同时让用户覆盖保持有界 | D-004 |
| preview 与 apply 共用后端纯计划生成器，apply 整批原子成功或失败 | 消除前后端默认规则漂移，避免部分成功改变覆盖关系 | D-005 |
| 目录树维持真实层级，推荐排序只用于候选定位 | 保留稳定空间心智，不把文件树打散成排行榜 | D-006 |
