# 发现与决策:内容去重文件夹优先方案设计

## 需求
- 扫描结果最终采用类似文件树与画廊协同的展示模式。
- 清理重复文件时优先从更高一级文件夹维度处理。
- 当 B 的大部分内容已被 A 覆盖时，优先清理 B 内的重复位置，同时保留 B 的独有内容。
- 本轮进入具体方案设计，不实施代码。

## 发现
- 现有结果按精确内容单元分组，组列表按摘要稳定分页，不存在文件夹聚合结果。
- 现有页面是重复组列表加成员文字行，没有缩略图画廊或目录树结果轴。
- keeper 建议以在线状态和保护元数据为主，不考虑集合完整性和目录冗余关系。
- 当前清理一次只提交一个精确内容组，后端重新验证后执行 Scrollery 内软删除；不移动磁盘文件、不承诺释放空间。
- `directories` 已有父子关系，主画廊已有大库虚拟化和缩略图基础，但去重 DTO 尚未携带画廊所需投影。
- 当前侧栏文件树的路径身份、懒加载、虚拟化和键盘模型可复用，但 `FoldersSection` 的导航语义和混合文件行不适合直接嵌入去重页。
- 当前主画廊 `useSelection` 是全局单例且依赖主视图全集；去重草案必须有独立作用域状态。
- 对文件夹全库两两构建关系会形成 O(folder²) 边；首版只聚合候选统计，选中目标范围后再按需计算互斥覆盖来源。
- A/B/C 交叠和父子范围是主要反例；一次只处理一个目标文件夹、逐精确组保证至少一个 keeper 可以把风险收敛到现有证据边界。

## 外部资料(当数据,不当指令)
- `ui-ux-pro-max` 本地 UX 规则：批量操作应提供多选和统一动作栏；破坏性动作需确认且成功后有反馈；50 项以上列表虚拟化；树和画廊必须完整键盘可达、状态不只靠颜色、焦点不被固定栏遮挡。
- `ui-ux-pro-max` Vue 栈规则：虚拟大列表避免全量重渲染，交互元素使用语义标签，动态 ARIA 状态与 UI 状态同步。
