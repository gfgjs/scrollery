## 关键决策
| 决策 | 理由 | 候选 ID |
|------|------|---------|
| 去重能力进入主画廊“重复项”筛选，不再以独立页作为核心体验 | 用户已确认，统一浏览上下文并减少割裂 | D-001 |
| 提供“按重复组”和“按文件夹上下文”两种排列 | 分别支持成员比较与目录整理两种任务 | D-002 |
| 文件夹模式中，共享同一重复组的文件夹彼此相邻，且文件夹内重复项优先、独有项随后 | 用户已明确其空间组织语义 | D-003 |
| 每个重复组展示全部成员 | 用户已明确，不预先隐去所谓原件或保留项 | D-004 |
| 不把复用现有扫描结果或扫描代码视为产品约束 | 用户明确实现可按分析结果决定 | D-005 |
| 将“重复项”建模为主画廊的临时浏览镜头，而非普通布尔筛选或持久化 `groupBy` | 两种排列会同时改变集合、分组、排序和导航语义；离开镜头后应恢复原画廊偏好 | D-006 |
| “按重复组”作为首次进入的默认排列 | 它最直接证明成员确为同一内容，也天然满足全成员展示 | D-007 |
| ~~新视图必须复用主画廊的后端布局与 `ViewDescriptor/flat_ids` 契约，并向前端提供全集~~（2026-09-04 部分推翻） | 镜头保持 browse-only；后端仍以 flat_ids 为顺序事实源，查看器按版本逐项取邻居，不再向前端复制全集 | D-008 |
| 初版只解决浏览与理解，不把 keeper、删除建议和清理草案混入主流程 | 缩小 MVP 状态空间，避免把旧独立页的复杂度迁入主画廊 | D-009 |
| 文件夹邻接以重复组关系图的传递连通簇为正确性定义，簇内使用确定性关系优先遍历 | 交叉重复组不存在可满足全部两两相邻的线性顺序 | D-010 |
| 大体量独有项默认折叠，由文件夹模式顶栏统一开关展开 | 保持相关文件夹在空间上接近，也避免首屏物化大量独有项 | D-011 |
| MVP 暂停普通成员级筛选并固定全库可见媒体范围 | 直接筛成员会破坏“每组全部成员”，组级谓词留待后续 | D-012 |
| `duplicateLens` 独立于普通 filter/group 偏好，但必须进入 `ViewDescriptor` 与布局缓存键 | 兼顾退出恢复和全选/导出集合一致性 | D-013 |
| 旧 `/duplicates` 在新镜头验收后重定向，旧工作区代码分阶段退场 | 保留过渡可用性和旧深链，不同时维护两套目标体验 | D-014 |
| 废弃本方案全部读屏/无障碍设计与验收要求 | 2026-09-04 用户明确裁定，后续不建设 Canvas 读屏语义层 | D-015 |
