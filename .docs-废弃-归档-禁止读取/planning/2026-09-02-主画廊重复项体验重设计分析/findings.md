# 发现与决策:主画廊重复项体验重设计分析

## 需求
- 主画廊新增“重复项”筛选，替代问题较多的“重复内容”独立页作为核心入口。
- 排列一按重复组连续展示，如 `A1 A2 A3 | B1 B2`。
- 排列二按文件夹上下文展示；共享同一重复组的文件夹相邻；文件夹内重复项在前、独有项在后。
- 每个重复组展示全部成员。
- 是否复用现有扫描结果或扫描实现不是产品要求，由后续技术分析决定。
- 当前阶段先分析，不直接改代码。

## 发现
- 主画廊不是“取一批媒体后在前端再筛选”的结构，而是由筛选/视图状态驱动后端生成完整布局，再交给 DOM/Canvas 双渲染和虚拟滚动。重复视图必须进入该完整布局契约；若只过滤当前可见行，`totalRows`、滚动高度、全选、范围选择和导出都会失真。
- 当前主画廊只支持 `date | folder | none` 分组，且 Rust 布局几何对未知分组会落入日期分支。两种新排列不能只追加一个字符串枚举，必须有明确的集合、排序、分隔符和轴语义。
- 当前 `ViewDescriptor` 与后端 `view_to_sql` 决定 Ctrl+A、批处理和导出的真实集合。重复镜头未进入 descriptor 之前，不应开放这些全量操作。
- 现有精确去重证据链可复用：`dedup_index` 按 `(unit_digest, unit_size)` 动态成组，并校验 `ready`、当前 `hash_version`、`source_revision`、活跃根目录及媒体可见性。普通 `content_hash` 不是精确重复身份。
- 当前独立 `DuplicatesView` 同时承担文件夹树、范围摘要、独立画廊、比较抽屉和清理草案；其选择、分页和虚拟化与主画廊是第二套实现。它适合保留作未来清理工作台的参考，不适合作为新浏览体验的基础。
- 当前文件夹查询按真实树/名称和 `item_id` 分页，并没有实现“共享重复组的文件夹相邻”或“重复在前、独有在后”。在前端对已分页结果重排会破坏 keyset 分页和滚动稳定性，因此必须由后端给出稳定复合顺序。
- “共享重复组的文件夹相邻”本质上是文件夹关系图：文件夹是节点，重复组是连接多个文件夹的超边。多个组交叉时无法保证每一对共享文件夹都紧挨，最稳定可解释的定义是把传递相连的文件夹组成连续簇，再在簇内给出确定顺序。
- 文件夹模式的集合是“所有包含精确重复项的直接文件夹内的全部项目”；文件夹内按“重复、尚未确认、独有”分段。只有分析完成且当前证据未发现重复的项目才能称为独有，pending/error/offline/missing/stale 都属于尚未确认。
- 大文件夹中的大量独有项会把下一个关联文件夹推得很远，削弱“相关文件夹靠在一起”的体验。建议独有段默认折叠或渐进加载，但是否折叠需要产品裁决。
- 其他媒体筛选若直接作用于成员，可能把重复组的一部分隐藏，违反“每组展示全部成员”。建议 MVP 暂停不兼容的成员级筛选；若需要组合，应采用“任一成员匹配则展示整组”的组级谓词。
- 重复分析会分批更新索引，但现有主画廊的 `data_version` 不随分析完成变化。新镜头需要一个已提交的去重结果版本或完成事件，避免刷新到半组结果并确保布局缓存失效。
- 主画廊现有的 DOM/Canvas、虚拟滚动、缩略图、查看器和选择基础设施可以复用；需扩展的是数据源、有效分组、分隔符、滚动轴、视图键和失效键，而不是再造一套画廊。
- 初版应区分“尚未分析、分析中/旧结果更新中、分析完成无重复、附加筛选无匹配、证据陈旧/来源变化”五类状态，不能统一显示“暂无重复”。
- 用户已确认：文件夹关系使用传递连通簇，大体量独有项默认折叠，MVP 暂停会隐藏单个成员的普通筛选。
- 具体方案采用全库镜头与返回快照；普通筛选值保留但暂停，退出后恢复。镜头模式写入 URL，普通 `uiStore.groupBy` 不被修改。
- 文件夹模式使用直接目录，祖先路径只展示不重复成块；纯独有/纯未知目录不进入结果，确保每个文件夹块都由至少一个当前有效重复成员触发。
- 独有项折叠采用文件夹模式的全局开关。关闭时 unique 项不进入 `flat_ids`，但每个文件夹头仍显示独有数量，避免 Canvas 中引入大量逐段交互行。
- 新布局只需在逐项常驻数据增加 bucket 与短 ordinal，在 separator 增加 kind、关联簇和分类计数；完整路径继续按 viewport hydrate，避免长 group key/路径在百万项中重复驻留。
