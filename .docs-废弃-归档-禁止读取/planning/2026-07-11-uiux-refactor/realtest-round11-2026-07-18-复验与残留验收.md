## 2. §7 视图路由化 + URL 同步〔🆕 首验，DevTools Console 版〕

> round10 §7 原文通篇写「地址栏变 X」——但 Tauri WebView **没有地址栏**，此前无法测。round10 已改用
> DevTools Console 验证法，零代码改动，完整原文见
> [realtest-round10 §7](realtest-round10-2026-07-15-合并验收.md#7-视图路由化-url-同步round8)。
> 本轮把方法与全部断言点收进来，便于连续走完不用来回切文件。

**方法**：F12 打开 DevTools → Console。「地址栏应为 X」→ 敲 `location.hash` 回车看返回值；
「地址改成 Y 回车」→ 敲 `location.hash = 'Y'`；「刷新」→ `location.reload()`。

### 2.1 视图路由化

- [ ] **smart-album 各占独立路径**：侧栏点「收藏/实况/最近/回收站/全部照片」→ `location.hash` 分别读出
      `#/favorites` `#/live-photos` `#/recent` `#/trash` `#/`；画廊内容随之切换。
- [ ] **深链恢复 smart-album**：`location.hash = '#/favorites'` → 进入收藏视图，侧栏高亮收藏。其余三个同理。
- [ ] **folder 筛选态（模式 B）→ `/folder/:id`**：分组设为「日期」或「无」→ 侧栏点某文件夹 → hash 变
      `#/folder/<数字id>`，画廊筛成仅该目录；`location.reload()` 后仍在该目录。
- [ ] **folder 滚动锚点态（模式 A）不进 URL**：分组设为「文件夹」→ 侧栏点不同文件夹 → hash **保持 `#/`**，
      画廊平滑滚动到该文件夹段（有意如此——滚动位置不该进 history）。
- [ ] 🔴 **新增扫描根/移动文件夹后自动选中**：新增扫描根，或移动文件夹后自动选中该目录 → hash 应变
      `#/folder/<id>`（而非停在 `#/` 被回填成「全部」而丢选中）。**这是修的 clobber 点，重点验**。
- [ ] **前进/后退**：全部→收藏→某文件夹 间点几次，浏览器后退 → 能逐步回上一个视图，视图与 hash 一致。
- [ ] **KeepAlive/滚动不回归**：全部照片滚到中间 → 切收藏 → 切回全部 → 滚动位置恢复、不重新加载闪白。
- [ ] **切视图清选区、同视图内改筛选/排序不清**：切视图选区清空；同一视图内改筛选/排序不应清选区。

### 2.2 view-pref（分组/排序/方向/布局）URL 同步

- [ ] **改 view-pref 即写 URL**：工具栏改「分组=文件夹/排序=文件名/方向 asc/布局=宫格」→ hash 出现
      `?group=folder&sort=filename&order=asc&layout=grid`（仅非默认值出现）。
- [ ] **深链恢复**：`location.hash = '#/?group=folder&sort=filename&layout=grid'` → 画廊按该分组/排序/布局呈现。
- [ ] 🔴 **URL 覆盖 persist**：设置里把默认分组设为「日期」（持久化）→ 用带 `?group=none` 的 hash 深链进入
      → 画廊显示「无分组」；去掉 hash 的 group 键刷新 → 回落持久的「日期」。
- [ ] **order 跨刷新恢复**：切排序方向 → hash 出现/移除 `order=asc` → `location.reload()` 后方向保持
      （sortOrder 无持久化，只有 URL 能跨刷新恢复它）。
- [ ] 🔴 **语义搜索不污染 view-pref URL**：进语义搜索 → groupBy 被临时改「无分组」，但 hash **不应出现
      `group=none`**；退出语义搜索 → 分组复位、hash 恢复真实值；开→关→刷新，分组应回到语义前的值，
      不卡在「无分组」。

### 2.3 search（查询/范围/模式）URL 同步 ⚠ 高风险

- [ ] **提交搜索即写 URL**：普通/文件名搜索提交 → hash 出现 `?q=<词>`（及非默认 `scope=`/`mode=`）；
      清空搜索 → 相关键从 hash 移除。
- [ ] **深链恢复普通搜索**：`#/?q=IMG&mode=normal` 刷新/深链 → 恢复为文件名搜索「IMG」，结果正确。
- [ ] 🔴 **深链恢复语义搜索（触发 IPC）**：`#/?q=猫&mode=semantic` 深链/刷新 → **真实执行语义搜索**
      （不是只改地址不查询），画廊出语义结果。重点：AI worker 未就绪时不崩、有 loading、最终出结果或
      明确错误（不静默失败）。
- [ ] **scope 恢复**：文件名搜索把范围切到「目录/日期/设备/地理位置/全局」→ hash 出现 `scope=folder` 等
      → 刷新恢复。
- [ ] **mode 恢复副作用正确**：`#/?q=x&mode=semantic` 深链进入 → 退出语义 → 分组复位到深链时 hash 里的值
      （或持久默认），不卡在「无分组」。
- [ ] **恢复顺序**：`?group=folder&q=y&mode=normal` 复合 hash → 恢复后既是文件名搜索「y」又按文件夹分组，
      两者共存不互相冲掉。

### 2.4 组合 / 回归

- [ ] **三者共存**：`?favorite=1&group=folder&q=z&mode=normal` → 收藏筛选 + 文件夹分组 + 文件名搜索「z」
      全部生效，刷新后全部恢复，互不冲掉。
- [ ] **URL 干净性**：回到默认（无筛选/默认分组排序布局/无搜索）→ hash 应为干净的 `#/`（或 `#/favorites`
      等纯路径），无残留空 query 键。
- [ ] **collection/person 详情不受影响**：进 `#/collections/:id`、`#/persons/:id` → view-pref/search 仍可用；
      语义搜索面板只在主库血统视图显示。
- [ ] 🔴 **无控制台报错/无死循环**：全程 Console 无 vue-router 重复导航告警、无 hash 抖动（反复 replace）、
      无 Duplicate keys。

## 4. F11 线两项遗留〔🆕 首验，`038656f` / `99dce7d`〕

### 4.1 分离模式工具栏常驻〔`038656f`〕

> 前置：设置里把标题栏模式切到「分离」（`useTitlebarMode`，与合并/分离一键切换同一开关）。
> 已知代价（用户已接受）：**分离模式下 F11 不再是纯沉浸画廊**——这条独立 bar 会一直留着，
> 只有默认的「合并」模式才是无顶栏的纯沉浸。

- [ ] **F11 沉浸态不隐藏**：分离模式下按 F11 进沉浸画廊 → 独立的工具栏/chips 条应**保持常驻**，
      不随其它 chrome 一起隐藏。
- [ ] **跨路由不消失**：分离模式下从画廊切到设置页/查看器/其它路由 → 这条 bar 应**始终存在**，
      不会在切路由时消失又重新出现。
- [ ] **非画廊页显示标题**：分离模式下停在设置页等非画廊路由 → 这条 bar 应显示当前路由标题
      （`route.meta.title`），不是空条。
- [ ] **合并模式仍是纯沉浸**：把标题栏模式切回「合并」→ F11 进沉浸态应**无顶栏**，与分离模式行为不同，
      两态切换互不干扰。
- [ ] **查看器路由不给槽**：查看器内不应出现这条独立 bar（按设计，查看器有自己的控制条）。

### 4.2 收藏夹软删读路径〔`99dce7d`，需重启一次〕

> 前置：合集页删除一个**用户自建**收藏夹（先放几张图进去，走正常删除确认流程，非本轮新增功能，
> 走的是已验收过的软删除路径）。

- [ ] **不点撤销，等 toast 消失**，让这个夹保持软删状态。
- [ ] **关闭 App → 重新打开**。
- [ ] 合集页应出现**「已删除 (N)」**区域，列出这个软删的收藏夹（此前的缺口：删除即永久滞留在 DB，
      无 UI 可捞回）。
- [ ] 点击该夹的恢复入口 → 收藏夹**重新出现**在正常列表，且**成员照片仍在**（走既有 `restore_collection`）。
- [ ] **系统夹**（图片/视频/音频/文档收藏）不出现在「已删除」区，不受影响。
- [ ] 若当前没有任何软删收藏夹 →「已删除」区**不应出现**（仅在有软删夹时显示）。
