# 决策:官网维持纯静态 h5,不上后端(2026-07-17)

> 出自官网 v2 重设计任务(worklog:[2026-07-17-官网重设计](../worklogs/2026-07-17-官网重设计/task_plan.md));scrollery-site 仓已按此落地(`b97ad36`)。

## 决定

1. **技术栈 = 纯静态 h5**(HTML + 原生 CSS/JS),不引入 Vue/框架,零依赖零构建零跟踪(延续站仓 v1 约章)。
2. **不上后端**;将来如需动态能力,按「静态 → CF Pages Functions(同仓、按需)→ 独立 Workers 服务(商业化时)」渐进,官网仓始终保持零构建。

## 理由

- 官网职责=展示 + mailto 获客 + 未来静态分发(GitHub Releases/CDN),全部静态可承载;Cloudflare Pages 已有 push 即部署链路,零运维、零攻击面。
- 内容型站点 SEO 优先:Vue SPA 需 SSR/预渲染才有等效 SEO,纯增构建与维护复杂度,无交互状态收益。
- 零跟踪约章(站仓 README)排除统计/分析类后端;联系走 contact@scrollery.app(只收不发)。
- 逐项检视过的潜在后端需求及其无后端解:表单→mailto(将来 CF Pages Functions);下载计数→不做(或客户端读 GitHub API);newsletter→不做;许可证签发/更新检查→属产品基础设施(Part8),不属官网;社区→GitHub Issues。

## 重评触发条件

- 内测申请量大到邮件流程不堪 → 上 CF Pages Functions 表单(仍同仓)。
- Part8 商业化落地需要定价页/支付跳转 → 支付与许可证仍走产品侧服务,官网只放静态链接。
- 需要服务端渲染的多语言 SEO(独立 URL 而非整页双语切换)→ 届时重评估静态生成器,仍不引入运行时后端。
