# 决策:保留查看器路由，以常驻画廊覆盖层呈现

> 出自 [Canvas缩略图渲染重做](../worklogs/2026-08-18-Canvas缩略图渲染重做/task_plan.md) 的真实 Windows WebView2 验收。

## 决定

1. `/view/:id` 继续是图/视频查看器唯一的 URL、历史与深链事实源。
2. 进入该路由时，`MediaGrid` 不再因 `RouterView` 切换被失活或移入 KeepAlive 缓存容器；同一画廊 DOM 持续作为底层帧。
3. `ContentViewer` 在画廊内容区以绝对覆盖层呈现。关闭查看器时立即撤掉覆盖层，不等待画廊首帧、不使用 Vue route Transition，也不引入交接计时器。
4. 查看器存续期只暂停底层画廊的键盘、ResizeObserver 与性能采样，并冻结既有几何；返回后立即恢复原节点与交互。侧栏按钮保持在覆盖层之上。

## 理由

- 用户实测表明“等待画廊最终首帧再让查看器离场”虽可遮住交接空档，却造成明显迟滞，不能接受以等待换稳定。
- 路由替换画廊 DOM 才是 Canvas backing store、测量和首帧重新激活的共同空档；保留 DOM 可消除该空档，同时不放弃 URL、后退栈和深链能力。
- 该方案没有恢复旧补丁中 gallery-ready、路由水合或查看器关闭的混合状态机；Canvas 生命周期和路由呈现保持可独立验证。

## 重评触发条件

- 若 direct deep link 到 `/view/:id` 的首开性能被实测证明受常驻底层画廊影响，需要单独测量并优化初始加载，不得通过关闭延迟掩盖。
- 若未来查看器需要跨内容区或系统级全屏呈现，再评估覆盖层宿主位置；仍须保留路由地址语义与无等待关闭原则。
