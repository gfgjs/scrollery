# 决策:视频播放器自研 UI + 快捷键契约变更(2026-07-22)

> 出自视频播放器重构任务(worklog:[2026-07-23-视频播放器重构](../worklogs/2026-07-23-视频播放器重构/task_plan.md))。

## 决定

1. **UI 层自研 headless Vue 播放器**,不引入 Vidstack/Plyr/media-chrome/Video.js 等第三方播放器 UI 库。
2. **视频上下文快捷键契约变更**:`←`/`→` 由「切上下条目」改为「seek ±5s」;切条目改绑 `Shift+←`/`Shift+→`。`kind === 'image'` 的 `←`/`→` 切条目行为不变(命令注册表 `when` 谓词按 kind 分域,零双绑)。

## 理由

- 自研:调研时点 Vidstack/Plyr/media-chrome 均已官宣合并进 Video.js v10、1.x 维护降速,第三方生态存在时点风险;项目已有六主题 CSS token 体系与 Vue 3 SFC 规范,自研零皮肤冲突且定制自由度更高;七组件+八 composables 施工量在轻档范围内可控。
- 快捷键:seek 使用频次远高于切条目,YouTube/VLC/mpv 等主流播放器均是裸方向键 seek 的肌肉记忆;视频上下文切条目仍保留 Shift+←→/滚轮/顶栏三条路径,未失能力。

## 重评触发条件

- 若真机走查发现用户对 ←/→ 语义变更强烈不适应(高频误触),可重新评估是否需要设置项切换新旧行为,而非直接回退。
- 若二期引入 remux/libmpv(见 status/视频播放器重构.md 二期候选)、需要更复杂的字幕渲染(ass/ssa)或弹幕等重度定制能力,届时重新评估是否仍应自研而非采用 media-chrome 等纯 headless 原语层(不含解码后端,兼容性更好)。
