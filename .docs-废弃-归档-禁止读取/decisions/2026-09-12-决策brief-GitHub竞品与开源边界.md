**Lap 的两个硬缺口**(经源码核实,非猜测):
1. **人脸模型许可不可商用**——InsightFace README 原文:代码 MIT 无限制,但「**The training data containing the annotation (and the models trained with these data) are available for non-commercial research purposes only**」,手动下载与自动下载同受此限([来源](https://github.com/deepinsight/insightface))。Lap 作为免费 GPL 项目尚可辩解;任何想**收钱或商用**的 fork/衍生都踩雷。本产品默认轨刻意选 YuNet+SFace(`src-tauri/src/db/schema/early.rs:435` 注释「商用友好(YuNet MIT + SFace Apache-2.0)」),并把 SCRFD/ArcFace 隔离为需 `verified` 的独立非商用轨(`face_commands.rs:602`)。
2. **中文语义搜索无出货模型支撑**——`scripts/download_models.sh` 只拉 `openai/clip-vit-base-patch32` 的 ONNX 文本/视觉编码器,无中文或多语 CLIP。README 的「50+ languages」在当前模型清单下**无法兑现为原生中文能力**。

## 3. 竞争力分析

### 3.1 真实优势(有代码 / 许可证据)

1. **商用安全的人脸栈**:见 §2.5。这是**结构性**差异——竞品不是「配置没调好」,而是要改就得向 InsightFace 买商业授权或换模型重训。
2. **中文原生语义搜索**:Immich 需自行替换模型(社区实践),Lap 出货英文 CLIP,PhotoPrism/LibrePhotos/Photoview/Lychee 无语义搜索。Chinese-CLIP 是少数**竞品无法靠改配置追平**的默认体验。
3. **可收费的冷门格式插件平台**:Ed25519 签名 registry + sidecar worker 隔离 + 激活/卸载闭环(PSD 已跑通)在开源阵营**没有等价物**;这是「能卖」的地基,也是供给独占性最强的一块。

### 3.2 被高估的优势(纸面成立,证据不支持)

| 宣称 | 现实 |
|---|---|
| 全离线隐私第一 | 桌面同类(Lap/digiKam/TagSpaces/nomacs)全都离线。**只对云/服务端竞品成立**,在桌面阵营不是卖点。 |
| 本地 AI 语义 + 人脸 | **已是入场券**:Immich/PhotoPrism/digiKam/Damselfly/Lap/photofield 均有。差别在中文与商用许可,不在「有没有」。 |
| 文件夹树零破坏磁盘 | Lap 明确 "No library lock-in … work directly with your existing folders";Damselfly 自称致敬 Picasa。真差异只剩「零写回 + 策展成果可导出」的执行完整度。 |
| 百万级无卡顿 | **无公开可验证证据**(未发布、无 benchmark)。Lap 已宣称 100k+。这是 must-deliver 门槛,不是差异化卖点。 |
| 买断无订阅 | 桌面阵营普遍买断或免费;只对 Mylio/Lightroom/PhotoPrism 会员/Ente 订阅成立。 |
| 付费插件生态 | AI/人脸/exotic 三付费插件中,**AI 与人脸当前没有任何 entitlement 门**(grep 无 `ai_not_entitled`/`face_not_entitled`),且功能已实现并随开源码公开——「付费插件」目前是规划而非资产。 |

### 3.3 结构性劣势

1. **未发布、社区为零**:公开镜像 `gfgjs/scrollery` 1★、0 fork、**最后 push 2026-07-06**(停滞约 2 个月、GitHub 许可字段仍显示 Apache-2.0,未随 08-25 MPL 迁移更新)。「开源换采纳」目前没有任何实证。
2. **单人 vs 有资助的团队**:对手 Immich 有 FUTO 资助的近 10 人全职;Lap 虽同为单人但**已发布并领先一个版本周期**。
3. **范围过宽**:265 个 IPC 命令、阅读器/文档校对/音频播放器并存。2026-07-13 新立项 Review 已判「购买动机不叠加、一句话定位变糊」,该结论**本次调研未发现任何推翻证据**。
4. **发布工程未完成**:`release.yml` 只构建免费版(无签名、无 updater、无 `.sig`);无付费构建管线;`src-tauri/gen` 只有 `schemas`,**无 Android/iOS 工程**;无 `v*` release tag。
5. **付费点与免费竞品正面撞车**:AI 搜索、人脸、编辑(裁剪/旋转/缩放/调整)在 Lap **全部免费**;唯一供给独占的是 exotic 格式包。

### 3.4 一句话定位检验

可以成立的差异句只有一句:**「唯一把『商用可授权的人脸 + 中文原生语义搜索 + 冷门格式插件』装进一个零运维桌面应用的买断产品。」**
不能成立的句子:「离线」「本地 AI」「文件夹树」「百万级」——这些单独拿出来都会被 Lap/digiKam/Immich 当场反驳。

### 3.5 对 Part8 付费结构的附带修订建议

调研证据指向:**现有三插件付费组合的优先级是反的。**

- **保留付费:`exotic-formats`**。供给独占、无免费等价物、Part0 已判为首发正确项。
- **不建议把 AI / 人脸作为主付费点**。它们已被免费竞品覆盖,且当前未 gate;对已经免费开放的能力事后收费,正是 Part0 §3.3 自列的「必被贴 crippleware」反模式。
- **不建议把编辑作为付费点**(D-112 现裁决)。Lap 免费提供裁剪/旋转/翻转/缩放/调整;free 版不给编辑会在评测里被直接判为阉割。若坚持,应把它并入「高级包」而不是单独标价。
- **建议的付费重心**:①exotic 格式包;②官方签名安装包 + 托管更新 + 官方支持(一次性或年度);③「支持者 license」(Immich-FUTO 式自愿付费,可覆盖核心);④**B2B 商用授权/合规包**——「商用可授权的人脸栈 + 全程可审计」正好是企业与半专业用户愿意付钱、而免费竞品给不了的东西。
- ImageGlass 是最近的可行先例:单人维护、14.3k★、GPLv3 Classic 免费 + 付费 Pro/商用许可,**付费点很窄但成立**。

> 本节是对 Part8 定价结构的修订建议,需用户单独拍板;不随 §4 的开源裁决自动生效。

## 4. 开源边界裁决:部分开源 vs 完全开源

### 4.1 先厘清「开」的是什么

「部分开源」在本仓的实际含义比字面小得多。读 `copy.bara.sky` 与代码后确认:

- 公开投影**只排除一个目录**:`crates/scrollery-pro/**`(另加 `docs/**`、`.agents/**`、`AGENTS.md` 与同步配置)。
- `crates/scrollery-ai-core`(5,534 行)、`scrollery-plugin-api`(215 行)、`scrollery-exotic-trust`、`scrollery-free-stub`(69 行)、`exotic-protocol`、`exotic-workers`、`src-tauri/src/ai/**`(clip/face/face_pipeline)、`src-tauri/src/editing/**` **全部已在公开投影内**。
- 因此:**AI 管线、人脸管线、编辑、插件协议、验签原语、免费桩,都已经开源了。**

### 4.2 实测:当前闭源层几乎不构成护城河

`crates/scrollery-pro/src/lib.rs`(唯一闭源源码文件,**约 150 行**)的内容是:

1. `include_str!` 生产公钥 keyset(是**公钥**,不是私钥);
2. keyring 读写 token;
3. 调用**开源** `scrollery-exotic-trust` 的 `verify_token` / `evaluate_token`。

三点推论:

- **算法不在闭源层**:Ed25519 验签原语本身开源。闭源层没有可保护的技术。
- **私钥不在任何地方**:按设计私钥离线/HSM,永不入二进制——开不开源都一样。
- **免费桩可被 fork 一行改掉**:`scrollery-free-stub` 是开源文件,`evaluate()` 恒返回 `Unlicensed`;fork 改掉这个返回值即可自解锁。Part0 §10.3 声称的「stub 无可绕过路径」经代码复核**不成立**。

**真正的护城河与源码无关**:付费载荷(ONNX 权重 / exotic worker 包)不公开分发 + 官方签名私钥离线。这两条在「完全开源」下同样成立。

而闭源层有**三项实际成本**:
- **维护成本**:Copybara INTERNAL 标记剥离 + `FORBIDDEN` 禁词 verify + `oss-gate` 发布门 + free-stub/pro 双构建 + 文档处处区分公开/私有——对单人维护是纯开销,且每次同步都是一次泄漏风险演练。
- **叙事成本**:一个以「隐私 / 完全离线 / 可审计」为最强卖点的产品,留一个「不能看的信任根」,是在用最贵的资产换最便宜的保护。
- **法律成本**:CLA 已签、再授权权已在手;反而多一层写「闭源商业组件」的条款维护。

### 4.3 三条路线的证据对照

| 路线 | 含义 | 证据 | 判语 |
|---|---|---|---|
| **A 维持现状(部分开源)** | 藏 `scrollery-pro`(~150 行)+ 付费载荷 | 保护≈0(§4.2);Chevereto 同类模式仅 990★;Redis/MongoDB/n8n/Sentry 的许可收紧未摧毁其业务,但那是因为**有筹码的成熟产品**,不是小项目剧本 | 花成本买不到东西 |
| **B 源码全开 + 商业边界后移**(**建议**) | MPL-2.0 覆盖全部第一方源码;付费=载荷 + 官方签名/更新/支持 + 商标 | **ImageGlass**(GPLv3 Classic 免费 + 付费 Pro,单人 14.3k★);**Immich+FUTO**(AGPL 不变,2024-11 起卖**可选 product key ≈US$24.99/年**,社区接受且无功能墙);**Eagle**(闭源一次性约 $30,2017 年卖到今天);Sublime Text/Beyond Compare/REAPER(钱来自**本体/官方构建**,不来自插件) | 保住全部真实付费点,同时拿到可审计叙事 |
| **C 全部免费(含权重)** | 连付费载荷也开放,靠捐赠 | Immich 有 114k★ + FUTO 资助;Lap 已占住免费位;本产品 1★;捐赠维生成功率低(见 FOSDEM 2026 "Free as in Burned Out") | 在零社区时收入≈0,不可逆 |

**三条与本案直接相关的机制性结论**(来自本路调研):

1. **用户为"省心"付费,不为源码付费**。签名构建、自动更新、打包好的模型/格式包、官方支持,才是付费锚点;"源码不可得"从未被证明是转化来源。
2. **开源本身不产生分发**。Obsidian 插件作者的公开实测是「~7 views/day、共 2 单」,并断言「distribution is the whole problem」;本产品公开镜像 1★ 是这条规律的现场标本。**开源是必要条件,不是增长引擎。**
3. **AGPL 对本地桌面二进制几乎没有防白嫖能力**(Jellyfin 从 GPL 的 Emby 分叉即证据),其主要效果是吓退企业与商业集成者;若要既开源又不劝退生态,**MPL-2.0 是比 AGPL 更合适的选择**(文件级 copyleft、允许与闭源文件链接、商店摩擦最小)。本产品已选 MPL,方向正确。

### 4.4 建议:采用路线 B

**裁决建议:源码完全开源(MPL-2.0 覆盖全部第一方源码,含 `crates/scrollery-pro`),把商业边界从「源码」后移到「付费载荷 + 官方渠道 + 商标」。**

对外可诚实表述为:

> 第一方源码 100% 开源、可审计;付费购买的是官方签名构建、持续更新与托管分发、付费模型/格式包,以及官方支持。

理由归纳:
1. 闭源层不提供可测量的保护(§4.2),去掉它不损失任何真实付费点。
2. 它换来对本品**最强卖点**的完整支撑:隐私产品最贵的资产是「你可以自己看」。
3. 它消除单人维护下的同步门禁/双构建负担与泄漏风险面。
4. 付费载荷与官方渠道仍是真壁垒:fork 可以改 gate,但拿不到权重/格式包、签不了名、也拿不到更新通道——与今天完全一样。
5. 商标 + `TRADEMARK.md` 继续阻止 fork 冒名,与源码许可无关。

**为什么开源 gate 代码不会降低盗版门槛**(必须写清,否则容易被误读为「白送」):Part0 §8.3 已经自认「纯本地离线软件防破解只有威慑与抬高成本,无绝对阻断」,并指出「**enc_seed 按 plugin 共享 + token payload 明文可读 → 任一付费 token 泄漏即泄漏插件级模型密钥**」。也就是说,破解门槛从来是「拿到一个有效签名 token + 付费载荷」,而不是「看不到 150 行验签胶水」。把这 150 行公开,不改变这条门槛;真正要守的是**私钥(离线)与载荷分发(授权 CDN)**——两者都不在源码里。

### 4.5 反方论证与触发条件

**反方(保留意见)**:
- 若实测证明「闭源/独占」确实是付费转化的主因,路线 B 会削弱说服力;但当前**没有任何证据**支持这一点,而开源不可逆——所以这个决定必须在发布前定,不能等数据。
- 若未来确有必须闭源的重型商业组件(云同步 / 团队协作 / 企业合规服务),**为那个组件新建闭源 crate 是合理的**;不要把边界浪费在今天的 150 行上。

**触发重评的条件**:
1. 发布后 12 个月,付费转化数据显示核心转化来自「源码不可得」而非「载荷/签名/支持」→ 重新评估。
2. 实测中文语义搜索相对 Lap 无显著优势 → §3.1 第 2 条作废,整体定位需重估。
3. `exotic-formats` 插件无人付费 → 插件商业模式整体重估(与开源边界无关,但同属本线)。
