## 2. 数据流全景

```
 你(+Claude) commit
      │
      ▼
┌─ scrollery-private ──────────────────────────────────────────┐
│  dev 分支 ──push──▶ 私有 CI（需实际可用的 runner）           │
│      │ CI 绿后 ff                                             │
│      ▼                                                       │
│  main 分支 ──push 触发──▶ sync-oss(PowerShell 快照+推送前扫描)    │
└──────────────────────────────────│───────────────────────────┘
        内部文件过滤:统一规则排除内部文档、配置、工具与缓存
        (代码与 Cargo.lock 原样投影,公开树与私有树同构)
                                   │
                                   ▼
┌─ scrollery(公开镜像) ────────────────────────────────────────┐
│  sync-staging ──▶ oss-gate(托管 ubuntu,公开仓免费):          │
│    前端+Rust workspace+独立 RAW 原锁验证+gitleaks│
│  全绿后 ──提升──▶ main（维护者快进同一已验提交；drift-alarm 核对作者）│
└──────────────────────────────────────────────────────────────┘

 scrollery-registry:scripts/exotic-internal-registry.mjs 产三件套 → 人工 push → 应用内商店经
   raw URL 拉取(编译期 PICASA_REGISTRY_BASE_DEFAULT 注入,运行时 PICASA_REGISTRY_BASE 可覆盖)
 scrollery-site:改 index.html → push main → Cloudflare Pages 自动部署 → scrollery.app
```

**方向铁律**:私有 → 公开单向;公开仓一切内容都是投影产物。想改公开仓的任何文件 = 改私有仓对应文件,走同步。

## 3. 分支模型与日常工作流

- **日常开发全部在 `scrollery-private` 的 `dev`**。commit 信息中文;每 push 自动跑五 job CI(零计费,本机)。
- **发布到公开树** = `dev` ff 到 `main`(`git push origin dev:main`),`main` push 自动触发 sync-oss → 公开 gate → 提升。日常无需操作公开仓。
- 本地快速验证(与 CI 同源):
  ```
  cargo fmt --check && cargo clippy --workspace --locked -- -D warnings && cargo test --workspace --locked
  npm run lint && npm run typecheck && npm test && npm run build
  node scripts/generate-notice.mjs --check     # 依赖变更后须重生成 NOTICE.md
  node scripts/check-rename-gate.mjs           # D10 改名门禁(active)
  ```
- **投影校验**：使用 `scripts/publish-oss.ps1` 共用入口导出指定已提交树，推送前扫描内容与元数据、核对提交树一致；公开门禁通过后才提升 main。操作与运行条件见 [同步现行说明](../refactor_2026/Part6_3c_Copybara同步配置草稿.md)。
- **发内测安装包**:`scripts/build-internal-installer.ps1`(编译期注入内测 keyset + registry base → MSI/NSIS)。
- **更新官网**:改 `d:\photoapp\scrollery-site\index.html` → push → 自动上线。

## 5. 密钥与凭据地图(在哪、干什么、红线)

| 凭据 | 位置 | 用途 | 红线 |
|---|---|---|---|
| `OSS_SYNC_DEPLOY_KEY` | 私有仓 Actions secret | 快照流程**只写公开仓**的 SSH deploy key | 永不给私有写权 |
| 内测签名 keyset | 本机 `.internal-signing/`(gitignored) | 签内测插件三件套 + license | 与生产信任根隔离;不入仓 |
| 生产 keyset | **尚不存在**——待离线机 ceremony([手册](2026-07-06-D1-签发机与key-ceremony.md)) | 生产插件/license 信任根 | 私钥永不入仓/不进 CI/不出现在 fixture |
| updater 签名钥 | 本机 `.release-keys/`(dev 钥) | Tauri updater 工件签名 | Part7-T8 首发前转正换钥(换钥=既有安装断更新) |
| OS keyring | service=`scrollery`(常量在 `scrollery-plugin-api::KEYRING_SERVICE`) | license token / API key 存储 | 改 service 名=用户丢激活 |
| GitHub 凭据 | `gh` CLI 登录态 | runner 注册 token、API 操作 | registration token 用后即弃,不落盘 |

**公开面门禁**：任何公开 push 前扫描精确拟公开树与提交元数据；`oss-gate.yml` 在公开投影树运行前端、Rust workspace 与独立 RAW 的原锁检查/测试和公开历史扫描。源码检查不代表安装包验收。
