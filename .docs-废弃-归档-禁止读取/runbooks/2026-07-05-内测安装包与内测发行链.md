# 内测安装包与内测发行链(2026-07-05)

> **快照日期:2026-07-05。** 本文是内测(internal testing)发行链的设计记录 + 操作 runbook +
> 内测者指南。定位:让「安装 → 运行 → 商店下载插件 → 激活 → 冷门格式解码」全链可被真人走查,
> **不是**正式发行渠道(正式信任根/CDN/签名产线归 Part7-T13~T16 与 Part8)。
> 若后续密钥重铸/发行源迁移/①②注入点被 ③b/Part8 取代,须回此文补「已过时」标注。

## 1. 背景与决策

Part2/5/6 已把 exotic 插件平台全栈建成(商店 UI、gate/激活、下载安装、worker 运行时),但端到端
链路存在三个**物理断点**,导致无法产出可真machine测试的安装包:

| 断点 | 现状(2026-07-05 前) | 裁决 |
| --- | --- | --- |
| 信任根 | 内置 keyset 为「私钥已弃」占位公钥(fail-closed),`_note` 预告「发布前由发布流水线替换」 | 做**编译期 keyset 注入**(build.rs 装配 OUT_DIR),即该替换机制的提前落地;运行时零旁路(SEC-02 不动摇) |
| 发行源 | `DEFAULT_REGISTRY_BASE_URL` 为 `.invalid` 占位;运行时 env 覆盖不适合装机用户 | `option_env!("PICASA_REGISTRY_BASE_DEFAULT")` 编译期默认值;运行时 `PICASA_REGISTRY_BASE` 优先级不变 |
| 签发端 | dev 生成器(D1 本地原型)是 file:// + debug-only 双旁路形态 | 派生**内测生成器**(release worker + 真 HTTPS)+ **license 签发脚本**;dev 与内测共用 `scripts/lib/exotic-signing.mjs` |

**关键性质:内测链没有任何安全豁免。** 验签/sha256/zip 白名单/防回滚与生产完全同一套代码;
内测与生产的差异被收敛为两个「部署配置」(信任根公钥集 + registry 基址),二者均编译期固化。

**托管分叉(用户拍板 2026-07-05):新建公开仓 raw URL。** psd-worker 源码本就随 Copybara 在公开
镜像树,编译产物公开托管不构成源码/密钥泄漏;工件由内测键签名,与未来生产信任根隔离。

## 2. 构成件

| 件 | 位置 | 说明 |
| --- | --- | --- |
| keyset 编译期装配 | `crates/scrollery-exotic-trust/build.rs` + `src/crypto.rs` | 默认复制仓内占位集(逐位一致);`PICASA_EXOTIC_KEYSET_FILE` 注入替换(env 名按 R2-7 §2-E「缓改」裁决保留旧词根);注入时构建日志留 `cargo:warning` 痕 |
| registry base 编译期默认 | `src-tauri/src/ipc/exotic_commands.rs` `DEFAULT_REGISTRY_BASE_URL` | 优先级:运行时 env > 编译期 option_env > `.invalid` 占位 |
| 共享签名库 | `scripts/lib/exotic-signing.mjs` | Ed25519 密钥/keyset/存储式 zip/包清单对/index 签名/license token 原语;dev 与内测生成器同源 |
| dev 生成器 | `scripts/exotic-dev-registry.mjs` | 行为不变(file:// + debug 旁路),改为引用共享库 |
| 内测生成器 | `scripts/exotic-internal-registry.mjs` | release worker + HTTPS package_url + 内测键;keyset = 占位集+内测键**超集**(注入态下既有测试断言仍成立) |
| license 签发 | `scripts/exotic-issue-license.mjs` | `payload.sig` token(默认永久,`--days N` 可限期);key_id `license-internal-2026-07` |
| 构建脚本 | `scripts/build-internal-installer.ps1` | 固化两个注入 env + `npx tauri build` + 产物列举 |
| 产物核验测试 | `src-tauri/src/exotic/installer.rs` `internal_registry_artifact_tests`(#[ignore]) | 生产同套校验链核验内测三件套(无 dev 开关——即装机形态) |
| 内测私钥/产物 | `.internal-signing/`(gitignored) | pem 私钥仅签发机本机;丢失=重铸内测信任根(允许) |
| 发行源仓 | `github.com/gfgjs/scrollery-registry`(公开) | `exotic/v1/{index.json,index.sig,exotic-image-psd.zip}`;`.gitattributes * -text` 钉死字节精确 |

内测密钥体系(三层隔离):`dev-*-local`(.dev-registry,debug 专用)/ `*-internal-2026-07`
(.internal-signing,内测安装包)/ 生产键(尚不存在;`exotic-keyset-prod.json` 随 ③b 入 pro,
私钥离线/HSM——内测工具链**永不**经手)。

> **2026-07-11 行为变更(debug 自取)**:两个 build.rs(exotic-trust 与 pro)在**无显式
> `PICASA_EXOTIC_KEYSET_FILE` 注入且 PROFILE=debug** 时,若本机存在
> `.internal-signing/internal-keyset.json`(仅验签公钥)则自动以其为编译期信任根,
> 构建日志留 `cargo:warning=…(debug 自取内测集)` 痕。动机:dev 构建此前从未被注入,
> 信任根恒为 fail-closed 占位集,已装的内测签名插件(psd)在 dev 里恒 `bad_signature`;
> 该缺口长期被彩排期旁路掩蔽,cargo clean 后暴露(签发机=开发机的天然产物)。
> Release 构建、CI runner 与无 `.internal-signing/` 的机器不受影响(仍占位集或显式注入);
> SEC-02(Release 无运行时旁路)不动。首次创建 `.internal-signing/` 后需手动重建一次
> (build.rs 对不存在文件不留 rerun 声明,避免每次构建都重跑)。

## 3. Runbook(签发机 = 本机)

```powershell
# A. 重建/续期 registry(worker 更新、index 60 天到期前,任一触发)
cargo build --release -p psd-worker
node scripts/exotic-internal-registry.mjs        # 三件套落 .internal-signing/registry/,seq 自增
cargo test -p scrollery --lib internal_registry_artifacts -- --ignored   # 产物自检
# 把三件套复制进 scrollery-registry 仓的 exotic/v1/ 并 push(路径须与发行基址一致)

# B. 给测试者签发激活 token(每人/每期一枚,永久或 --days 30)
node scripts/exotic-issue-license.mjs            # 输出整行 token,交给测试者

# C. 构建内测安装包
node scripts\exotic-internal-registry.mjs        # 若 keyset 尚未生成
scripts\build-internal-installer.ps1             # 产物在 target/release/bundle/{msi,nsis}/
```

注意:换了 `internal-*.pem` 私钥(重铸)后,**必须**重跑 A(keyset/三件套重签)+ C(重建安装包),
旧安装包对新 registry 会验签失败(fail-closed,预期行为)。

**序号语义(2026-07-05 病历 #1 后)**:index `sequence` 与 `package_sequence` = 生成时刻
epoch 秒——设备端防回滚基线(appdata `exotic/registry/index.seq`)是**跨签发源共享**的
(dev 与装机 release 同 identifier 同 appdata),小计数器序号会被历史基线拒收
(`rollback_rejected`),且计数器文件跨机重置会令已装设备永久拒收;epoch 秒无状态、
天然全局单调。展示版本号(1.0.N)仍用本地小计数器,权威排序以 package_sequence 为准。

## 4. 内测者指南

1. **安装**:运行 `Scrollery_0.1.0_x64-setup.exe`(NSIS)或 `.msi`。(产物名随 `tauri.conf.json` 的 `productName`——2026-07-06 R2-7 改名前构建的包名为 `Picasa Next_0.1.0_…`;换新包须先卸旧版,见 [CHANGELOG](../../CHANGELOG.md) 更名条目的升级路径。)未做代码签名(T13-T15 未至),
   SmartScreen 会提示「未知发布者」——「更多信息 → 仍要运行」。
2. **基础走查**:选目录扫描 → 网格浏览/滚动 → 双击看图(JPEG/PNG/HEIC 等常规格式走内置管线)。
3. **插件商店**:设置/侧栏进「插件」→ 刷新(拉取内测 registry,应出现「PSD 图像引擎」)。
4. **激活**:粘贴发给你的 token → 激活成功(授权态 Licensed)。
5. **安装插件**:点安装 → 下载(约 0.6 MB)→ 验签解包 → 完成。
6. **冷门格式解码**:把 `.psd` 文件放入已被扫描的目录(或新扫一个含 PSD 的目录)→ 网格中 PSD
   应出缩略图(psd-worker 进程解码)。
7. **AI/在线能力**(可选):模型按需从 HuggingFace(含镜像回退)下载;校对功能需自备 OpenAI key。

已知边界(如实告知,勿当 bug 报):自动更新不可用(内测包无 updater 配置);「主题」目前是内置
明暗切换,无主题市场;产品名/图标为占位(R2-7 未拍板);安装器未签名。

## 6. 与红线的对照

- 生产私钥/凭证永不入公开仓:未触碰——本链只使用内测键;占位集照旧;生产私钥仍不存在（公钥集可公开,非秘密）。
- Release 无验签/授权旁路(SEC-02/D8):维持——注入发生在编译期,运行时代码路径零新增;
  `PICASA_EXOTIC_DEV_*` 两旁路仍 debug-only。
- 签名凭据不入 CI:维持——内测私钥仅本机 `.internal-signing/`(gitignored),CI 无内测签名步骤。
- pro 不入公开仓:未触碰——发行源仓只含编译产物(其源码本在公开树)与签名工件。
