## 错误账
| 错误 | 尝试 | 解法 |
|------|------|------|
| 4K/5000 项密度 harness 复用 SVG 导致全量 `Image()` fallback，缓存仅 194 格、1 FPS | 首轮标准往返基准 | 密度场景改用小型 raster 走真实 `createImageBitmap` 路径；该轮数据作废，不用于结论 |
| 整屏自适应预取在快滚闸门放行的同一 draw 内同步启动数千个 fetch/decode，极速滚动出现“顿一下再追帧跳过一段” | 用户真实图库复验第一版 | 可见区与预取共用 64 个在途槽；预取改为每片最多 64 项/2ms 的可续跑 idle iterator，滚动或 gate 变化立即取消旧计划 |
| C 版冷区几乎无改善，只把替换方向从固定上→下改成随滚动方向 | 用户真实图库复验 | 撤销视觉绘制反转；D 版继续验证 8 槽快滚通道与单段 WebP 处理 |
| D 版冷区仍无改善，但极速滚动已无顿挫 | 用户真实图库复验 | 撤销无收益的 8 槽与单段 WebP 实验；保留 64 全局在途上限、idle 分片和扩容 LRU。冷区转交 120/240 多档源方案 |
