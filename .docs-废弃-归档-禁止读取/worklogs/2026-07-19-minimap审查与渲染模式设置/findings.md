# 发现与决策:minimap 审查与渲染模式设置

## 需求
- 审查画廊右侧 minimap 相关代码。
- 简单且确定的问题直接修复,拿不准的列清单交由用户裁决。
- 新增设置:仅渲染色块 / 渲染缩略图;选择缩略图时显式提醒加载会有延迟。

## 发现
- 当前 minimap 位于 `src/components/media/MinimapAxis.vue`,由 `MediaGrid.vue` 在无缝分组或不分组场景挂载。
- 显隐已通过 `app_config.seamless_minimap` 持久化;渲染模式尚无独立配置。
- 工作区已有图片编辑线的未提交改动,包含中英文 i18n 文件;本任务须仅做精准增量编辑并保留既有修改。
- `role="scrollbar"` 原先不可聚焦且无键盘处理;已补 `tabindex`、可见焦点及方向键/Page/Home/End 导航。
- 滚轮转发原先忽略 `deltaMode`,且同帧事件都以旧 `currentY` 为基准导致吞量;已归一像素/行/页并在待提交位置连续累加。
- 缩略图缓存签名原先不含 `cacheDir`,缓存目录迁移后可继续显示旧位图;现将目录纳入身份并在变化时中止旧请求、清缓存。
- “仅色块”切换原先没有模式概念;现显式中止在途图片 fetch、释放 bitmap,启动配置水合前也守在色块态以杜绝偏好值晚到抢跑。
- chunk LRU 删除 `loading` 项后,旧 Promise 原可迟到写回绕过 `MAX_CHUNKS`;共享 `'loading'` 还会让旧 catch 误删新请求。现改逐请求 Symbol token,只有当前 owner 可落地/删除。
- 纯色块与缩略图两模式共用 placeholderColor 底层;缩略图绘于色块上,透明图也不再露出透明画布。

## 用户裁决与落地
- 用户允许已有 scrubber 的日期/分组视图使用 minimap。现以会话态轴模式按钮切换“时间轴 / Minimap”，默认仍为时间轴；无 scrubber 数据时自动落到 minimap。
- 用户要求微缩略图失败重试。现初次失败后按 400ms、1200ms 最多额外重试 2 次；预算耗尽后本资源签名保持色块，不触发主缩略图自愈，避免重生成与 IO 风暴。
- 重试请求以每次 Symbol token 绑定所有权；模式/目录换代后旧 fetch/decode 迟到不得清除或提交新请求状态。
