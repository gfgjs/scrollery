## §1 背景:目标是「廉价迭代 + 实测比较」,不是冻结

> 🔴 用户约束([[no-contract-freeze-during-dev]]):**开发测试阶段不冻结任何契约**——不该把未经实测比较、未经市场验证的东西定死。这取代了 Part5 T7 与 Part0 §4 的「发布即冻结」立论。

本设计要同时满足两条约束,且二者**同向不冲突**:

- **A · 稳定可用**:多选当前三症状(G1)+ 竞态(G2)必须修好,交互**当下**稳定、可用、不丢选区。这是「能用」,不是「定死」。
- **B · 可插拔多模式 + 可演进([[selection-modes-stay-decoupled]])**:选择是核心交互,哪种 UX 模式(橡皮筋框选 / lasso / additive-range / 按内容或语义选)最优需**实测比较 + 市场验证**;**所有手势语义、接口外形在开发期都可改**,不焊死任何一种。

### 1.1 化解思路:两层模型,**两层都临时可改**

把选区拆成「协议层」与「策略层」——**不是为了冻结协议层,而是为了让改动局部化、让多方案能并存比较**:

| 层 | 内容 | 性质 |
|----|------|------|
| **协议层 Intent** | 物理手势 → 抽象选择意图的**映射**;选择状态对消费者暴露的**外形** | 临时、可版本化演进;改它影响面**收敛**(只动调度骨架,不散落到各消费方) |
| **策略层 Mode** | 意图如何作用到状态的**解释**(additive vs replace、range 语义、框选命中规则) | 🔌 可插拔;换/加模式 = 换/加 strategy,**不动消费方、不动后端命令** |

- **为什么仍分两层**:不是要冻结协议,而是要把「选择逻辑的变化」关进**两个可控的盒子**——改交互语义只动协议层调度,改某模式行为只动策略层。这样无论是修 bug、试新手势、还是 A/B 比较两种框选,改动都**便宜且不外溢**,正好服务「实测比较」。
- **策略层可插拔的直接收益**:能**同时**实现 classic 与候选模式,在真实使用中比较、灰度、让用户选——这是「市场验证」的落地机制,与「冻结」相反。
- 协议层若实测后要改(增减意图、调整手势槽位语义),**允许改**;代价被两层结构压到最小。发布后也只在有数据支撑时才逐步收敛,而非提前定死。

## §3 核心设计:SelectionState 表示(脱离 DOM 的根)

把选区从「DOM 节点集合」改为「稳定 id 的判别联合」,**镜像后端 `SelectionDescriptor`**:

```ts
// 选区状态 — 前端镜像后端 SelectionDescriptor,消费方不感知 kind 差异
export type SelectionState =
  // 显式枚举:中小规模,直接持有 id 集
  | { kind: 'explicit'; ids: Set<number> }
  // 全选语义:百万级不物化 id,只存「全选 + 排除集」标记
  | { kind: 'all'; excluded: Set<number> }
```

消费方只通过**抽象访问器**读选区,永不直接 `for..of selectedIds`:

```ts
isSelected(id): boolean
  // explicit → ids.has(id);all → !excluded.has(id)
selectedCount(totalViewCount): number
  // explicit → ids.size;all → totalViewCount - excluded.size
isEmpty(): boolean
toDescriptor(view: ViewDescriptor): SelectionDescriptor
  // explicit → { kind:'Explicit', ids:[...] }
  // all      → { kind:'SelectAll', view, excludedIds:[...] }
```

- **解决 Ctrl+A 百万级**:`all` 态不物化 id,内存恒定;展示「已选全部 N 项」(N 由 layout summary 的总数或 `count_selection` 给)。
- **解决执行落点**:`toDescriptor()` 直出后端 `SelectionDescriptor`,批量命令(S4 迁移后)直接吃,不经前端枚举百万 id 过 IPC。
- **`all` 态的 view 来源**:由 `uiStore`(scope:activeSmartAlbum/activeDirectoryId/activeCollection/activePersonId)+ `filterStore`(filter)+ sort 组装当前 `ViewDescriptor`(§5.2)。

> ⚠️ 过渡期(S4 落地前):`all` 态可由前端调 `get_view_ids` 取布局序全集、减去 `excluded` 物化成 `Explicit` 喂旧命令——**但仅作过渡**,百万级会退化为 IPC 传大数组,S4 落地后立即切回描述符直传。设计上 `toDescriptor()` 是稳定出口,过渡逻辑封装在调用侧、不污染状态模型。

## §4 顺序来源:布局序 flat_ids(脱离 DOM 的第二支柱)

range / select-all 的「顺序」与「全集」必须来自**布局序**,不来自可视 DOM。

### 4.1 新 composable `useViewIds`

```ts
// 持有当前视图的布局序全集 id + O(1) 索引,随 layout_version 失效重取
const viewIds = shallowRef<number[]>([])           // 大数组用 shallowRef,避深代理
const idIndex = new Map<number, number>()          // id → 布局序 index,O(1)
async function refresh(layoutVersion: number)      // invoke get_view_ids;ViewStale 则清空待下次
function indexOf(id): number                        // idIndex.get(id) ?? -1
function rangeBetween(aId, bId): number[]           // 用 idIndex 取 [min,max] 切片
function allIds(): number[]                          // viewIds(过渡期物化用)
```

- 接 [IPC.GET_VIEW_IDS](../../src/constants/ipc.ts)(**需新增常量** `GET_VIEW_IDS: 'get_view_ids'`)。
- `shallowRef` 持百万数组(项目前端规约:大数组用 shallowRef 避 Vue 深代理开销)。
- `layout_version` 来自 `mediaStore`(布局摘要已有 version);布局失效 → `refresh` 重取 → 旧 range 锚点失效保护。

### 4.2 三症状如何被根治

| 症状 | 旧病灶 | 新解 |
|------|--------|------|
| G1① Shift 跨视口失效 | `indexOf` 在仅可视 `orderedIds` 上 = -1 | `useViewIds.rangeBetween` 在布局序全集上算,跨视口必命中 |
| G1② Ctrl+A 只选一屏 | `selectAll(getAllVisibleItemIds())` | Ctrl+A → `SelectionState = { kind:'all', excluded:∅ }`,不物化 |
| G1③ 框选只选渲染节点 | `applyDragRange` querySelectorAll 可视 DOM | 框选**命中**仍用 DOM(只能命中可见),但**range 结果**用 `rangeBetween(锚点, 命中点)` 在布局序上扩展 → 跨已滚动区间稳定 |

> 框选的本质约束:指针只能悬停在**可见**项上,所以「命中点」必然可见;但「锚点→命中点」之间可能横跨已滚出屏幕的项,用布局序 index 算 range 即可把不可见项纳入,无需它们在 DOM 里。

## §5 手势 → 意图 当前协议词汇表(T7,临时可改)

> 🔴 **不冻结**([[no-contract-freeze-during-dev]]):以下是**当前临时协议**,开发期可随实测/反馈增改手势槽位或意图语义。两层结构保证这类改动影响面收敛。新增模式既可新增 `SelectionIntent` variant,也可在有数据支撑时调整既有槽位——**不预设「只增不改」的冻结约束**。

### 5.1 SelectionIntent(抽象意图,协议层)

```ts
export type SelectionIntent =
  | { type: 'replace'; id: number }                 // 单击:清空 + 选中单项
  | { type: 'toggle'; id: number }                  // Ctrl/Cmd+单击:翻转单项
  | { type: 'range'; anchorId: number; toId: number } // Shift+单击:锚点→目标布局序区间(并入)
  | { type: 'selectAll' }                           // Ctrl/Cmd+A:全选语义标记
  | { type: 'clear' }                               // Esc / 点空白:清空
  | { type: 'invert' }                              // 反选
  | { type: 'dragStart'; id: number; additive: boolean } // 框选起手(additive=是否叠加既有)
  | { type: 'dragOver'; toId: number }              // 框选移动到命中项
  | { type: 'dragEnd' }                             // 框选结束
```

### 5.2 手势 → 意图(当前映射,可改)

| 物理手势 | 意图 | 备注 |
|---------|------|------|
| 单击项 | `replace` | 单选;之后可拖移动(§5.3) |
| Ctrl/Cmd+单击 | `toggle` | 加/减单项 |
| Shift+单击 | `range`(anchor=lastClicked) | 跨视口靠 flat_ids |
| Ctrl/Cmd+A | `selectAll` | `all` 态,不物化 |
| Esc | `clear` | |
| 框选拖拽(空白起手) | `dragStart(additive=false)` → `dragOver*` → `dragEnd` | 起手在已选项上则 deselect 模式 |
| Ctrl+框选 | `dragStart(additive=true)` | 叠加既有选区 |

### 5.3 拖放手势(移动/复制,与选择手势**正交,同属当前临时协议**)

| 手势 | 行为 | 落点 |
|------|------|------|
| 左键拖项→文件夹 | 移动 | 走 `historyStore.moveMedia`(T6 撤销一致) |
| Shift+左键拖 | 复制 | 走 `historyStore.copyMedia` |
| 右键拖→文件夹 | 落点菜单(移动/复制/取消) | |

> 🔴 T6:现 `onMoveCopyConfirm`([MediaGrid.vue:1240](../../src/components/media/MediaGrid.vue#L1240))直接 `invoke('move/copy_media_items')` **绕过 historyStore 撤销** → 改走 `historyStore`,与 `performMediaDrop` 同路径。

## §6 可插拔机制:SelectionMode 策略(满足约束 B)

### 6.1 策略接口

```ts
// 一个选择模式 = 把 SelectionIntent 解释为对 SelectionState 的变换
export interface SelectionMode {
  readonly id: string                 // 'classic' | 'rubber-band' | 'lasso' | ...(未来)
  readonly label: string              // 设置页展示名
  apply(
    state: SelectionState,
    intent: SelectionIntent,
    ctx: SelectionContext,            // { viewIds, lastClickedId, totalCount }
  ): SelectionState                   // 纯函数:旧态 + 意图 → 新态
}
```

- `apply` 是**纯函数**(项目规约:优先纯函数、最小副作用)→ 易测、易换、无隐藏状态。
- **起步模式 `classic`**:实现 §5 的桌面照片管理器语义(单击替换 / Ctrl 翻转 / Shift 区间 / Ctrl+A 全选 / 框选),作为**当前默认起点**(非定死)。**现阶段只实现这一个 + 搭好 seam**——不预造未验证的模式(KISS);需要比较时再增,且 classic 本身也可随实测调整。
- 未来模式(rubber-band 增量框选、lasso 套索、semantic-select 按语义)= 新增一个实现 + 注册,**协议层与消费方零改动**。

### 6.2 注册与激活

```ts
const registry = new Map<string, SelectionMode>([['classic', classicMode]])
const activeModeId = ref('classic')   // 未来:从 config 读,设置页可切
```

- 现在只注册 `classic`;`activeModeId` 暂固定。**待实测比较/市场验证**时再:① 实现候选模式(可与 classic **并存**做 A/B);② 设置页暴露切换;③ config 持久化。这正是「不冻结、用数据选」的落地路径。
- 由于 `apply` 是纯函数且 `SelectionState`/`SelectionIntent` 外形**当前稳定**(可改但影响收敛),加模式**不触碰** `useSelection` 调度骨架、不触碰 MediaGrid、不触碰后端命令。

### 6.3 与既有 API 的迁移关系

`useSelection` 重构为:**手势采集层** + **`mode.apply` 调度** + **`SelectionState` 持有**。现有导出名尽量保留(`isSelected`/`clearSelection`/`selectedCount` 等)以减小 MediaGrid 改动面;`selectRange(from,to,orderedIds)` 等「物化 id 数组」签名改为内部走 `useViewIds`,对外简化。

## §9 验收标准

1. **Shift 跨视口**:滚动后 Shift+Click 选中锚点→目标的完整布局序区间(不再 -1 静默失效)。
2. **Ctrl+A 全库**:百万库 Ctrl+A 内存恒定,工具栏显「已选全部 N 项」;批量操作作用于全集(过渡期物化 / S4 后描述符直传)。
3. **框选稳定**:框选跨已滚动区间纳入不可见项;每帧不全量扫 DOM。
4. **竞态**:快速单击不被误判拖拽(详情可开);主画廊与语义结果选区互不串。
5. **撤销一致**:移动/复制经 historyStore,可 undo/redo。
6. **当前协议文档化(非冻结)**:§5 词汇表落为「当前临时协议」并回写 Part5 §3.1.4,明确标注开发期可改。
7. **可插拔 seam**:`SelectionMode` 接口 + registry 就位,`classic` 为当前起步模式;新增/替换模式无需改协议/消费方/后端(以一个 stub 模式单测证明 `apply` 可替换、可与 classic 并存)。
