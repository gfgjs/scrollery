  (worker 派发的 FaceDet 搬运 + faces_to_records)、`embedding` 字节序(vector_store/

## 3. worker_e2e 黄金向量改造(S3)

删 ort 后 harness 失去进程内参考侧。方案:**黄金向量对拍**——
1. S3 执行时(删除前最后一次双后端运行)把 8 图 + 3 查询的参考向量导出为
   `src-tauri/tests/golden/worker_e2e_vectors.json`(含 profile id/模型 sha 前缀,防错拍);
2. 之后 harness 只跑 worker 侧,与黄金向量对拍(阈值沿用 0.995;模型文件变更时黄金失效,
   由 sha 前缀检测并提示重生成流程);
3. 检索 top-1 一致性改为 worker 侧自洽(文本×图像打分排序稳定性);
4. ⚠️ 教训延续(memory `e2e-selfconsistent-blindspot`):黄金采样键须与生产 DB 连接
   验证(T18 后现场派生已闭合覆盖缺口,采样直接取 DB 键)。

## 5. 拍板项(无人值守裁决,记录备核)

1. **vram_probe 删除**(而非迁 ai-core example):一次性拍板工具,数据已归档。
2. **`ai_backend` 配置退役方式**:保留键但忽略值(日志提示),不做 schema 迁移——
   避免老配置库升级失败;一个版本周期后随例行清理删键。
3. **status 命令 provider/gpu 字段**:现状 SessionReady **不**回报 provider/gpu_name
   (仅 dims+caps),而 host 侧原值由进程内引擎初始化时持久化(worker 模式下变陈旧)。
   S2 时给 SessionReadyBody **additive 补 `provider`/`gpu_name` 回声字段**(手法同
   EncodeText/face 尺寸:serde default、不升版、不增 op),host 收到后写回既有
   `ai_provider`/`ai_gpu_name` config 键——status 命令读法零改动,冷启动前显示旧值/
   「待检测」。
